# 存货与应收账款质量·逐条挂源（cn-working-capital-quality）

`cn-earnings-note` 回答「利润好不好看」，本件回答**「利润是不是真的」**——同一批用户的下一个问题。

把存货、应收账款、合同资产三块的**余额、账龄、计提**逐条摊开，每个数字挂报表原句与锚。
**所有周转天数、增速、占比都必须回到报表原句**；原句没写又非要写，就标〔自算〕并交代分子分母
各出自哪句话。**不许拿两个数自己除出第三个，也不许拿两个数自己减出第三个。**

## 一、它管什么

| 管 | 不管 |
|---|---|
| 三块资产的余额、账龄、计提逐条挂原句 | 一份「经营质量良好／存疑」的概述 |
| 周转、增速、占比只认披露原句 | 拿营收除平均应收算周转、拿本期减上期算增速 |
| 自算的数单列并交代分子分母 | 把自算的和披露的混在一列，读者分不清哪个是编的 |
| 「计提」与「余额」分两行 | 拿账面余额减坏账准备自己得出账面价值 |
| 公告没写的写「未取到」 | 用常识、行业均值或推断补上 |

**切割句**：本件只做存货、应收账款、合同资产三块的质量。已出财报的逐数点评归 `cn-earnings-note`；
商誉减值归 `cn-goodwill-impairment-risk`；应收保理与 ABS 出表归 `cn-restructuring-tracker`。

## 二、三条不许自己减（本件的红线）

这三条是本件存在的理由。它们看起来都是「小学算术」，但报表里每一个都有陷阱：

1. **账面价值 ≠ 账面余额 − 坏账准备**。报表可能在同一个附注里既给余额、又给准备、又给账面价值，
   三个数各自独立；你自己减出来的那个数，可能漏了核销、可能口径不同（合并／母公司、期末／平均）。
   **除非报表同一句写了账面价值**，否则只能分两行照抄，不许合成一个数。
2. **存货跌价准备的「本期计提」≠「期末余额」**。期末余额是累计口径，本期计提是流量口径，
   中间还有转回、转销、汇率变动。拿一个推另一个，就会得出「本期计提大增」这种假结论。
3. **账龄只披露金额、没披露占比时，占比不许自己算**。账龄表的分母可能是账面余额、
   可能是扣除单项计提后的余额；分母选错，整张账龄结构读出来的风险画像就是错的。

## 三、五道机检

```
WC-STRUCT   五节齐且有序 · 每节至少一项 · 申报数两向对齐
WC-ANCHOR   原句非空 · 锚值非空（只剩 [S1] 视同空）· [S#] 能在来源索引里找到 · 来源行带 URL 与检索日
WC-NOSELF   周转/增速/占比/账龄占比/账面价值：原句没有就必须标〔自算〕并交代分子分母；两个数不许自己相减
WC-GAP      未取到两向点名 · 零缺口须显式写「无」· 禁「不适用／无此项／无需披露」
WC-LINE     红线四道：造假与暴雷 · 预测 · 评级目标价 · 建议关注
```

`WC-NOSELF` 是本件的承重格，判两件事：

- **一个数是怎么来的**。原句里没有这个数（百分比、天数），就必须标〔自算〕并写
  `分子：<哪句话> [S#]｜分母：<哪句话> [S#]`，缺任何一边即发。标了〔自算〕但只写分子不写分母，
  也发——只交代一半，读者仍然没法复核。
- **两个数不许自己相减**。`账面价值 = 账面余额 − 准备` 这种写法直接发，除非原句里就有账面价值。

**一行只归一个码**。一行既没原句又没标〔自算〕，那是「自算未标」（`WC-NOSELF`），不是
「原句为空」（`WC-ANCHOR`）；写了「不适用」归 `WC-GAP`。三种码各管各的行，避免同一缺陷报两次——
fixer 看到两条会以为要改两处。

## 四、数据通道

真实任务走通道正路：先看目录，再取定期报告正文与附注表格。

```bash
# 1) 看目录，拿 MCP 端点
curl -s https://cuecue.cn/api/mcp-catalog | head -c 500

# 2) 按 MCP 协议握手，确认三枚工具在场
curl -s -X POST "$MCP_ENDPOINT" -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

确认 `parse` / `get_parse_status` / `read_result` 三枚在场后：`parse` 把报告 URL 或本地路径交给通道
→ `get_parse_status` 轮询 → `read_result` 取正文与附注表格。

**零通道降级**：没有通道时先排骨架，再逐行补。

```bash
python3 -B scripts/make_outline.py --sources 材料清单.jsonl --out 骨架.md --subject 示例股份
```

清单每行必需 `title` / `url` / `asof`（检索日 `YYYY-MM-DD`）三键；`id` 可省，缺省按行序给 S1、S2…。
坏行（非法 JSON／缺键／日期不合形）**逐行点名不采信**；一条可用行都没有退 1，空清单不出骨架。
**骨架过不了机检是设计**——占位行会红，提醒你补完再交，不让空壳冒充成品。

**零 key 降级**：没有 `CUE_API_KEY` 时只走用户直供的财报与本地文件。代价是取不到渠道侧的附注表格
解析，锚只能落在用户给的那份上，跨期与跨表核对做不了。

## 五、怎么跑

```bash
# 机检一份质量卡
python3 -B scripts/check_working_capital.py 质量卡.md

# 自测：好样须过，坏样五枚各只发自己那道码
python3 -B scripts/check_working_capital.py --selftest

# 离线样例三档（零网络、零计费、30 秒内）
bash scripts/fixtures/run_fixtures.sh
```

退码：`0` 全过；`1` 有发红；`2` 用法错；`3` 文件读不了或空稿。

## 六、样例

`scripts/fixtures/` 下 1 枚好样 + 5 枚坏样，每枚**只**发自己那道码：

| 文件 | 期望 | 造的是什么 |
|---|---|---|
| `good-working-capital.md` | rc=0 | 15 项、1 项未取到、三块齐 |
| `bad-1-struct.md` | WC-STRUCT | 第五节标题从「口径与未取到」改成「口径」 |
| `bad-2-anchor.md` | WC-ANCHOR | 原句空 + 锚只剩 `[S1]` 缺定位 |
| `bad-3-noself.md` | WC-NOSELF | 周转天数裸写、账龄占比未标、账面价值自己减 |
| `bad-4-gap.md` | WC-GAP | 「不适用」+ 申报未取到数比正文多 |
| `bad-5-line.md` | WC-LINE | 大额减值／财务造假／目标价 |

`run_fixtures.sh` 三档：① 自测；② 样例（好样 rc=0，坏样各自只发其码）；③ 边界形制
13 条**正反对照**——在好样上逐行替换，该红的红、该不红的不红（自算交代清楚、原句含账面价值、
账龄含占比、免责句里的「投资建议」不误红、事实句里的「较上年同期」不误红、零缺口写「无」），
另加 `empty` 与 `nofile` 两条走 rc=3。

## 七、红线（随套件）

不判财务造假；不判暴雷与变脸；不预测；不给评级与目标价；不写「建议关注」；
不承诺收益；不代拟、不代算结论、不代客；不裁断会计处理是否合规。

判断类问题一律 `[待人工]`。

## 八、工件接口

- `consumes: [parsed-doc]` —— 吃 omni-reader 解析出来的定期报告正文与附注表格。
- `inputs: [announcement-doc, disclosure-file]` —— 公告原文与披露文件（原始入口）。
- `produces: [structured-note]` —— 在册且已有下游消费者。

本件**不产出** `change-brief`（该名全仓 0 消费者）。也不登记分红回购减持、重组进度、商誉或质押明细——
那些各有归口件。

## 九、已知边界

- `WC-NOSELF` 判「数能回到本行原句，或标了〔自算〕并交代分子分母」，**不判分子分母那两个数本身对不对**。
- 周转天数基准（360／365）报表没写时，本件不替你选，进「口径」行点名「未披露」。
- 账龄按原句照登，不重算口径；合并与母公司两套表都在时，以披露主表为准并注明。
- `WC-ANCHOR` 判来源编号能在索引里找到，不判来源是否权威。
- `WC-GAP` 判缺口两向对齐，不判「未取到」的那一项是否真的无法取得。
