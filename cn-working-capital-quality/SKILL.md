# 存货与应收账款质量·逐条挂源

`cn-earnings-note` 回答「利润好不好看」，本件回答**「利润是不是真的」**——同一批用户的下一个问题。
把存货、应收账款、合同资产三块的余额、账龄、计提逐条摊开，每个数字挂原句与锚。

**主轴**：所有周转天数、增速、占比**都必须回到报表原句**；原句没写又非要写，就标〔自算〕并交代
分子分母各出自哪句话。**不许拿两个数自己除出第三个**。

**切割句**：本件只做存货、应收账款、合同资产三块的质量。已出财报的逐数点评归 `cn-earnings-note`；
商誉减值归 `cn-goodwill-impairment-risk`；应收保理与 ABS 出表归 `cn-restructuring-tracker`。

## 0. 是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 三块资产的**余额、账龄、计提**逐条挂原句 | 一份「公司经营质量良好／存疑」的概述 |
| 周转、增速、占比**只认披露原句** | 拿营收除平均应收算周转、拿本期减上期算增速 |
| 自算的数**单列并交代分子分母出处** | 把自算的数和披露的数混在一列，读者分不清哪个是编的 |
| 「计提」与「余额」是**两个数**，分两行 | 拿账面余额减坏账准备自己得出账面价值 |
| 公告没写的写「未取到」 | 用常识、行业均值或推断补上 |

## 1. 触发场景

- 用户拿到年报／季报／半年报，问「存货和应收是不是压得太多了」。
- 用户问「应收周转天数多少、账龄怎么分布、坏账计提够不够」。
- 用户问「存货跌价准备本期提了多少、期末还剩多少」。
- 用户要把三块资产的余额变化和计提节奏排成一张逐条挂源的卡。

## 2. 取数纪律

1. **只认披露原文**：每个数字都要能回到财报或附注的原句与锚（`[S#]`）。研报、新闻、行情软件一律不作来源。
2. **原句优先**：能抄原句就抄原句。原句里有这个数，就写「」原句；原句里没有，才走第 3 条。
3. **自算单列**：同比增速、周转天数、周转率、占比、账龄结构占比——原句没有时**必须**标〔自算〕，
   并写明`分子：<哪句话> [S#]｜分母：<哪句话> [S#]`。缺任何一边即判红。
   **自算的数与披露的数不许混排**：一旦标〔自算〕，读者就该看得出这是本件算的，不是报表写的。
4. **三个不许自己减**（本件最要紧的三条红线）：
   - 应收账款的「坏账准备」与「账面余额」是两个数，**不许拿「账面价值＝余额−准备」自己减**，
     除非报表同一句里写了账面价值。
   - 存货跌价准备的「本期计提」与「期末余额」是两个数，同上，不许拿一个推另一个。
   - 账龄结构只披露了金额、没披露占比时，**占比不许自己算**；要写就标〔自算〕并交代分子分母。
5. **口径要交代**：同比是跟哪一期比、周转天数是 360 天还是 365 天基准、余额是期末还是平均——
   原句写了的照抄，没写的进「口径」行点名「未披露」。
6. **未取到两向点名**：头部「共 N 项·未取到 M 项」只写一处，N 必须等于正文实际项行数，
   M 必须等于标「未取到」的行数；多报是虚报、少报是漏报，两个方向都发；零缺口必须显式写「无」。
7. **不写「不适用」**：把「未取到」写成「不适用／无此项／无需披露」是替报表下结论，不是登记。
8. **判断留人工**：质量好坏、是否异常、是否造假、后续会不会暴雷，全部进「[待人工]」。

## 3. 输出契约（五节）

```
# 存货与应收质量卡·<YYYY-MM-DD>

## 一、存货

- 存货账面余额：「<原句>」 锚：<出处> [S1]
- 存货跌价准备期末余额：「<原句>」 锚：<出处> [S1]
- 本期计提跌价准备：「<原句>」 锚：<出处> [S1]
- 存货周转天数：「<原句含天数>」 锚：<出处> [S1]
- 存货同比增速：「<原句含百分比>」 锚：<出处> [S1]

## 二、应收账款

- 应收账款账面余额：「<原句>」 锚：<出处> [S1]
- 坏账准备期末余额：「<原句>」 锚：<出处> [S1]
- 本期计提坏账准备：「<原句>」 锚：<出处> [S1]
- 应收账款周转天数：「<原句含天数>」 锚：<出处> [S1]
- 账龄结构（1 年以内）：「<原句含金额与占比>」 锚：<出处> [S2]

## 三、合同资产

- 合同资产账面价值：「<原句>」 锚：<出处> [S1]

## 四、计提与转回

- 本期计提合计：「<原句>」 锚：<出处> [S1]
- 本期转回或收回：「<原句>」 锚：<出处> [S1]

## 五、口径与未取到

- 共 12 项·未取到 1 项
- 未取到 1 项：存货周转天数——季报未披露周转天数，需回年报「经营情况讨论与分析」核对。
- 口径：同比为与上年同期比；周转天数基准未披露；余额为期末口径。
```

自算行的写法（原句没有该数时）：

```
- 存货周转天数：〔自算〕 182.5 天
  分子：营业成本「本期营业成本 1,825,000,000 元」 [S1]｜分母：平均存货「期末存货 980,000,000 元、期初 850,000,000 元」 [S1]｜口径：360 天基准，本件自算未经验证
```

## 4. 数据通道（以 live catalog 现值为准）

真实任务走通道正路：先看目录，再取定期报告正文与附注表格。

```bash
# 1) 看目录，拿端点
curl -s https://cuecue.cn/api/mcp-catalog | head -c 500

# 2) 按 MCP 协议握手，确认三枚工具在场
curl -s -X POST "$MCP_ENDPOINT" -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

确认 `parse` / `get_parse_status` / `read_result` 三枚在场后，`parse` 把定期报告 URL 或本地路径交给通道，
`get_parse_status` 轮询，`read_result` 取正文与附注表格。

**零通道降级**：没有通道时，先跑 `scripts/make_outline.py --sources <材料清单.jsonl> --out <骨架.md>`
把手上已有的材料排成五节骨架与待挂行位，再逐行补原句与锚。清单每行必需 `title`／`url`／`asof` 三键。
代价：骨架只有形状没有事实，**过不了机检是设计**，别把它当成品交付。

**零 key 降级**：没有 `CUE_API_KEY` 时本件只走用户直供的财报正文与本地文件，代价是取不到渠道侧的
附注表格解析，锚只能落在用户给的那份上，跨期与跨表核对做不了。

## 5. 合规红线（随套件）

- 不判财务造假（造假、虚增、财务舞弊、做假账、粉饰报表）。
- 不判暴雷与变脸（暴雷、爆雷、业绩变脸、将出现大额减值、存在重大风险）。
- 不预测（预计、将会、有望、即将、下半年将）。
- 不给评级与目标价（目标价、评级、买入评级、增持评级、强烈推荐、建议买入、建议卖出）。
- 不写「建议关注」「值得关注」「重点关注」。
- 不承诺收益，不代拟、不代算结论、不代客。
- 不裁断会计处理是否合规（是否构成财务造假、计提是否充分、是否应计提）。

## 6. 快速流程（用户视角）

1. 把年报／季报／半年报（URL 或本地文件，可多份）交给本件。
2. 没有通道时先跑 `make_outline.py` 排骨架，有通道时直接取正文与附注。
3. 逐项登记三块资产的余额、账龄、计提，每项挂原句与锚；原句没有的数标〔自算〕并交代分子分母。
4. 报表没写的进「未取到」，点名要回哪份文件的哪一节；判断类问题全部进「[待人工]」。

## 7. 机检

```bash
python3 -B scripts/check_working_capital.py <质量卡.md>     # 五道码逐条发红，全过则 PASS
python3 -B scripts/check_working_capital.py --selftest      # 好样须过、坏样五枚各发其码
bash scripts/fixtures/run_fixtures.sh                       # 离线样例三档（零网络零计费）
```

五道码：
`WC-STRUCT` 五节齐且有序·每节至少一项·申报数两向对齐／
`WC-ANCHOR` 原句非空·锚值非空·`[S#]` 在场且能在来源索引里找到·来源行带 URL 与检索日／
`WC-NOSELF` 周转、增速、占比、账龄占比、账面价值：原句没有就必须标〔自算〕并交代分子分母，两个数不许自己相减／
`WC-GAP` 未取到两向点名·零缺口须显式写「无」·禁「不适用／无此项／无需披露」／
`WC-LINE` 红线四道：造假与暴雷·预测·评级目标价·建议关注。
