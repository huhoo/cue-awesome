# 限售解禁压力·逐条挂源

## 0. 这是什么、不是什么

| 是 | 不是 |
|---|---|
| 同一只股票**未来**数轮限售解禁按解禁日串成一条日历 | 已经发生过的减持、分红、回购登记 |
| 逐轮登记解禁日、解禁方类型、解禁股数、占总股本比、成本区间 | 判断解禁会不会砸盘、股价怎么走 |
| 占比的分母（总股本）**单独挂源**，不自己拿股数除 | 用「约」「左右」把没取到的数糊过去 |
| 每行挂原公告链接与检索日 | 转述二手报道、研报摘要 |
| 缺的逐轮点名，两向都点 | 给买卖建议、评级、目标价 |

**与 `cn-shareholder-return` 的分界（用户靠这一句分清两枚包）：**

- `cn-shareholder-return` 登记的是**已发生的股东行为**——分红、回购、减持、质押的公告说了什么。
- 本件排的是**未来解禁的时间表**——哪一天、解禁多少股、占总股本多少、解禁方是谁、成本在哪一档。
- 判据很硬：**基准日之前的解禁不进本件的日历**，那是已经发生的事，走 `cn-shareholder-return`；股权质押与解押的余额变化走 `cn-share-pledge-tracker`。

**「压力」在本件里是什么意思（先说清楚，防误读）：**

本件说的压力＝**两个可查的东西**：①每轮解禁股数**占总股本比**（分子挂解禁公告、分母总股本单独挂源，两处各一枚锚）；②每轮股份的**成本区间**（该轮股份的发行价或授予价原值，只登记、不与市价比较）。
这两个都能从公告里取到、能回原文核对。**档位与评价不是本件的事**——「这轮压力算大还是小」「解禁会不会带来抛压」「解禁后股价怎么走」，全部 `[待人工]`，本件不下这个结论，也不假装有个客观阈值。

## 1. 什么时候用

- 「这只票未来一年有几轮解禁」「下一次解禁是哪天、多少股」
- 「解禁股数占总股本多少」「解禁方是控股股东还是定增对象」
- 「当初的定增价／授予价是多少，现在解禁的成本在哪一档」

**不要用**：要查已经发生的减持进度（走 `cn-shareholder-return`）；要质押与解押的余额变化（走 `cn-share-pledge-tracker`）；要股价预测、买卖时机、评级与目标价（本件不产出，也不该由任何件产出）。

## 2. 取数纪律

1. **只认公告原文。** 每一条事实都要能回到一份公告、招股说明书或定增文件的链接与检索日。研报、新闻、股吧转述一律不作来源。
2. **基准日先定。** 头部写 `基准日：YYYY-MM-DD`（通常＝检索日）。日历里**每一行的解禁日都必须晚于基准日**——早于基准日的解禁是已发生的事实，不是本件的时间表。
3. **解禁日以公告披露的解禁日为准**，不以限售期起算日加推算、不以媒体爆料日为准。日期写 `YYYY-MM-DD`。
4. **日历按日期非降序。** 倒序的日历不是日历。
5. **占比的分母单独挂源。** 每一行「占总股本 X%」都要在同一行注明分母总股数与它的来源锚——分母与分子来自两处，就挂两枚锚。**不自己拿股数除**：公告写了比例就照抄公告的比例；公告没写比例而只写了股数，才用同行的总股本除以它，并在第六节写清口径。
6. **成本区间只认文件里写的价。** 定增对象看发行价、股权激励对象看授予价、首发原股东看发行价；文件没写就写未取到，不用「按市价估算」顶上。
7. **没取到就写没取到。** 正文写了「未取到 X」，第六节必须逐条点名 X；第六节点了名而正文没有这条表述，同样算错——两向都判。
8. **不改写数字。** 公告写 1.2 亿股就写 1.2 亿股，不写「约 1.2 亿股」「1 亿股左右」。

## 3. 输出契约（七节，按序）

```
AI 整理初稿｜请回原文核对｜不构成投资建议｜判断位 [待人工]

基准日：2026-11-09
跟踪口径：解禁（未来解禁的时间表与可算的压力比值，同一只股票的限售股逐轮串起来）

## 一、一句话结论
## 二、解禁总览
## 三、解禁日历
## 四、压力测算
## 五、未决事项
## 六、未取到与口径
## 七、来源
```

- **头部四件自标**逐字在位，写在第一个 `## ` 之前。
- **基准日**行必须以 `基准日：` 起头、值为 `YYYY-MM-DD`；缺或值不可认都发。
- **跟踪口径**行必须以「解禁」起头——这一格是本件与已发生股东行为的分界，必须自报。
- **二、解禁总览**每行：`- 项名：值 [S#]`，其中**必须有一行是总股本**（`- 总股本：N 股 [S#]`），它是第四节所有占比的分母，必须自己挂源；**每轮成本区间也写在这一节**，一轮一行（`- 第 N 轮成本区间：发行价或授予价 N 元／股 [S#]`），成本价只登记原文值，不与市价比较、不算价差。
- **三、解禁日历**每行：`- YYYY-MM-DD｜解禁方类型｜一句话事实 [S#]`。解禁方类型在册：控股股东／实际控制人／董监高／定增对象／股权激励对象／首发原股东／战略投资者／其他。
- **四、压力测算**每行：`- 第 N 轮 YYYY-MM-DD｜解禁 N 股／占总股本 X.XX%（分母总股本 N 股）[S#][S#]`，**至少两枚不同号的锚**——分子与分母各来自一处。
- **五、未决事项**：还没走完全部轮次的解禁计划，就一定有未决事项（下一轮的解禁日是否确定、股东是否已作承诺），空节等于把不确定性藏起来。
- **七、来源**每行：`- [S#] 公告标题 URL 检索日 YYYY-MM-DD`，编号与正文锚一一对应。

## 4. 数据通道

本件走 Cue 的 MCP 通道取公告与原文解析。先列目录，再按目录里的路由地址调 `tools/list`，确认工具在场后再取数：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | head -c 2000
# 从目录里取本组的路由地址，再确认工具在场
curl -s -X POST "$ROUTING_URL" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

拿到解禁公告与招股说明书／定增文件清单后，用 `scripts/make_outline.py` 把清单排成骨架，再逐条读原文补内容。

## 5. 合规红线

- **不产出股价预测、涨跌承诺、买卖与减持建议、评级、目标价、解禁压力档位评价。** 要写这类判断，只能同行挂 `[待人工]`，交给人。
- **不把「解禁」当「减持」。** 解禁是限售到期可流通，是否减持是股东的事；本件不写「解禁即抛」「必然套现」，也不写「抛压」。
- **不用改数词打底。** 「约」「左右」「大概」不得替公告里的确切数字。
- **不转述二手来源。** 没有公告链接与检索日的事实不进日历。
- **不猜解禁日。** 公告没写具体解禁日，就写未取到，不用「限售期满后即可流通」推算出一个日期。

## 6. 快速流程

1. 定基准日，收齐这只票的限售股来源材料：招股说明书、定增发行结果公告、股权激励授予公告、限售股上市流通公告。
2. 每份记下：解禁日、解禁方类型、股数、占总股本比、成本价、链接与检索日。
3. 排日历（`make_outline.py` 可代排），逐行补一句话事实。
4. 写第四节：每轮占比的分母总股本单独挂源，分子分母各挂一枚锚。
5. 写未决事项与未取到，两向对齐。
6. 跑 `python3 scripts/check_lockup.py <稿>.md`，红一条改一条。

## 7. 机检

```bash
python3 scripts/check_lockup.py <解禁稿>.md       # 五道，退码 0 全过 / 1 有发条 / 3 读不到文件
python3 scripts/check_lockup.py --selftest        # 包内夹具自检
bash scripts/fixtures/run_fixtures.sh             # 五档离线自检，30 秒，零网络零计费
```

五道：**道一 形制**（头部自标、基准日、跟踪口径、七节齐且有序、总股本行在场、日历三格齐且日期非降序且每行晚于基准日、压力测算行形制）／**道二 锚**（每行带锚、来源行齐 URL 与检索日、压力行至少两枚不同号锚）／**道三 红线**（股价预测、涨跌承诺、买卖建议、评级目标价、解禁压力档位评价、改数词零命中）／**道四 未取到两向点名**（正文与第六节按名目同指对，多列少列都发）／**道五 边界**（跟踪口径写成已发生／减持／分红／回购／股东回报，或日历不足两行 → 点名改走 `cn-shareholder-return`；写成质押解押 → 点名改走 `cn-share-pledge-tracker`）。

## 8. 零通道降级

没有 `CUE_API_KEY` 时，本包**不产出内容**，只把用户手上的解禁清单排成带形状的骨架：日历与来源行按清单落位，结论、占比与成本区间留占位。骨架跑机检必然红在占位行上——这是设计，提醒你补完再交，而不是让空壳冒充成品。代价说清楚：**没有通道就没有原文，没有原文就没有分母、没有成本价，没有这三样这份解禁稿就只剩一串日期**，压力的三个比值一个都算不出来。
