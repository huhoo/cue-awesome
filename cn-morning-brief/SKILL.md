# 晨会纪要·数据槽与覆盖率（盘前早报）

把**一个时点**（隔夜／盘前）的市场层与标的层压成一份八槽纪要：每槽挂来源与检索日，
头部申报「已填槽／总槽」，**缺了几槽就点名几槽**，判断位一律留 `[待人工]`。

**切割句**：本件是**时点驱动**的晨会纪要；`announcement-daily-cn` 是单一公司当日公告逐条清单，
`cn-research-brief` 是问题驱动的多源研究速览，`watchlist-digest-cn` 是自选清单的跟踪摘要，
`event-brief-cn` 是单份公告的事件速读。本件不逐份读公告，只取**覆盖标的的隔夜公告标题级**。

## 0. 是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 时点驱动（隔夜／盘前）的一页纪要 | 事件驱动的专题研究（那是 `cn-research-brief`） |
| 市场层五槽 + 标的层三槽，共八槽 | 一篮子标的的公告逐条流水（那是 `announcement-daily-cn`） |
| 每槽挂来源与检索日 | 只有结论、没有出处的一句话点评 |
| 头部申报「已填槽／总槽 = N/M」，与槽表逐行对账 | 覆盖率靠感觉写，槽表里数不出来 |
| 缺的槽逐槽点名、写清缺什么 | 把缺的槽写成「不适用／无此项／无需披露」 |
| 判断位一律 `[待人工]`，一字不代填 | 涨跌方向、买卖建议、评级目标价 |

## 1. 触发场景

- 开盘前要一页「隔夜发生了什么、今天要看什么」。
- 用户给一份覆盖标的清单（公司名或 6 位代码），问「这几只昨晚有公告吗」。
- 用户问「外盘、汇率、利率、两融昨天什么水平」，要能回到出处。
- 用户要一份可按日复跑、前一日的缺口能看出来的纪要。

## 2. 取数纪律

1. **时点先钉死**：头部写清 `YYYY-MM-DD` 与 `隔夜`／`盘前`。同一份纪要只服务一个时点，跨时点要分两份。
2. **八槽固定，不多不少**：市场层 `隔夜外盘`、`汇率与商品`、`利率与流动性`、`指数与成交`、`两融余额`；
   标的层 `标的隔夜公告标题`、`标的今日事件`、`今日披露与解禁`。槽名就是契约名，改名即形制不合。
3. **每槽一行，行内自洽**：状态只准 `已填` 或 `未取到`；已填的行必须有 `值或原句`、`来源`、`检索日`。
4. **覆盖率是数出来的，不是拍的**：`已填槽/总槽 = N/M（xx%）` 只准出现一处；`N` 必须等于槽表里
   `已填` 的行数，`M` 必须等于槽数（8），百分比必须等于 `N/M` 四舍五入（`.5` 进位）。
   **报出来的数必须能回到槽表，不能自己拼。**
5. **缺口两向点名**：`未取到槽：` 只准出现一处，所列槽名集合必须**等于**槽表里 `未取到` 的行。
   多报是虚报，少报是漏报，两个方向都发。零缺口写 `未取到槽：无`。
6. **公告只到标题级**：标的层只抄**标题原文**（书名号内逐字），不摘要、不解读、不判断影响。
7. **判断留人工**：市场强弱、板块轮动、政策影响、催化剂兑现、风险大小，全部 `[待人工]`。
   `[待人工]` 只豁免它**自己那一分句**；同一行后半照判。
8. **不写「不适用」**：把「未取到」写成「无此项／不适用／无需披露」是替数据源下结论，不是登记。

## 3. 输出契约（头部申报 + 五段）

```
## 一、头部申报与槽表
- 文件：<YYYY-MM-DD> <隔夜|盘前>｜覆盖标的：<N> 只｜来路：渠道原文／用户直供
- 已填槽/总槽 = 6/8（75%）
- 未取到槽：利率与流动性、两融余额

| # | 槽 | 层 | 状态 | 值或原句 | 来源 | 检索日 |
|---|---|---|---|---|---|---|
| ① | 隔夜外盘 | 市场层 | 已填 | 道琼斯 -0.42%、纳斯达克 +0.31%、标普 500 -0.11% | 交易所收盘页 | 2026-11-09 |
| ② | 汇率与商品 | 市场层 | 已填 | 美元兑人民币 7.1180；布伦特 68.40 美元／桶 | 官方中间价与结算页 | 2026-11-09 |
| ③ | 利率与流动性 | 市场层 | 未取到 | — | — | 2026-11-09 |
| ④ | 指数与成交 | 市场层 | 已填 | 上证 3,120.45 -0.35%；两市成交 8,120 亿元 | 交易所行情页 | 2026-11-09 |
| ⑤ | 两融余额 | 市场层 | 未取到 | — | — | 2026-11-09 |
| ⑥ | 标的隔夜公告标题 | 标的层 | 已填 | 「关于以集中竞价交易方式回购股份进展公告」等 3 条 | 披露平台标题列表 | 2026-11-09 |
| ⑦ | 标的今日事件 | 标的层 | 已填 | 2 只标的今日召开股东大会 | 交易所日历 | 2026-11-09 |
| ⑧ | 今日披露与解禁 | 标的层 | 已填 | 1 只标的披露三季报；无解禁 | 交易所日历 | 2026-11-09 |

## 二、市场综述
- 隔夜外盘：「道琼斯 -0.42%、纳斯达克 +0.31%」 锚：交易所收盘页｜检索日 2026-11-09
- 汇率与商品：「美元兑人民币 7.1180」 锚：官方中间价｜检索日 2026-11-09
- [待人工] 隔夜外盘与汇率对今日开盘的强弱，本件不判，一字不代填。

## 三、标的动态
- 示例股份（600001）｜「关于以集中竞价交易方式回购股份进展公告」 锚：披露平台标题列表｜检索日 2026-11-09
- 示例科技（300002）｜「2026 年第三季度报告」 锚：披露平台标题列表｜检索日 2026-11-09

## 四、政策行业
- [待人工] 隔夜政策与行业消息的取向与影响，本件不判。

## 五、催化剂
- 示例股份（600001）｜股东大会 锚：交易所日历｜检索日 2026-11-09
- [待人工] 催化剂能否兑现，本件不判。

## 六、风险提示
- [待人工] 风险大小、是否需回避，本件不判、不给方向。

## 七、未取到清单
- 未取到 2 槽：利率与流动性（缺当日资金价格）、两融余额（缺上一交易日余额），需回官方披露页核对。

## 八、待人工
- [待人工] 涨跌方向、买卖建议、评级目标价，全部留人工。
```

## 4. 数据通道（以 live catalog 现值为准）

真实任务走通道正路：先看目录，再取原文与附件正文。

```bash
# 1) 看目录，拿端点
curl -s https://cuecue.cn/api/mcp-catalog | head -c 500

# 2) 按 MCP 协议握手，确认工具在场
curl -s -X POST "$MCP_ENDPOINT" -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

拿到端点后按目录现报的工具名取件，把公告 URL 或本地路径交给通道，轮询状态后读正文与表格。

**零 key 降级**：没有 `CUE_API_KEY` 时本件只走用户直供的标题列表与本地文件，代价是取不到渠道侧的披露原文与附件正文解析，锚只能落在用户给的那份上，覆盖标的的隔夜公告标题可能漏。

## 5. 合规红线（随套件）

- 不预测涨跌与方向（预计上涨、预计下跌、有望上涨、将上涨、看多、看空、高开、低开、冲高）。
- 不给买卖建议（建议买入、建议卖出、加仓、减仓、建仓、清仓、推荐买入）。
- 不给评级与目标价（目标价、评级、买入评级、增持评级、强烈推荐）。
- 不承诺收益（稳赚、必涨、必跌、零风险、包赚）。
- 不代拟、不代算、不代下单、不代客。
- 不把「未取到」写成「无此项／不适用／无需披露」。
- 不摘要、不解读公告正文——本件只到标题级；正文精读走 `event-brief-cn`。

## 6. 快速流程（用户视角）

1. 给一个时点（隔夜／盘前）和一份覆盖标的清单（公司名或 6 位代码）。
2. 本件按八槽逐槽取数，每槽挂来源与检索日。
3. 头部申报「已填槽／总槽」，缺口逐槽点名。
4. 判断位全部 `[待人工]`，本件不接。

## 7. 机检

```bash
python3 -B scripts/check_morning.py <纪要.md>      # 五道码逐条发红，全过则 PASS
python3 -B scripts/check_morning.py --selftest     # 好样须过、坏样五枚各发其码
bash scripts/fixtures/run_fixtures.sh              # 离线样例三档（零网络零计费）
```

五道码：`MB-STRUCT` 五段齐且有序＋槽表八槽不重不漏／`MB-COVER` 覆盖率申报与槽表逐行对账、百分比不得自拼／
`MB-ANCHOR` 每槽与每条挂来源与检索日、判断位须 `[待人工]`／`MB-GAP` 缺口两向点名＋禁「不适用」／
`MB-LINE` 红线三道（涨跌预测、买卖建议与评级目标价、判断语气落在判断段外）。
