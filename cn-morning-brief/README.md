# 晨会纪要·数据槽与覆盖率

把**一个时点**（隔夜／盘前）压成一页八槽纪要：每槽挂来源与检索日，头部申报「已填槽／总槽」，缺了几槽就点名几槽，判断位一律 `[待人工]`。

## 一、打开就干：今天这三步

1. 给一个时点（隔夜／盘前）和一份覆盖标的清单（公司名或 6 位代码）。
2. 本件按八槽取数：市场层五槽（隔夜外盘·汇率与商品·利率与流动性·指数与成交·两融余额），标的层三槽（标的隔夜公告标题·标的今日事件·今日披露与解禁）。
3. 每槽挂来源与检索日；头部申报「已填槽／总槽 = N/M（xx%）」，`未取到槽：` 逐槽点名；判断位全部 `[待人工]`。

## 二、五道机检（零网络）

```bash
python3 -B scripts/check_morning.py <纪要.md>     # 五道码逐条发红，全过则 PASS
python3 -B scripts/check_morning.py --selftest    # 好样须过、坏样五枚各发其码
bash scripts/fixtures/run_fixtures.sh             # 离线样例三档（30 秒、零网络零计费）
```

| 码 | 判什么 |
|---|---|
| `MB-STRUCT` | 八段齐、五段有序；槽表八槽**不重不漏**、槽名即契约名；每行状态只准 `已填`／`未取到`，层级与槽对得上 |
| `MB-COVER` | `已填槽/总槽 = N/M（xx%）` 只准一处，且 **N 等于槽表「已填」行数、M 等于八、xx 等于 N/M 四舍五入**——三个数各自都要能回到槽表 |
| `MB-ANCHOR` | 已填槽行的值／来源／检索日三格不许空（`—` 视同空）；事实行须有 `锚：` 与检索日；四个判断段各须有 `[待人工]` |
| `MB-GAP` | `未取到槽：` 只准一处，所列槽名集合须**等于**槽表标缺的行（多报虚报、少报漏报）；「不适用／无此项／无需披露」一律发 |
| `MB-LINE` | 红线三道：涨跌预测与买卖建议与评级目标价／主题词×判断语气同段／越界精读（本件只到标题级） |

## 三、上手

```bash
# 单份纪要
python3 -B scripts/check_morning.py 我的纪要.md

# 自测（改机检后先跑这个）
python3 -B scripts/check_morning.py --selftest
```

## 四、首次开通 Cue（三步，可跳过）

1. 在 cuecue.cn 注册并拿到 `CUE_API_KEY`。
2. 导出到环境：`export CUE_API_KEY=...`。
3. 连通自查：

```bash
# 1) 看目录，拿端点
curl -s https://cuecue.cn/api/mcp-catalog | head -c 500

# 2) 按 MCP 协议握手，确认工具在场
curl -s -X POST "$MCP_ENDPOINT" -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

**不装也能跑**：没有 key 时本件只走用户直供的标题列表与本地文件，代价是取不到渠道侧的披露原文与附件正文解析，锚只能落在用户给的那份上，覆盖标的的隔夜公告标题可能漏。

## 五、边界与不承诺

- 不预测涨跌与方向（预计上涨、预计下跌、有望上涨、看多、看空、高开、低开、冲高、走强、走弱）。
- 不给买卖建议（建议买入、建议卖出、加仓、减仓、建仓、清仓、推荐买入、逢低吸纳）。
- 不给评级与目标价（目标价、买入评级、增持评级、强烈推荐）。
- 不承诺收益（稳赚、必涨、必跌、零风险、包赚、保证收益）。
- 不代拟、不代算、不代下单、不代客。
- 不把「未取到」写成「无此项／不适用／无需披露」。
- 不摘录、不解读公告正文——本件只到标题级。
- 不做单一公司当日公告逐条清单（那是 `announcement-daily-cn`）、不做问题驱动的多源研究速览（`cn-research-brief`）、不做自选清单增量摘要（`watchlist-digest-cn`）、不做单份公告事件速读（`event-brief-cn`）。

## 六、出错了怎么办

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `MB-COVER 百分比 … 不符` | 百分比是拍的，不是拿 N/M 算的 | 按 N/M 四舍五入重算；口径写在面文，不要自创 |
| `MB-COVER 申报已填 N 槽，槽表实有 …` | 申报数与槽表行数不同步 | 先数槽表有几行 `已填`，再写申报 |
| `MB-GAP 漏报：…` | 槽表标了「未取到」而申报没列 | 把缺的槽补进 `未取到槽：`；零缺口写「无」 |
| `MB-GAP 虚报：…` | 申报列了槽表标「已填」的槽 | 要么补实该槽，要么把它改成 `未取到` |
| `MB-STRUCT 槽表缺槽：…` | 八槽少写一槽 | 八槽是契约，缺一即不合；缺数据写 `未取到` 不删槽 |
| `MB-STRUCT 槽「…」应属 市场层/标的层` | 槽放错了层 | 市场层五槽、标的层三槽，按契约摆 |
| `MB-ANCHOR 槽「…」已填但缺来源` | 写了值没写来源 | 补来源与检索日；真取不到就把状态改 `未取到` |
| `MB-ANCHOR …段缺 [待人工]` | 判断段写成了事实叙述 | 判断位一律 `[待人工]`，一字不代填 |
| `MB-LINE 定式禁词：…` | 写了方向、建议或目标价 | 删掉，改成原句登记或进 `[待人工]` |
| `MB-LINE 越界精读` | 把公告正文摘进来了 | 只抄标题原文；正文精读走 `event-brief-cn` |

## 七、怎么开口（正例与反例）

**正例**

- 「开盘前给我一页：隔夜外盘、汇率、利率、指数成交、两融都怎么样？」
- 「这三只票昨晚有什么公告？今天有什么会？」
- 「今天有哪些披露和解禁要留意？」
- 「昨天那份纪要缺了哪两槽，今天补上了吗？」

**反例**

- 「今天大盘会涨吗？」→ 本件不判方向，只登记事实。
- 「这几只票该买哪只？」→ 本件不给买卖建议。
- 「帮我读一下这份三季报讲了什么。」→ 那是单份公告速读，改走 `event-brief-cn`。
- 「把我关注的十只票今天的新公告逐条列出来。」→ 那是自选清单增量摘要，改走 `watchlist-digest-cn`。

## 八、能力边界（诚实清单）

- 覆盖率判的是**三个数各自能回到槽表**（N＝已填行数、M＝八、xx＝N/M 四舍五入），不判你取到的数是不是真的最新——事实层回官方原文核。
- 锚判的是**来源与检索日在场且检索日是日期形**，不判来源是否权威（那是人工核对的事）。
- 检索日认 `2026-11-09` 与 `2026 年 11 月 9 日` 两种写法；更怪的写法会被判「不是日期形」，按面文写。
- 「主题词×判断语气」那道路意收窄：**语气词不收「将／会／必」**，因为本域大量事实句写「将于今日披露」「今日将有 2 只解禁」，收进来会成片假红。
- `[待人工]` 只豁免它**自己那一分句**；同一行后半写的断言照发。
- 公告只判到**标题级在场**，不判标题内容是否与你关注的标的匹配（标的层归属请人工核对）。
