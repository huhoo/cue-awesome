# skill-review-cn

**装之前先给一枚 skill 体检：声明层、前置层、面文承诺、样例是否真跑通、许可与出处五面，每条发现都回到一处带检索日的原文，装不装留给人判断。**

评分与销量不稀缺，**稀缺的是每条结论都能回原文核对**。差异化在两道硬门禁：没有锚的发现进不了第二节，写了「跑通」却没给那条命令与它这次的退码就发红。

**输入**：一枚待装的 skill——本地目录，或商店页／仓库页经解析通道取回的正文
**输出**：五节体检报告（被检对象／逐条发现／五个检查面／未取到与口径／来源）＋来源行那一层的 `文件:行号` 与检索日
**代价**：五节契约 + 一道机检；解析通道开没开，决定的是「远端那份正文与本地是否一致」那一层——两条路各自缺什么、走哪条，写在 §二 与 §四
**机检**：`scripts/check_review.py` 五道（形制／锚／判决词／检查面覆盖／真跑申报），零网络、零执行被检件代码；反证矩阵长在这支脚本里

## 一、打开就干：今天这三步

| 步 | 动作 | 怎么做 | 不做会怎样 |
|---|---|---|---|
| ① | **先看形状**（30 秒、零网络、零计费） | `bash scripts/fixtures/run_fixtures.sh` —— 三档一次跑完：机检自测、五枚坏样逐枚单跑、采集器出骨架且该红就红。末行自报「档数=3｜合期望=3｜不合=0｜不可判=0」 | 没见过形状就上手，容易把「扫了个分」当成「核过原文」；这一档 30 秒就能看出两者的差别 |
| ② | **登记来源，逐面挂锚** | 每个读到的面一行：`- [S#] 标题（文件:行号 或 URL ｜检索日 YYYY-MM-DD）`；正文每条发现行末挂一个 `[S#]`。`scripts/collect_review.py` 能把本地那几枚文件先排成骨架 | 缺检索日或缺定位的来源行发 `E-ANCHOR`；没有锚的发现写进第二节同样发 `E-ANCHOR`——那时回来逐条补，比现在一条条挂贵 |
| ③ | **过机检，再交人** | `python3 -B scripts/check_review.py <报告.md>`，按详行的 `E-*` 码逐条改；改完仍只是**草稿**：装或不装由你定，本件不代下这个判断 | 安全类断言漏进正文、五个面漏了一面、跑没跑写含糊，都会跟着报告进到人的判断里；这三类都是机检能拦的形制层，内容层还得回原文 |

替你决定装或不装、给一枚分数、跑一遍被检件的代码**不在这三步里**——本件只对「这一枚被检件的面文当下写了什么」负责，且只对形制负责。

## 二、装上机 → 连通道 → 出结果

**装本件自己（主路）**：`npx skills add huhoo/cue-awesome --skill skill-review-cn`——这条只装本包；装完在你这一侧重列一次已安装 skill，清单里看得到 `skill-review-cn` 这个名字才算文件到位。没有 CLI 环境时的兜底是把本目录整个放进宿主支持的 skills 目录（`~/.workbuddy/skills/`）。

本件唯一的取证腿是 `cue-omni-reader`（解析）：被检件在远端时，商店页／仓库页／README 那几枚正文靠它取回成本地能读的那一份——**本机没有那份文件也能读**，这是本件的主路，不是可选装饰。它的已连判据（纯解析腿，没有 curl 可以替代它）：宿主列工具走 MCP 的 `tools/list` 握手——返回里认得到 `parse`、`get_parse_status`、`read_result` 这几枚才算已连。列不到就是没连：本件照旧只检盘上那几枚本地文件，代价是「远端面文与本地这一份是否一致」那一层整块缺位（缺的是「装之前实际会拿到什么」那一层证据，不是排版）。三层各自能证到什么，互不等价：**装好 skill ≠ 已配凭据 ≠ 通道已连**。key 取自本地凭据设施，不进聊天、不在终端回显，本面不新增任何凭据读取动作；解析的消耗以服务端返回为准，本件不代估也不代付，花之前一定先问。

## 三、离线样例：30 秒看到形状

```bash
cd skill-review-cn
bash scripts/fixtures/run_fixtures.sh
# 档① 机检自测：好样须过、五枚坏样须各发它该发的那一道 → selftest: ALL GREEN
# 档② 逐枚单跑坏样：一枚一行，逐行报「期望只发 E-X／实发码 E-X」——各发各的道，不并成一个总数
# 档③ 采集器出骨架：scripts/collect_review.py 把靶件排成五节骨架，骨架过机检期望红在「样例真跑」那一行
```

自己上手时同样两条命令：

```bash
python3 -B scripts/collect_review.py --target ../被检的包目录 --out 我的体检.md
python3 -B scripts/check_review.py 我的体检.md
```

采集器只读、不执行被检件任何代码（连它自己的 runner 都不跑——那是决定，不是默认）。它登记的发现全部带 `文件:行号`：声明层的键在位与缺位、前置层 `requires` 现读什么、面文承诺摘出哪些承诺句、许可与出处三件是否同盘在场。目录里读不到 `SKILL.md`／`README*.md` 任一枚时它退 1 并说明——没有出处不出骨架，那是没检，不是待填。

## 四、依赖与两条路的代价

- `python3`：机检与采集器都用它，纯标准库、零网络、不发任何请求。
- 解析辅助 `cue-omni-reader` 是可选的：**不装不报错，代价是体检只剩盘上已有的那一份本地副本**——远端正文读不进来，「远端面文与本地是否一致」那一层永远缺位，报告只能对本地那一份负责。装与不装都先问你要不要用，消耗花之前一定先问。
- 连了通道也不等于取到正文：取数以实际返回为准；截断、只给摘要不给正文、页面改版取不到那段的，一律落第四节点名，不拿常识补。
- 行号会随被检件改动失效：报告里的 `文件:行号` 只在检索日那一刻成立，隔一天重装可能就是另一个形状。

## 五、机检五道与自校验

| 道 | 码 | 卡什么 |
|---|---|---|
| 道一 形制 | `E-FORMAT` | 头部四件自标逐字在位；五节齐且按一二三四五有序；第一节表态位没挂 `[待人工]` 就发红 |
| 道二 锚 | `E-ANCHOR` | 第二节每条发现行末带 `[S#]` 且第五节有对应行；来源行必须同时带 `文件:行号` 或 URL 与检索日 |
| 道三 红线 | `E-BANWORD` | 可放心装／建议安装／建议上架／一定可用／安全无害／不会有问题一类断言零命中（同行挂 `[待人工]` 才放行） |
| 道四 覆盖 | `E-COVERAGE` | 五个检查面各须一条挂锚发现或在第四节点名未取到；第五节一行来源都没有＝没有出处 |
| 道五 真跑申报 | `E-VERIFY` | 写了「真跑通／跑过」就必须同句给出 `cmd=… rc=整数`；没跑就把这行删掉、落第四节 |

```bash
python3 -B scripts/check_review.py --help                                 # 五道说明，零网络
python3 -B scripts/check_review.py --selftest                             # 好样须过、五枚坏样须发红
python3 -B scripts/check_review.py scripts/fixtures/good-review.md        # 应 PASS
python3 -B scripts/check_review.py scripts/fixtures/bad-format.md         # 应 FAIL：头部自标缺件且缺第三节
python3 -B scripts/check_review.py scripts/fixtures/bad-no-anchor.md      # 应 FAIL：发现行没锚
python3 -B scripts/check_review.py scripts/fixtures/bad-safety-verdict.md # 应 FAIL：下了安全判决没挂待人工
python3 -B scripts/check_review.py scripts/fixtures/bad-missing-face.md   # 应 FAIL：五个检查面缺一面
python3 -B scripts/check_review.py scripts/fixtures/bad-unverified-claim.md  # 应 FAIL：写了跑通没给命令与退码
python3 -B scripts/check_review.py scripts/fixtures/good-review.md --quiet   # 只报末行与计数
```

**枚数与行数一律取脚本自报行**（`FAIL: <文件>（N 条）`／`PASS: <文件>（…）` 后那行「扫过 N 行，发条 0 条」），本文不复写计数——一复写就成了第二个真值源。

## 六、包里有什么

```
SKILL.md                       主指令：定位/输入/四步/五节契约/通道与降级/红线/边界（必读）
README.md / README.en.md       本文件（中文权威／英文对照）
CHANGELOG.md                   版本记录
scripts/check_review.py        机检五道（纯标准库，--help 可跑；判定全集在脚本，本文只指路）
scripts/collect_review.py      离线采集器（读本地靶件盘面出五节骨架，不执行被检件代码）
scripts/fixtures/              好样一枚＋坏样五枚＋合成靶件两枚面＋离线三档 runner
```

## 七、常见问题与反模式

| 你想这么用 | 本件接不接 | 为什么 |
|---|---|---|
| 「装之前帮我把这枚 skill 的面文过一遍」 | 接 | 五面逐条挂原文正是它的用途 |
| 「扫一遍给个分就行」 | 不接 | 只有分数没有原文，回头没人能核对；那一类工具很多，不差这一枚 |
| 「顺手替我判断装不装」 | 不接 | 判断位归人；写了就发 `E-BANWORD`，除非同行挂 `[待人工]` |
| 「跑跑它的样例看会不会炸」 | 不代跑 | 本件不执行被检件代码；你跑了就同句写 `cmd=… rc=整数`，机检认这条申报 |
| 「没通道也先给我一份成品」 | 给的是骨架 | 缺的是远端一致性那一层证据，不是排版——骨架红在待填位正是为了提醒这一步没做 |
| 「对着商店页写体检」 | 接，但要留证 | 走解析通道把正文取回来登记成来源行；取不到就落第四节，不凭页面印象写 |
