# 装前先给一枚 skill 体检（设计权威）

**定位**：把「这枚 skill 值不值得装」拆成五个能逐条回原文的检查面。评分与销量不稀缺，**稀缺的是每条结论都能回到一处带检索日的原文**。
**不是**安装器，不是评分器，不替你决定装或不装，也不会自己发布。

## 0. 是什么 / 不是什么
| 是 | 不是 |
|---|---|
| 五面体检：声明层／前置层／面文承诺／样例真跑／许可与出处，各挂一个 `[S#]` | 不是扫描器打分：只给分数不给原文的那一类，本件不产 |
| 只读被检件的面文与盘上文件，**不执行被检件任何代码** | 不是沙箱：跑样例是你的决定，跑过就要同句写 `cmd=… rc=整数` |
| 未取到的单独成节、逐条点名，并同句写明缺的是哪一层证据 | 不是把空白填圆：读不到的要么点名要么不写 |
| 判断位一律 `[待人工]`，安全类断言零命中（机检发红） | 不是担保：本件不写「安全无害／可放心装」那一类话 |
| 来源行必须带 `文件:行号` 或 URL ＋ 检索日 | 不是「最新版本我看过了」：没有检索日的体检读不出时效 |

## 1. 输入
- 一枚被检件：本地目录（含 `SKILL.md`／`README*.md`），或经解析通道取回的远端正文（商店页／仓库页／README，落成 `parsed-doc`）。
- 可选：被检件自己的样例命令——**跑不跑由你决定**，本件不代跑也不代判。
- 检索日由本次运行给出；被检件的名字与版本只照盘面登记，不替你推断。

## 2. 工作流（四步，每步都可停）
1. **取面**：本地就直接读那几枚文件；远端就走解析通道把正文取回成本地那份——本件只认盘上读得到的东西。
2. **登记来源**：每个读到的面一行，写 `文件:行号` 或 URL ＋ 检索日；`scripts/collect_review.py` 能把这一层排成骨架。
3. **逐面写发现**：五个检查面各写自己的条目，只写盘面确实载着的话，行末挂该来源编号 `[S#]`；跑没跑样例按实写，写了「跑通」就同句给那条命令与它这次的退码。
4. **过机检**：`python3 -B scripts/check_review.py <报告.md>`，按详行的 `E-*` 码逐条改。机检过完仍只是**草稿**：装或不装由人定，本件不代下这个判断。

## 3. 输出契约（五节，机检按此判）
1. `## 1、被检对象`：名字、版本、读到的面、装不装表态位（要表态只能挂 `[待人工]`）。
2. `## 2、逐条发现`：每条一行、行末一个 `[S#]`；五个检查面各自至少一条挂锚发现或在第四节点名。
3. `## 3、五个检查面`：逐面写清查什么、本次落到第几节——这一节是方法自述，机检不把它当覆盖证据。
4. `## 4、未取到与口径`：未取到的逐条点名并同句写缺的是哪一层证据；再加检索日与读取方式两条口径。
5. `## 5、来源`：一行一源，`- [S#] 标题（文件:行号 或 URL ｜检索日 YYYY-MM-DD）`。
头部另有四件自标：AI 整理初稿／请回原文核对／不构成上架或安装建议／判断位 [待人工]，逐字在位。

## 4. 通道与降级（两条路各自缺什么，写在同一句里）
- **主路＝解析通道**：被检件在远端（商店页／仓库页／README）时，正文走解析通道取回——**本机没有那份文件也能读**，这一层的已连判据照仓内既有面写：宿主列工具走 `tools/list` 握手，返回里认得到 `parse`／`get_parse_status`／`read_result` 这几枚才算连上。命令与三层自查见 `README.md` 的「装上机 → 连通道 → 出结果」那一节。
- **降级＝只读本地**：本件仍能跑 `scripts/collect_review.py`，把盘上那几枚文件排成五面骨架；代价同句写清——**「远端面文与本地这一份是否一致」那一层整块缺位**，缺的是「装之前实际会拿到什么」那一层证据，不是排版；此时报告只能对本地副本负责。
- 骨架不是体检报告：`collect_review.py` 固定留一行「样例真跑」待填位，机检按设计在这行发 `E-VERIFY`——跑过就填那条命令与退码，没跑就删掉这行、改到第四节点名。

## 5. 红线（机检守，不由人守）
- 安全类与安装类断言零命中：可放心装／建议安装／建议上架／一定可用／肯定没问题／安全无害／不会有问题——要提及就同行挂 `[待人工]`。
- 写了「真跑通／跑过」却没附那条命令与它这次的退码＝发红；跑不了就别写，把它落进第四节。
- 没有锚的发现不进第二节；锚在第五节没有对应行、来源行缺 `文件:行号` 或 URL、缺检索日，都发 `E-ANCHOR`。
- 本件不发请求、不代付费：解析通道的消耗以服务端返回为准，本件不代估也不代付，花之前一定先问。

## 6. 最小可复跑链（零网络、零计费、不执行被检件代码）
```bash
python3 -B scripts/collect_review.py --target scripts/fixtures/target-demo --out 我的骨架.md
python3 -B scripts/check_review.py 我的骨架.md                     # 期望发 E-VERIFY：样例真跑仍是待填位
python3 -B scripts/check_review.py scripts/fixtures/good-review.md # 期望 PASS：五节齐、逐条挂原文、五个面全覆盖
python3 -B scripts/check_review.py --selftest                      # 好样须过、五枚坏样须各发它该发的那一道
bash scripts/fixtures/run_fixtures.sh                              # 离线三档一次跑完，末行自报档数与不合枚数
```

## 7. 边界（含与自家三枚的分工）
- 本件只对「这一枚被检件的面文当下写了什么」负责，且只对形制负责：内容对不对、值不值得装，要人回原文判断。
- 与 `cue-lead-pieces` 的分工：那一件核的是**你自己的稿子里引文与出处逐字对不对**，本件核的是**别人那枚 skill 的面文写了什么、盘面撑不撑得住**——对象不同，一头在内一头在外。
- 与 `cn-research-brief` 的分工：那一件把**一批来源**排成多源速览（横向铺问题），本件只围**一枚被检件**做五面体检（纵向钉一个对象）。
- 与 `omni2docx` 的分工：那一件是**转换**（把已有文档变成另一种格式的文件），本件是**审读**（把盘面变成挂原文的事实清单），产物形制不同、互不替代。
- 不跑被检件的代码：要跑由你决定并同句给出命令与退码——这是本件与「扫描器代跑一遍给个分」那一路的根本区别。
