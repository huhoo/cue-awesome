# convertible-bond-terms-cn

**给一份 A 股可转债的募集说明书或发行公告，产出八项条款逐字卡：规模与期限、票面利率、转股价格、转股期、向下修正、有条件赎回、回售、担保与评级，每项挂原句＋来源锚；转股收益与强赎判断一律 `[待人工]`。**

它只管一只可转债的条款怎么写：普通公司债（不含权）在 `bond-terms-cn`，定增与再融资方案在 `placement-terms-cn`，公告清单在 `announcement-daily-cn`。可转债的命门是**修正、赎回、回售这三组触发条款**——「满足约定条件」「详见公告」这种话在本件过不了闸，这条界线是本件存在的理由。

## 一、打开就干：今天这三步

1. 给一份文件：募集说明书、发行公告或披露页定位；没写的那一项要求它写「未检索到」，不许按同类转债惯例补。
2. 读前两段：头部申报＋八项逐字速读——这两段只要文件到手就能出，不需要任何通道。
3. 盯三组触发条款：下修线、强赎线、回售线必须带数字原值（如 85%／130%／70% 与 N 个交易日）；遇到空泛语就让它进缺数清单。

## 二、五道机检（零网络）

产物交给 `scripts/check_cb_card.py` 过闸：五段齐＋八项名目行级在场（每枚名目须占一行，散文里提到不算）／每项原句与锚（书名号内空或只剩一个字算缺原句，「锚：」后面空着也发）／红线断言只准出现在 `[待人工]` 行／齐缺申报恰一枚且与未检索到行数对账／**触发条款不许空泛**（修正、赎回、回售三项须带数字触发原值，「满足约定条件」「详见公告」「视股价而定」出现即发）。

```bash
python3 scripts/check_cb_card.py --help                          # 参数说明
python3 scripts/check_cb_card.py --selftest                       # 好样须过、坏样五道齐发、钉阈按整族各钉一档、对照样不误伤、临时件自清（枚数由自测自报）
python3 scripts/check_cb_card.py scripts/fixtures/good-cb-card.md     # PASS（发条 0 条）
python3 scripts/check_cb_card.py scripts/fixtures/bad-cb-card.md      # FAIL（五道各发，逐条点名行号）
```

## 四、首次开通 Cue（三步，可跳过）

本件的取证腿有两条：**原文取数**（找募集说明书与发行公告原文，走数据腿）与**附件解析**（长附件与多页 PDF，走解析腿）。两条都是可选——不装也能按你直供的文件出卡；代价是条款在附件里的那几组触发数字只能停在「未检索到」，得你回原文核。

1. 注册 <https://cuecue.cn>；
2. 在 <https://cuecue.cn/hub/api-key> 取 `CUE_API_KEY` 存入本地凭据——**不要贴进聊天**，agent 不经手密钥；
3. 装这两枚：`cue-data-mcp` 走原文取数腿，`cue-omni-reader` 走附件解析腿。一条命令两种写法：
   - 整套：`npx skills add sensedeal/cue-skills`（它会列出该集合公开的各枚 skill，按提示挑要装的）；
   - 单装：`npx skills add sensedeal/cue-skills --skill cue-data-mcp`（把末尾那枚名字换成 `cue-omni-reader` 就只装那一枚）。

配置指路同样只给指针、不复述开通步骤：找原文走数据腿，官方配置页 <https://cuecue.cn/hub/mcp>；长附件与 PDF 走解析腿，官方配置页 <https://cuecue.cn/hub/omni-reader>；取 key 走 <https://cuecue.cn/hub/api-key>。

### 连通自查（各条腿能证到哪一层）

```bash
# 1) 目录可达（匿名）：只证 catalog 能读，不叫「已连」
curl -s "https://cuecue.cn/api/mcp-catalog" | head -c 200

# 2) 域路由现值：从返回里取该域的 routing.url 与 transport，别把域名抄死
# 3) 带 key 实连后发 tools/list——只证该数据腿端点被接受，不证别的入口
curl -s -X POST "$ROUTING_URL" -H "Authorization: Bearer $CUE_API_KEY" \
  -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | head -c 400
```

装好 skill ≠ 已配凭据 ≠ 数据腿已连：这一层的判据只管数据腿那一路——带 key 按目标域 `routing` 实连且该端 `tools/list` 有返回，才证那把 key 被接受，也只证数据腿连上；解析腿的连通另按它自己那面的判据读。

## 五、边界与不承诺

- 转股收益、转股价值、套利空间、是否会被强制赎回、下修会不会发生、评级与目标价一律 `[待人工]`；禁一定能转／必被赎回／建议申购／稳赚／零风险／保证收益；判断式结论由两道规则逮——「主题词＋判断语气同段」与「裁定前缀＋效力判断」，「X 会」机构名与「会 X」名词（会计·会议·会员）里的「会」先从语气域两头洗掉，「赎回价格由董事会拟定」「会议记录载明票面利率梯度」不误红而「回售应予否决」照发；免责只按分句算，「本件不接申购；转股收益一定能兑现」的后半句照发；
- 不接申购与转股操作：本件不出申购单、不做转股指令、不代客操作；
- 触发条款逐字按规则判：机检先把项行拆成字段，只认该项原句，**先剥日期**，再要求同一段同时给出触发量纲与触发语境，并核触发数**归不归本项**——下修／赎回／回售三组各归各的数，把别组的完整触发句搬进本项同样算缺；空泛语（满足…条件／详见公告／另行公告／另定／待定）只是那句话的措辞，换同义词换不掉这一判；
- 未检索到＝照实写「未检索到」，禁以同类转债惯例补写，也不写「无该项」顶替；
- 域与工具名以 live catalog 现值为准，本件不列固定清单、不承诺枚数，也不承诺该域是否开放与原文的实时性。

## 六、出错了怎么办

| 症状 | 来路 | 恢复动作 |
|---|---|---|
| 好几项是「未检索到」 | 文件是摘要件，或条款在附件深处 | 起附件解析腿补原句；起不动就保留缺数点名，不补写 |
| 数据腿连不上 | 凭据缺位或该域未 live | 按 §四 自查；前两段仍可出，代价见 §四 那一句 |
| 机检发红 | 缺锚／缺原句／触发条款空泛／齐缺不符 | 按逐条点名的行号补齐；补不出的进缺数清单，不删行凑数 |
| 说明书与发行公告数字不一致 | 两处文本本就两版本 | 两句原句并列进「口径对照」，各挂各锚，不做取舍判断 |

## 七、怎么开口（正例与反例）

- 正例：「这只转债的转股价怎么定的」「什么条件下公司能强赎」「回售要跌多少、连续几天」「下修触发线是多少」「票面利率梯度怎么写的」。
- 反例：「转股能赚多少」「现在该不该申购」「会不会被强赎」——收益、申购与强赎预测不在本件，进 `[待人工]`。

## 八、能力边界（诚实清单）

行情与资金流类数值不在本件能力内（该域以 live catalog 现值为准，未开放就不承诺）；本件不做转股套利测算、不预测触发、不给申购建议；本件不做多只转债的横向比较（跨主体底稿走 `dd-checklist`），不做普通公司债条款（走 `bond-terms-cn`）；本件也不持久存你的文件，卡出完就交还给你。
