# 更新日志

### 0.1.0 — 2026-11-02（本枚首次建包：招股说明书的八项逐字速览卡，两条取证腿、五道机检与中英双技能面随包）
- 选题来路与它的弱处（写在顶条不藏）：这一枚与同批的路演纪要都落在需求池取数的末位，属**弱依据**；开它的依据是「套件要增件、要开渠道」这条指令本身，不是池子数据。因此本枚面文、卡面与顶条一律不写名次、不写安装量、不写「会带来什么」，判据只看装得上、连得上、机检跑绿、面文不超实。
- 与其它几件的分工：本件只管一份招股说明书读成什么样。相邻四件各管一层、写死不重叠：单份方案的条款拆解在 `placement-terms-cn`，公告清单级速览在 `announcement-daily-cn`，跨主体公开风险底稿在 `dd-checklist`，单份公告的事件级速读在 `event-brief-cn`。落点＝`SKILL.md` 定位句、两份说明面的导语与能力边界节、`SKILL.en.md` 同形两处。
- 产出契约（速览卡五段，缺一即退回）：头部申报（发行人全称／稿件版本／受理与问询轮次／八项齐缺申报／本次是否发起过解析腿）→ 八项逐字速览（形制＝`- 项名：原句逐字 锚：<章节／页码>`，八项＝发行与上市安排、主营业务与收入结构、募集资金投向、客户与供应商集中度、研发与核心技术、主要风险因素、股权结构与实际控制人、财务口径）→ 口径对照（同一事实多处原句并列、各挂各锚，不取其一当结论）→ 缺数清单 → 待人工。原文在 `SKILL.md`「输出契约」那一节；八项名目与五段由随包机检逐判，缺哪一项也要占一行点名，不靠约定。
- 本枚独有的两道判据（都是「面文不超实」这一条的具体化）：**自述不当事实**——原句里出现自称或最高级（领先／先进水平／国际先进／最大／龙头／首创／之最／顶尖，以及「全球·国内·行业·全国·世界＋第一」）必须同带「发行人自述，无第三方依据」，标不出来就不写进结论；这条在实现中被收窄过一次，第一版按「第一」裸判会把「第一大客户占比」这类**带统计口径的排名描述**误当成自述夸张，收窄后的界与理由写在 `references/self-claimed.md` 与机检件的说明段里，并由自测的「剥自述标注」反证真打过。**前瞻不当既成**——「公司将」「预计」「力争」「在研」「拟」那类限定词整句留着，不做副词手术。另有一道页码落点判：锚里落不回页码（第 N 页／页码／P.N 三种形制之一）就发红，免得「锚」退化成任意一句出处。
- 两条取证腿：原文与稿件在数据腿上，几百页正文的按节取用在解析腿上；深研那枚 `cue-research` 是独立入口（自带运行脚本），它的凭据同那把 key，取 key 走 <https://cuecue.cn/hub/api-key>。两条都写成可选并各自带代价——不装也按用户直供的正文出卡，代价是深处章节拿不到，研发与风险两节常停在「未检索到」，而自称句最集中的恰是那两节。指路只给指针、不复述开通步骤：数据腿官方配置页 <https://cuecue.cn/hub/mcp>；解析腿官方配置页 <https://cuecue.cn/hub/omni-reader>；取 key 走 <https://cuecue.cn/hub/api-key>。域与工具名以 live catalog 现值为准，面文不列固定清单、不承诺枚数，也不承诺稿件更新的实时性。
- 名形制：`displayName` 取「招股书速览」＝意图词「招股书」落在词首＋名短；目录名与 frontmatter `name` 同值 `prospectus-digest-cn`，`slug` 为 `cue-prospectus-digest-cn`。本枚随带中英双技能面与中英双说明面，两面的 `name`∥`version`∥`slug`∥`displayName` 同值。
- 随包机检：`scripts/check_prospectus.py` 五道——五段齐与八项名目在场、每项原句与页码锚、自称句未标即发、红线断言只准出现在 `[待人工]` 行、齐缺申报与清单对账；零网络。`--selftest` 直接吃 `scripts/fixtures/` 那两份样例（好样须过、坏样五道齐发并逐条点名行号），另含剥锚、剥页码、剥自述标注、删一项名目、把齐缺申报改歪五档反证，各判各的道；临时件建在一次性目录里、退出时自清。两份夹具里的发行人、人名、代码与数字均为虚构示例，不当作任何真实招股书的引用。
- 首测：本枚建包当拍各闸的读数与出包 digest 以各闸自报行为准，本条不复写。
