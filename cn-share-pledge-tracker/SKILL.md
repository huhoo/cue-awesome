# 股权质押与解押跟踪·逐条挂源

把同一股东的**多笔**质押与解押公告串成一条**余额变化线**：每笔登记出质人、质权人、股数、
占所持比例、占总股本比例、质押期间，累计与剩余写成「前值 → 后值」，每笔挂公告原句与锚。

**切割句**：本件只回答「质押余额怎么变」；**分红回购减持归 `cn-shareholder-return`**，
**单份公告讲什么归 `event-brief-cn`**。本件不判平仓风险、不评比例高低、不预测股价。

## 0. 是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 同一股东多笔质押/解押串成余额变化线 | 单份公告的事件速读 |
| 每笔六要素（质押）／三要素（解押）逐条登记 | 只写「又质押了一笔」这种一句叙述 |
| 累计与剩余写成「前值 → 后值」 | 只写当前余额，看不出变化 |
| 比例只认公告原句写的百分比 | 拿质押股数除以持股数或总股本自己算 |
| 公告没写的逐笔写「未取到」 | 用「不适用／无需披露」替公告下结论 |

## 1. 触发场景

- 用户拿到一份或多份质押/解押公告，问「这个股东质押了多少、还剩多少」。
- 用户问「质押比例是多少、占所持多少、占总股本多少」。
- 用户要把同一股东隔几周的几次质押串起来看余额怎么变。
- 用户问「解押了多少、什么时候解的」。

## 2. 取数纪律

1. **只认公告原文**：每笔事实都要能回到一份公告的原句与锚。研报、新闻、股吧转述一律不作来源。
2. **质押行六要素齐**：出质人、质权人、质押股数、占所持比例、占总股本比例、质押期间，缺一即发。
3. **解押行三要素齐**：出质人、解押股数、解押日期，缺一即发。
4. **比例只认公告原句**：某笔的百分比必须出现在该行自己的书名号原句里；公告没写就写「未取到」，
   **不许拿质押股数除以持股数或总股本自己算**——分母可能是持股数、可能是总股本、可能是剔除回购专户后的股本，
   算错一个分母，风险读数就全错。
5. **累计与剩余必须是两处之差**：写成 `前值 → 后值`，两侧各有数字。只有一处不构成变化。
6. **未取到两向点名**：头部「共 N 笔质押变动·未取到 M 笔」只写一处，N 与 M 都必须等于变动明细段的实际行数与
   「未取到」行数；多报是虚报，少报是漏报，两个方向都算错。
7. **不写「不适用」**：把「未取到」写成「无此项／不适用／无需披露」是替公告下结论，不是登记。
8. **判断留人工**：平仓风险、比例高低、股价影响，全部进「待人工」。

## 3. 输出契约（质押跟踪卡五段）

```
## 一、头部申报
- 文件：<公司> <公告名>｜来路：官方原文／用户直供｜附件腿：已发起／未发起
- 共 N 笔质押变动·未取到 M 笔

## 二、本次变动明细
- 质押：「<原句，含出质人·质权人·质押股数·占所持比例·占总股本比例·质押期间>」 锚：<出处>
- 解押：「<原句，含出质人·解押股数·解押日期>」 锚：<出处>
- 质押：未取到（未取到清单已点名）

## 三、累计与剩余
- <出质人>：累计质押 <前值> → 累计质押 <后值>
- <出质人>：占其所持股份 <前值> → 占其所持股份 <后值>
- <出质人>：占公司总股本 <前值> → 占公司总股本 <后值>

## 四、未取到清单
- 未取到 M 笔：<第几笔>——<缺什么>，需回<哪份文件>核对。

## 五、待人工
- [待人工] <质押比例是否偏高／是否存在平仓风险／对股价的影响> 全部留人工；本件不接代办，也不给风险判断。
```

## 4. 数据通道（以 live catalog 现值为准）

真实任务走通道正路：先看目录，再按工具名取原文与附件正文。

```bash
# 1) 看目录，拿端点
curl -s https://cuecue.cn/api/mcp-catalog | head -c 500

# 2) 按 MCP 协议握手，确认三枚工具在场
curl -s -X POST "$MCP_ENDPOINT" -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

拿到端点后确认 `parse` / `get_parse_status` / `read_result` 三枚在场，
再用 `parse` 把公告 URL 或本地路径交给通道，`get_parse_status` 轮询，`read_result` 取正文与表格。

**零 key 降级**：没有 `CUE_API_KEY` 时本件只走用户直供的公告正文与本地文件，代价是取不到渠道侧的披露原文与附件正文解析，锚只能落在用户给的那份上，跨期核对做不了。

## 5. 合规红线（随套件）

- 不判平仓风险（有平仓风险、面临平仓、爆仓风险、触及预警线、触及平仓线、风险可控、风险不大、质押安全）。
- 不评比例高低（质押比例偏高、偏低、合理、过高、充分、不足）。
- 不预测股价（股价将、股价会、利空、利好、压制股价、提振股价、拖累股价）。
- 不给评级与目标价。
- 不承诺收益（稳赚、零风险、保证收益、必涨、必跌）。
- 不代拟、不代算、不代申报、不代客。
- 不裁断效力（质押是否有效、是否违规、是否合规）。

## 6. 快速流程（用户视角）

1. 把质押/解押公告（URL 或本地文件，可多份）交给本件。
2. 本件逐笔登记六要素（质押）／三要素（解押），每笔挂原句与锚。
3. 累计与剩余写成「前值 → 后值」，看得出余额怎么变。
4. 公告没写的进未取到清单，点名要回哪份文件。
5. 判断类问题全部进「待人工」，本件不接。

## 7. 机检

```bash
python3 -B scripts/check_pledge_tracker.py <卡面.md>     # 五道码逐条发红，全过则 PASS
python3 -B scripts/check_pledge_tracker.py --selftest    # 好样须过、坏样六枚各发其码
bash scripts/fixtures/run_fixtures.sh                    # 离线样例三档（零网络零计费）
```

五道码：`SP-STRUCT` 五段齐·变动行级在场·质押六要素／解押三要素齐·累计行须是两处之差／
`SP-QUOTE` 原句与锚不得为空／`SP-LINE` 红线三道／
`SP-GAP` 未取到两向点名 + 比例不得自算／`SP-BOUND` 写成股东回报速读或单份公告速读时点名改走对应件。
