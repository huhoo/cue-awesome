# 业绩预告速读·区间与修正逐条挂源

把**一份**业绩预告／业绩快报拆成六项要素：预告类型、区间上下限、同比变动幅度、变动原因、是否修正过、披露日——每项挂「」原句与检索日。没写的逐条点名。

**不取中值、不算幅度、不推断正式数、不给评级与目标价。**

---

## 一、打开就干：三步

1. **取到原文**：这份预告的公告原文，若有更正公告一并取到。
2. **六项逐项抄原句**：预告类型、区间下限、区间上限、同比变动幅度、变动原因、披露日。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_forecast.py 你的预告稿.md
```

退码 `0` 全过、`1` 有发条、`3` 读不到文件。

---

## 二、五道机检在管什么

| 码 | 名称 | 判什么 | 最常拦住的情况 |
|---|---|---|---|
| `FC-STRUCT` | 形制 | 头部四件自标在第一个 `## ` 之前；`基准日：YYYY-MM-DD` 在场；`数据口径：` 在场；六节齐且按序；二节六项齐；预告类型在册；披露日形制；区间下限不大于上限；修正沿革不空且修正过的前后两值齐 | 六项漏一项；类型写成「大幅增长」这种不在册的说法；修正过却只写后值 |
| `FC-QUOTE` | 原句与锚 | 六项每项必须挂非空的「」原句与 `[S#]`；每行有锚或 `[待人工]`；来源行齐编号＋URL＋检索日；来源不得空 | 写了「变动原因」却没引原句；引号是空的 `「」`；来源行只有标题没有链接 |
| `FC-LINE` | 红线 | 不判「超预期／不及预期」、不给评级目标价、不预测股价、不给买卖建议、不推断正式财报数、`约`／`左右`／`大概` 改数词，一律零命中 | 写「本次预告超预期」「股价将上涨」「建议增持」 |
| `FC-CALC` | 不得自算 | **区间中值不许自己取**、**同比与修正幅度只认原句**、**修正幅度不许拿前后相减** ——引号外出现中值词、百分比、算式、幅度标签后直接跟数字，全发 | `中值 35,000 万元`、`同比增幅 58.74%`、`(下限+上限)/2` |
| `FC-BOUND` | 边界 | `数据口径` 须以「业绩预告」或「业绩快报」起头；正文提到已出财报／公告清单／隔夜全景却没点名对应件，点名 | 把预告稿写成财报点评；口径写成「已出财报的点评」 |

### 这一枚最要紧的一格：不得自算

业绩预告给的是一个**区间**，不是点数。卡面最容易犯的三个动作，全在这一格里：

1. **自己取中值**——`(32,000 + 38,000) / 2 = 35,000`。这个 35,000 在披露里**没有**。披露写了中值就抄，没写就不许出现「中值／中枢／均值」。
2. **自己算同比**——拿本期除以去年同期。披露写「比上年同期增长 45.12% 至 72.35%」就抄这一句，自己算出来的百分比在原文里找不到。
3. **自己算修正幅度**——修正前 2 亿、修正后 3.2 亿，相减得 1.2 亿。披露里没这句。**前后两值并列登记**，幅度有就抄、没有就写未取到。

判定方式是「引号外」：`「比上年同期增长 45.12% 至 72.35%」` 里的百分比合法（那是原句），引号外的任何百分比都发。第五节写「未取中值，未做前后相减」这类**否定式声明**不误伤——那是口径声明本身。

### 是否修正必须明写

```markdown
## 三、修正沿革

- 修正前：「预计 20,000 万元至 24,000 万元」[S1]
- 修正后：「预计 32,000 万元至 38,000 万元」[S1]
- 修正说明：「本次业绩预告系对前次预告的更正」[S1]
```

没修正过的写 `- 修正情况：「未发生修正／首次披露」[S#]`。**含糊**——既不写修正也不写未修正——和空节一样发 `FC-STRUCT`。

## 三、快速开始

先列目录，再按目录里的路由地址确认工具在场，取到公告与原文解析后再落笔：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | head -c 2000
# 从目录里取本组的路由地址，确认工具在场
curl -s -X POST "$ROUTING_URL" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

拿到文件清单后，可以先把骨架排出来：

```bash
python3 scripts/make_outline.py 清单.jsonl 骨架.md
```

再逐条读原文，把占位行换成带锚的原句。

## 四、首次开通 Cue

本包走 Cue 的 MCP 通道取公告与原文解析。首次使用要拿一个凭据（`CUE_API_KEY`），在 Cue 控制台开通后写进环境变量即可，包本身不存凭据、不打印凭据。

不装也能跑：零通道时本包只把用户手上的预告区间排成骨架，代价是**看不到原文**——没有原文就没有原句，六项里四项挂不上锚，这份稿只剩用户口述的几个数。

## 五、边界与不承诺

- 本件登记的是**披露说了什么**，不是对业绩好坏的评价。
- **不判超预期／不及预期**——那是一句评价，不是披露。要写只能挂 `[待人工]`。
- **不推断正式财报数**：预告是区间，年报是点数，本件不换算、不说「正式数应为」。
- 评级、目标价、买卖建议、股价预测：本件不产出。
- 不转述研报、新闻、股吧。没有公告链接与检索日的事实不进本件。

## 六、出错了怎么办

| 症状 | 多半是 | 怎么改 |
|---|---|---|
| `FC-STRUCT` 说二节缺某项 | 六项漏写了 | 补上 `- 项名：「原句」[S#]`，六项一个不能少 |
| `FC-STRUCT` 说类型不在册 | 用了「大幅增长」这类说法 | 换成在册九种之一：预增／预减／扭亏／首亏／续盈／续亏／略增／略减／不确定 |
| `FC-STRUCT` 说自称修正过但缺修正前 | 只写了后值 | 补 `- 修正前：「…」[S#]` |
| `FC-QUOTE` 说某项没挂原句 | 只写了数字没引话 | 把披露原句放进「」里，再挂 `[S#]` |
| `FC-QUOTE` 说引号是空的 | 写了 `「」` 占位 | 填上原句，或改写成「未取到」并进第五节 |
| `FC-CALC` 说出现「中值」 | 自己取了区间中值 | 删掉；披露没写就没有这个数 |
| `FC-CALC` 说引号外有百分比 | 自己算了同比或修正幅度 | 把百分比挪进引号（如果原句有），否则删掉 |
| `FC-CALC` 说出现算式 | 用了 `(下限+上限)/2` 之类 | 删掉算式，只登记两个端点值 |
| `FC-LINE` 说命中「超预期」 | 下了评价 | 删掉评价，或整句挂 `[待人工]` |
| `FC-BOUND` 说口径没起头 | 口径句写成了财报点评 | 改成以「业绩预告」或「业绩快报」起头 |

## 七、怎么开口

- **正例**：「这家公司刚发的业绩预告说了什么」「预计净利润区间是多少」「同比变动幅度公告里怎么写」「这次预告修正过没有，修正前后各是多少」「变动原因原话是什么」
- **反例**：「这业绩超预期吗」「股价会涨吗」「给我个目标价」「值不值得买」——这些本件不产出，会直接回 `[待人工]`。

---

## 八、能力边界（诚实清单）

- 只认披露原文。披露写得含糊的地方，本件跟着含糊并点名未取到，不替它补全。
- 预告常只给合并口径的净利润区间，分季度、分产品拆分一般不披露，这类只能记到「未取到」。
- 变动原因常是一句概括性描述，本件照抄，不替它归因。
- 机检判的是形制与口径，判不了内容真假。数字对不对，最终要人回原文核对——这也是头部那四件自标的意思。
