# 业绩预告速读·区间与修正逐条挂源

## 0. 这是什么、不是什么

| 是 | 不是 |
|---|---|
| **单份**业绩预告／业绩快报文件，六项要素逐项登记 | 已出完整财报的点评（收入、利润率怎么变、为什么变） |
| 每项挂「」原句与检索日，缺的逐条点名 | 判断「超预期／不及预期」，或据此预测股价 |
| 是否修正过：修正前、修正后两值并列 | 自己取区间中值，或拿前后两值相减得修正幅度 |
| 一律照抄披露里的数，不换算、不改写 | 推断正式财报数、给评级与目标价 |
| 单份文件的逐项登记 | 当日全部公告的清单，或一篮子标的的隔夜全景 |

**三条分界（用户靠这三句分清邻近件）：**

- `cn-earnings-note` 评的是**已经出的完整财报**——收入怎么变、毛利率怎么变、为什么变。本件**不评业绩**，只登记预告／快报本身说了什么。
- `announcement-daily-cn` 是**单一公司当日全部公告**的清单。本件只取其中**业绩预告／业绩快报**这一类，且逐项登记不列清单。
- `cn-morning-brief` 是**一篮子标的**的隔夜全景。本件是**单份预告文件**的逐项登记。

**「不得自算」在本件里具体指哪三件（先说清楚，防误读）：**

1. **区间中值不许自己取。** `(下限 + 上限) / 2` 是卡面算出来的数，披露里没有这一句。披露写了中值就照抄并挂锚；没写就不许出现「中值」「中枢」「均值」。
2. **同比幅度只认原句。** 披露写「比上年同期增长 45.12% 至 72.35%」就抄这一句；卡面自己拿本期除以去年同期得出的百分比，在原文里找不到。
3. **修正幅度不许自己拿前后相减。** 修正前 2 亿元、修正后 3.2 亿元，两者相减得 1.2 亿元——这个数披露里没有。修正前、修正后两值**并列登记**，幅度披露有就抄、没有就写未取到。

## 1. 什么时候用

- 「这家公司刚发的业绩预告说了什么」「预告类型是预增还是扭亏」
- 「预计净利润区间是多少到多少」「同比变动幅度多大」
- 「这次预告修正过没有，修正前后各是多少」
- 「变动原因公告里怎么写的」

**不要用**：要评已出的完整财报（走 `cn-earnings-note`）；要当日全部公告的清单（走 `announcement-daily-cn`）；要一篮子标的的隔夜全景（走 `cn-morning-brief`）；要判断超预期与否、评级、目标价、股价走势（本件不产出，也不该由任何件产出）。

## 2. 取数纪律

1. **只认披露原文。** 每一项都要能回到一份预告／快报文件的链接与检索日。研报、新闻、股吧转述一律不作来源。
2. **每条都引原句。** 六项里的每一项都写成 `- 项名：「原文原句」[S#]`，引号里是公告的原话，不是改写。引号空着等于没挂。
3. **不改写数字。** 披露写 32,000 万元就写 32,000 万元，不写「约 3.2 亿」「3 亿元左右」。
4. **不取中值。** 见第 0 节三条。
5. **不自己算幅度。** 同比、环比、修正幅度，披露没写就写未取到，不拿两个数相除或相减顶上。
6. **是否修正必须明写。** 修正过的，修正前与修正后两值并列（`- 修正前：「…」[S#]` / `- 修正后：「…」[S#]`）；没修正过的，写「未修正／首次披露」。含糊——既不写修正也不写未修正——同样算错。
7. **没取到就写没取到。** 正文写了「未取到 X」，第五节必须逐条点名 X；第五节点了名而正文没有这条表述，同样算错——两向都判。
8. **不推断正式数。** 预告是区间，年报是点数。本件不写「正式数将为」「据此推算」，区间登记完就结束。

## 3. 输出契约（六节，按序）

```
AI 整理初稿｜请回原文核对｜不构成投资建议｜判断位 [待人工]

基准日：2026-11-09
数据口径：业绩预告（单份预告文件逐项登记，不评已出财报，不推断正式数）

## 一、一句话结论
## 二、预告要素
## 三、修正沿革
## 四、未决事项
## 五、未取到与口径
## 六、来源
```

- **头部四件自标**逐字在位，写在第一个 `## ` 之前。
- **基准日**行必须以 `基准日：` 起头、值为 `YYYY-MM-DD`；缺或值不可认都发。
- **数据口径**行必须以「业绩预告」或「业绩快报」起头——这一格是本件与已出财报点评的分界，必须自报。开票距已出报告近、正文引了财报综述，写 `数据口径：业绩预告＋已出财报对照（预报为主，财报段走 cn-earnings-note）`，不改名目。
- **二、预告要素**六项齐，一行一项，格式 `- 项名：「原句」[S#]`：
  预告类型（在册：预增／预减／扭亏／首亏／续盈／续亏／略增／略减／不确定）、区间下限、区间上限、同比变动幅度、变动原因、披露日（`YYYY-MM-DD`）。
  下限不得大于上限；比较大小不产出任何新数。
- **三、修正沿革**：修正过的写 `- 修正前：「…」[S#]` 与 `- 修正后：「…」[S#]`，再补一行说明；没修正过的写 `- 修正情况：「未发生修正／首次披露」[S#]`。空节等于把沿革藏起来。
- **四、未决事项**：预告到正式财报之间一定留下未决事项（区间何时收窄、有无业绩承诺、审计是否或有调整），空节等于把不确定性藏起来。
- **五、未取到与口径**：逐条点名未取到的项；口径行写清区间与幅度是照抄还是未取。
- **六、来源**每行：`- [S#] 文件标题 URL 检索日 YYYY-MM-DD`，编号与正文锚一一对应。

## 4. 数据通道

本件走 Cue 的 MCP 通道取公告与原文解析。先列目录，再按目录里的路由地址调 `tools/list`，确认工具在场后再取数：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | head -c 2000
# 从目录里取本组的路由地址，再确认工具在场
curl -s -X POST "$ROUTING_URL" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

拿到预告与快报文件后，用 `scripts/make_outline.py` 把清单排成骨架，再逐条读原文补内容。

## 5. 合规红线

- **不判超预期／不及预期。** 那是一句评价，不是披露。要写只能同行挂 `[待人工]`。
- **不给评级、目标价、投资建议、买卖与减持建议。**
- **不预测股价**，不写「将上涨／将下跌／有望走强」。
- **不推断正式财报数。** 预告区间不换算成点数，也不说「正式数应为」。
- **不用改数词打底。** 「约」「左右」「大概」不得替披露里的确切数字。
- **不转述二手来源。** 没有公告链接与检索日的事实不进本件。

## 6. 快速流程

1. 定基准日，取到这份预告／快报的原文（含更正公告，若有）。
2. 六项逐项抄原句：预告类型、区间下限、区间上限、同比变动幅度、变动原因、披露日。
3. 查是否修正过：修正过的把修正前与修正后两值并列；没修正过的明写未修正。
4. 写未决事项与未取到，两向对齐。
5. 跑 `python3 scripts/check_forecast.py <稿>.md`，红一条改一条。

## 7. 机检

```bash
python3 scripts/check_forecast.py <预告稿>.md     # 五道，退码 0 全过 / 1 有发条 / 3 读不到文件
python3 scripts/check_forecast.py --selftest      # 包内夹具自检
bash scripts/fixtures/run_fixtures.sh             # 三档离线自检，30 秒，零网络零计费
```

五道：**道一 形制**（头部自标、基准日、数据口径、六节齐且有序、二节六项齐、预告类型在册、披露日形制、下限不大于上限、修正沿革不空且前后两值齐）／**道二 原句与锚**（六项每项挂非空「」原句与 `[S#]`、每行有锚或 `[待人工]`、来源行齐编号与 URL 与检索日、来源不得空）／**道三 红线**（超预期评价、评级目标价、买卖建议、股价预测、推断正式数、改数词零命中）／**道四 不得自算**（引号外出现中值、百分比、算式、幅度标签后直接跟数字，一律发；「未取中值」这类否定式声明不误伤）／**道五 边界**（数据口径须以业绩预告或业绩快报起头；正文提到已出财报／公告清单／隔夜全景却没点名对应件，点名）。

## 8. 零通道降级

没有 `CUE_API_KEY` 时，本包**不产出内容**，只把用户手上的预告区间排成带形状的骨架：六项与来源行按用户给的清单落位，结论与口径留占位。骨架跑机检必然红在占位行上——这是设计，提醒你补完再交，而不是让空壳冒充成品。代价说清楚：**没有通道就没有原文，没有原文就没有原句，没有原句这六项里四项都挂不上锚**，这份预告稿只剩用户口述的几个数。
