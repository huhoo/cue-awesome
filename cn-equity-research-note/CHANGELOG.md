# 更新日志

### 0.1.0 — 2026-11-08（首版：未出财报期的个股研究初稿，七节契约 + 五道机检）

- 本件做什么：把「一家公司还没出财报的这一段」变成「一份每条都能回到一处带检索日来源的研究稿」。四节内容（业务拆解／竞争位／驱动因子／风险清单）每条发现行末挂一个 `[S#]`，第七节逐条给 URL 与检索日；未取到的逐条点名；判断位一律 `[待人工]`。
- 与 `cn-earnings-note` 的分界（本件存在的理由）：那一件做**已出财报**的点评——四期差异、科目勾稽、指引与兑现对照、覆盖账本，输入必须有财报；本件做**未出财报期**的个股研究，输入是公告＋研报＋新闻，不要求财报。头部那行 `财报状态：` 是这条分界的机检入口：写成「已出」由道五点名改走那一件，写个认不出的值由道一发红。
- 五道机检（`scripts/check_note.py`，零网络、纯标准库）：
  - 道一 `E-FORMAT` 形制：七节齐且有序；头部四件自标逐字在位；`财报状态：` 行在场且值可认；四个内容节各至少一行（空节＝不是一份研究稿）；结论位写成占位即红。
  - 道二 `E-ANCHOR` 锚：每条发现行末一个 `[S#]`；该编号在第七节有对应行；来源行同时带 URL 与检索日 `YYYY-MM-DD`。
  - 道三 `E-BANWORD` 红线：评级／目标价／建仓清仓／必涨必跌／稳赚无风险／跑赢大盘／严重低估严重高估一类断言零命中，除非同行挂 `[待人工]`；改数词（约／左右／大概）不得替数字打底。
  - 道四 `E-COVERAGE` 未取到两向点名：正文写了未取到而第六节没列发红，第六节列了而正文没有这条表述同样发红；两向都按**名目同指**对（剥括号注与标点后，字面全等／一方完整含另一方且短的一方 ≥4 字／汉字集合重合率 ≥0.6），同一件事换个写法不判红。
  - 道五 `E-SCOPE` 边界：`财报状态：` 写成「已出」时点名改走 `cn-earnings-note`，不是只报形制错。
- 红线里那条收窄（写进件内，防后人放宽）：**股东增减持是事实陈述，不是推荐语**——「控股股东计划减持不超过 2%」照常登记；禁的是「建议增持」「建议减持」这类推荐动作。机检按词族收，不按「增持／减持」两个字收。runner 档⑤ 的边界①与②成对钉住这个收窄的两个方向。
- 零通道那一头：`scripts/make_outline.py` 把材料清单排成一张待填骨架，四个内容节各按来源挂一行「未取到（骨架）」的发现位，第六节逐条点名，结论位留占位。**代价同句写清**：缺的正是公告检索与原文解析那一层，所以骨架只会有形状、不会有权衡后的结论——骨架过不了机检是设计，不是待补的疏漏。材料清单里非法 JSON 行、缺键行、日期不合形的行一律未采信并逐行点名，不静默跳行；一条可用行都没有时退 1。
- 离线 runner（`scripts/fixtures/run_fixtures.sh`，零网络、零计费、产物只落临时目录跑完即删）五档：① 机检自测（好样 1 枚 + 坏样六道 6/6 + 钉阈三形 + 反证四档 + 临时根自清）② 好样与六枚坏样逐枚单跑，每枚报它自己的退码与码集，不并成一个总数 ③ 零通道骨架 ④ 骨架过机检须红在结论占位那一行 ⑤ 边界形逐枚单跑（增减持事实陈述不误红／推荐语必红／财报状态已出→道五点名／状态值认不出→形制红／改数词必红）。末行自报「档数=5｜不合=N｜不可判=N」；退码 0 全合期望、1 有不合、3 取值域故障（脚本或夹具取不到，不读成「零违例」）。
- 工件名：`consumes: parsed-doc`（在册 canonical，由现役件产出并被多枚现役件消费，故本件入度 ≥1）；`inputs: announcement-doc / source-file`（在册 inputs 族，写进包面 `inputs:` 键，不参与算边）；`produces: research-brief`（在册 canonical）。未新增任何工件名，未改 `artifact-types.yaml`。
- 通道与降级：主路＝公告检索与原文解析（数据腿 `cue-data-mcp` 定位、解析腿 `cue-omni-reader` 取正文）；降级＝零通道骨架。三层自查照仓内既有面写：**装好 skill ≠ 已配凭据 ≠ 通道已连**。本件不发请求、不代付费，消耗以服务端返回为准。
- 未做（写在这里防后人误读）：不做估值建模与财务预测；不做行情与资金流数值；不判断方案优劣与内幕信息可能；不持久存用户文件；不发布、不代下结论。
