### 0.1.0 — 2026-11-09（首版：未出财报期的个股深度研究五节契约 + 五道机检）

**先接旧版。** 本件目录在 M595 曾以另一套契约（`consumes: parsed-doc`、七节、`E-FORMAT`/`E-ANCHOR`/`E-BANWORD`/`E-COVERAGE`/`E-SCOPE` 五个码名）落过一版。M608 领退判定「壳与本体不一致」，本轮按领单重做：五节形制、三元组原句锚、道四改判「不得自算」，码名统一为 `ER-*` 前缀。旧版在 git 历史 `b386632` 可取回，不在此并列两套口径。

**这是什么。** 给一个股票代码或公司名称，在**财报尚未披露**的那一段，产出一份五节齐的个股研究初稿：业务拆解／竞争位／驱动因子／风险清单／关键数字表。每个数字与每条判断行末挂三元组「」原句＋〔锚：页/节/表〕＋`[S#]`；来源行带可点 URL 与检索日。不出评级、目标价、股价预测与看好/看空。

**与两枚现役件的分界（本件存在的理由）：**

- `cn-earnings-note` 做**已出财报**的点评——四期差异、科目勾稽、指引与兑现对照，输入必须有财报。本件**不要求财报**，做的是预期期的个股研究。
- `cn-research-brief` 是**问题驱动**的多源速览，你问什么它答什么。本件是**标的主键驱动**：给代码/名称，出一份结构化的公司研究。
- 研报原文抓取那一类工具搬的是研报结论；本件把研报当来源之一，但**观点必须能回到句子**，不搬结论。

**五道机检**（`scripts/check_note.py`，零网络、纯标准库）：

- `ER-FORM` 形制：头部四件自标（AI 整理初稿／请回原文核对／不构成投资建议／判断位 `[待人工]`）在第一个 `## ` 之前；`主体：` 与 `截至日：YYYY-MM-DD` 在场；六节齐且按序（四节正文＋关键数字表＋来源）；四节各至少一条发现行，节内只许 `- ` 发现行；关键数字表有表头与数据行，表头含「原句」「锚」「来源」三列。
- `ER-ANCHOR` 原句与锚：每条发现行以「」原句＋〔锚：…〕＋`[S#]` 收尾，原句与锚不得为空；关键数字表数据行须同时有原句与 `[S#]`；来源行须齐 `[S#]`＋可点 http(s) URL＋检索日 `YYYY-MM-DD`；正文引用的每个 `[S#]` 必须在来源节登记。
- `ER-REDLINE` 红线：评级（买入/增持/中性/推荐/看好/看空…）、目标价与目标市值、股价与市值走势预测、跑赢跑输、严重低估高估、必涨必跌稳赚零风险一类断言零命中。含 `[待人工]` 的分句**只豁免它自己那一句**（按 `；;。，,｜` 切分），同行后半句照样发。
- `ER-NOSELF` 不得自算：发现行与表行里的百分数必须能在**同一行的「」原句里逐字找到**；找不到的须标 `〔自算〕`，并在同一行同时给出 `分子…[S#]` 与 `分母…[S#]`。标了 `〔自算〕` 却缺分子或缺分母的来源同样发。分子分母的 `[S#]` 必须挂在自己那个数上，不许跨过 `｜`、引号或锚的收尾去借下一处来源。
- `ER-SCOPE` 边界：出现「已出财报／财报点评／四期差异／科目勾稽／覆盖账本」点名改走 `cn-earnings-note`；出现「问题清单／逐问作答／问题驱动／多源速览」点名改走 `cn-research-brief`；出现「研报摘要／研报结论／研报原文摘录」点名本件只认能回到句子的原句。

**两处「不红」是设计，不是漏网**（写在这里防后人放宽）：

- `未取到 …` 行本身没有原句可挂——它缺的就是那份材料，只要求挂 `[S#]` 指向查过的那一处。
- `[待人工]` 行是判断位交付给人的那个位置，同样没有原句可挂。

**三处易误红，已在档三钉死正反两向：**

- 标了 `〔自算〕` 且分子分母各挂源 → **不红**；只标 `〔自算〕` 而分母无出处 → **红**。
- 非百分数的自算（如「约为 2.15 倍」）不强制标 `〔自算〕` → 不红。
- `[待人工]` 整句成立 → 不红；`[待人工]` 后面接「建议买入」→ 红。

**离线 runner**（`scripts/fixtures/run_fixtures.sh`，零网络、零计费、产物只落临时目录跑完即删）三档：

- 档一 机检自测（`--selftest` 11 条内置夹具，含三枚反证）。
- 档二 好样 1 枚＋坏样 7 枚逐枚单跑，每枚只许发它自己那一道码；另有两枚反证（整句 `[待人工]` 应零发条、`[待人工]` 后半句接评级应只发 `ER-REDLINE`）。
- 档三 边界 14 条：在好样上**逐行替换／插入／删除**做正反对照——该红的红（自算缺分母、引用了没登记的来源、三元组不在行末、空节、已出财报语境、问题驱动语境…），该不红的不红（自算并交代分子分母、整句 `[待人工]`、未取到行无原句）。`empty` 空稿与 `nofile` 缺文件走 `rc=3`。

末行自报「档数=3｜不合=N｜不可判=N」；退码 `0` 全合期望、`1` 有不合、`3` 取值域故障（脚本或夹具取不到，不读成「零违例」）。

**工件名与两栏语义边界（领单要求在此定一次，防下游读到两个答案）：**

- `consumes: parsed-doc`（在册 canonical，12 枚现役件在消费）——**已经落到本件工作区、可直接引用的解析产物**。它是「边」：上游件产出、本件消费。
- `inputs: announcement-doc / source-file`（在册 inputs 族）——**用户或外部必须自己提供的入参**，写进包面 `inputs:` 键，**不参与算边**，也不算我们的漏。
- 一句话分界：**`consumes` 是别人给我的半成品；`inputs` 是我开工前必须向人讨的原料。**
- `produces: structured-note`（在册 canonical，2 枚现役件在消费：`cn-customer-concentration`、`ic-memo-cn`）。**不使用 `research-brief`**：全仓 50 件 `consumes` 栏里 `research-brief` 消费者为 0 枚，那样出边是死的；且 `research-brief` 是 `cn-research-brief` 已产出的名字，本件认领它会与「问题驱动 vs 标的驱动」这条分界混腔。未新增任何工件名，未改 `scripts/artifact-types.yaml`。
- 英面不承担声明：按 `artifact-types.yaml` 第 12 行「en 面不承担声明」，`SKILL.en.md` 不带 `consumes`／`inputs`／`produces` 三键。
