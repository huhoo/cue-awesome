# 个股深度研究·逐条挂源（设计权威）

**定位**：把「一家公司还没出财报的这一段」变成「一份每条都能回到一处带检索日来源的研究稿」。要点不稀缺，**稀缺的是每条要点都能回到一处带检索日的来源**。
**不是**决议，不是荐股，不是单源转述，也不会自己发布。

## 0. 是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 未出财报期的个股研究：业务拆解、竞争位、驱动因子、风险清单四节，每条发现行末一个 `[S#]` | 不是财报点评：已出财报期的四期差异、科目勾稽、覆盖账本走 `cn-earnings-note`，本件不重复那一套 |
| 来源行必须同时带 URL 与检索日（个股研究的时效以检索日为凭） | 不是时间不写的「最新消息」：日期缺位机检直接发红 |
| 未取到与口径单独成节，逐条点名 | 不是把空白填圆：没取到的要么点名要么不写 |
| 判断位一律 `[待人工]` | 不是评级器：目标价／买卖／走势类断言零产出，命中即红 |
| 无通道时出一张有形状的骨架，红在结论占位那一行 | 不是把骨架当交付：结论位留占位是设计，不是待补的疏漏 |

**与 `cn-earnings-note` 的分界（用户靠这一句分清两枚包）**：那一件做**已出财报**的点评——四期差异、科目勾稽、指引与兑现对照、覆盖账本，输入必须有财报；本件做**未出财报期**的个股研究——业务怎么拆、竞争位在哪、驱动因子是什么、风险清单有哪些，输入是公告＋研报＋新闻，**不要求财报**。财报空窗期用本件，财报落地后逐数核口径用那一件；两枚不互相覆盖，也不互为替代。

## 1. 输入

- 一批材料：公告原文、研报、新闻、经解析得到的文档（`parsed-doc`）；或你手上已有的材料。
- 或一个待查问题：本件先把它拆成可逐条核对的发现位，再等材料填。
- 主体与检索窗口由你给；本件不替你选主体，也不替你定时间范围。
- **财报状态由你确认**：本件只做未出财报期，头部那一行「财报状态：」是它与财报点评的分界，写错就走错件。

## 2. 工作流（四步，每步都可停）

1. **收源**：逐条登记来源，一行一条，标题＋URL＋检索日（`YYYY-MM-DD`）——日期是取数那一刻的日期，不是文章发布日期。
2. **摘条**：每条发现一行，只写来源里确实载着的话；行末挂该来源的编号 `[S#]`。跨源不一致时两条都留、不合并、不取平均。四个内容节（业务拆解／竞争位／驱动因子／风险清单）各至少一行——没有风险清单的研究稿不是研究稿。
3. **点名**：任何「没取到／没检索到」写进第六节并逐条列出——正文写了未取到而第六节没有它，机检发红；第六节列了而正文没有这条表述，同样发红。两向都按**名目同指**对（不是整节里出现过「未取到」三个字就算点过名）：名目先剥括号注与标点，再按「字面全等／一方完整含另一方且短的一方不少于 4 字／汉字集合重合率 ≥0.6」三种情形认同一件事——同一件事换个写法不判红，真没点到才判红，真多列也判红。
4. **过机检**：`python3 -B scripts/check_note.py <研究稿.md>`，按详行的 `E-*` 码逐条改。机检过完仍只是**草稿**：结论位要不要填、怎么填，由人定。

## 3. 输出契约（七节，机检按此判）

1. `## 1、一句话结论`：一句实句；写成占位会被判红。
2. `## 2、业务拆解`：主营构成、客户与供应商结构、产能与在建项目，每条一行、行末一个 `[S#]`。
3. `## 3、竞争位`：份额、可比公司对照、关键件自供与外购，每条一行、行末一个 `[S#]`。
4. `## 4、驱动因子`：下游周期、产能释放、政策与目录、并购与整合，每条一行、行末一个 `[S#]`。
5. `## 5、风险清单`：客户集中、产能消化、整合、供应集中、口径风险，每条一行、行末一个 `[S#]`。
6. `## 6、未取到与口径`：未取到的逐条点名（名目与正文一对一对得上，少列与多列都发）＋口径说明（谁给的数、什么口径）。
7. `## 7、来源`：一行一源，`- [S#] 标题（URL ｜检索日 YYYY-MM-DD）`。

头部另有五件自标：AI 整理初稿／请回原文核对／不构成投资建议／判断位 [待人工] 四件逐字在位，加一行 `财报状态：未出（最近一期：…）`——写成「已出」会被道五点名改走 `cn-earnings-note`，写个认不出的值会被道一发红。

## 4. 通道与降级（两条路都真跑过）

- **主路＝公告检索与原文解析**：公告与研报的定位走数据腿（`cue-data-mcp`），长附件与多页 PDF 的正文取回走解析腿（`cue-omni-reader`）。实连判据照仓内既有面写：装好 skill ≠ 已配凭据 ≠ 通道已连——这一判据只管数据腿那一路：带 key 按目标域 `routing` 实连且该端 `tools/list` 有返回，才证那把 key 被接受、也只证数据腿连上；解析腿的连通另按它自己那面的判据读。命令与三层自查见 `README.md` 的「首次开通」那一节。配置指路：数据腿官方配置页 <https://cuecue.cn/hub/mcp>、解析腿官方配置页 <https://cuecue.cn/hub/omni-reader>，取 key 走 <https://cuecue.cn/hub/api-key>。
- **降级＝零通道**：本件仍能跑 `scripts/make_outline.py`，把已有材料清单排成一张待填骨架；代价同句写清——**缺的正是公告检索与原文解析那一层，所以骨架只会有形状、不会有权衡后的结论**（结论位留占位，机检按设计发 `E-FORMAT`）。骨架不是研究稿，别把它当交付。

## 5. 红线（机检守，不由人守）

- 评级／目标价／建仓清仓／必涨必跌／稳赚无风险／跑赢大盘／严重低估严重高估一类断言零命中；要提及就同行挂 `[待人工]`。
- **股东增减持是事实陈述，不是推荐语**：写「控股股东计划减持不超过 2%」照常登记；禁的是「建议增持」「建议减持」这类推荐动作——机检按词族收，不按「增持／减持」两个字收。
- 改数词（约／左右／大概）不得替数字打底；数值只照来源写，口径不齐就落第六节。
- 没有锚的要点不进内容节；对不上来源的锚发 `E-ANCHOR`。
- 本件不发请求、不代付费：解析与检索的消耗以服务端返回为准，本件不代估也不代付。

## 6. 最小可复跑链（零网络、零计费）

```bash
python3 -B scripts/make_outline.py --sources scripts/fixtures/sources.jsonl --out 我的骨架.md
python3 -B scripts/check_note.py 我的骨架.md            # 期望发 E-FORMAT：结论位仍是占位＝骨架不是交付
python3 -B scripts/check_note.py scripts/fixtures/good-note.md   # 期望 PASS：七节齐、逐条挂源、判断词零命中
python3 -B scripts/check_note.py --selftest                    # 好样须过、六枚坏样须各发它该发的那一道
bash scripts/fixtures/run_fixtures.sh                            # 离线三档一次跑完，末行自报档数与不合枚数
```

## 7. 边界

- 本件只对「这一批材料被逐条挂实地排成一份研究稿」负责，且只对形制负责：内容对不对要人回原文核。
- 已出财报期的逐数点评不要用本件——那是 `cn-earnings-note` 的活；本件不重复四期差异与科目勾稽。
- 单一来源的场景不要用本件——那是一篇转述；多源互校才是它的用途。
- 需要成体系的投决讨论稿走投决备忘录那一件；本件只出研究稿。
