# cn-equity-research-note

**给一家还没出财报的公司，产出七节个股研究初稿：业务拆解、竞争位、驱动因子、风险清单四节逐条挂源，每条发现带一条可回查来源与检索日，未取到的逐条点名，判断位一律留人工。**

要点不稀缺，**稀缺的是每条要点都能回到一处带检索日的来源**。差异化不在排版，而在两道硬门禁：没有锚的要点进不了内容节，没点名的缺口过不了机检。

**输入**：一批材料（公告原文／研报／新闻／解析件）＋主体与检索窗口，或一个待查问题
**输出**：七节研究稿（一句话结论／业务拆解／竞争位／驱动因子／风险清单／未取到与口径／来源）
**代价**：七节契约 + 一道机检；通道腿（公告检索／原文解析）开没开，决定的是多源取证与逐条出处那一层——两条路各自缺什么、走哪条，写在 §二 与 §四
**机检**：`scripts/check_note.py` 五道（形制／锚／红线／未取到两向点名／财报状态边界），零网络；反证矩阵长在这支脚本里

**它和 `cn-earnings-note` 不是一件事（这一句是本件存在的理由）**：那一件做**已出财报**的点评——四期差异、科目勾稽、指引与兑现对照、覆盖账本，输入必须有财报；本件做**未出财报期**的个股研究——业务怎么拆、竞争位在哪、驱动因子是什么、风险清单有哪些，输入是公告＋研报＋新闻，**不要求财报**。财报空窗期用本件，财报落地后逐数核口径用那一件；两枚不互相覆盖，也不互为替代。头部那行「财报状态：」就是这条分界的机检入口——写成「已出」会被点名改走那一件。

## 一、打开就干：今天这三步

| 步 | 动作 | 怎么做 | 不做会怎样 |
|---|---|---|---|
| ① | **先看形状**（30 秒、零网络、零计费） | `bash scripts/fixtures/run_fixtures.sh` —— 五档一次跑完：机检自测、好样坏样逐枚单跑、零通道骨架、骨架该红就红、边界形逐枚单跑。末行自报「档数=5｜不合=0｜不可判=0」 | 没见过形状就上手，容易把「排得整齐」当成「有出处」；这一档 30 秒就能看出两者的差别 |
| ② | **登记来源，逐条挂源** | 每个来源一行写进第七节：`- [S#] 标题（URL ｜检索日 YYYY-MM-DD）`；四个内容节每条发现行末挂一个 `[S#]`。跨源不一致就两条都留，不合并、不取平均 | 缺检索日的来源行发 `E-ANCHOR`；没有锚的要点写进内容节同样发 `E-ANCHOR`——那时你要回来逐条补，比现在一条条挂贵 |
| ③ | **过机检，再交人** | `python3 -B scripts/check_note.py <研究稿.md>`，按详行的 `E-*` 码逐条改；改完仍只是**草稿**：结论要不要下、怎么下，由人定 | 未取到没点名、判断词漏进正文、来源与锚对不上，都会跟着稿子进到人的判断里；这三类都是机检能拦的形制层，内容层还得回原文 |

评级与目标价、买卖与时机建议、已出财报期的逐数点评**不在这三步里**——本件只对「这一批材料被逐条挂实地排成一份研究稿」负责，且只对形制负责。

## 二、装上机 → 连通道 → 出结果

**装本件自己（主路）**：`npx skills add huhoo/cue-awesome --skill cn-equity-research-note`——这条只装本包；装完在你这一侧重列一次已安装 skill，清单里看得到 `cn-equity-research-note` 这个名字才算文件到位。没有 CLI 环境时的兜底是把本目录整个放进宿主支持的 skills 目录（`~/.workbuddy/skills/`）。

本件的取证腿是两枚可选辅助：`cue-data-mcp`（公告与研报的定位，走数据腿）与 `cue-omni-reader`（把 PDF／网页／音视频转成可摘的文本，走解析腿）。通道侧的实连走这条正路：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | python3 -c 'import json,sys
rows=json.load(sys.stdin)["data"]["domains"]
[print(r.get("id"), r.get("external_status"), (r.get("routing") or {}).get("url", "-")) for r in rows]'
DOMAIN_ID="<把这里换成上一行列出的那个域 id>"
ROUTING_URL="$(curl -s "$CATALOG" | python3 -c 'import json,sys
rows=json.load(sys.stdin)["data"]["domains"]
hit=[r["routing"]["url"] for r in rows if r.get("id")==sys.argv[1] and r.get("routing")]
print(*hit,sep="\n") if hit else sys.exit("未取到：该 id 不在目录现值里（或它没有 routing 里的 url 字段）——先跑上面那行列出现场的 id 再填")' "$DOMAIN_ID")"
[ -n "$ROUTING_URL" ] || { echo "取值失败：ROUTING_URL 为空——先跑上面那行列出现场 id，再把 DOMAIN_ID 换成其中之一" >&2; exit 1; }
curl -s -X POST "$ROUTING_URL" \
  -H "Authorization: Bearer $CUE_API_KEY" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' \
  -w '\nHTTP %{http_code}\n'
```

`CATALOG` 是本面唯一一处目录入口字面（赋一次、散文不重抄）；`$ROUTING_URL` 是从该域 `routing` 里的 `url` 字段现取的逐字值，别把域名或路径抄死在这张面上。三层各自能证到什么，互不等价：**装好 skill ≠ 已配凭据 ≠ 通道已连**。匿名 `GET` 只证**目录可达**，本面不把它叫「已连」；带 key 实连且 `tools/list` 有返回才证那把 key 被接受，通过＝HTTP 200 且 `result.tools` 非空（只按形状认，本面不列工具名也不承诺枚数）。解析那一腿走宿主 MCP：**连上之后**宿主列出的工具里应当能看到这些名字——remote-only 那一面是 `parse`、`get_parse_status`、`cancel_parse` 三枚，带 Bridge 的那一面再加 `read_result`、`read_outline`、`discard_result`、`save_result`，共七枚；两路枚数不同，拿一个固定数判两路必错一边。名字在场只证它们被暴露，不证解析跑得通——URL 那一腿要拿一枚真实 URL 跑一次 parse 才证该路，本地文件那一腿要拿一枚真实本地文件跑一次 parse 才证该路（remote-only 不读本地件）；本件不自证也不代跑。目录返回里没有的域本面不装也不承诺；连接报错不等于域无数据，如实报。key 取自本地凭据设施，不进聊天、不在终端回显，本面不新增任何凭据读取动作；解析与检索的消耗以服务端返回为准，本件不代估也不代付，花之前一定先问。配置指路：数据腿官方配置页 <https://cuecue.cn/hub/mcp>、解析腿官方配置页 <https://cuecue.cn/hub/omni-reader>（本件两条腿都可能用上——公告与研报的定位走数据腿，长附件与 PDF 的正文取回走解析腿），取 key 走 <https://cuecue.cn/hub/api-key>。

## 三、离线样例：30 秒看到形状

```bash
cd cn-equity-research-note
bash scripts/fixtures/run_fixtures.sh
# 档① 机检自测：好样须过、六枚坏样须各发它该发的那一道 → selftest: ALL GREEN
# 档② 好样与六枚坏样逐枚单跑：每枚报它自己的退码与码集，不并成一个总数
# 档③ 零通道骨架：scripts/make_outline.py 把 scripts/fixtures/sources.jsonl 排成一张待填骨架
# 档④ 骨架过机检：期望发 E-FORMAT——结论位仍是占位，骨架不该被当成研究稿交付
# 档⑤ 边界形逐枚单跑：增减持事实陈述不误红／推荐语必红／财报状态已出→道五点名／状态值认不出→形制红／改数词必红
```

自己上手时同样两条命令：

```bash
python3 -B scripts/make_outline.py --sources 你的材料.jsonl --out 我的骨架.md
python3 -B scripts/check_note.py 我的骨架.md
```

来源行必需三键：`title`／`url`／`asof`（检索日 `YYYY-MM-DD`），`id` 可省、缺省按行序给 `S1／S2…`。非法 JSON 行、缺键行、日期不是 `YYYY-MM-DD` 的行一律**未采信并逐行点名**，不静默跳行；一条可用行都没有时退 1——空清单不出骨架，那是没有出处，不是待填。

## 四、依赖与两条路的代价

**主路（有通道）**：公告与研报的定位走数据腿，长附件与多页 PDF 的正文取回走解析腿。两条腿都开时，本件能给出「每条发现都回到一处带检索日的原文」这一层；缺哪条腿，缺的就是那一层——数据腿缺位时公告与研报只能靠你直供，解析腿缺位时附件里的原句只能停在「未检索到」。

**降级（零通道）**：`scripts/make_outline.py` 把已有材料清单排成一张待填骨架。**代价同句写清**：缺的正是公告检索与原文解析那一层，所以骨架只会有形状、不会有权衡后的结论——结论位留占位，机检按设计发 `E-FORMAT`。骨架不是研究稿，别把它当交付。

## 五、边界与不承诺

- 评级、目标价、买卖与时机建议一律 `[待人工]`；不出「建议买入」「建议增持」「必涨」「稳赚」「零风险」「跑赢大盘」「严重低估」这类断言；
- **股东增减持是事实陈述，不是推荐语**：写「控股股东计划减持不超过 2%」照常登记；禁的是「建议增持」「建议减持」这类推荐动作；
- 已出财报期的逐数点评不在本件：四期差异、科目勾稽、覆盖账本走 `cn-earnings-note`；头部「财报状态：」写成「已出」会被机检点名；
- 单一来源的场景不要用本件——那是一篇转述；多源互校才是它的用途；
- 未检索到＝照实写「未检索到」，禁以行业惯例补写，也不写「无该项」顶替；
- 域与工具名以 live catalog 现值为准，本件不列固定清单、不承诺枚数，也不承诺该域是否开放与文件的实时性。

## 六、出错了怎么办

| 症状 | 来路 | 恢复动作 |
|---|---|---|
| 好几条是「未检索到」 | 材料只有公告标题，正文在附件里 | 起解析腿补原句；起不动就保留缺数点名，不补写 |
| 数据腿连不上 | 凭据缺位或该域未 live | 按 §二 自查；骨架仍可出，代价见 §四 那一句 |
| 机检发红 `E-ANCHOR` | 发现行没挂锚，或锚在第七节没有对应行，或来源行缺 URL／检索日 | 按逐条点名的行号补齐；补不出的进第六节缺数清单，不删行凑数 |
| 机检发红 `E-COVERAGE` | 正文写了未取到而第六节没列，或第六节列了而正文没有这条表述 | 两向都要对得上；同一件事换个写法不判红（按名目同指对），真没点到才红 |
| 机检发红 `E-SCOPE` | 头部「财报状态：」写成了「已出」 | 改走 `cn-earnings-note`，或把研究窗口挪到财报空窗期 |
| 机检发红 `E-BANWORD` | 写了评级／目标价／买卖建议，或用了「约／左右」替数字打底 | 改中性陈述或同行挂 `[待人工]`；数值照来源写，口径不齐落第六节 |
| 判断句被误红 | 那行写的是「控股股东计划减持不超过 2%」这类事实陈述 | 机检按词族收（「建议增持／建议减持」才红），裸「减持」不红；若仍红，看是不是同句带了别的推荐语 |

## 七、怎么开口（正例与反例）

- 正例：「这家公司靠什么赚钱、客户是谁」「它在行业里排第几、和谁比」「未来一年靠什么增长」「有哪些风险」「这份公告对业务意味着什么」。
- 反例：「值不值得买」「目标价多少」「现在能不能进」「财报这个季度怎么样」——买卖与时机、目标价、已出财报的逐数点评不在本件，一律 `[待人工]` 或改走 `cn-earnings-note`。

## 八、能力边界（诚实清单）

行情与资金流类数值不在本件能力内（该域以 live catalog 现值为准，未开放就不承诺）；本件不做估值建模与财务预测（DCF／三表模型由专门工具做）；不判断方案优劣与内幕信息可能；也不持久存你的文件，稿子出完就交还给你。
