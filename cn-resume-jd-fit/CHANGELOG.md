# 更新日志

### 0.1.0 — 2026-10-24（建件：一份简历对一枚 JD 的双向核对，要求逐条挂回原话、缺口分两栏点名）
- 建因：现役 21 枚里没有一枚做「两个输入互相对表」这件事——审件的审一枚软件包的面文，速览的是多源横向铺问题，笔记的是单源纵向成条；而招聘侧的日常动作恰好是「这份简历配不配这枚岗位」，今天没人把这一步做成可回查的东西。腿天然咬合：简历与 JD 都是文档，走解析通道那一条，远端链接、PDF、截图那侧也能读。
- 造了什么：四节契约（一句话结论只一行 ≤80 字／逐条对齐 3–15 行，每行要求与证据两段逐字引文各挂一枚锚／缺口两栏点名／来源带 文件:行号 或 URL ＋ 解析日）、一支五道机检 `scripts/check_fit.py`（形制与条数带／双锚与定位／两侧逐字回原文／缺口点名／录用与排序断言零命中，纯标准库、零网络、判定全集在脚本里）、一支离线采集器 `scripts/collect_fit.py`（把 JD 要求段逐条搬进第二节，证据位一律留待填，不代人匹配）、夹具八枚（合成简历与合成 JD 各一枚＋好样一枚＋坏样五枚）＋离线三档 runner `scripts/fixtures/run_fixtures.sh`。
- 三道硬门禁的形状：①证据那句必须逐字在简历里、要求那句必须逐字在 JD 里——两侧都比对，只给一侧时另一侧明写不可判、不并入通过；这一形沿用另一枚件在首屏摘要那格修好的判据法（同一行给了两个定位就两个各自比，读其一会把假的那枚放过）。②每条对齐行必须两个锚，单锚就是「有一半回不去」。③判为无证据的要求必须在第三节那一栏留名，不留名等于悄悄丢一条。另有一道把「推荐录用／排名／打分／淘汰」一类人评断言整体拦下，要提就同行挂 [待人工]。
- 两条路：主路走解析通道（远端那两份由宿主 `tools/list` 握手返回里的 `parse`／`get_parse_status`／`read_result` 认已连，本机没有那份文件也能读）；降级只读本地那两份，代价同句写在两面——「JD 与简历是不是当前这一版」那一层整块缺位，缺的是「你核的是不是对方现在用的那份」这层证据，不是排版。骨架按设计发红：采集器留的证据待填位不是简历原文的逐字句，机检在这一行发 `E-QUOTE`，匹配那一步没做就不该被当成核对报告交付。
- 词表：consumes 用在册的 parsed-doc，produces 用在册的 review-report 与 source-index——**未新增任何工件名**。另报两处选择与代价：①review-report 这枚名已有两枚产方（另一枚是审件那一路），本件是第三枚，边只按规范名相等，多枚产同名在本仓口径里合法；②这枚件的两项 produces 目前都没有消费方（图上出度 0，入边由 parsed-doc 来），我核过另一枚在册名 structured-note 是有消费方的，但它对上的下游是投决备忘那条读研报笔记的路——为了孤点数字好看而接一条不存在的关系是造假边，我弃用并把这条判断留在账上。
- 反证怎么跑：`--selftest` 与 runner 档②都逐枚断言「码集恰等于该发的那一道」，并自报「注入生效＝是／否」——上一批我撞过一次写死锚点导致的空注入，这一批把生效与否做成必报列；好样另跑一支不给两侧原文的，验不可判那条形制的两个分支都被读。
- 现测：新件硬闸 rc=0（合闸=11 不合=0，TMPDIR=/tmp 跑的）；首屏尺 rc=0（名册=22 不合=0，本件落通道正路的形乙一档）；安装式对表 rc=0（名册=22｜①三面现值=21、只在包内其它面=1、未取到=0｜形制点名=0 处）；场景图 rc=0（全包=22｜非孤点=13｜表一 9 枚清单里没有本件）；lint --strict rc=0（末行 22 skill(s), 0 error(s), 0 warning(s)）；卫生闸 rc=0（末行 面 196，ERROR 0，WARN 233）；发布物闸 rc=0（PASS，成品面指路齐、两枚入口闸内真跑退码 0、18 条目）；离线 runner 末行自报「档数=3｜合期望=3｜不合=0｜不可判=0」，在 /tmp、自有临时根、其下子目录三处各跑一遍同一数。机检另有十枚自供注入逐枚单跑：来源行摘掉解析日／锚指向无源行／证据行只剩一枚锚 各发 `E-ANCHOR`；要求那句改成转述 发 `E-QUOTE`；对齐行数掉到 2 行、结论超 80 字 各发 `E-FORMAT`；两栏只剩点名失败、两栏全空 各发 `E-COVERAGE`；结论写「打分」发 `E-RANK`；再加一支「只给 JD 一侧原文」的，退码 0 且明写不可判 5 项——每枚都自报「注入生效＝是／否」，空注入不当过关用。
- 数据边界：本件不发请求、不上传、不落盘到本包之外、不读人事系统；报告含两侧原文（其中有人身信息），存放与转发由用户自己负责并先告知当事人——这条写进两面与红线，不只写在心里。
