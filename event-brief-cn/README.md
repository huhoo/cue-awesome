# event-brief-cn

**贴一份刚出来的 A 股临时公告，回来一张五段速读卡：关键数逐字带出处锚，影响链只列候选，要人核的地方全挂在待核清单。**

不是研报观点，也不是投资建议——它管的是「公告刚落地那会儿，先把事实与出处立起来」；公告以官方源为准，转手来源降 C 级并提示回原文。

**输入**：公告公开 URL ／ 公告原文粘贴 ／ 附件文件（三种都行）
**输出**：`assets/公告速读卡.md` 填好的一张卡——事件类型判定、关键数快表、影响链候选、同类对照、待核清单
**代价**：前两段（类型判定＋关键数）不依赖任何通道，拿到原文就能出；后三段要不要发起检索由你决定，发起前先报耗时与消耗
**机检**：`scripts/check_card.py` 四道（形制／锚与依据／红线／计数与申报），零网络

---

## 一、打开就干：今天这三步

这三步是本件唯一的「现在就要做」，每步都标了不做会怎样：

| 步 | 动作 | 怎么做 | 不做会怎样 |
|---|---|---|---|
| ① | **钉住两个日期与一个来源** | 从公告原文抄**披露日**与**数据日**，来源只记官方件（巨潮／交易所／公司披露页的文件名或 URL＋定位）；披露日与你所问日期不一致时，卡片里要明说 | 把旧公告当新的读，后面每一段都建立在错的时间点上 |
| ② | **填关键数快表，逐字带锚** | 金额、比例、日期、期限、主体名**一个都不改写**，每行补「P× 第×段」这类原文定位；填不出锚的那行删掉 | 转述必掉精度；无锚的数字既查不了也背不了锅 |
| ③ | **跑一遍机检再谈引用** | `python3 scripts/check_card.py 我的卡.md`，按详行的 `E-*` 码逐条改 | 带着空锚和判断句的卡被引用出去，等于把 AI 初稿当结论 |

后两段（影响链候选、同类对照）**排在这三步之后**，不是之前：它们要么需要检索、要么需要人确认，快不得。

## 二、五段卡与四道机检

| 段 | 内容 | 机检卡不卡 |
|---|---|---|
| 一 事件类型判定 | 回购／增持减持／业绩预告／重大合同中标／分红送转／停复牌／处罚问询／股权变动／资产减值／其他，**单选**；选「其他」须附「按原文标题归类」句 | 卡：未勾选、多选、判定句空都发 `E-FORMAT` |
| 二 关键数快表 | 逐字摘录＋出处锚 | 卡：有数无锚发 `E-ANCHOR`；写「约／左右」发 `E-BANWORD` |
| 三 影响链候选 | 至多三条，格式固定「候选：〈机制〉 ← 依据：〈原文逐字段落 或 可核通道现值〉」，收尾「不构成判断」 | 卡：缺依据发 `E-ANCHOR`；超三条发 `E-COVERAGE` |
| 四 同类对照 | 同公司 24 个月内同类公告；有则列日期与逐字差异，无则勾选「未检索到同类／检索未覆盖，待核」 | 卡：既无行又无声明发 `E-COVERAGE` |
| 五 待核清单 | 需人看的原文行、需补的数据点，评级／目标价／持续影响判断全挂 `[待人工]` | 卡：缺 `[待人工]` 汇总发 `E-COVERAGE` |

头部另有一组硬要求：**「AI 整理初稿」「不构成投资建议」「回原文核对」三件套**＋披露日／数据日／来源三要素，缺一即 `E-FORMAT`。

### 首次开通 Cue（三步，可跳过）

本件的取证腿有三条：公告与监管域的取数（data-mcp）＋附件与长文的解析（omni）＋同类对照与背景检索（cue-research）。
**不装不报错**——卡片前两段（类型判定＋关键数）不依赖任何通道，拿到原文就能出；后三段的检索与解析都有降级路（你手动供料＋agent 自由检索），代价是证据密度与可回查性下降。

1. 注册 <https://cuecue.cn>（新账号注册送 500 积分、每日 10 积分，以服务端为准）；
2. 在 <https://cuecue.cn/hub/api-key> 取 `CUE_API_KEY` 存入本地凭据——**不要贴进聊天**，agent 不经手密钥；
3. 安装本件取证用到的三枚 skill：`cue-omni-reader` 走解析腿，`cue-data-mcp` 走公告与监管域取数腿，`cue-research` 走同类对照与背景检索腿——后三段要不要跑由你定，前两段不依赖任何通道。这些都由 Cue 官方技能集合（sensedeal）发布，一条命令两种写法：
   - 整套：`npx skills add sensedeal/cue-skills`（它会列出该集合公开的各枚 skill，按提示挑要装的）；
   - 单装：`npx skills add sensedeal/cue-skills --skill cue-omni-reader`，把末尾那枚名字换成 `cue-data-mcp` 或 `cue-research` 就只装那一枚。

   装完把三件事分开自查，它们互不等价：**装好 skill ≠ 已配凭据 ≠ 通道已连**。
   - 装好＝你这一侧重新列一次已安装 skill，清单里能看到上一步那几枚的名字（这只证明文件到位，不证明取到数）；
   - 配好凭据＝第 2 步那把 `CUE_API_KEY` 存在于本地凭据设施即可——不要把它的值贴进聊天，也不要在终端回显；
   - 已连＝带上那把 key 按目标域 `routing` 里的 `url` 实连（`Authorization: Bearer <$CUE_API_KEY>`，并带 `Accept: application/json, text/event-stream`——缺这个头会 406，是协议行为不是鉴权失败；上一格判的是那把 key 在不在本地凭据设施里，**它被不被服务端接受，要到这一格才判得出**），且 `tools/list` 有返回。怎么问：向该域 `routing` 给出的地址发一个 JSON-RPC 的 `tools/list` 请求。算通过的回字：HTTP 200，且返回体里 `result.tools` 非空（逐字形如 `{"result":{"tools":[…]}}`，工具名与入参 schema 就在那一格里）——**工具清单以那份返回现值为准，本件不预先承诺有哪几枚、也不硬编码工具名**。匿名 `GET` 块里那枚 `CATALOG` 拿得到当场返回**只证目录可达**，本件不把它叫「已连」：它给的是各域 `external_status` 与 live 域的 `routing`，返回里没有的域本件不装也不承诺。连接报错≠域无数据，如实报，只重试错误标明可重试的部分。

   ```bash
   CATALOG="https://cuecue.cn/api/mcp-catalog"
   curl -s "$CATALOG" | python3 -c 'import json,sys
   rows=json.load(sys.stdin)["data"]["domains"]
   [print(r.get("id"), r.get("external_status"), (r.get("routing") or {}).get("url", "-")) for r in rows]'
   DOMAIN_ID="<把这里换成上一行列出的那个域 id>"
   ROUTING_URL="$(curl -s "$CATALOG" | python3 -c 'import json,sys
   rows=json.load(sys.stdin)["data"]["domains"]
   hit=[r["routing"]["url"] for r in rows if r.get("id")==sys.argv[1] and r.get("routing")]
   print(*hit,sep="\n") if hit else sys.exit("未取到：该 id 不在目录现值里（或它没有 routing 里的 url 字段）——先跑上面那行列出现场的 id 再填")' "$DOMAIN_ID")"
   [ -n "$ROUTING_URL" ] || { echo "取值失败：ROUTING_URL 为空——先跑上面那行列出现场 id，再把 DOMAIN_ID 换成其中之一" >&2; exit 1; }
   curl -s -X POST "$ROUTING_URL" \
     -H "Authorization: Bearer $CUE_API_KEY" \
     -H "Accept: application/json, text/event-stream" \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' \
     -w '\nHTTP %{http_code}\n'
   ```

   块里 `CATALOG` 是本面唯一一处目录入口字面（赋一次、散文不重抄）；`ROUTING_URL` 由上面那两行现取——取的是该域 `routing` 里的 `url` 字段逐字值，本面不硬编码域名或路径，凭据变量取自上一层那把本地凭据（不进聊天、不在终端回显），本块不新增任何凭据读取动作。通过判据仍以那句为准，本块不另立第二套。
   一句现场精度：这处端点可能以 SSE 形回字（一行 event、紧跟一行 data），要看的 result.tools 就在那条 data 载荷里——判据不变，只是回字在外层多包了一层。
   一条命令形（不必手改块里那一行）：`cd event-brief-cn && python3 -B scripts/cue_connectivity_check.py --domain <你的域 id> --post`。这支随包件缺省一个包都不发——不带 --post 时只把该域 routing 里的 url 取出来给你看；有哪些域 id 可填，先跑同一支脚本的 `--list`（只列在场域与 url，不发 POST）。本件不另立判据：退码 0，退 4＝还没证过连通（带上 --post 再跑一次），退 5＝连上了但现场值没满足它，退 1＝取不到、发不出去、或 HTTP 层报错（含 4xx 与 5xx），退 6＝目的地没过凭据外发两关（本件拒发，一个凭据字节都不附），退 7＝目录入口本身不是 https。按默认目录入口时，本件只验运行端点连通，不向渠道发布、不产生受理。**换源不免检**：无论那个 url 来自缺省目录、--catalog-url 还是 --catalog-file 那份快照，带 key 那一次发出去之前都要过同一道两关——scheme 必须是 https，且 host 命中授权后缀（缺省那一枚由件头那处目录入口现值推出，不是本件另编的一张清单；要显式放行别处请带 --allow-host）；过不了就拒发，并把拒绝原因与那个 host 印在回字里，本件不读 key、也不构造那个请求。代价同句写明：老的「换进去什么就打什么」那一形关掉了，换来的是凭据不会外发到未授权目的地；若你的正当端点恰在授权后缀之外，退 6 是请你用 --allow-host 显式认下它，不是断言那枚端点不该存在。

所有消耗**花之前一定先问**：深研单次 3–15 分钟且消耗 credits，发起前逐条报给你确认（「好的／嗯」式单字应答不构成确认）；解析腿按件计费，发起前先报「预计耗时与消耗」再征询。先报的是耗时量级与这笔消耗是否发生，不是报价格——计费与可用性以服务端返回为准，本件不写任何价格类字样，不复述域清单、不写工具数量。

装本件自己：npx skills add huhoo/cue-awesome --skill event-brief-cn（这条只装本包；装完在你这一侧重列一次已安装 skill，清单里看得到 event-brief-cn 才算文件到位）。手动放置也行：把本目录复制进宿主的 skills 目录（如 ~/.claude/skills/event-brief-cn）。

## 四、边界与不承诺

- 本件产出的是**工作稿与结构**，不是法律意见也不是投资建议；评级、目标价、走势与持续影响判断一律 `[待人工]`，本件不代答。
- 数字**逐字**摘录，不四舍五入、不写「约」；未取到的写「未检索到」并进待核清单，不以常识补写公告内容。
- 数据通道一律以 **live catalog 现值**为准：本件不复述工具清单、不写工具数量、不承诺任何未开放的域或实时性（禁硬编码是本件的红线，也是仓规 §5-2）。
- 附件与长文的解析走既有解析通道：格式与大小、能否取到、如何计费**以实际返回为准**，本件不复制那份清单、也不推算费率。
- **不可逆动作前要一次显式确认**：发起深研检索（会消耗时间与额度）、对外提交、付费前，先复述「对象 + 后果 + 时点」再等明确回应；「好的」「嗯」「行」这类单字应答不构成确认。事情没做成之前，不写「已经帮您查好了」这类完成时话术。
- 转手来源（自媒体截图、群转发）一律标 C 级并提示回原文核对；引用于任何正式场合前，关键数请回官方件核对。

## 五、出错了怎么办（症状 → 原因 → 恢复动作）

**未见于本次返回的一律写「未检索到」**：参数名、字段名、枚举值没有出现在本次工具返回里的，不得凭印象填写；写「未检索到」并记入待核清单或覆盖率账，不得留空顶替。

**Error 级＝blocker**：机检报出的 Error 级条目不得称「无害」「可忽略」「先交出去再说」；修完，或在交付面显式申报，才算出口。

出口形制按 `check_card.py` **当前出口**现跑取得：失败是一行 `FAIL: <文件>（N 条）`，其下每条详行**先打错误码前缀（四枚 `E-*` 之一）**（如 `[E-FORMAT] [时点]`、`[E-ANCHOR] [关键数]`、`[E-BANWORD] [禁词]`），道名后是行号与该道规格；末行 `码表:` 只列本次真正用到的码与含义。全过印 `PASS: <文件>（…）` 并附「扫过 N 行、发条 0 条」两类计数。

本件用**四枚**码，与姊妹件的码表逐字同源（姊妹包不随本发布物交付，比对须回仓内看）；第五枚 `E-LEDGER` 属账本状态机面，本件无账本，故不启用（不是漏配）。全集与归类规则以脚本现值为准，任意目录整行粘贴即可定位：

    grep -n "^E_LEGEND" ~/.workbuddy/skills/event-brief-cn/scripts/check_card.py

| 症状（详行前缀） | 原因 | 恢复动作 |
|---|---|---|
| `[E-FORMAT] [头部] / [时点]` | 三件套缺件，或披露日／数据日／来源留空或占位 | 补齐头部；来源只记官方件定位——是否官方由人核，机检只判来源留空或仍是占位；两日期不一致时在卡内明说 |
| `[E-FORMAT] [五段] / [类型] / [判定句]` | 五段缺段或乱序，类型未单选，判定句没照原文 | 按 §二 顺序补段；单选只留一个 ☑；判定句照原文标题写 |
| `[E-ANCHOR] [关键数] / [依据]` | 数字没有原文定位，或影响链「依据」是空的／占位 | 补合式锚（页／段／行＋数字）；**补不出来就删那行，不许猜** |
| `[E-BANWORD] [禁词] / [改数] / [待人工域]` | 出现收益承诺类词；关键数写成约数；评级·目标价·走势没挂 `[待人工]` | 改中性陈述或删除；数字回原文逐字抄；判断类移入待核清单并标 `[待人工]` |
| `[E-COVERAGE] [条数] / [对照] / [申报]` | 影响链超三条；同类对照既无行又无声明；待核清单没有 `[待人工]` 汇总 | 候选砍到三条以内；无同类就勾选声明；把要人判的项全挂进第五段 |

## 六、怎么开口（触发示例：三条正例 + 一条反例）

**开口请带上时点，输出标数据日期**：请求里给出报告期／基准日或回看窗口；成品首行标注**数据日期**，当它与用户所指日期不一致时，正文禁用「今日」「最新」，一律改写为「截至 <日期>」。

| 正例 | 会得到 |
|---|---|
| 「××公司刚发的增持公告，先帮我把关键数钉出来，带原文定位」 | 第一、二段先出（类型判定＋逐字关键数），后三段由你按需发起 |
| 「这份业绩预告的数字帮我逐字抄出来并标页码段码」 | 关键数快表，每行一带锚的原文定位；查不到的行删而不是补 |
| 「收到一张处罚决定书，帮我把要人核的条款列成待核清单」 | 第五段待核清单＋`[待人工]` 汇总位 |
| **反例：「这个公告是不是利好，明天会涨吗」** | 本件不答。走势与评级一律 `[待人工]`；它只给你逐字事实与出处，判断留给人 |

## 七、能力边界（诚实清单）

- 五段契约、四道机检、两件夹具齐备；好样发条数与坏样四道齐发**以脚本自报行为准**，本文不复写枚数。
- **真公告实测跑过 4 例**：四例 `check_card.py` 逐例 exit 0，单点破坏反证 4 枚全 exit 1（门禁真能 FAIL），逐字回查通过率 **4/4**。覆盖回购／监管函／行政处罚／定期报告四类，**单主体各一次**；业绩预告、停复牌、股权变动等六类未覆盖，**4/4 不外推为「十类全过」**。全链账目在内部台账，可应要求提供（账在仓内，不随发布物交付）。
- **实测边界三条如实**：①通道全文有长度硬截断（现值以通道返回为准），财务数与处罚数额需官方页面／PDF 第二层腿补得；②深交所监管措施只回字段不回全文，该类正文事由进待核清单；③抽取层页脚与报告目录载页存在 ±1 级差，卡内页码一律注「以 PDF 实物页为准」。
- **4/4 是逐字回查通过率，不是准确率、不是耗时**；本件不给耗时、命中率或增长类数字，名述面也不写时长类表述。
- **通道面以 live 现值为准**：本件不复述域清单与工具数；取不到就进待核清单的纪律不变。
- 同类对照依赖检索面；无检索时**合法出口是勾选「未检索到同类／检索未覆盖，待核」**，机检认这个声明。
- 本卡是工作稿。引用前关键数请回官方件核对——这句不是免责话术，是第五段存在的理由。
