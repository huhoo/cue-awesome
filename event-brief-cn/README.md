# event-brief-cn

**贴一份刚出来的 A 股临时公告，回来一张五段速读卡：关键数逐字带出处锚，影响链只列候选，要人核的地方全挂在待核清单。**

不是研报观点，也不是投资建议——它管的是「公告刚落地那会儿，先把事实与出处立起来」。需求凭据见仓内 `verify/demand-mining-2026-10-09.md`（平台裸流第一簇）。

**输入**：公告公开 URL ／ 公告原文粘贴 ／ 附件文件（三种都行）
**输出**：`assets/公告速读卡.md` 填好的一张卡——事件类型判定、关键数快表、影响链候选、同类对照、待核清单
**代价**：前两段（类型判定＋关键数）不依赖任何通道，拿到原文就能出；后三段要不要发起检索由你决定，发起前先报耗时与消耗
**机检**：`scripts/check_card.py` 四道（形制／锚与依据／红线／计数与申报），零网络

## 一、打开就干：今天这三步

这三步是本件唯一的「现在就要做」，每步都标了不做会怎样：

| 步 | 动作 | 怎么做 | 不做会怎样 |
|---|---|---|---|
| ① | **钉住两个日期与一个来源** | 从公告原文抄**披露日**与**数据日**，来源只记官方件（巨潮／交易所／公司披露页的文件名或 URL＋定位）；披露日与你所问日期不一致时，卡片里要明说 | 把旧公告当新的读，后面每一段都建立在错的时间点上 |
| ② | **填关键数快表，逐字带锚** | 金额、比例、日期、期限、主体名**一个都不改写**，每行补「P× 第×段」这类原文定位；填不出锚的那行删掉 | 转述必掉精度；无锚的数字既查不了也背不了锅 |
| ③ | **跑一遍机检再谈引用** | `python3 scripts/check_card.py 我的卡.md`，按详行的 `E-*` 码逐条改 | 带着空锚和判断句的卡被引用出去，等于把 AI 初稿当结论 |

后两段（影响链候选、同类对照）**排在这三步之后**，不是之前：它们要么需要检索、要么需要人确认，快不得。

## 二、五段卡与四道机检

| 段 | 内容 | 机检卡不卡 |
|---|---|---|
| 一 事件类型判定 | 回购／增持减持／业绩预告／重大合同中标／分红送转／停复牌／处罚问询／股权变动／资产减值／其他，**单选**；选「其他」须附「按原文标题归类」句 | 卡：未勾选、多选、判定句空都发 `E-FORMAT` |
| 二 关键数快表 | 逐字摘录＋出处锚 | 卡：有数无锚发 `E-ANCHOR`；写「约／左右」发 `E-BANWORD` |
| 三 影响链候选 | 至多三条，格式固定「候选：〈机制〉 ← 依据：〈原文逐字段落 或 可核通道现值〉」，收尾「不构成判断」 | 卡：缺依据发 `E-ANCHOR`；超三条发 `E-COVERAGE` |
| 四 同类对照 | 同公司 24 个月内同类公告；有则列日期与逐字差异，无则勾选「未检索到同类／检索未覆盖，待核」 | 卡：既无行又无声明发 `E-COVERAGE` |
| 五 待核清单 | 需人看的原文行、需补的数据点，评级／目标价／持续影响判断全挂 `[待人工]` | 卡：缺 `[待人工]` 汇总发 `E-COVERAGE` |

头部另有一组硬要求：**「AI 整理初稿」「不构成投资建议」「回原文核对」三件套**＋披露日／数据日／来源三要素，缺一即 `E-FORMAT`。

## 四、边界与不承诺

- 本件产出的是**工作稿与结构**，不是法律意见也不是投资建议；评级、目标价、走势与持续影响判断一律 `[待人工]`，本件不代答。
- 数字**逐字**摘录，不四舍五入、不写「约」；未取到的写「未检索到」并进待核清单，不以常识补写公告内容。
- 数据通道一律以 **live catalog 现值**为准：本件不复述工具清单、不写工具数量、不承诺任何未开放的域或实时性（禁硬编码是本件的红线，也是仓规 §5-2）。
- 附件与长文的解析走既有解析通道：格式与大小、能否取到、如何计费**以实际返回为准**，本件不复制那份清单、也不推算费率。
- **不可逆动作前要一次显式确认**：发起深研检索（会消耗时间与额度）、对外提交、付费前，先复述「对象 + 后果 + 时点」再等明确回应；「好的」「嗯」「行」这类单字应答不构成确认。事情没做成之前，不写「已经帮您查好了」这类完成时话术。
- 转手来源（自媒体截图、群转发）一律标 C 级并提示回原文核对；引用于任何正式场合前，关键数请回官方件核对。

## 五、出错了怎么办（症状 → 原因 → 恢复动作）

**未见于本次返回的一律写「未检索到」**：参数名、字段名、枚举值没有出现在本次工具返回里的，不得凭印象填写；写「未检索到」并记入待核清单或覆盖率账，不得留空顶替。

**Error 级＝blocker**：机检报出的 Error 级条目不得称「无害」「可忽略」「先交出去再说」；修完，或在交付面显式申报，才算出口。

出口形制按 `check_card.py` **当前出口**现跑取得：失败是一行 `FAIL: <文件>（N 条）`，其下每条详行**先打错误码前缀（四枚 `E-*` 之一）**（如 `[E-FORMAT] [时点]`、`[E-ANCHOR] [关键数]`、`[E-BANWORD] [禁词]`），道名后是行号与该道规格；末行 `码表:` 只列本次真正用到的码与含义。全过印 `PASS: <文件>（…）` 并附「扫过 N 行、发条 0 条」两类计数。

本件用**四枚**码，与姊妹件的码表逐字同源；第五枚 `E-LEDGER` 属账本状态机面，本件无账本，故不启用（不是漏配）。全集与归类规则以脚本现值为准，任意目录整行粘贴即可定位：

    grep -n "^E_LEGEND" ~/.workbuddy/skills/event-brief-cn/scripts/check_card.py

| 症状（详行前缀） | 原因 | 恢复动作 |
|---|---|---|
| `[E-FORMAT] [头部] / [时点]` | 三件套缺件，或披露日／数据日／来源留空或占位 | 补齐头部；来源只记官方件定位；两日期不一致时在卡内明说 |
| `[E-FORMAT] [五段] / [类型] / [判定句]` | 五段缺段或乱序，类型未单选，判定句没照原文 | 按 §二 顺序补段；单选只留一个 ☑；判定句照原文标题写 |
| `[E-ANCHOR] [关键数] / [依据]` | 数字没有原文定位，或影响链「依据」是空的／占位 | 补合式锚（页／段／行＋数字）；**补不出来就删那行，不许猜** |
| `[E-BANWORD] [禁词] / [改数] / [待人工域]` | 出现收益承诺类词；关键数写成约数；评级·目标价·走势没挂 `[待人工]` | 改中性陈述或删除；数字回原文逐字抄；判断类移入待核清单并标 `[待人工]` |
| `[E-COVERAGE] [条数] / [对照] / [申报]` | 影响链超三条；同类对照既无行又无声明；待核清单没有 `[待人工]` 汇总 | 候选砍到三条以内；无同类就勾选声明；把要人判的项全挂进第五段 |

## 六、怎么开口（触发示例：三条正例 + 一条反例）

**开口请带上时点，输出标数据日期**：请求里给出报告期／基准日或回看窗口；成品首行标注**数据日期**，当它与用户所指日期不一致时，正文禁用「今日」「最新」，一律改写为「截至 <日期>」。

| 正例 | 会得到 |
|---|---|
| 「××公司刚发的增持公告，先帮我把关键数钉出来，带原文定位」 | 第一、二段先出（类型判定＋逐字关键数），后三段留待你决定是否发起 |
| 「这份业绩预告的数字帮我逐字抄出来并标页码段码」 | 关键数快表，每行一带锚的原文定位；查不到的行删而不是补 |
| 「收到一张处罚决定书，帮我把要人核的条款列成待核清单」 | 第五段待核清单＋`[待人工]` 汇总位 |
| **反例：「这个公告是不是利好，明天会涨吗」** | 本件不答。走势与评级一律 `[待人工]`；它只给你逐字事实与出处，判断留给人 |
