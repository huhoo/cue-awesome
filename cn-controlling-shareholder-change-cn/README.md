# 实控人变更与要约收购·逐条挂源（cn-controlling-shareholder-change-cn）

把**一次控制权变动**拆成八项要素，逐项挂公告原句与锚。谁出让、谁受让、多少股、多少比例、
多少钱、变更前后控制权归谁——**比例与对价只认披露写的**，不拿股数乘价格，不拿两个数相除。

A股控制权变更是最贵的一类事件：一次协议转让可能换掉实际控制人，一次部分要约可能改写股权结构。
市面上对这类事件的整理，最常见的四种坏法都在同一处——**把数算出来了**：

- 公告只写股数不写比例，卡面自己拿股数除总股本，分母选错（总股本／剔除回购专户／表决权口径）就全错；
- 公告写「转让价格以协议为准」，卡面自己拿股数乘每股价格，乘出一个公告里没有的金额；
- 要约收购只披露了要约价、没披露溢价率，卡面自己减出溢价率，基准价一错整条读数就错；
- 八项要素缺几项，用常识补上，读者看不出哪一格是推断的。

本件的立场只有一句：**报出来的数必须能回到证据**。回到不了，就写「未取到」。

## 一、它管什么

| 管 | 不管 |
|---|---|
| 控制权归属的**变动过程**：谁取得、以什么方式、多少钱 | 分红回购减持的结果登记（`cn-shareholder-return`） |
| 六类路径：协议转让／表决权委托／二级市场增持／要约收购（含部分要约）／司法拍卖／继承 | 并购重组的交易进度（停牌／预案／过会／实施，`cn-restructuring-tracker`） |
| 八项要素逐项挂原句与锚 | 质押与解押明细（`cn-share-pledge-tracker`） |
| 比例与对价只认披露原句 | 拿股数乘价格算对价、拿两个数相除算比例 |
| 要约价与溢价率分列两行 | 把溢价率拿要约价和市价自己减出来 |
| 公告没写的写「未取到」 | 用常识、行情或推断补上 |

**切割句**：本件只管控制权**归属的变动过程**。分红回购减持是股东行为的结果，走
`cn-shareholder-return`；并购重组追踪的是交易进度（停牌到实施），走 `cn-restructuring-tracker`；
质押质押与解押是担保状态，走 `cn-share-pledge-tracker`。质押若正好是变更路径的一环，
本件只**引用**不重登。

## 二、八项要素

1. **变更方式** —— 六类路径之一，取公告原句。
2. **出让方** —— 原句含持股数时一并带上。
3. **受让方** —— 原句。
4. **变动股数** —— 原句。
5. **变动比例** —— 百分比必须在这行自己的书名号原句里；只写股数不写比例 → 「未取到」。
6. **交易对价** —— 金额必须在这行自己的原句里；写「另行约定」→ 「未取到」，不许乘。
7. **变更前控制权归属** —— 原句。
8. **变更后控制权归属** —— 原句。

第 7、8 两项拆成两格，是因为这两格常常分别是两个不同的人／主体；合成一格，「前是谁、后是谁」
就读不出来了。

## 三、要约收购专段

要约路径（含部分要约）另开一段，两行分列：

```
- 要约价：「本次要约价格为每股 12.00 元」 锚：报告书 第四节 一  [S1]
- 溢价率：「较前 30 个交易日均价 9.88 元溢价 21.40%」 锚：报告书 第四节 二  [S1]
```

规矩三条：

- **要约价与溢价率不许写在同一行**——两个数放一行，读者没法判断溢价率是拿哪个价减出来的。
- **溢价率的百分比必须在该行原句里**。公告只写「溢价」不写数字 → 「未取到」，不许自己减。
- **溢价率的原句必须带基准口径**（前 30 日均价／前 1 日均价／停牌前价／基准价）。原句只写
  「溢价率 21.40%」而不说基准是谁，读者无法复核，判红。

非要约路径整段写一行：`- 本笔不涉及要约收购，无要约价与溢价率。`

## 四、五道机检

```
CC-STRUCT  六段齐 · 八项要素行级在场 · 申报数两向对齐
CC-QUOTE   原句非空 · 锚值非空（只剩 [S1] 视同空）· [S#] 能在来源索引里找到
CC-CALC    不得自算：比例与对价必须在本行原句里；溢价率不许自己减、不许与要约价同行
CC-LINE    红线三道：利好利空 · 推断后续动作 · 评级目标价／股价预测
CC-BOUND   写成股东回报、重组进度或质押明细时点名改走对应件
```

`CC-STRUCT` 的申报数两向对齐：头部「共 N 项要素·未取到 M 项」只写一处，N 必须等于明细段实际
要素行数，M 必须等于标「未取到」的行数——多报是虚报，少报是漏报，两个方向都发。

`CC-CALC` 是本件的承重格，判四件事：

1. `变动比例` 行的百分比不在该行书名号原句里 → 发（自算比例）；
2. `交易对价` 行的金额不在该行原句里 → 发（自算对价）；
3. `要约价` 与 `溢价率` 出现在同一行 → 发（分列两行才算登记）；
4. `溢价率` 行的百分比在原句外，或原句没有基准口径词 → 发（自算溢价率／无法复核）。

## 五、数据通道

真实任务走通道正路：先看目录，再取报告书正文与附件。

```bash
# 1) 看目录，拿 MCP 端点
curl -s https://cuecue.cn/api/mcp-catalog | head -c 500

# 2) 按 MCP 协议握手，确认三枚工具在场
curl -s -X POST "$MCP_ENDPOINT" -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

确认 `parse` / `get_parse_status` / `read_result` 三枚在场后：`parse` 把报告书 URL 或本地路径
交给通道 → `get_parse_status` 轮询 → `read_result` 取正文与表格。

**零 key 降级**：没有 `CUE_API_KEY` 时只走用户直供的报告书正文与本地文件。代价是取不到渠道侧
的披露原文与附件正文解析，锚只能落在用户给的那份上，跨文件核对做不了。

## 六、怎么跑

```bash
# 机检一份变更卡
python3 -B scripts/check_control_change.py 变更卡.md

# 自测：好样须过，坏样五枚各只发自己那道码
python3 -B scripts/check_control_change.py --selftest

# 离线样例三档（零网络、零计费、30 秒内）
bash scripts/fixtures/run_fixtures.sh
```

退码：`0` 全过；`1` 有发红；`2` 用法错；`3` 文件读不了或空稿。

## 七、样例

`scripts/fixtures/` 下 1 枚好样 + 5 枚坏样，每枚**只**发自己那道码：

| 文件 | 期望 | 造的是什么 |
|---|---|---|
| `good-control-change.md` | rc=0 | 八项齐、一项未取到、非要约路径 |
| `bad-1-struct.md` | CC-STRUCT | 要素明细缺「变更后控制权归属」 |
| `bad-2-quote.md` | CC-QUOTE | 原句空 + 锚只剩 `[S1]` 缺定位 |
| `bad-3-calc.md` | CC-CALC | 变动比例 15.00% 自算在原句外 |
| `bad-4-line.md` | CC-LINE | 重大利好／后续将／目标价 |
| `bad-5-bound.md` | CC-BOUND | 未取到清单里混进分红方案项行 |

`run_fixtures.sh` 三档：① 自测；② 样例（好样 rc=0，坏样各自只发其码）；③ 边界形制
11 条**正反对照**——在好样上逐行替换，该红的红、该不红的不红（真要约三样齐、原句含金额、
机构名里的「会」不误红、待人工整行留白），另加 `empty` 与 `nofile` 两条走 rc=3。

## 八、红线（随套件）

不判利好利空；不推断新实控人后续动作；不预测股价；不给评级与目标价；不承诺收益；
不代拟、不代算、不代申报、不代客；不裁断效力（变更是否有效、是否违规、是否构成控制权变更）。

判断类问题一律 `[待人工]`——本件不接代办，也不给方向。

## 九、工件接口

- `consumes: [parsed-doc]` —— 吃 omni-reader 解析出来的权益变动报告书／要约收购报告书正文与表格。
- `inputs: [announcement-doc, disclosure-file]` —— 公告原文与披露文件（原始入口）。
- `produces: [structured-note]` —— 本件产出的是「一次控制权变动的八项要素登记」，在册且已有下游消费者。

**为什么不写 `change-brief`**：这个名字虽在 `structured-note` 族里，但全仓消费者 0（3 个产方、
0 个消费方），写它等于本件出度为 0、落进表一孤点清单。登记过的别名不等于被真实消费的名字——
判边只认「有产方且有消费方」。本件**不产出** `daily-digest`、`change-brief`，也不登记分红回购减持、
重组进度或质押明细——那些各有归口件。

## 十、已知边界

- `CC-CALC` 判「数能回到本行原句」，不判原句里的数是否为真（事实层回官方原文核）。
- 比例只认原句，不替你换口径：公告写「占总股本 15.00%」，本件照登，不复核分母。
- 溢价率只判「百分比在原句里且原句带基准口径」，不判基准价本身取得对不对。
- `CC-QUOTE` 判来源编号能在索引里找到，不判来源是否权威。
- 公告只判到要素级在场，不判这份报告书是否就是该标的、该时点最该看的那一份。
