# 变更记录

### 0.1.0 — 2026-11-09（首版）

- 新件 `cn-controlling-shareholder-change-cn`：把**一次控制权变动**拆成八项要素逐项挂公告原句与锚——
  变更方式、出让方、受让方、变动股数、变动比例、交易对价、变更前控制权归属、变更后控制权归属。
  六类路径（协议转让／表决权委托／二级市场增持／要约收购含部分要约／司法拍卖／继承）。
  缺口不进常识，进「未取到清单」并点名要回哪份文件；判断位一律 `[待人工]`。
- 五道机检 `CC-STRUCT` / `CC-QUOTE` / `CC-CALC` / `CC-LINE` / `CC-BOUND`。
- 本域最要紧的一格在 `CC-CALC`：**不得自算**，判四件事——
  ① `变动比例` 的百分比必须在该行自己的书名号原句里，公告只写股数时判「未取到」，
  不替你拿股数除总股本（分母可能是总股本／剔除回购专户后的股本／表决权口径，错一个分母控制权读数全错）；
  ② `交易对价` 的金额必须在该行原句里，**不许拿变动股数乘每股价格自己算总价**——
  公告常写「转让价格以协议为准」「另行约定」，乘出来的那个数是卡面编的；
  ③ `要约价` 与 `溢价率` 必须**分列两行**，写在同一行判红（两个数放一行，读者看不出溢价率减的是哪个价）；
  ④ `溢价率` 的百分比必须在该行原句里，且该行原句必须带基准口径（前 30 日均价／前 1 日均价／
  停牌前价／基准价）——**披露没写就不许自己减**，拿要约价减市价，基准一错整条读数就错。
  这与 `cn-share-pledge-tracker` 的「比例不得自算」、`cn-morning-brief` 的「覆盖率三数各自回槽表」
  同族：报出来的数必须能回到证据，不能自己拼。
- `CC-STRUCT` 的两向点名：头部「共 8 项要素·未取到 N 项」只写一处，`8` 必须等于明细段实际要素行数，
  `N` 必须等于标「未取到」的行数——多报是虚报、少报是漏报，两个方向都发。
  八项中的「变更前／变更后控制权归属」拆成两格：这两格常常分别是两个不同主体，合成一格读不出「前是谁、后是谁」。
  **确认**：这一拆分写在面文与判据里，不是实现偏差。
- `CC-QUOTE` 锚值非空按「定位词在场」判：`锚：  [S1]` 只有来源编号、没有定位，视同锚值为空。
- `CC-BOUND` 把三条边界做成机检而非散文：写成股东回报（分红回购减持）→ 点名 `cn-shareholder-return`；
  写成重组进度（停牌／预案／过会／实施）→ 点名 `cn-restructuring-tracker`；
  写成质押解押明细 → 点名 `cn-share-pledge-tracker`。质押若正好是变更路径的一环，只引用不重登。
- 工件接口：`consumes: [parsed-doc]`（吃 omni-reader 解析出来的报告书正文与表格）、
  `inputs: [announcement-doc, disclosure-file]`、`produces: [structured-note]`。
  **不写 `change-brief`**：该名虽在 `structured-note` 族里，但全仓 3 个产方、**0 个消费方**，
  写了等于出度为 0、落进表一孤点清单。别名在册 ≠ 被真实消费。
- 样例：好样 1 枚、坏样 5 枚（STRUCT／QUOTE／CALC／LINE／BOUND 各一枚，每枚只发自己那道码）、
  runner 三档（自测／样例／边界 11 条正反对照 + `empty`／`nofile` 走 rc=3）。
- 已知边界：`CC-CALC` 判「数能回到本行原句」，不判原句里的数是否为真（事实层回官方原文核）；
  比例照登不复核分母；溢价率只判「百分比在原句里且原句带基准口径」，不判基准价取得对不对；
  `CC-QUOTE` 不判来源是否权威；公告只判到要素级在场，不判这份报告书是否就是该标的该时点最该看的那份。
