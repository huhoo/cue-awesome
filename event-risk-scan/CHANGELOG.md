### 0.2.14 — 2026-10-20（连通块不再要人手抄 routing；值指向对象里的 url；块自己把 HTTP 状态打出来）

- 病灶三条：①上一轮补上的命令块要求用户把目录里该域 routing 的现值手工抄进变量——抄错就连不上，这是「装完之后连不连得上」这条链上最后一处人肉环节；②旧面文那句把 routing 说成可以直接逐字粘贴的单个值，而目录返回里 routing 是一个对象（含 path、url、transport、protocol_version、headers 五个键），能直接发请求的是其中的 url——照旧面文抄就是把整枚对象当地址发，命令必然跑不通；③块里 POST 用静默开关发出去，把「通过＝HTTP 200」留给读者自己核，块本身一个状态都不打。
- 改法（单锁之外，只动本面包的面文）：块内按顺序补五件——把目录入口赋一次给变量（本面唯一一处该字面，散文不再重抄）、先列一遍在场域与其 routing 里的 url、按用户填的域标识现取 url、取不到时一句人话并退码 1（显式判空，不用「未设即报错」那形——它退 127，会被读成命令找不到）、最后 POST 那行加状态输出形把 HTTP 码自己打出来。散文四处同步改：匿名 GET 那句改为指块里那枚变量、「按目标域 routing 实连」改为「按 routing 里的 url 实连」、取值句改述为现取过程并写明取的是对象里的 url 字段。中英两面各按本语言原文改，不代译、不复写第二处通过判据。
- 判据现值（每真值源一枚，逐面 23 枚）：该节围栏仍 1 枚（并入现有块、未另开）｜块内五串齐在 5/5｜块本体语法检查退码各 0｜同节「通过判据」行仍恰 1 枚每面（未新增第二处真值）｜块内含状态输出形｜值指向 routing 里的 url｜每面目录入口字面恰 1 处（约束收紧扣死）。

### 0.2.12 — 2026-10-20（自测末行把两组数拆开：好样枚数与发条数不再挤进同一个比值标签）

- 病灶：本包自测末行原先在 好样 那一格里写的是「一个比值」（旧形把两个数都算发条：前一位写死为零，后一位＝本次实发条数）——读起来像「好样共 N 枚、过了 M 枚」，实际两个数都在数发条。同仓另一族脚本里同一个标签指的却是「通过枚数／好样总枚数」，同一个自报标签在两族里说两件不同的事＝一处事实两处真值，只不过长在自报文本上。危险不是不好看：一旦好样真被发条，末行会印成比值形如「零比二」，读起来像「两条正例一条没过」，自测照样转红却报出错的病因，下一位照着查错方向。
- 改法：末行把两组各带单位拆开印——「好样 N 枚·发条 M 条（规格 0）」；枚数由好样夹具集现算（一枚好样＝一份夹具卡，取夹具集的长度，不写死字面量），发条数由本次实发条数现算，两值不再挤进同一个比值。逐枚详行同步改成按夹具集列名——夹具集只有一枚时该行与旧行逐字同，加第二枚时它自己变长，不会只报一枚。
- 射程：只动自测的打印行与那枚夹具集的组织方式；判定逻辑、阈值、错误码集合、夹具内容一字未动，好坏样两侧的实际检查各照旧。
- 正控（原样跑）：末行现读「好样 1 枚·发条 0 条（规格 0）」且退码 0；同一包连跑两趟，剥掉耗时后逐字节同。
- 反控（防今日这种误读那一型）：整包副本落临时根，往 good-scan-card.md 注入一句本包红线话术，注入自证＝该串在这枚夹具里改前零命中、改后一枚命中；末行随之同时出现「发条 1 条」且整档转 FAIL 退 1，详行点名意外发条那一条。仓内一字未动，副本只落临时根。
