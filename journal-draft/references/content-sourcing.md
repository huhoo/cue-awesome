# content-sourcing — 取料源矩阵与记账

## 一、五层源，按顺序走

L1 → L5 的顺序也是**成本由低到高**、同时也是**可信度从高到低**的顺序。不要一上来就上 L4。

| 层 | 源 | 典型用途 | 工具 | 代价 |
|---|---|---|---|---|
| **L1** | 企业自有源 | 官网新闻、公众号推文、年报 / 公告、内部稿库、已发布软文、过往期刊 | `omni-reader` MCP / xParse / 直接抓网页 / 本地文件 | 几乎为零 |
| **L2** | 权威原文 | 政府红头文件、监管通函、交易所规则、判决文书、法规条文 | 官网原文直取、`pkulaw`（北大法宝）、`yuandian-mcp`（元典） | 低 |
| **L3** | 结构化数据（外部） | 财务 / 行情 / 宏观 / 产业链 / 基金持仓 / 榜单 | `neodata`、`westock` MCP | 低 |
| **L3i** | 结构化数据（**内部**） | 产销、客户、渠道、编制、能耗、质量、售后等自家经营数据 | 企业内部系统（ERP / CRM / HR / MES / BI）导出后本地读 | 低，但**涉密**——见下方「L3i」一节 |
| **L4** | 深度研究 | 行业背景、竞对、政策影响、跨源交叉验证、没法直接拿到的外部佐证 | **`cue-research`** | 消耗 Cue 额度 |
| **L5** | 补图 | 拿不到授权照片的配图、插画、数据可视化 | **agent 自带的多模态出图能力**（用户侧零配置：不要 key、不接外部服务） | 必须标注为 AI 生成；印刷用途优先真实素材 |

**判据**：能抄原文就别研究，能查结构化数据就别写叙述，能用已有素材改写就别新写。每一篇先问「这篇能不能 80% 靠 L1+L2 完成」。

### L3i —— 非金融企业的结构化数据在**内部**，不在 MCP 接口上

`neodata` / `westock` 覆盖的是公开市场的财务与行情。**制造业、零售、医药、地产、
消费品、教育这类企业的刊物，最有价值的数字在自家系统里**：产销与产能、渠道库存、
客户结构、质量与售后、能耗与碳排放、编制与培训。取法与四条硬约束：

1. **口径先于数字**。同一个「客户数」，去重口径、统计期、含不含试用，结论能差一倍。
   正文里给数字就要给口径（`data/dashboard.md` 里记口径注，随正文走）。
2. **涉密与授权**。内部数据属企业保密信息，**上传给任何外部服务前必须单独征得用户同意**
   （硬规则 5），能本地读就不上传。这一条对 `--material` 与 Omni 解析同样适用。
3. **不用「据内部数据」一句话带过**。要么给出「口径 + 统计期 + 数据源系统」，
   要么在交付说明里说明「数据由业务方提供、未独立核验」。
4. **与公开口径打架时以公开为准并标注**。若内部数字与年报/公告不一致，
   **不要在刊里写内部数字**——刊物若同时面向投资者，这会构成选择性披露风险。

## 二、L1 企业自有源怎么搜

按这个清单逐项过，把结果直接登记进 `outline.md` 的「素材」列：

1. **官网**：新闻中心 / 投资者关系 / 公告 / 案例库 / 团队页
2. **公众号**：近 3–6 个月推文（历史消息页或第三方聚合）
3. **年报 / ESG 报告 / 招股书**：事迹、数据、时间线的富矿
4. **内部稿库**：已发布的软文、新闻通稿、演讲稿、活动回顾
5. **过往期刊**：本期可直接复用的固定件与可延展话题
6. **HR / 市场部**：新入职人员名单、获奖、活动照片

解析 PDF / 长文 / 音视频走 `omni-reader` MCP 或 xParse。**中文 PDF 优先 xParse**，跨模态（音频 / 视频 / 网页）优先 omni-reader。

**omni-reader 在 L1 上的正确用法**：公众号文章、官网新闻这类 **URL 直接 `parse(url=...)`**；本地 PDF/PPTX/音视频传绝对路径（`result_delivery="artifact"` + `save_result` 落盘再读）。OMNI 的富文本保留标题层级、列表和表格，用来抽取「这条动态说了什么 / 涉及哪些主体 / 有没有数字」很省事；但它**不保留图片**，配图必须另外向用户索要或单独抓取原页面。完整调用写法见 [`omni-channel.md`](omni-channel.md)。

## 三、L4 Cue 深度研究怎么用在这一步

这是整套流程里唯一「要花真钱」的环节，务必用在刀刃上。

> **「要花真钱」不等于「可以默认不用」。** 这一层是否启用，必须在 B1 里**主动推荐并逐条给判定**
> （值得用 / 一般 / 不值得 + 你得到什么 / 不用差在哪 / 花多少），由用户确认——用户说不用才降配，
> 且要在 `review.md` 写明损失了什么（硬规则 5）。判定的依据是**这一期的实际内容**，
> 不是照抄模板：本期没有需要外部佐证的选题，就直说「本期不必跑」。
> 首次使用还要一次说全开通三步（注册 cuecue.cn → 在 `/hub/api-key` 取 `CUE_API_KEY` →
> 装 `cue-research` 技能；新账号注册即送 500 积分、每日再 +10、**花前必先确认**）。
> 判定口径与话术见 [`cue-onboarding.md`](cue-onboarding.md)。

### 什么时候值得动 Cue

- 需要**外部佐证**来支撑一个观点（例：「香港代币化监管领先」→ 需要与其他市场对比）
- 需要**交叉验证**企业自己发布的数字
- 话题是新的，**企业自己的素材里没有**（行业趋势、竞对动向、政策链条影响）
- 要给文章加**别人没有的信息增量**

### 什么时候不该动 Cue

- 素材就在企业官网/公众号里 → 直接改写
- 只是要一份文件原文 → 去官网或 L2 的法律库
- 只是要一个数据 → 走 L3 的结构化数据接口

### 三种调用姿式

**① 优先走搭子**（既有框架、省额度、产出稳）

```bash
python3 ~/.workbuddy/skills/cue-research/scripts/research_run.py \
  --template-id <template_id> \
  --query "<业务语言写：研究什么、时间窗口、给谁看、要求逐条注明来源>"
```

**② 没搭子 → 自由式**（必须先 `/api/rewrite`）

```bash
python3 ~/.workbuddy/skills/cue-research/scripts/research_run.py \
  --query "<rewritten_mandate>"
```

**③ 让报告模仿本刊调性** —— 这是本流水线的关键一招

```bash
python3 ~/.workbuddy/skills/cue-research/scripts/research_run.py \
  --query "<...>" --mimic-file "<样例 PDF 或某篇样文>"
```

自由式专属；`--mimic-*` 不能与 `--template-id` 同用。把**期刊样张**喂进去，让研究报告天生带本刊的写法与结构，省掉一轮「研究报告腔 → 期刊腔」的改写。

**④ 让研究基于企业自有材料**（上期内刊、内部稿、官网导出）

```bash
... --material "<本地文件路径>"
```
必须**先问过用户**再上传保密材料；文件只单次绑定，重跑要重传。

> 硬约束：不自作主张选搭子，必须让用户从 ≤2 个候选里挑；跑之前必须明确确认额度开销；结果统一以后台跑 + 读 `RESULT` 行的方式取，不要同步等。详见 `cue-research` 技能自带的说明文件（该件不在本仓，路径不在此承诺）。

## 四、EvidenceCard 与覆盖度总表

**每个要在期刊里落笔的事实，都要有一张卡**，放在 `evidence/<条目>.md`：

```markdown
- 主张: 香港代币化产品二级市场交易已开放          ← 期刊里实际要写的那句话
- 来源: 香港证券及期货事务监察委员会
- 题目: 有关代币化证监会认可投资产品二级市场买卖的通函
- 日期: 2026-04-20
- 链接: https://...
- 原文摘录: 「发行人应持续监控二级市场交易和流动性情况」
- 可信度: 一手
- 用于: outline#12 债券上链全景图
```

`可信度` 只能是三种：`一手`（原文亲眼所见）/ `二手`（权威媒体或机构转述）/ `待验证`。

`evidence/index.csv` 是覆盖度总表，一列一行：

```
outline_id,条目标题,证据数,一手数,待验证数,是否可动笔
01-01,港澳地区法规动态,12,12,0,可
02-03,跨境用工税务,3,1,2,阻塞
```

**规则**：`待验证数 > 0` 或 `证据数 < 条目所需` 的条目，+draft 阶段**禁止硬写**。要么回去补证，要么移出本期备选告知用户。

## 五、成本记账

每期做完，`issue-brief.md` 末附一张表，下期启动时先看它：

| 项目 | 数量 | 单位成本 | 小计 |
|---|---|---|---|
| Cue 搭子 run | n 次 | 经验值 | - |
| Cue 自由式 run | n 次 | 经验值 | - |
| omni-reader 解析页数 | n 页 | 0.067 credits/页 | - |
| 图像生成 | n 张 | - | - |

第一次跑完把实际消耗填进去，第二期就能给出**提前预算**，而不是事后惊吓。

> **首次使用不必先充值**：新账号注册即送 **500 积分**、此后每天再 **+10**，
> 先用赠送额度把一期跑下来。额度与计费以服务端实时策略为权威；
> **跑每一项之前都会先报额度、等你确认**，不会先花后说。
