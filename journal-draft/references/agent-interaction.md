# Agent 交互规范 — 提问预算 · 续跑台账 · 交付动作

> 用户在 agent 里用这个技能时，付出的代价只有两项：**提供的素材量、被问的次数**。
> `SKILL.md` §1 写了这个契约，但七阶段流程里散落着至少 7–9 处「必须问」，
> 与「标准模式 3 次确认」直接打架。本文件把这两项变成**可核对的预算与台账**。

---

## 一、提问预算（硬约束）

`SKILL.md` §1 承诺 std = 3 次确认。按正文逐阶段数，实际会触发的必问有：

| 出处 | 触发 |
|---|---|
| Stage 2 `+brief` | 三张清单后的确认批 |
| Stage 3 `+plan` | 大纲确认（含备选取舍） |
| Stage 4 `+gather` | 硬规则 5：用 Cue / 上传材料前必须征得同意并报额度 |
| Stage 5B `+art` Step 1 | 有没有企业素材库 |
| Stage 5B `+art` Step 2 | `manual` 图位主题确认（实测 13 图位里 10 个） |
| Stage 5B `+art` Step 3 | 出图通道与消耗告知（硬规则 9） |
| Stage 6 `+check` | 阻塞项逐条 |
| Stage 7 `+spec` | 是否沉淀、命名 |

**8 处 vs 承诺的 3 次。** 用户感受到的就是「说好问三次，实际被问了八次」。
修法不是删掉这些确认（每一条都有硬规则撑着），而是**前移 + 打包**：

| 批次 | 时机 | 必须装进去的问题 | 上限 |
|---|---|---|---|
| **B1 开工批** | `+brief`，一次发完 | ① 固定件是否沿用 ② 期号 / 封面年月 / 封面主题 ③ 必须收录的硬内容 ④ 目标页数与 deadline ⑤ **素材与授权**（有无企业素材库、材料能否上传）+ **Cue / Omni 通道建议**（逐条给「值得用 / 一般 / 不值得」+ 理由 + 成本，含首次开通三步） | 5 |
| **B2 大纲批** | `+plan`，一次发完 | ① 篇幅配平确认 ② 备选取舍 ③ **`manual` 图位的主题**（此时栏目已定、正文未写，改主题成本最低） | 5 |
| **B3 交付批** | `+check` 后 | 阻塞项摘要 + 达成率偏差 >20% 的解释 + 还需用户做什么 | ≤3 条 |

**std 总上限 = 3 批 / ≤13 问。fast = 0 批。fine 不限批数，但每批仍 ≤5。**

### 三条前移规则

1. **Cue 通道前移，而且是「推荐」不是「授权」**：这一条不许写成一个可跳过的开关，
   更不许用默认值替用户答掉（硬规则 5）。B1 里要**对着本期实际内容逐条给判定**
   （值得用 / 一般 / 不值得 + 你得到什么 / 不用差在哪 / 花多少），再请用户确认；
   首次使用还要把开通三步一次说全（注册 cuecue.cn → 在 `/hub/api-key` 取 `CUE_API_KEY` →
   装 `cue-research` 技能 / 接 Omni Bridge；新账号注册即送 500 积分、每日再 +10、花前必先确认）。
   材料上传同意也放这里（硬规则 5）——不要等到 `+gather` 才问，
   那时用户已经等了半小时，才发现要授权，等于白等。
   判定口径、话术模板与降级留痕见 [`cue-onboarding.md`](cue-onboarding.md)。
2. **素材前移**：企业素材库（logo 矢量 / 实拍 / 往期图表）放进 **B1**，不要等到 `+art` Step 1。
   有素材库的刊物整个配图策略都不同（全走 `reuse`，零出图）。
3. **配图主题前移**：`manual` 图位主题并入 **B2**。等到 `+art` 才问，正文已经按「此处无图」写完了，
   补图就要回头改文。`plan_images.py` 的 `image-plan.md` 第二节已经把待定主题列成可直接粘贴的清单，
   在 B2 里把它附上即可。

### 提问格式（三件套，缺一不算合格提问）

- **带默认值**：写成「问题 → 默认建议」。用户回「按你的来」即全部按默认推进。
- **一次发完**：禁止零碎连环问（硬规则 3）。
- **不问能查到的**：能从样例 `stylespec.json`、上期 `last-issue.md` 或企业官网上读到的，一律不问。

## 二、进度台账（中断续跑）

七阶段跨小时：一次 Cue 深度研究 3–25 分钟，多任务并行时整期可能横跨两次会话。
**目前没有任何文件记录「走到哪、哪些已确认」**——会话一断，接手只能重问用户，
这是最伤体验的一种返工。（`runbook.md` 是**跨期**经验台账，不承担本期进度。）

开工时建 `journal/<刊名>-<期号>/progress.md`（模板：`assets/templates/progress.template.md`），
**每完成一个阶段追加一行**：

| 阶段 | 状态 | 产出文件 | 已确认项 | 待确认项 | 时间 |
|---|---|---|---|---|---|

`已确认项` 一栏是台账的主要价值：**记下用户已经答过什么，续跑时不再重问。**

### 续跑判断（每次接手先做这四步）

1. 读 `progress.md`，找最后一个 `done` 的阶段 —— 从它的下一个阶段继续。
2. **已确认项不再重问**，直接引用台账里记的答案。
3. 若 `pending.md` 存在，先读它 —— 里面是 fast 模式或中断时留下的外推项。
4. 产物存在但台账无记录 → **以产物为准**（`content.json` 在即视为 `+draft` 已跑），补记台账再继续。
   台账缺失时不要从头重跑，更不要重问已确认的问题。

## 三、模式落地（fast / std / fine）

`SKILL.md` §1 定义了三种模式，但只有 std 有对应流程；fast 承诺的 `⟨待确认⟩` 标记没有任何落地机制。
补齐如下：

| 模式 | 提问 | 外推项去哪里 | 交付时必须说 |
|---|---|---|---|
| **fast** | 不问 | 全部外推写进 `pending.md`，逐条注明「依据什么推的」 | 「有 N 处按上期外推，清单在 `pending.md`」 |
| **std**（默认） | B1 / B2 / B3 三批 | 不适用 | 达成率 + 阻塞项 + 待补图位 |
| **fine** | 逐单元确认（每批仍 ≤5） | 不适用 | 同上 + 逐条确认记录 |

### `⟨待确认⟩` 不许写进 `content.json` 的任何字段值

`build_draft.py` / `export_pdf.py` / `export_editable.py` 都**不做这个词的清理**
（只有 `plan_images.py` 在图注里剥掉它，因为它确实会出现在内容里）。
写进字段值会**直接印进 PDF / docx 成品**，而 `crosscheck.py` 不会报——
一份带「⟨待确认⟩」的刊物交到用户手上，是当众出丑。

外推项只落在 `pending.md`。`crosscheck.py` 现在会扫 `content.json` 全文字符串，
命中 `⟨` / `⟩` 即报警告（提示项，不拦交付）。

## 四、交付动作（最后一步，最容易漏）

硬规则 10 要求三件套，但没有任何一句说**怎么交到用户手上**。
在 agent 里，用户看不到文件等于没交付。每期收尾固定四步：

1. **把文件推到用户面前**：版面稿 `draft.pdf` 与文字稿 `draft.docx` 用文件预览打开，
   不要只回一句「已生成」。
2. **附三句话**：① 页数与达成率 ② 阻塞项条数 ③ 还需要用户做什么（补图 / 确认外推 / 授权）。
3. **交付清单**（写进 `review.md` 末尾）：文件名 → 给谁 → 下一步动作。
4. `progress.md` 标记 `done`。

## 五、环境与解释器

- **文档里的 `python` 是占位符**，不代表本机有 `python` 这个命令。先确认解释器：
  `python --version` 失败就试 `python3`；都失败则用平台自带的托管解释器绝对路径。
  把解释器路径记进 `progress.md`，续跑时不必再试。
- **依赖一次性核完**：`+learn` 前先跑一次冒烟（README §1）。缺 `pymupdf` 会把
  `+learn` 与 PDF 出稿一起废掉（硬规则 10 直接破），缺包要一次性报给用户，不要跑到一半才发现。
- **出图不依赖任何包、不依赖任何 key**：`pillow` 只影响印前校验，缺了脚本会写
  `checked: false`，不假装检查过——不必为此拦住流程。

## 六、可以跳的阶段（附代价）

| 情形 | 可跳 | 代价 |
|---|---|---|
| 已装派生技能（`journal-<企业>-<类型>`） | `+learn` 整段 | 无。这是派生技能存在的意义 |
| 用户明确说「不要参考旧刊，重新设计」 | `+learn` | 丢掉品牌 DNA，产出退化为通用稿（硬规则 1 的例外） |
| 用户只要「先看看形态」 | `+gather` | **量级门禁仍需过**；无证据的内容一律不得写成已核实 |
| 只改文字、不动版面 | `+brief` / `+plan` / `+gather` | 从 `draft.docx` → 编辑改 → `import_docx.py --base` 回填 |
| 本期与上期栏目结构一致 | `+plan` 的篇幅配平可从 `last-issue.md` 直接外推 | 仍需 B2 确认一次 |

**`+check` 与 `crosscheck.py` / `check_freshness.py` 不可跳。** 它们拦的是静默错误——
版面不会报错、门禁不会报错、写出来也是通顺的。
