# 配图：AI 生成图怎么用才不会毁掉一本刊

## 〇、先定调：配图排在最末，且默认不开

期刊底稿里，配图是**最容易一次性毁掉全部工作**的环节。文字写错一句话，改一句；
图里出现一张人脸、一行乱码字、半个假 logo，整页就得重来，而且往往要到
打印打样才会被发现。

所以本技能的默认立场是：

> **能不用 AI 图就不用。真要用，先过 plan，再逐张验收。**

顺序永远是：`+plan 定下板块 → +gather 拿证据 → +draft 出文字稿 → 最后才配图`。
在文字还没定的时候配图，等于先把最贵的部分做两遍。

## 一、四类决策（脚本自动判，人复核）

`plan_images.py` 对每个图位给出四类之一：

| 决策 | 含义 | 典型 |
|---|---|---|
| `skip` | 不该配图 | 面积 <900mm² 的 logo/图标位；装饰线、色块 |
| `reuse` | 用真实素材 | 企业 logo、实拍照片、产品图、既有图表、官方图表 |
| `manual` | 需要图，但本期主题未知 | 样刊的整版图位基本都属于这一类——**样刊的图是它自己的内容，推不出新刊要画什么** |
| `gen` | 主题明确，可安全生成 | 有图注的 figure 块；抽象意象、场景氛围、几何陪衬 |

`skip` 那条是硬规则不是建议：**小面积图位几乎必然是 logo 或二维码**，
生成出来的假 logo 会让整本刊作废。

`manual` 是本设计的关键——它把「看起来缺图」和「可以动手生成」分开。
实测跑 91 页样例 + 8 页新刊 content：**13 个图位里只有 1 个是 gen，10 个是 manual**。
如果不管三七二十一全部生成，这 10 张必定全是废图。

## 二、主题从哪来

`manual` → `gen` 的转换靠人（或 agent 代拟 + 人确认）。代拟时的依据优先级：

1. 该页的 `figure.caption`（有图注最好用）
2. 该页第一个 `h1/h2` 标题
3. 该单元所属的 UnitPattern 语料语气

没有以上任何一条时，**不要凭关键词硬凑**。留着不配图，版面一样成立。

## 三、Prompt 的固定结构

```
<主题>, <媒介>, <风格锚>, <构图>, <色板约束>, no text, no letters, no logos, no human faces
```

实测样例生成的一条：

```
流程示意, abstract vector illustration, minimal editorial illustration,
restrained geometric shapes, generous negative space, calm and professional tone,
diagrammatic clarity, simple shapes, clear visual hierarchy,
palette limited to #A10F34、#1A1A1A、#F5F5F0, no text, no letters, no logos, no human faces
```

几个刻意的选择：

- **媒介默认写 `vector illustration`，不写 `photorealistic`。**
  企业期刊一旦追求写实，AI 的结构错误（透视、比例、反光）会非常显眼；
  抽象/矢量/编辑插图的容错率高一个数量级。
- **负向提示分两层。** 通用红线（文字/人脸/logo/水印/二维码）**写死在脚本里**，
  谁都改不了；行业/企业敏感的题材（律所就别出现天平、法槌、握手素材照）
  放 `imagery.json` 的 `avoid`，由人维护。
- **色板从 StyleSpec 的 palette 直接搬**，不重新用自然语言描述一遍。
  写「暗红色」不如写 `#A10F34`——后者可校验。

## 四、一致性：整本刊看起来是一套的唯一办法

逐张独立出图，**必然风格漂移**。这一点无论模型多好都成立，因为每次采样是独立的。

唯一有效的办法是**参考图级联**：同 `consistency_group` 内先出第一张，之后把第一张当
参考图做图生图。这一步直接用 agent 的图生图能力，**不需要任何外部端点或账号**。

实测里 `plan_images.py` 会把 (role, 尺寸档) 相同的槽位归为同一组，
实测样例跑出 6 个一致性分组，对应 7 个代表性槽位。分组数越少，整本刊越统一——**这本身就是个可优化的指标**：
如果一期要配 12 张图却分了 10 个组，说明选题太散，应当建议用户收敛主题。

## 五、出图：只用 agent 自带能力，用户侧零配置

**不要接外部文生图服务。agent 本身就是多模态的**，出图是它的内置能力：
按 `image-plan.json` 里组好的 prompt 逐张生成、落盘即可。

这是硬要求，不是偏好：

- 不要求用户申请图像 API key
- 不引入外部模型供应商、不写 provider preset、不做端点兼容层
- 不把「配一次环境变量」写进流程
- 出图能力由 agent 自带，成本也在 agent 侧

需要向用户交代的只有三件事：**做几张、放在哪、产出可能带水印**。

### 水印（实测，印刷前必须处理）

内置出图的产出可能在右下角带「AI生成」水印——半透明白字，在浅色底上肉眼几乎看不出
（实测右下角区域灰度均值 235.6，整图 227.7，只差 8），**但印刷会显现**。
这种"看得见的时候已经晚了"的坑，只有靠实测而非推断才能发现。

三条应对，按推荐度排序：

1. **用真实素材**——本技能从头到尾的第一顺位
2. **重出一张**——换构图重出，往往就避开了
3. **裁边补救**——`adopt_images.py --crop-watermark` 裁掉右侧 10% / 底部 9%。
   实测水印落在 83.6% × 90% 位置，该裁边能干净去除（复检右下角探针已无残留字样）；
   代价是构图有损失，属**补救而非推荐**

## 六、印前校验（这一步是必需的，不是锦上添花）

出完不等于能用。`adopt_images.py` 对每张图做：

1. **居中裁切**到 plan 给的目标长宽比（出图的原始比例几乎从不会正好等于版位比例）
2. **缩放**到 `@300dpi` 的理想像素，并把 dpi 写进 PNG 元数据
3. **亮度检查**：灰度均值 <45 判过暗（印刷后糊成一团），>232 判近乎空白
4. **主色距离**：量化取主色，算到品牌色板的欧氏距离，**>100 判「不像一套的」**

实测过 两 张合成图：品牌红 `#A10F34` 那张距离 **0.0** 且无告警；
跑偏的青蓝 `(30,200,255)` 那张距离 **220.2**，告警如期触发。

没有 Pillow 时脚本会明确写 `checked: false`，**绝不假装检查过**。
安装：`python -m pip install pillow`。

## 七、填回 content

```bash
python scripts/adopt_images.py --plan ./images/image-plan.json --out ./images/gen \
    --adopt fig_0=/abs/path/a.png,fig_3=/abs/path/b.png \
    --patch-content ./content.json
# → content.patched.json，直接喂给 build_draft.py
```

回填靠 `block_index` 精确定位 `pages[i].blocks[j]`——早期版本靠「第几个
figure 块」重数来匹配，结果因为编号从 0 还是从 1 不一致而回填了 0 处。
现在 plan 侧记录精确索引，patch 侧直接用，实测精确命中 `page6 block7`。

## 八、还要向人确认的事

配图阶段大概率要问用户这四件事，打包成一次提问：

1. 有没有企业素材库（logo 矢量、实拍、产品图、往期图表）？有就全走 `reuse`
2. `manual` 的这些图位，本期主题分别是什么？（逐条给默认建议）
3. 要不要配 AI 图？确认张数与位置即可——**不需要你提供任何 key、账号或装额外工具**
4. 图片涉及人脸/真实地点/客户标识吗？涉及就一律不用 AI 图（合规 + 失真双重风险）

## 九、链路实测记录（用真实图跑过一遍）

不能只跑 `--help` 就当通过。用一张 1200×760 的合成图（非纯色，模拟出图产物）走完整链路，
实测结果：

| 环节 | 实测 |
|---|---|
| `plan_images.py`（对新刊 content） | 6 个 figure 图位**全部判 `gen`**（都有图注）；样刊 spec 侧另有 13 个槽位：reuse 1 / manual 5 / skip 1 |
| `adopt_images.py` | 1200×760 → 2031×1270 @300dpi，luma 172.5，回填 1 处，`manifest.json` 与 `content.patched.json` 均生成 |
| HTML | 1 个 `<img>`，src 指向回填的绝对路径 |
| PDF | 第 33 页 1 个**嵌入式**图片对象（不是外链）；原刊 PDF 图片对象为 0，故新增图片可精确归因 |
| docx | 内嵌 1 张图；6 个图位都留了 `‖图位‖ {...}` 标记（空图位 `src: ""` + 图注） |
| md | 1 条 `![图注](路径)`，空图位 5 条 `⟨待补图⟩` |
| `crosscheck.py` | HTML/MD/PDF 各 617 / 592 / 617 条文本全覆盖，结论「三件套一致」——**配图不会让交叉校验误报** |

## 十、两个实测踩到的坑

### 1. plan 里的 `page_no` 是 content 的逻辑页索引，不是 PDF 物理页号

`fig_0` 在 `content.pages[9].blocks[0]`，渲染后落在 **PDF 第 33 页**——中间隔着 24 页，
因为图文高度不同会让自动分页整体重排。拿 `page_no` 去 PDF 里找图必然找错页。
它只用于 `--patch-content` 回填（对 content 的 JSON 数组索引），**不是给人当页码看的**。

### 2. 样刊 spec 侧的槽位（`slot_*`）回填不了 content

`plan` 里同时混着两类槽位：

- `fig_*`：来自**新刊 content 的 figure 块**，带 `page_no` / `block_index`，能精确回填
- `slot_*`：来自**样刊 spec 的 image_slots**（cover / hero / inline），`page_no` 为 `None`。
  它们只用于判定 `reuse` / `manual` / `skip`，指的不是新刊的版面位置，**不要拿去 `--adopt`**

已知限制：`slot_*` 的 id 可能重复（实测出现两个 `slot_0_0`），`manifest.json` 按 slot_id
合并时会互相覆盖。因为 `slot_*` 本就不参与回填，暂未处理——但若将来要支持封底/封面图位回填，
得先给它们生成唯一 id。

### 3. 回填时自动清理图注占位前缀（v0.9.1 起已自动化）

早期 `adopt_images.py` 只回填图片路径、**不动图注文字**。实测样刊的 `caption` 原本写的是
「图位待补：香港数字资产监管框架示意」——图补上了，前缀还留着，一路印进成品 PDF。

现已改为：**回填 `src` 的同时剥掉图注的「图位待补：」占位前缀**。前缀清单与
`plan_images.topic_from_text()` 共用一套（两边不得各写一套，否则会漏剥）。
运行时打印 `patched 6 处（其中 6 处同时剥掉了图注的「图位待补：」占位前缀）`。

付印前仍建议人工通读图注——自动剥离只认这几个已知前缀，「（待确认）」之类的
内嵌标记不会被处理。

## 十一、真出图实测（不是只有合成图）

链路最终是用**真出图**跑通的：

| 环节 | 实测 |
|---|---|
| 出图 | 1536×1024，prompt 由 `plan_images.py` 组好（主体「香港数字资产监管框架示意」＋媒介＋风格锚＋安全约束） |
| `adopt_images.py` | → 2031×1270 @300dpi，luma 222.4，无告警 |
| PDF 摆位 | **172.0 × 107.6 mm**（撑满版心宽），落在第 33 页文章首页，图片对象嵌入式 |
| 体积 | 未配图 690KB → 配 1 张 3761KB |

### 顺带修掉两个真 bug（都是「图放进去才暴露」的）

1. **figure 只占半栏。** `export_pdf.py` 把图塞进固定 52mm 高的框里等比缩放，
   实测 1.6:1 的横图只摆到 **84.6mm**——版心 172mm 的一半，右侧大片空白；
   而 `plan_images.py` 按版心宽算出的 2031px 反倒白多了两倍像素。
   改为按图片真实比例撑满可用宽（新增 `img_mm()`，上限 110mm）。
2. **分页器与实际渲染不同口径。** `build_draft.py` 里 figure 高度写死 62mm，
   与上一条配合不上；把摆位改准后立刻报「第33页(article)内容溢出 25.6mm」。
   新增 `fig_height_mm()`（零依赖解析 PNG/JPEG 头取比例），与 `img_mm()` 同口径。
   改完：配图版 74 页、无告警；**未配图版回归仍 74 页、时效门禁 0/0**。

### 一个必须记住的教训：一定要传 `imagery.json`

这次验证**漏传了 `--imagery`**，`avoid` 清单为空，出图模型就堂而皇之画了
**天平 + 握手**——正是律所刊最该避开的题材（模板里的 `avoid` 早就写着
`scales of justice` / `gavel` / `handshake`）。
现已在 `plan_images.py` 里加告警：`avoid` 为空时打印 `[WARN]` 提醒。

另外实测**再次确认右下角带「AI生成」水印**（浅色底上肉眼不明显，但印刷会显现）。

## 十二、六图全量出图：两个只有「多张一起出」才会暴露的问题（v0.9.1）

第 22 期 6 个文内 figure 位**全量真出图**（这次 `imagery.json` 带了 `avoid` 清单）。
链路跑通，但暴露出此前只出单张时看不到的两个问题。

### 1. 图生图会把参考图的**结构**一起搬过来，不只是风格

按第四节「参考图级联」的做法：先出 fig_0，其余 5 张以它为 `image1`、
`input_fidelity: low` 做图生图。结果 6 张里 **1 张作废**：要的是「四条通栏横条
平行排列」，出来只有 3 条，并且把参考图里的**扇形汇聚连线**复制了进来——
prompt 里根本没要连线。

**结论：`input_fidelity: low` 只压低「像不像原图」，并不解除参考图对构图骨架的牵引。**
级联适合**同一套版式反复出现**的图（栏目题图、系列图标）；对**每张结构都不同**的
示意图，应当逐张纯文生图，靠写死的风格锚（媒介＋色板＋留白＋禁忌）统一，
而不是靠参考图。本次 fig_2 重出即改用纯文生图，一次通过。

### 2. 水印「裁哪一条」必须先量，不能写死

「AI生成」水印固定在右下角，实测占高 ≤6%、占宽 ≤8%（1536×1024 实测
x 92.1%–99.3%、y 94.0%–98.9%），所以**裁底边 8% 或裁右边 10% 的任意一条**
都能去掉它。早期 `adopt_images.py` 写死「右 10% + 底 9% 两条一起裁」，
本次实测证明它必然伤图：

| 图 | 底留白 | 右留白 | 旧规则（右10%+底9%） | 新规则（先量后裁） |
|---|---|---|---|---|
| fig_0 三列 | 12.2% | 24.4% | 可 | 裁底 8% |
| fig_1 四列 | 9.1% | 16.0% | 可 | 裁底 8% |
| fig_2 通栏横条 | 15.9% | **7.9%** | **切掉横条端头** | 裁底 8% |
| fig_3 嵌套框 | 8.9% | 22.6% | 可 | 裁底 8% |
| fig_4 地层 | 9.3% | 20.9% | 可 | 裁底 8% |
| fig_5 漏斗 | **6.7%** | 14.4% | **切掉圆形底部** | 裁右 10% |

现改为 `choose_watermark_crop()`：**先量内容外接矩形**（与左上角背景色差异 >60 的
像素，step=2 采样），再挑留白够的那条窄带——底边 ≥8% 优先（不动宽度，宽幅图更安全），
否则右侧 ≥10%；**两条都不够就拒绝裁并报警**，交人工重出或修图，绝不盲裁。
每张图量到的四个边界值写进 `manifest.json` 的 `watermark_crop` 字段，可逐张复核。

源头也堵了一道：`plan_images.build_prompt()` 现在强制要求
`keep the bottom-right corner clear of content, leave at least 10% empty margin
along the bottom edge` —— 把**可裁性**做进 prompt，而不是事后补救。

### 结果（第 22 期全量配图）

- 6 张全部收录：2031×1270 @300dpi，luma 157.9–231.3，主色到品牌色板距离 9.2–20.1
  （阈值 100）；fig_3 亮度 231.3 逼近 232 的「近乎空白」警戒线，属已知偏浅
- PDF **75 页**（未配图 74 页），6 张图各占 **172.0 × 107.6 mm**（撑满版心宽），无溢出告警
- 图注占位前缀全部剥离；`crosscheck` 617 / 592 / 617 条全覆盖，结论「三件套一致」
- 时效门禁：pages 0.824 / articles 1.0 / chars 0.689

### 出图成本与废图率

本次共调用 8 次出图（6 个图位 + 2 次重出），**废图 2 张**：
fig_0 首次混入天平（`avoid` 清单写进 prompt 仍被画出——**avoid 是概率性约束，不是保证**）、
fig_2 首次缺一条且串入参考图连线。按单张 5–10 credits 估，废图率 ~25%。
**结论：配图预算要按「图位数 × 1.3」估，且每张都必须肉眼过一遍。**

## 十三、语义图不该走文生图（v0.9.3，第 22 期六图全部重画）

第十二节那 6 张图，**链路全绿但图全废**。用户反馈原话是「图不达意」，逐张核对下来，
问题比「不达意」更重：

| 图 | 图注要表达的 | 画面实际 |
|---|---|---|
| fig_0 | 三线**分工**（发行人 / 交易平台 / 咨询管理，并列） | 三块红底 + 方/圆/三角，三条线**汇聚到一点** —— 与「分工」矛盾 |
| fig_2 | 零关税 / 加工增值 / 通关 / 实质性运营四条主线 | 四根一模一样的红杠，圆/方/菱/三角与这四个政策**无任何对应** |
| fig_3 | 组织形式 / 募集方式 / 牌照 / 税务四层框架 | 四层嵌套框，层内无标签可辨 |
| fig_1 / 4 / 5 | 四步流程 / 四维合规 / 五路汇聚 | 同类抽象色块 |

六张里五张的信息量是**零**：读者看图得不到任何东西，图上没有一个字能与图注对应。

### 根因在方法选择，不在出图模型

当时为了绕开三类翻车（天平/法槌等法律陈词滥调乱入、中文变乱码、写实照片不像），
在 prompt 里主动写了「仅用几何形状，不用任何具体物件」。**把所有具象语义抽干净之后，
剩下的形状不承载任何信息。** 更关键的是：这类图的语义全部落在
**标签文字 + 拓扑关系**上，而扩散模型恰好做不了这两件事——写不对中文，
也维持不住「三个框并列」「四条线汇聚」这种精确关系。

**越是要求它「图达意」，就越只能用几何抽象兜底，就越空洞。** 这是一条死路。

### 解法：语义图用代码画

`scripts/gen_diagram.py`（PyMuPDF 自绘，中文走系统字体 simhei / STHeiti / PingFang）。
一份 JSON 定义 = `size_mm` + `palette` + `blocks[]`，版式块：

| 块类型 | 用途 | 第 22 期用例 |
|---|---|---|
| `columns` | 并列卡片（主色标题条 + 说明 + 标签/内容条目） | fig_0 三线分工 |
| `flow` | 横向流程块 + 箭头，内容垂直居中 | fig_1 四步机制 |
| `rows` | 逐行：左侧主色标签块 + 右侧要点 | fig_2 / 3 / 4 / 5 |
| `stack` | 纵向层次（宽度可递减以表嵌套） | 备用 |
| `converge` | 多路汇聚到一点 | 备用 |
| `footer` | 通栏横带；`tone: "tint"` 为浅底深字 | 各图结论条 |

排版细节已经处理过，别重复踩：中文**标点避头**（句号逗号不落行首）、
`rows` 标签太长时**自动缩一号字**而不是把词断成两行、`flow` 块内文字**垂直居中**
（否则贴顶、下半留空）、超框时告警「内容高 X 超出可用 Y」。

新旧路线对比：

| | 文生图（旧） | gen_diagram（新） |
|---|---|---|
| 中文 | 画不对，只能回避 → 图上无字 | 系统字体真渲染，逐字可核 |
| 拓扑 | 每张漂移，参考图级联还会串结构 | 代码保证，重复渲染结果一致 |
| 内容出处 | 无 | 每条要点取自正文，可回溯核对 |
| 确定性 | 废图率 ~25%，每张都要肉眼过 | 无随机性；放不下会告警 |
| 输出 | 1536×1024 位图，还需裁水印 | 172×107.5mm 矢量 PNG + PDF，无水印 |
| 成本 | 5–10 credits/张 | 0 |

同一批六张图改用本脚本后一次通过，体积 170–260KB（纯色块压缩率高），
`adopt_images` 体检：luma 201.9–224.7、主色到品牌色板距离 1.4–20.6，无告警；
PDF 仍 75 页、六图各占 172.0 × 107.6mm、`crosscheck` 617 / 592 / 617 一致。

### 判据：怎么分语义图与氛围图

- **语义图**（走 `gen_diagram.py`）：图注里出现「示意 / 框架 / 流程 / 路径 / 分层 /
  分工 / 结构 / 机制 / 步骤」，或图中任何信息需要用文字标签承载。
- **氛围图**（才走文生图）：封面、题花、栏目分隔页、装饰性大图。
  **这类图不配技术性图注**——给纯装饰图配「××框架示意」，本身就是不实陈述。

写文档时还要留意：**图注措辞不能超出图能表达的范围**。原 fig_0 图注写「三线分工」
而画面是汇聚，就是「图注先写、没人回头核对图」的结果。硬规则 25 已固化这条。
