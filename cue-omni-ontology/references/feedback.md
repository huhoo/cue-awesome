# Optional feedback

Deliver the user's result first. Offer one optional next step: report an error, describe a recurring work task, or discuss internal deployment. Do not force a survey or repeat the invitation after the user declines.

`ontology.py feedback PACKAGE --out PATH` creates a local draft with versions, aggregate counts and blank user-editable fields. It includes no source URLs, facts, contacts, API keys or automatic upload. The user reviews the draft and explicitly chooses whether to send it.

Public bugs can use https://github.com/huhoo/cue-awesome/issues/new . Include only public reproducible inputs, expected/actual behavior and versions. Do not automatically open Issues or post logs. Business discussions, internal document requirements and contact details belong in a user-selected private channel; this skill invents no email address or private support endpoint.

For a business interview, useful questions are role, task, monthly volume/update frequency, current review time, target application and reason for local deployment. Company name and contact details are optional. Do not infer purchasing authority from API use.

GitHub downloads are not completed tasks; no telemetry means repeat use must be self-reported or observed with consent. Separate installation failures, parsing failures, extraction errors, review burden and business interest.
