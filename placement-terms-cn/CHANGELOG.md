# 更新日志

### 0.1.0 — 2026-11-02（本枚首次建包：A股定增方案的条款逐字卡，两条取证腿与四道机检随包）
- 选题来路：清单级速览那一层由 `announcement-daily-cn` 补上之后，紧接着的那一问是「这一份定增到底写了什么」——价格下限的原句、锁定期、摊薄测算、审批走到哪一格。单份公告的事件级速读已有 `event-brief-cn`，跨主体的公开风险底稿已有 `dd-checklist`，一般合同条款比对已有 `cn-contract-clauses`；「一份定增方案的条款骨架＋逐字原句＋出处」这一层本仓没有对应件，本枚补这一层，四处分工在 `SKILL.md` 的定位句与 `README.md` 导语、能力边界那两节各写一句，不重叠也不互指空位。
- 产出契约（条款卡五段，缺一即退回）：头部申报（方案与版本／文件来路／十项齐缺数申报／本次是否发起过解析腿）→ 条款逐字表（形制＝`- 条款名：原句逐字 锚：<来源定位>`，十项各占一行，未取到的那行写「未检索到」，不省行不留空）→ 与上一版差项（两份原文都取到时才写差项，各挂各的锚）→ 缺数清单（逐条点名缺的是三要素里哪一格）→ 待人工。原文在 `SKILL.md`「输出契约」那一节；十项名目（发行方式、定价基准日、发行价或价格下限、发行数量与募资上限、发行对象与认购方式、限售期、募集资金用途、摊薄与回报测算、业绩承诺与补偿、审批链条与当前节点）由随包机检按名目逐判，缺项不省行这条是机检判的，不靠约定。
- 红线：摊薄对存量股东的影响、参与是否划算、审批还剩几步、锁定期满后的供给压力一律挂 `[待人工]`；审批链条只记已见诸披露的那一格，没出现的那格写「未检索到」，不推下一步；原句逐字——不四舍五入、不写「约」、不把「不低于定价基准日前二十个交易日均价的八成」那类限定结构压成一句折扣话；转手来源（截图、群转发）降 C 级并提示回原文。
- 两条取证腿：披露清单在数据腿上，附件正文与长附件在解析腿上。两条都写成可选并各自带代价——不装也按用户直供的原文出卡，代价是条款落在附件里的那些项只能停在「未检索到」，而摊薄测算与业绩补偿恰恰常在附件里。指路只给指针、不复述开通步骤：数据腿官方配置页 <https://cuecue.cn/hub/mcp>；解析腿官方配置页 <https://cuecue.cn/hub/omni-reader>；取 key 走 <https://cuecue.cn/hub/api-key>；深研那枚 `cue-research` 是独立入口（自带运行脚本），它的凭据同那把 key，取 key 走同一页。域与工具名以 live catalog 现值为准，三面不列固定清单、不承诺枚数与审批状态的实时性。
- 名形制：`displayName` 取「定增条款」＝意图词落在词首＋名短；目录名与 frontmatter `name` 同值 `placement-terms-cn`，`slug` 为 `cue-placement-terms-cn`，`SKILL.md` 的 H1 随 displayName 走同一短形。
- 随包机检：`scripts/check_terms.py` 四道——五段齐与十项名目在场、每项原句与锚、红线断言只准出现在 `[待人工]` 行、缺数与申报对账；零网络。`--selftest` 直接吃 `scripts/fixtures/` 那两份样例（好样须过、坏样四道齐发并逐条点名行号），另含剥锚、删名目、把缺数申报改歪三档反证，各判各的道；临时件建在一次性目录里、退出时自清。
- 首测：本枚建包当拍各闸的读数与出包 digest 以各闸自报行为准，本条不复写。
