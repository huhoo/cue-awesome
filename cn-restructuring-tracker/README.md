# 并购重组进度跟踪·逐条挂源

同一笔 A 股并购重组的多份公告，按时间轴串成一条线：标停牌、预案、草案、问询、过会、核准、实施各进度节点，写清每步之间的变化（对价、支付方式、业绩承诺、锁定期），每步逐条挂原公告与检索日。缺的逐条点名，两向都点。

**它不做什么**：不评级、不给目标价、不判断买卖时机、不猜过会概率、不评价估值高低。这些位置留 `[待人工]`，交给人。

## 一、打开就干：今天这三步

| 步 | 做什么 | 产出 |
|---|---|---|
| 1 | 收齐同一笔交易的多份公告（至少两份） | 一份公告清单：披露日、节点、标题、链接 |
| 2 | 排时间轴，逐行补一句话事实 | 第三节「进度时间轴」 |
| 3 | 逐对相邻公告找变化，写成「前值 → 后值」 | 第四节「每步变化」，每行两枚锚 |

跑 `python3 scripts/check_tracker.py <稿>.md` 校一遍，红一条改一条。

## 三、离线样例

`scripts/fixtures/` 里有一份完整好样与五枚坏样，各坏一道：

```bash
bash scripts/fixtures/run_fixtures.sh
```

五档：判据自检／好样与五枚坏样逐枚单跑／排骨架／骨架必须红在占位行／边界五形。30 秒跑完，零网络、零计费、零凭据。

## 四、依赖与两条路的代价

- 依赖：`python3`（纯标准库，无第三方包）。
- **有通道**：能取公告原文，能读出每步之间的差——这是本件唯一有价值的形态。
- **没有通道**：只能把已有清单排成骨架，结论与变化留占位。**代价说清楚：没有原文就没有变化，没有变化这份跟踪稿的核心价值为零**，只剩一个待填的表格。骨架跑机检会红在占位行上，这是设计，不是故障。

## 五、边界与不承诺

- **与 `ma-restructuring-terms-cn` 的分界**：那一枚是**条款速读**，读**一份**重组文件拆成八项逐字卡；本件是**跨期跟踪**，读**同一笔交易的多份**公告串时间轴。时间轴不足两行就是条款速读的活，机检会点名让你改走那一枚。
- 不承诺：不判断这笔交易能否成功、不预测股价、不评价对价高低、不猜过会概率。
- 不承诺：公告本身没披露的，本件不会替它补。没取到就写没取到。

## 六、出错了怎么办

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 机检报「时间轴只有 N 行」 | 只拿到一份公告 | 改走 `ma-restructuring-terms-cn`，或把多份公告凑齐 |
| 机检报「每步变化只有 1 枚锚」 | 变化只指了一处 | 前后两值各挂它自己那一处公告 |
| 机检报「第六节的点名缺一项」 | 正文写了未取到，第六节没列 | 第六节逐条补上 |
| 机检报「第六节多列一项」 | 第六节点了名，正文没这条表述 | 要么正文补上，要么第六节删掉 |
| 机检报「节点不在册」 | 用了「上会」「受理」这类词 | 换成在册八格之一，或把事实写进那一行 |
| 机检报「日期倒序」 | 时间轴排反了 | 按日期升序重排 |

## 七、怎么开口

- 「这笔重组到哪一步了」
- 「从停牌到现在，对价和锁定期改过几次」
- 「草案相对预案改了什么」
- 「把这几份公告串成一条时间轴」

## 八、能力边界

- 输入：同一笔交易的多份公告（`ma-restructuring-document`、`announcement-doc`），或已解析的文档（`parsed-doc`）。
- 产出：一份跨期跟踪稿（`change-brief`），七节，每步逐条挂源。
- 不做：条款速读（走 `ma-restructuring-terms-cn`）、评级与目标价、买卖建议、过会概率。
