# 并购重组进度跟踪·逐条挂源

## 0. 这是什么、不是什么

| 是 | 不是 |
|---|---|
| 同一笔交易的多份公告串成一条时间轴 | 一份公告的条款拆解 |
| 标进度节点：停牌／预案／草案／问询／过会／核准／实施（终止是终态） | 判断这笔交易好不好、值不值 |
| 每步变化写成「前值 → 后值」，前后各挂它自己那一处公告 | 只写「对价上调了」这种一句叙述 |
| 每行挂原公告链接与检索日 | 转述二手报道、研报摘要 |
| 缺的逐条点名，两向都点 | 用「约」「左右」把没取到的数糊过去 |

**与 `ma-restructuring-terms-cn` 的分界（用户靠这一句分清两枚包）：**

- `ma-restructuring-terms-cn` 是**条款速读**——读**一份**重组文件，拆成八项逐字卡（概况、对方、标的、定价、支付、承诺、锁定、审批），每项挂原句。
- 本件是**跨期跟踪**——读**同一笔交易的多份**公告，按时间轴串起来，标进度节点与**每步之间的变化**。
- 判据很硬：**时间轴不足两行，就是条款速读的活**，改走 `ma-restructuring-terms-cn`。本件的价值全在「两处之间的差」，只有一处就没有差。

## 1. 什么时候用

- 「这笔重组到哪一步了」「从停牌到现在改过什么」
- 同一笔交易隔了几周又出新公告，要把前后串起来看
- 要核对「草案相对预案改了什么」——对价、支付方式、业绩承诺、锁定期

**不要用**：只拿到一份公告要拆条款（走 `ma-restructuring-terms-cn`）；要评级、目标价、买卖时机（本件不产出，也不该由任何件产出）；要猜过会概率。

## 2. 取数纪律

1. **只认公告原文。** 每一条事实都要能回到一份公告的链接与检索日。研报、新闻、股吧转述一律不作来源。
2. **节点以公告披露日为准**，不以审核系统受理日、不以媒体爆料日为准。日期写 `YYYY-MM-DD`。
3. **时间轴按日期非降序。** 倒序的时间轴不是时间轴。
4. **变化必须两处。** 每步变化写成 `前值 → 后值`，前后各挂它自己那一处公告的锚。只挂一处不构成差。
5. **没取到就写没取到。** 正文写了「未取到 X」，第六节必须逐条点名 X；第六节点了名而正文没有这条表述，同样算错——两向都判。
6. **不改写数字。** 公告写 8.6 亿元就写 8.6 亿元，不写「约 8.6 亿元」「9 亿元左右」。

## 3. 输出契约（七节，按序）

```
AI 整理初稿｜请回原文核对｜不构成投资建议｜判断位 [待人工]

跟踪口径：跨期（同一笔交易的多份公告按时间轴串起来，标进度节点与每步变化）

## 一、一句话结论
## 二、交易概况
## 三、进度时间轴
## 四、每步变化
## 五、未决事项
## 六、未取到与口径
## 七、来源
```

- **头部四件自标**逐字在位，写在第一个 `## ` 之前。
- **跟踪口径**行必须以「跨期」起头——这一格是本件与条款速读的分界，必须自报。
- **三、进度时间轴**每行：`- YYYY-MM-DD｜节点｜一句话事实 [S#]`。节点在册：停牌／预案／草案／问询／过会／核准／实施／终止。**「终止」是终态不是进度节点**，出现即须是最后一行。
- **四、每步变化**每行：`- 变化项：前值 → 后值 [S#][S#]`，**至少两枚不同号的锚**。
- **五、未决事项**：交易还没走到实施或终止，就一定有未决事项，空节等于把卡点藏起来（走到实施或终止后本格可空）。
- **七、来源**每行：`- [S#] 公告标题 URL 检索日 YYYY-MM-DD`，编号与正文锚一一对应。

## 4. 数据通道

本件走 Cue 的 MCP 通道取公告与原文解析。先列目录，再按目录里的路由地址调 `tools/list`，确认工具在场后再取数：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | head -c 2000
# 从目录里取本组的路由地址，再确认工具在场
curl -s -X POST "$ROUTING_URL" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

拿到公告清单后，用 `scripts/make_outline.py` 把清单排成骨架，再逐条读原文补内容。

## 5. 合规红线

- **不产出评级、目标价、买卖动作、涨跌承诺、过会获批概率、估值评价。** 要写这类判断，只能同行挂 `[待人工]`，交给人。
- **不用改数词打底。** 「约」「左右」「大概」不得替公告里的确切数字。
- **不转述二手来源。** 没有公告链接与检索日的事实不进时间轴。
- **不猜节点。** 公告没写「已过会」，就不写「已过会」；写「已收到审核会议通知」并挂那一份公告。

## 6. 快速流程

1. 收齐同一笔交易的多份公告（至少两份，否则走 `ma-restructuring-terms-cn`）。
2. 每份记下：披露日、节点、标题、链接。
3. 排时间轴（`make_outline.py` 可代排），逐行补一句话事实。
4. 逐对相邻公告找变化，写成「前值 → 后值」，前后各挂锚。
5. 写未决事项与未取到，两向对齐。
6. 跑 `python3 scripts/check_tracker.py <稿>.md`，红一条改一条。

## 7. 机检

```bash
python3 scripts/check_tracker.py <跟踪稿>.md     # 五道，退码 0 全过 / 1 有发条 / 3 读不到文件
python3 scripts/check_tracker.py --selftest      # 包内夹具自检
bash scripts/fixtures/run_fixtures.sh            # 五档离线自检，30 秒，零网络零计费
```

五道：**道一 形制**（头部自标、跟踪口径、七节齐且有序、时间轴三格与日期非降序、终止在末行）／**道二 锚**（每行带锚、来源行齐 URL 与检索日、变化行至少两枚不同号锚）／**道三 红线**（评级、目标价、买卖动作、涨跌承诺、过会概率、估值评价零命中）／**道四 未取到两向点名**（正文与第六节按名目同指对，多列少列都发）／**道五 边界**（跟踪口径写成单份／条款／速读，或时间轴不足两行 → 点名改走 `ma-restructuring-terms-cn`）。

## 8. 零通道降级

没有 `CUE_API_KEY` 时，本包**不产出内容**，只把用户手上的公告清单排成带形状的骨架：时间轴与来源行按清单落位，结论与每步变化留占位。骨架跑机检必然红在占位行上——这是设计，提醒你补完再交，而不是让空壳冒充成品。代价说清楚：**没有通道就没有原文，没有原文就没有变化，没有变化这份跟踪稿的核心价值为零**，只剩一个待填的表格。
