# catalyst-calendar

**[中文](README.md) · [English](README.en.md)**

**把你持仓里「确定的日子」排成一张日期正排的日历——每个日期背后都是一条查得着的公告或一条法条，仅此而已，不加判断。**

它回答的真实问题很朴素：**「未来三个月，我这些持仓各自有什么日子要盯？」**
回购方案期限哪天截止（公告明写的才算）、激励归属是哪天、股东会与说明会何时开、分红除权什么时候、
问询回复截止在哪、ST 生效/复牌是哪天、年报还有多少天法定期限——
这些事散在公告流里，人肉盯会漏，交给日历：`buyback`/`esop`/`disclosure_cn`/`regulatory_cn`/`statute`
五域直查为主，深研最多 1 次补解禁/减持原表，产出 `calendar.md` + 可回查来源表。

**输入**：主体集（官方全称或代码，≤10 个）+ 前瞻窗口（缺省今起 90 天）
**输出**：`calendar-<日期>-<n>主体/` —— `calendar.md`（日期正排表+「未来 30 天要盯」段+来源附录）· `sources.jsonl` · `progress.md` 台账
**代价**：四段管线+一道门禁；research ≤1 次（可零），花之前必问

## 一、是什么 / 不是什么

| 你要 | 用什么 |
|---|---|
| 持仓事件日历（带披露锚的日程表） | **本 skill** |
| 某只票的财报深度点评 | 姊妹件 `cn-earnings-note` |
| 选股、择时、「这个日子是不是利好」 | 不做——**事件只陈述，利好利空判词全禁**（日历上「问询回复截止」旁边的永远只是日期和锚） |
| 传闻/预期里的「将回购」「拟减持」 | 不做——未披露不入表 |

## 二、快速开始（三步）

1. **装**：本目录放进 agent 的 skills 目录。
2. **说**：「我的持仓是美的集团、东方雨虹、宁德时代，给我排未来 90 天的催化剂日历」（中英触发词都行）。
   ≤4 问补齐输入契约（主体集/窗口/关注类/输出目录，逐条带默认值），开工建台账。
3. **收**：`+scope → +events → +derive → +build` 后过 `+check`（`check_calendar.py` 的全部机检道，判据形状以脚本现值为准，
   两条现跑自查命令见 §五 注行；正式调用参数以 `SKILL.md` §3 命令式为准），**不过不交付**。

## 三、防的就是日期幻觉

这件东西最大的风险不是分析错，是**编出一个不存在的日期**。硬约束按 `references/event-taxonomy.md` §1 的「入类第一闸」执行：

- 每条先过二选一：已有披露在场**且含明确日期**，或法定推导**且适用条件在法条锚内可判**——过不了闸根本不进表；
- **不做任何日期算术**：公告没写完整截止日，「公告日+360 天」这类推算一律不产行——起算日、自然日还是交易日、含不含首尾、变更如何覆盖，全都没有定义，推出来的日期不可核；
- 每条日期回指公告索引号 / 函件号 / URL / `conv_id`+路径 / `statute:` 规格串，**按类型×锚型映射逐行校验**（映射以脚本现值为准）；六位以上纯数字本身就是合法锚形之一（索引号与证券代码族），**所以"页上有数字"不等于"这行有锚"**——要核的是那一列指不指得回披露；
- 窗外条目走六列形制的独立第 5 列「窗外余档」（锚列永远末列纯锚，注锚不互挤）；空置即 FAIL；查了没有就写「未检索到」——**空日历合法，编造日历违法**。

回购 1%/2% 进度这类无事前日期的「已发生动态」放日历末附注区，不冒充前瞻事件。
