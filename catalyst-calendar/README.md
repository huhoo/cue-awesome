# catalyst-calendar

**本文件为中文主面；英文版是同目录下的 `README.en.md`（仓库内查阅用——渠道页不解析相对链接，这里不做可点切换）。**

**把你持仓里「确定的日子」排成一张日期正排的日历——每个日期背后都是一条查得着的公告或一条法条，仅此而已，不加判断。**

它回答的真实问题很朴素：**「未来三个月，我这些持仓各自有什么日子要盯？」**
回购方案期限哪天截止（公告明写的才算）、激励归属是哪天、股东会与说明会何时开、分红除权什么时候、
问询回复截止在哪、ST 生效/复牌是哪天、年报还有多少天法定期限——
这些事散在公告流里，人肉盯会漏，交给日历：`buyback`/`esop`/`disclosure_cn`/`regulatory_cn`/`statute`
五域直查为主，深研最多 1 次补解禁/减持原表，产出 `calendar.md` + 可回查来源表。

**输入**：主体集（官方全称或代码，≤10 个）+ 前瞻窗口（缺省今起 90 天）
**输出**：`calendar-<日期>-<n>主体/` —— `calendar.md`（日期正排表+「未来 30 天要盯」段+来源附录）· `sources.jsonl` · `progress.md` 台账
**代价**：四段管线+一道门禁；research ≤1 次（可零），花之前必问

## 一、是什么 / 不是什么

| 你要 | 用什么 |
|---|---|
| 持仓事件日历（带披露锚的日程表） | **本 skill** |
| 某只票的财报深度点评 | 姊妹件 `cn-earnings-note` |
| 选股、择时、「这个日子是不是利好」 | 不做——**事件只陈述，利好利空褒贬全禁**（日历上「问询回复截止」旁边的永远只是日期和锚） |
| 传闻/预期里的「将回购」「拟减持」 | 不做——未披露不入表 |

## 二、快速开始（三步）

1. **装**：本目录放进 agent 的 skills 目录。
2. **说**：「我的持仓是美的集团、东方雨虹、宁德时代，给我排未来 90 天的催化剂日历」（中英触发词都行）。
   ≤4 问补齐输入契约（主体集/窗口/关注类/输出目录，逐条带默认值），开工建台账。
3. **收**：`+scope → +events → +derive → +build` 后过 `+check`（`check_calendar.py` 的全部机检道，判据形状以脚本现值为准，
   两条现跑自查命令见 §五 注行；正式调用参数以 `SKILL.md` §3 命令式为准），**不过不交付**。

## 三、防的就是日期幻觉

这件东西最大的风险不是分析错，是**编出一个不存在的日期**。硬约束按 `references/event-taxonomy.md` §1 的「入类第一闸」执行：

- 每条先过二选一：已有披露在场**且含明确日期**，或法定推导**且适用条件在法条锚内可判**——过不了闸根本不进表；
- **不做任何日期算术**：公告没写完整截止日，「公告日+360 天」这类推算一律不产行——起算日、自然日还是交易日、含不含首尾、变更如何覆盖，全都没有定义，推出来的日期不可核；
- 每条日期回指公告索引号 / 函件号 / URL / `conv_id`+路径 / `statute:` 规格串，**按类型×锚型映射逐行校验**（映射以脚本现值为准）；六位以上纯数字本身就是合法锚形之一（索引号与证券代码族），**所以"页上有数字"不等于"这行有锚"**——要核的是那一列指不指得回披露；
- 窗外条目走六列形制的独立第 5 列「窗外余档」（锚列永远末列纯锚，注锚不互挤）；空置即 FAIL；查了没有就写「未检索到」——**空日历合法，编造日历违法**。

回购 1%/2% 进度这类无事前日期的「已发生动态」放日历末附注区，不冒充前瞻事件。

## 六、常见问题与反模式（你想这么用 → 本件不接，因为 → 替代去向）

口径：本节只把本件**已审清的拒答条款与夹具形状**重组成人能一眼查的表，不新增任何承诺；
褒贬类、评级类词在这里只作「哪一类被禁」的类别名出现，机检判据全集以 `check_calendar.py` 现值为准（定位命令见 §五 注行）。

| 你想 | 本件接不接，为什么不接 | 替代去向 |
|---|---|---|
| 拿「公告日 + 方案期限天数」算出截止日 | **不接**。日期算术全线撤权：起算日、自然日还是交易日、含不含首尾、方案变更后谁覆盖谁，全都没定义过（v1 曾授权，对抗评审后整条收回） | 公告原文自己写明完整截止日才建行；没写就没有这一行，`progress.md` 记一行理由 |
| 在日历行上标哪条是好事、哪条是坏事 | **不接**。事件只陈述日子与锚，多空褒贬那一类零豁免（唯一不扫的是类型列整列） | 判断留给人写；本件交出的每一格永远是日期 + 锚 |
| 把传闻与点评里的预期表述也排进表 | **不接**。入类第一闸要「披露在场 + 明确日期」两件事齐，缺任一不进表 | 等披露到场再建行；无事前日期的进度动态进「已发生动态」附注区，不冒充前瞻 |
| 一次排一整批持仓（几十只） | **不接**。主体集上限 10，超限必然导致逐主体锚失守（机检计数） | 拆成 ≤10 的分批各跑一次，各建自己的台账 |
| 问「哪个日子适合动手」 | **不接**。择时不是日历的产物 | 会前速览用 `tear-sheet`，带锚风险账用 `dd-checklist` |
| 按既往节奏推下一次会议或披露日 | **不接**。推断式日期属幻觉家族，自白与推断词形在机检里直接拦 | 只有载明会期的通知公告在场，才建那一行 |

## 七、出错了怎么办（症状 → 原因 → 恢复动作）

**未见于本次返回的一律写「未检索到」**：参数名、字段名、枚举值没有出现在本次工具返回里的，不得凭印象填写；写「未检索到」并记入待核清单或覆盖率账，不得留空顶替。

**Error 级＝blocker**：机检报出的 Error 级条目不得称「无害」「可忽略」「先交出去再说」；修完，或在交付面显式申报，才算出口。

以下形制按 `check_calendar.py` **当前出口**现跑取得：失败是一行 `FAIL: <文件>（N 条）`，其下每条详行**先打错误码前缀（五枚 `E-*` 之一）**（如 `[E-FORMAT] [参数]`、`[E-BANWORD] [禁词]`、`[E-ANCHOR] [双向]`），道名后是行号与该道规格；末行 `码表:` 只列本次真正用到的码与含义。全过印 `PASS: <文件>（§v2-B+§v3-B 全过, 表行 N, --window …）`。

五码是**全族同源**的封闭集（本件与四件姊妹件的码表逐字一致）：`E-FORMAT`＝形制/输入/表序不合式、`E-ANCHOR`＝锚/证据链缺失或断链、`E-BANWORD`＝禁词/评级/幻觉/待人工域命中、`E-COVERAGE`＝计数/覆盖/申报对不上、`E-LEDGER`＝账本状态机/互链断。本文不复述每枚码的处置细节——**处置已写进出口那一行的 `码表:` 里**，全集与归类规则以脚本现值为准（任意目录整行粘贴，把 `E_LEGEND` 换进 §五 那条 grep 即可）：

    grep -n "^E_LEGEND" ~/.workbuddy/skills/catalyst-calendar/scripts/check_calendar.py

| 症状（详行前缀） | 原因 | 恢复动作 |
|---|---|---|
| `[E-FORMAT] [表] / [日期] / [序]` | 表头、列位、日期形制或行序不合本件契约 | 按该行括号内给的规格改形制后复跑；改不动的那行删掉，不补内容 |
| `[E-FORMAT] [参数] 缺 --window(…)` | 正式命令式必传窗口（反 wall-clock） | 补 `--window YYYY-MM-DD~YYYY-MM-DD`，且与正文标题声明的窗口逐字一致（不一致另发一条窗口类详行） |
| `[E-ANCHOR] [双向] 第 N 行锚 '…' 在 sources 无对应` | 表行的锚没入账，或入账了但原始快照缺失/哈希对不上 | 为该锚补 `sources.jsonl` 行并把原始回包落进 `evidence/`（哈希可核），或删该行；**不许为凑链虚构锚** |
| `[E-BANWORD] [禁词] / [评级] / [幻觉] 第 N 行…` | 交付件里出现褒贬、评级或推断那一类词 | 按码表处置：改中性陈述或删除。本件唯一不扫的是类型列；词表全集见 §五 定位命令 |
| `[E-COVERAGE] [摘要] …` | 摘要/计数与主表对不上（含保留区申报缺失） | 逐类补账，或如实标「未检索到」；不得以删行让计数看似相符 |
| 域没装 / 某类目查不到 | 通道缺失，或该类目在公开面本无工具 | 走降级路径：用户贴公告清单（标直供，同样落 `evidence/` 并标来源级别）；深研不发起则该类整类标「未检索到」，**不以常识补日**。代价是覆盖度 |
| Traceback 而不是 `FAIL …（N 条）` | 属事故：本件定义纯 stdlib、零网络、零崩溃，解析点全 try 化 | 停手：把稿件与整条命令记进 `progress.md` 回报；先跑 §五 的守护样命令区分稿件问题与脚本问题，不要自己改判据 |

## 八、怎么开口（触发示例：三条正例 + 一条反例）

**开口请带上时点，输出标数据日期**：请求里给出报告期／基准日或回看窗口；成品首行标注**数据日期**，当它与用户所指日期不一致时，正文禁用「今日」「最新」，一律改写为「截至 <日期>」。
最简形态就是 §二 那句。下面三条是它接得住的其他形状，反例是真会发生的相邻需求（本件不接，指路姊妹件）。

- **正例（多主体 + 指定类别 + 指定输出目录）**：「持仓十只：美的集团、东方雨虹、宁德时代、比亚迪、招商银行、
  长江电力、中兴通讯、保利发展、海尔智家、阳光电源。只看未来 60 天的解禁与监管回复期限，别的类别先不要，
  结果写到 `~/work/cal/`」——关注类可以点，窗口可以给非默认值，缺的项按默认补齐并逐条回显给你过目。
- **正例（单主体 + 口语窗口）**：「美的集团下个月有哪些确定的日子？」——窗口会被换算成起止两天并回显，
  台账里能看到它用了哪个窗口。
- **正例（英文说法）**：`List the confirmed dates in the next 90 days for my holdings: Midea, Oriental Yuhong.`
  ——本件 frontmatter 的触发词面当前是中文句形，英文用户建议直接点名 skill（`catalyst-calendar`）以免自动命中不稳。
- **反例（相邻需求，本件不接）**：「这几只票最近的风险点都摊开、查不到什么也一并记账」
  → 那是 `dd-checklist` 的活（九类带账清单）；「先给我一页纸带去见客户」→ `tear-sheet`。
  本件只排已经确定的日子，不摊风险、不出速览。
