# catalyst-calendar

**[中文](README.md) · [English](README.en.md)**

**把你持仓里「确定的日子」排成一张日期正排的日历——每个日期背后都是一条查得着的公告或一条法条，仅此而已，不加判断。**

它回答的真实问题很朴素：**「未来三个月，我这些持仓各自有什么日子要盯？」**
回购做到哪一档了、激励归属是哪天、分红除权什么时候、问询回复截止在哪、年报还有多少天法定期限——
这些事散在公告流里，人肉盯会漏，交给日历：`buyback`/`esop`/`disclosure_cn`/`regulatory_cn`/`statute`
五域直查为主，深研最多 1 次补解禁/减持原表，产出 `calendar.md` + 可回查来源表。

**输入**：主体集（官方全称或代码，≤10 个）+ 前瞻窗口（缺省今起 90 天）
**输出**：`calendar-<日期>-<n>主体/` —— `calendar.md`（日期正排表+「未来 30 天要盯」段+来源附录）· `sources.jsonl` · `progress.md` 台账
**代价**：四段管线+一道门禁；research ≤1 次（可零），花之前必问

---

## 一、是什么 / 不是什么

| 你要 | 用什么 |
|---|---|
| 持仓事件日历（带披露锚的日程表） | **本 skill** |
| 某只票的财报深度点评 | 姊妹件 `cn-earnings-note` |
| 选股、择时、「这个日子是不是利好」 | 不做——**事件只陈述，利好利空判词全禁**（日历上「问询回复截止」旁边的永远只是日期和锚） |
| 传闻/预期里的「将回购」「拟减持」 | 不做——未披露不入表 |

## 二、快速开始（三步）

1. **装**：本目录放进 agent 的 skills 目录。
2. **说**：「我的持仓是美的集团、东方雨虹、宁德时代，给我排未来 90 天的催化剂日历」（中英触发词都行）。
   ≤4 问补齐输入契约（主体集/窗口/关注类/输出目录，逐条带默认值），开工建台账。
3. **收**：`+scope → +events → +derive → +build` 后过门禁 `+check`（`check_calendar.py` 四道：
   声明行/逐行含锚/禁词表/日期格式与窗口），**不过不交付**。

## 三、防的就是日期幻觉

这件东西最大的风险不是分析错，是**编出一个不存在的日期**。三道硬约束：

- 每条日期回指公告索引号 / URL / `conv_id` 三式之一，裸行即门禁 FAIL；
- 法定期限类必须由 `statute` 当场取回的法条推导，规则不写死；
- 窗外条目必须同行注「窗口外余档」，无注即 FAIL；查了没有就写「未检索到」——**空日历合法，编造日历违法**。

## 四、首次开通 Cue（三步，可跳过）

注册 <https://cuecue.cn>（新账号注册送 500、每日 10，以服务端为准）→ <https://cuecue.cn/hub/api-key> 取 `CUE_API_KEY` 入本地凭据（别贴进聊天）→ 装 `cue-data-mcp` / `cue-research` / `cue-omni-reader`。
**不装不报错**：降级为用户贴公告清单（标直供）；research 不发起则解禁/减持类整类「未检索到」，绝不以常识补日。所有消耗花之前先问。

## 六、当前状态（诚实清单）

- **v0.1.0 未实测**：本件随写随有文档与门禁脚本并行在制，端到端真实跑一次（多主体+真窗口）的实测记录回填前，耗时与覆盖度都是设计值。
- **未提交技能市场**：上架（P2）整体冻结中，与姊妹件同闸，时机由 Owner 定；仓库内可见性以根 README 与 `CHANGELOG.md` 为准。
- 主体集上限 10 个；`margin`（两融折算率）有意不入列——与事件日历无关。
- 日历不含行情数值流（`equity_market` 通道未开放）；不含任何评级或目标价概念。
