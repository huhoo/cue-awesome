# catalyst-calendar — 持仓催化剂日历（AI 初稿）

> 交付的是**带披露锚的日程表**，不是交易信号。日历上每一个日期都必须能回指一条在场公告或一条法条。
> 铁律与通道契约语法继承姊妹件 `cn-earnings-note`；本件最大风险=**日期幻觉**，全部设计围绕它。

## 0. 什么时候用 / 不用

| 你要 | 用什么 |
|---|---|
| 「未来三个月这些持仓各有什么确定的日子」的日历 | **本 skill** |
| 某只票的深度点评/兑现度对账 | `cn-earnings-note`（覆盖账本在其契约内） |
| 选股、择时、利好利空判断 | 不做——判词类表述全禁（铁律 3） |
| 传闻/预期类「事件」 | 不做——未披露不入表（铁律 2） |

## 1. 铁律

1. **输出是 AI 初稿**：标题后前 5 行内含 AI 声明行（机检①）。**评级概念零容忍是机检事实**：`买入/增持/减持/持有/推荐/目标价` 等词出现即 FAIL，**豁免区只有一处=类型列**（封闭枚举内的中性披露词组如「减持计划预披露」合法）；事件、状态、摘要、来源锚列与 sources 的 claim 全文扫、无豁免——本件比姊妹件更严，没有「[待人工] 留白位」这回事，评级在这里根本不适用。
2. **入类第一闸（二选一，否则根本不入日历）**：①已有披露在场**且含明确 `YYYY-MM-DD`**；或 ②`statute` 规则推导**且适用条件在锚内可判**（条件不满足即拒推，快报类无条件者不推）。**未披露的推测事件、任何日期算术**（如「公告日+360 天」推算截止日——v1 判例越权已全线撤权，仅公告原文明写完整日期才可入，锚=该公告）一律不是条目。
3. **只陈述，不判断**：禁预判涨跌、禁「利好/利空/暴涨/会涨/抄底/逃顶」判词与姊妹件禁用词表（机检③词表=`cn-earnings-note` 禁用词全集+本件六词）。事件的中性陈述例：「回购方案期限截止日（公告明写）」「问询回复截止日」。
4. **无锚即删条**：数字与日期回指不了 `sources` 的条目，直接从日历删除并在台账记弃条原因；**日期一律 `YYYY-MM-DD` 全格式**（机检④），窗口外但确有必要的条目填**独立第 5 列「窗外余档」**（值=空 或 `窗口外余档(YYYY-MM-DD，早于/晚于窗口端)`；余档列空置即 FAIL——窗外是日期幻觉高发口，锚列永远纯锚不承载余档注）。
5. **花之前必问**：cue-research ≤1 次（解禁/减持原表）与一切计费动作同姊妹件纪律——发起前报告耗时与消耗，只转述服务端计费事实。

## 2. 输入契约（≤4 问，逐条带默认值）

- **主体集**：官方中文全称或代码，≤10 个（逐个过消歧，姿势同 `cn-earnings-note/references/data-channels.md` §1）
- **窗口**：`YYYY-MM-DD~YYYY-MM-DD`，缺省=今起 90 天（缺省只作用于输入对齐；`+check` 一律传定稿后的字面窗口，禁读墙钟，见 §3）
- **关注类**（可选）：如「只看回购与分红」——缩窄 §3 取数面，不扩
- **输出目录**：默认 `./calendar-<日期>-<n>主体/`

## 3. 管线（四段+门禁，可续跑；开工建 `progress.md` 台账）

- `+scope`：主体集消歧+窗口落表；逐主体 `disclosure_cn` 拉窗口内公告清单存锚。
- `+events`：按分类学 v2 逐类取数——入类先过第一闸（`references/event-taxonomy.md` §1），再归十类封闭枚举（§2）；`buyback`/`esop`/`disclosure_cn`/`regulatory_cn` 域直查（工具级发现规则同 data-channels §1，入参 schema 现发现）；解禁/减持原表按缺口决定是否发起 research ≤1（L3 标注+L1 前置见分类学 §4.3）。股东大会（全部议案类，含临时）/业绩与投资者说明会/风险警示（ST/*ST）实施与撤销生效日/停复牌生效日四类为 v2 补收项。无事前日期的进度类披露（回购 1%/2% 节点等）入「已发生动态」附注区，不占日历行。omni 仅在公告原文必须解析时调用（域面 section 全文优先，三级路径同姊妹件）。**`margin` 域不入列**——能力面=两融折算率，与事件日历无关（Q1 对账定案）。
- `+derive`：法定期限类仅对**适用条件在法条锚内可判**者推导（如定期报告披露期限条款含报告期类型与主体类别），**每条挂 `statute` 当场取回的法条原文锚，锚值规格=`statute:<法名>第N条(<要点短引>)`**——名称+条号+短引三件齐，禁裸串；sources 对应行 `kind=statute` 且 ref 可复核（反编造法定锚）；规则文本不写死在日历里，条件不可判的期限（如未分主体的快报类）拒推不落行。
- `+build`：按主体节组装 `calendar.md`——**形制契约（§v3-A）**：表格六列顺序钉死 `日期|事件|类型|状态|窗外余档|来源锚`（锚列永远末列纯锚）；**节名规则**：主体节=一级 `##` 且标题**不属于保留词封闭集 `{未来30天要盯 | 已发生动态 | 附录}`**，摘要/附注区的识别只按保留词、禁拿字面「主体」当节前缀；「未来30天要盯」段只列不评；「已发生动态」区收无事前日期的进度类披露（带锚不占日历行）；附录=与 `sources.jsonl` 一一对应的来源索引。
- `+check`（不过不交付）：
  ```bash
  python3 scripts/check_calendar.py <calendar.md> --sources <sources.jsonl> --window <YYYY-MM-DD~YYYY-MM-DD>
  ```
  **`--window` 必传**（=输入契约定稿后的窗口字面值；checker 禁读墙钟——「今起 90 天」只是输入缺省，进入机检前必须落为显式窗口，否则历史产物隔天重跑结论漂移）。机检要点：①声明行 ②**六列**表头状态机+数据行逐行列级锚校验（公告索引号/函件号规范式/URL/`conv_id`+路径/`statute:` 规格串；事件、状态、余档列数字不得冒充锚）③禁词表+**评级词零容忍（豁免区仅类型列）** ④日期全格式、按主体节非降序、窗外条目余档列空置 FAIL ⑤正文锚↔sources 双向可解析（「被引用」只认来源锚列解析键，附录文本出现不算）+类型×锚型映射（监管类必函件号，法定类必 statute）⑥主体数 ≤10。FAIL 回改复跑。

## 4. 输出契约

```
calendar-<日期>-<n>主体/
├── calendar.md      交付物：声明行+主体节（六列正排表）+30 天要盯段+已发生动态附注区+附录来源
│                    （节名规则与保留词封闭集见 §3 +build 形制契约）
├── sources.jsonl    行式同姊妹件契约（id/kind/ref/claim/confidence/asof；法定行 kind=statute、
│                    ref=法名+条号；research 件带 conv_id+路径）
└── progress.md      台账：各段进度+弃条记录+research 实况
```

## 5. 通道依赖与降级

首次开通 Cue 三步同姊妹件（注册→api-key→装 skill；不装不报错）。降级路径：data-mcp 不可得→用户贴公告清单（标 L2 直供）；research 不发起→解禁/减持类整类标「未检索到」，**不以常识补日**。全降级仍可用，代价是日历覆盖度。

## 6. 边界与拒答

- 「帮我挑什么时候卖」→ 拒绝：日历陈述日子，不产出择时判断。
- 「把传闻/预期的事件加进表」→ 拒绝并引铁律 2。
- 主体集 >10 个 → 提示拆分（保取数质量与每主体锚完整）。
