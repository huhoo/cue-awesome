# journal-types — 刊物类型 × 读者 × 行业：先定位，再动手

> 本技能的方法论骨架（StyleSpec / UnitPattern / EvidenceCard / 八页面模板）是通用的，
> 但**默认值全部是照着一本律所客户通讯调的**。换一类刊物，不改这三件事就会跑偏：
> **合规底线（谁来会签）、期号逻辑（怎么编号）、单元形态（写多长、怎么收尾）**。
>
> 用法：`+brief` 之前先过这里的三问，把答案填进 `issue-brief.md` 第一节。
> 判错的代价是静默的——刊物跑得通、门禁全绿，但合规章节答非所问、期号跳号、单元字数全错。

## 〇、先答三问（每个问题都决定后面改什么）

| 问 | 决定 | 落到哪 |
|---|---|---|
| **谁看？**（读者身份） | 合规底线与语体，以及**必须会签的部门** | §一 → `qa-checklist.md` §四 |
| **什么节奏？**（周期性） | 期号怎么编、可复用比例、时效窗口多久 | §二 → `issue-brief.md` §一 + `check_freshness --window` |
| **什么形态？**（内容结构） | UnitPattern 怎么抽、八模板够不够、要不要人工补页型 | §三 → `unit-patterns.md` + `outline.md` |

**注意**：这三问与行业无关，与「是不是律所」也无关。
企业内刊、券商月报、制造业绩效简报都走同一套三问，只是答案不同。

## 一、读者类型 → 合规底线（这是硬约束，不是文风偏好）

读者是谁，决定**哪些话绝对不能说**、以及**谁有权放行**。写错这一层，
稿子读起来毫无问题，但发出去就是事故。

| 读者 | 典型刊物 | 不能碰的（阻塞项） | 必须会签 |
|---|---|---|---|
| **外部客户（付费方）** | 律所/咨询的客户通讯、行业观察 | 无依据的「最/第一/唯一/领先」；对服务效果的承诺（「保证胜诉」「确保通过」）；同行贬损式比较 | 市场 + 法务 |
| **员工** | 企业内刊、员工杂志、季度文化刊 | 未定案的人事任免与处分；薪酬与考核个例；未公开的组织调整；员工个人信息（含照片、健康、家庭）无授权 | HR + 法务 + PR |
| **投资者 / 股东** | IR 通讯、年报、业绩简报 | **选择性披露**（同一重大信息不能只给部分人）；未公告的重大事项；业绩预测与盈利承诺；对股价的评论 | 董秘/IR + 法务（上市企业必过） |
| **公众 / 潜在客户** | 品牌杂志、ESG/可持续报告、白皮书 | 虚假或引人误解的商业宣传；ESG 数据无口径无依据（反漂绿）；未授权的第三方数据与榜单 | PR + 法务（+ ESG 委员会） |
| **经销商 / 渠道** | 渠道通讯、代理商月报 | 与正式商务政策不一致的价格/返利口径；跨区域承诺；独家授权表述 | 渠道/销售 + 法务 |
| **监管 / 同业** | 合规简报、行业观察 | 对监管规则的曲解或选择性引用；用二手报道代替原文 | 合规负责人 |

**三条跨读者通用底线**（任何刊物都不可协商）：

1. **他人在先权利**：商标、图片、字体、肖像，未授权不用。AI 生成图不得冒充实拍（硬规则 6）。
2. **可溯源性**：每条事实有 EvidenceCard；引用外部结论写明机构 + 年份 + 榜单/文件全称。
3. **归属清晰**：外部研究结论不得写成企业自己的观点（引用 vs 自述必须可分辨）。

## 二、周期形态 → 期号逻辑与复用比例

`issue-brief.template.md` 默认写「期号 = 上期 N-1 递推」——**这只对周期连续型成立**。
其余四类照抄就会跳号或写错封面。

| 形态 | 例子 | 期号怎么定 | 可复用比例 | 时效窗口 | 特有风险 |
|---|---|---|---|---|---|
| **周期连续型** | 月刊 / 双月刊 / 季刊 | 上期 N-1 递推 | 固定件 ~20%，正文全新 | 默认 6 个月 | 旧闻充新刊（STALE） |
| **特刊 / 专辑型** | 「数据合规专辑」「出海专辑」 | **独立命名或专辑号，不递推** | 结构复用、内容全新 | 同周期刊 | 误沿上期期号 → 跳号；栏目为专题一次性重排，不必沿用上期栏目树 |
| **年鉴 / 回顾型** | 年度回顾、年度观察、年报 | **按年份**（2026 年度），无期号 | 高（往期内容汇编、数据复盘） | **放宽到 12 个月或豁免** | 时效门禁会把「回顾去年的事」全判 STALE——必须写 `freshness_exceptions` 并说明「回顾性内容，非旧闻充新」 |
| **汇编 / 案例集型** | 实务案例集、白皮书 | 版本号（第 2 版）或年份 | 中（新案例 + 旧案例更新） | 视性质 | **脱敏与当事人授权**：案例中的客户名、金额、案情细节；已结案与在办的处理不同 |
| **高频简报型** | 周报、快讯、日刊 | 期号 + 日期 | 极低，模板化程度最高 | **缩短到 1 个月** | 交付周期必须压到小时级；`mode=fast` 是常态；单元字数压到 80–200 字 |

**动作**：`+brief` 时先按上表定形态，再决定期号写法和 `check_freshness.py --window` 的取值
（**不要一律用 6**）。年鉴/回顾型必须在 `meta.freshness_exceptions` 里逐条写明理由。

## 三、内容形态 → 八页面模板够不够用

渲染器内建八个页面模板：`cover / quote / masthead / toc / divider / unit_list / article / backcover`。
它们覆盖的是「**封面 + 目录 + 若干栏目 + 若干长文 + 封底**」这一种刊物骨架。

| 刊物形态 | 八模板够不够 | 要做什么 |
|---|---|---|
| 条目 + 长文混合（客户通讯、行业月报） | **够** | 直接跑，`unit_list` 承载条目、`article` 承载长文 |
| 纯文章型（深度观察、研究刊） | **够**（退化成 1 个 UnitPattern） | `unit-patterns.md` 只抽一条 U1；`unit_list` 可不用 |
| 高图表型（年报、ESG 报告、经营简报） | **不够** | 数据页、图表页、时间轴**没有内建模板** → 走下面的「缺页型出路」 |
| 汇编型（案例集、名录、手册） | **部分** | 名录/表格页没有模板；案例正文可用 `article` |
| 高频简报型（周报） | **够，但要瘦** | 只出 `cover + toc + unit_list`；`article` 不用 |

### 缺页型的四条出路（按推荐顺序）

1. **用 `article` 承载 + 块类型拼**：`h1/h2/li/quote/note/figure/disclaimer` 七种块已支持，
   数据清单可以用 `li` + `note`（口径说明）拼出来，不如图表好看但**内容不丢**。
2. **图位交给 `gen_diagram.py`**：`columns`（并列指标卡）/`rows`（逐行指标）/
   `flow`（时间轴）/`stack`（分层）四种版式本来就覆盖了大部分「数据页」需求。
   数字图上取，正文里就不必再排表。**这条路最省事，优先用。**
3. **回父技能加页面模板**：需要真正的跨页表格时，改 `build_draft.py` 的组件 +
   `stylespec.json` 的 `page_templates`。改完**必须重跑 `crosscheck.py`**（硬规则 15）。
4. **人工在 InDesign 里补**：明说哪几页不归本流水线，写进 `review.md` 的未复现项。

## 四、行业合规检查集（挂到 `qa-checklist.md` §四）

`qa-checklist.md` §四给的是**通用底线**（绝对化用语、肖像授权、AI 图标注……）。
下面按行业补**专有禁止项**，按刊物的行业各取一行，不要全抄。

| 行业 | 专有禁止项 | 依据方向 |
|---|---|---|
| **律所 / 专业服务** | 对办案结果的承诺或暗示；与同行比较排名（除引用官方榜单）；客户名称与案情细节未授权披露 | 律师执业广告与业务推广规范 |
| **银行 / 保险 / 基金 / 券商** | 保本保收益、预期收益率；未经风险揭示的产品推介；选择性展示业绩区间；适当性错配 | 投资者适当性、资管产品宣传规范 |
| **医药 / 医疗器械** | 处方药在大众媒介的广告；功效断言（「治愈」「根治」）；未标禁忌与不良反应；临床数据无出处 | 药品广告审查、医疗器械广告规范 |
| **食品 / 保健食品** | 疾病预防或治疗功能宣称；与药品混淆的表述；保健食品未标警示语 | 食品安全法、广告法 |
| **教育 / 培训** | 升学率、通过率承诺；「名师」「保过」类绝对化；学科类培训的时段与渠道限制 | 广告法 + 教培行业管理 |
| **科技 / 互联网** | 用户数据来源合法性；个人信息未脱敏；算法能力的绝对化宣称；开源许可证义务 | 个人信息保护法、开源合规 |
| **制造 / 工业** | 产能与良率数据口径不明；认证标识（CE/UL/3C）误用；安全生产数据表述 | 认证标识使用规范 |
| **房地产** | 未取预售许可即宣传销售；升值或投资回报承诺；价格与优惠表述不清 | 房地产广告规定 |
| **零售 / 消费品** | 比较广告的贬损风险；促销「原价」标注不实；「全网最低」类表述 | 价格法、广告法 |

**上市公司的额外一条**：刊物若同时面向投资者，须过 §一「投资者」那一行的
选择性披露与未公告事项检查——这一条优先级高于本表的行业行。

## 五、通用单元类型库（非律所场景常用）

`unit-pattern.template.md` 只给了 slot 结构，没给「有哪些单元」。
律所场景下常见的是法规动态/观察/业绩/新闻；其余行业的栏目，可按此表起手改：

| 单元 | slots | 常见字数 | 收尾 |
|---|---|---|---|
| **产品 / 服务发布** | 名称 + 一句话价值 / 核心能力 3 点 / 适用场景 / 获取方式 | 150–300 | CTA |
| **客户案例** | 客户与需求 / 方案 / 结果（带数据）/ 客户评价 | 300–800 | 无 CTA，权威感收尾 |
| **员工故事** | 人物与岗位 / 加入缘由 / 在做的事 / 一句话 | 200–500 | 抒情或内部号召 |
| **里程碑 / 大事记** | 日期 + 事件 + 意义 | 每条 40–120 | 无 |
| **活动回顾** | 时间地点 + 主题 + 参与方 + 成果 / 花絮 | 200–600 | 图集或下期预告 |
| **数据看板** | 指标名 + 本期值 + 同比/环比 + **口径注** | 表格 | 口径必须注明，不可省 |
| **荣誉 / 榜单** | 奖项全称 + 颁发机构 + 年份 + 获奖主体 | 每条 40–100 | 无 |
| **专访** | 人物 + 问答 3–5 组 | 800–2000 | 抒情升华 |
| **答疑 / FAQ** | 问 + 答 | 每条 80–200 | 无 |
| **制度 / 通知** | 依据 + 要点 + 生效日 + 责任部门 | 200–500 | 无 |
| **法规动态 / 政策速递**（原示例） | 地区前缀 + 日期主体导语 + 要点 + 影响评价 + CTA | 180–320 | 「阅读原文」 |
| **业绩 / 交易快讯**（原示例） | 日期 + 板块 / 项目 + 角色 + 金额或标的 + 团队 | 200–520 | 无 CTA |

**用法**：抽 UnitPattern 时先在这张表里找最接近的一行，再拿样例的真实语料校准字数与句式——
**不要凭表里的字数硬写**，它是起手区间，不是实测值。

## 六、非典型场景的适配动作（对照表）

| 你的情况 | 要额外做什么 | 哪一步做 |
|---|---|---|
| **创刊号 / 完全没有往期刊物** | 无 StyleSpec 可抽 → 走「无样例三条出路」（`SKILL.md` 硬规则 1 之后）；**不要空手直接写** | `+learn` 前 |
| **只有图片版 / 网页版样刊** | 几何层退化成「量比例」；必须人工抄栏目树与单元边界；在 `review.md` 标明 | `+learn` |
| **样刊是网页打印稿** | 命中 `extract_style.py` 的打印稿告警 → 换设计稿，不要硬跑 | `+learn` |
| **双栏 / 多栏版面** | 渲染器只出单栏；**必须在 `+learn` 结束时前置告知**，并把「分栏未复现」写进 `review.md` 未复现项 | `+learn` 收尾 |
| **非 A4 开本** | 封面/引言/目录/编委会/封底的组件几何按 A4 调的，需人工微调；同上前置告知 | `+learn` 收尾 |
| **双语 / 多语言刊** | 见 §七 | `+brief` |
| **同一期内部分册发行**（如客户版 + 员工版） | 拆成两份 `content.json`，共用 stylespec 与图片；**不要用一份 content 加开关** | `+plan` |
| **需要多角色会签**（法务 / PR / HR / 董秘） | 交付时除三件套外，附 `review.md` 的签核清单；文字稿按角色拆节 | `+check` |
| **往期内容大幅复用**（年鉴、汇编） | `+plan` 的 A 类复用比例会很高；**复用项也要逐条核事实**（人离职、电话变更、数据过期） | `+plan` |

## 七、双语 / 多语言刊

律所、外资企业、出海品牌的常态，但本框架**没有内建双语渲染**。可行做法：

1. **同一份 content.json，正文块内自带双语**（如 `中文 / English` 两行）——最简单，
   但对齐与断行难控，只适合短条目。
2. **两份 content.json 共用一份 stylespec**（推荐）：
   `content.zh.json` + `content.en.json`，各自出三件套。
   要点：`issue` 的刊名/页脚文字按语言各写一份；图片路径共用；
   **两份必须都过 `crosscheck.py`**（硬规则 15），页数差异 >10% 要查是不是漏译。
3. **对照版**（左右栏或上下对照）：属版式改造，回父技能加页面模板，或人工在 InDesign 做。

英文稿的额外检查：英文行宽（每行 60–75 字符为宜）、连字符断词、
中文标点不得混入、专有名词首现给全称、日期体例统一（`10 April 2026` 而非 `2026.04.10`）。

## 八、给非律所用户的三个提醒

1. **本技能的示例全部来自律所刊**（`examples/` 两个样例都是）。这不是适用范围限制——
   框架抽象的是「栏目 → 单元 → slot」这套结构，与行业无关。但读示例时要**把「法规动态」当成
   「你家的高频短条目栏目」来理解**，不要因为示例是律所就以为不适用。
2. **合规检查不要照抄《qa-checklist》§四的那种金融/法律口气**。按 §一读者行 + §四行业行组合。
3. **取料通道要按你家的数据条件调**：`content-sourcing.md` 的 L3 写的是金融数据接口
   （`neodata`/`westock`）。非金融企业最有价值的结构化数据在**内部系统**（ERP 的产销、
   CRM 的客户、HR 的编制），这类数据**涉密、需授权、且往往要脱敏**——上传前必须单独征得同意
   （硬规则 5），口径与统计期必须在正文标注，不可只写「据内部数据」。
