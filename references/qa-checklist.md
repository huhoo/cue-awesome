# qa-checklist — 底稿校订清单

产出 `review.md`：分**阻塞项**（不解决不许交付）与**建议项**（可留给用户定夺）。每一项都要给出**具体位置和改法**，不要写「建议优化」这种空话。

## 一、事实与溯源（阻塞）

- [ ] 每一条事实陈述，都能在 `evidence/` 里找到对应的 EvidenceCard
- [ ] 卡片里的日期与正文写的日期一致
- [ ] 引用的文件名、文号、机构名与原文逐字一致（书名号《》、编号）不漏
- [ ] 没有「据公开资料显示」「据统计」这类无源说法
- [ ] 标着 `待验证` 的条目，没有混进正文
- [ ] 外部研究结论没有被写成企业的观点（归属要清楚）

## 二、时空一致性（阻塞）

- [ ] 期号连续，与上一期不重复、不跳号
- [ ] 封面年月 = 正文时间窗 = 版权页信息，三者一致
- [ ] 事件日期没有超过本期出版日（不能写未来的事）
- [ ] 「截至目前」「近日」这类模糊时间，要么给出具体日期，要么删掉
- [ ] 同一件事在两个地方的时间表述不打架

## 三、人与称谓（阻塞）

- [ ] 人名用字与官网 / 官方名单逐字核对（尤其是生僻字）
- [ ] 职务、头衔统一口径（"律师" / "同学" / "先生女士"别混）
- [ ] 机构全称与简称统一，首次出现给全称
- [ ] 名单顺序与职务分工没有错位
- [ ] 离职 / 新入职的人不再出现在旧岗位表述里

## 四、合规红线（阻塞）

> **分三层跑，不要只跑第一层。** 第一层任何刊物都要过；第二层按**读者身份**取值；
> 第三层按**行业**取值。判据与依据见 [`journal-types.md`](journal-types.md) §一（读者）与 §四（行业）。
> 换一类刊物（客户通讯 → 内刊 / IR 通讯 / ESG 报告），**这一节要整段重取**。

### 4.1 通用底线（任何刊物）

- [ ] 无「最大」「第一」「唯一」「领先」等无依据的绝对化表述
- [ ] 第三方评价（榜单 / 奖项）注明机构、年份、榜单全称
- [ ] 外部结论与企业自述**可分辨**（不得把他人研究写成自己的观点）
- [ ] 人物肖像有授权；他人商标、图片、字体未经授权不用
- [ ] 数据类表述给出**口径与统计期**（不能只写「据内部数据」）
- [ ] AI 生成的配图已在 `images/plan.md` 标注（不得冒充实拍）

### 4.2 按读者身份取值（至少命中一条）

- [ ] **外部客户**：无对服务效果的承诺或暗示；无同行贬损式比较
- [ ] **员工（内刊）**：无未定案的人事任免与处分、无薪酬考核个例、
      员工个人信息（含照片）已获授权
- [ ] **投资者 / 股东**：无选择性披露、无未公告重大事项、无业绩预测或盈利承诺、无股价评论
- [ ] **公众 / 潜在客户**：无虚假或引人误解的商业宣传；ESG 数据有口径（反漂绿）
- [ ] **渠道 / 经销商**：价格与返利口径与正式商务政策一致，无跨区承诺
- [ ] **监管 / 同业**：引用规则用原文，无曲解或选择性引用

### 4.3 按行业取值（至少命中一条，详表见 `journal-types.md` §四）

- [ ] **律所 / 专业服务**：无办案结果承诺、无同行比较排名、客户名称与案情细节已获授权
- [ ] **金融（银行/保险/基金/券商）**：无保本保收益、无收益率承诺、无适当性错配、
      无业绩区间选择性展示
- [ ] **医药 / 医疗器械**：无处方药大众媒介广告、无功效断言、已标禁忌与不良反应
- [ ] **食品 / 保健食品**：无疾病预防治疗宣称、已标警示语
- [ ] **教育 / 培训**：无升学率与通过率承诺、无「保过」「名师」类绝对化
- [ ] **科技 / 互联网**：数据来源合法、个人信息已脱敏、无算法能力绝对化宣称
- [ ] **制造 / 工业**：产能与良率有口径、认证标识（CE/UL/3C）未误用
- [ ] **房地产**：无未取预售许可即宣传销售、无升值或回报承诺
- [ ] **零售 / 消费品**：比较广告无贬损、促销「原价」属实、无「全网最低」类表述

> **上市公司额外一条**：刊物若同时面向投资者，须过 4.2 的「投资者 / 股东」行——
> 这一条的优先级高于 4.3 的行业行。

### 4.4 配图合规（全部刊物）

- [ ] 涉投资、医疗、功效类内容若带免责声明，声明文字是**照搬模板**而非改写
- [ ] **每张配图都肉眼看过**——`avoid` 清单是概率性约束（实测 prompt 里写明
      「不要天平」仍画了天平），并确认右下角**没有「AI生成」水印残留**
      （`--crop-watermark` 只在留白够时才裁，两条边都不够会报警而不是硬裁）
- [ ] 已配图的图注里**不再保留「图位待补：」前缀**（`adopt_images.py` 回填时
      已自动剥离已知前缀，仍需人工通读确认无残留）
- [ ] 图注文字与画面**语义对得上**（脚本按索引回填，不校验图文是否指的同一件事）

## 五、可读性与无底图降级（阻塞）

**新刊几乎不可能有样刊那套满版底图**，而 StyleSpec 抽出来的色值是「压在图上」的颜色
（`meta` 常常是 `#FFFFFF`）。不降级就会交出一本「页码、目录页码、编委会、分隔页标题全部隐形」的刊物。

- [ ] 打开 `draft.html`，逐页确认没有「白纸上的白字 / 浅色字」
- [ ] 页码、目录页码、编委会、分隔页标题四处**逐一**肉眼看过（这四处是重灾区）
- [ ] 没有底图的封面 / 分隔页，渲染器已画兜底版式（`cover-fallback` / `divider-full`），不是空页
- [ ] 空图位渲染成占位斜纹块并带说明，没有留下无意义的破图
- [ ] **四条路同一个图位状态一致**：HTML 占位块 / PDF 告警 / md `⟨待补图⟩` /
      docx `[ 待图 ]`。`export_editable.py` 跑完会报「N 处图位没有可用图源」，
      **交付稿里出现 `[ 待图 ]` 就是还没配完**（空图位不会报错，只会安静少一张图）
- [ ] docx 全文搜一遍 `图片读取失败`：正常应 **0 命中**。命中说明有图位拿**目录**
      当图片源了（`exists()` 会接受目录，`src=""` 拼出来就是 content.json 所在目录）
- [ ] `--stats` 里没有 `overflow` 告警（估算高 > 可用高，会被 `overflow:hidden` 静默裁掉）

## 六、版面与合成（阻塞）

- [ ] 目录页码与正文实际页码逐条对齐（先确认 `page_offset`）
- [ ] 页码连续，无缺页、无重复、无封面页码误入正文
- [ ] 页眉刊名、logo 在每一页都在，且位置一致
- [ ] 图片分辨率足够（印刷 ≥300dpi，屏幕版 ≥150dpi）
- [ ] 图片没有被拉伸变形，出血位的安全区没有压到重要内容
- [ ] 正文没有溢出页边界，也没有大片空白
- [ ] 单个单元整块排版，不被跨页拦腰截断

## 七、两版一致（版面稿 × 文字稿，阻塞）

交付是两版：版面稿 `draft.html` / `draft.pdf`，文字稿 `draft.docx` / `draft.md`。同一份 `content.json` 出，但**中途任何一侧改了字，另一侧就失真**。

```bash
python3 <skill>/scripts/import_docx.py --docx out/draft.docx \
    --base content.json --out /tmp/check.json
```

- [ ] **导出 docx 后、送编辑前，先跑一次「空转测试」**：立刻回填，结果必须与原
      `content.json` **逐字节相同**（`json.load(a) == json.load(b)` 为 True）。
      没改过稿却报出改动 = 回填链在静默丢内容，必须先修脚本再交稿
      （实测一次空转暴露 5 处丢失：`**` 加粗、目录 `ref` 锚点、顶层 `meta` 时效豁免、unit 可选字段、空图位）
- [ ] 回填稿与原稿的差异，只剩明确知道的人工改动（改动清单会逐条列出）
- [ ] 改动清单里**不含** `<br>` / `**` / 空白这类归一化差异（含了就是脚本没跟上）
- [ ] 目录页码不是空的（内容用 `ref` 锚点时，导出/回填都必须带出锚点）
- [ ] 页数、`folio` 页码、期号年月，两版三处一致
- [ ] 出现「Pxx 找不到原始对照」说明有人动了整页，确认是有意还是误删
- [ ] 没有把 Word 里的替换图当成新增配图（Word 里换过的图回不来，`--base` 里的才是真的）

见 [`editable-output.md`](editable-output.md)。

## 八、文案质量（建议）

- [ ] 每个单元的字数在 UnitPattern 的区间内
- [ ] 标题长度一致量级，不至于一行塞不下
- [ ] 数字体例统一（阿拉伯数字 vs 中文数字）
- [ ] 标点统一（中英标点不混用，书名号、引号成对）
- [ ] 同一概念在全刊只有一种译法 / 一种叫法
- [ ] 每个单元按各自的固定件收尾（CTA / 服务转化 / 抒情升华，不混用）

## 九、与样例的度量比对（必须做，且是硬门禁）

```bash
python3 <skill>/scripts/build_draft.py --spec stylespec.json --content content.json --out out/ --stats
```

若 spec 里有 `scale_baseline`（派生技能已自动带上），`--stats` 会直接算达成率并打印：

```json
"baseline": {"pages": {"target": 91, "actual": 59, "ratio": 0.648}, ...},
"FAIL": ["chars"]
```

> **两个复核时的坑**（交付后复跑门禁必踩，2026-09-18 实测）：
> ① **必须带 `--spec`**。省掉它 → 控制台只留一行 `[WARN] spec 无 scale_baseline，量级门禁未生效`，
> 然后照常打印 `OK pages=…` 与 `exit=0` —— **看着像通过，其实根本没算达成率**。复核时看到这条 WARN 就说明命令下错了。
> ② `--out` 收的是**目录**（脚本自己拼 `draft.html`），传成 `./build/draft.html` 会 `FileExistsError: [WinError 183]`。

- [ ] **`FAIL` 列表为空**。任何一项达成率 <60% 就判不合格，回去补内容，不要靠写说明糊过去
- [ ] 达成率 60–100% 的项，在 `review.md` 里说明差额由什么构成（例：业绩快讯 8 则的素材来自市场部，本期为骨架）
- [ ] `articles` 数的是**逻辑篇数**不是物理页数（自动分页会把一篇拆成多页）

| 指标 | 样例 | 本期 | 达成率 | 说明 |
|---|---|---|---|---|
| 总页数 | 91 | ? | | |
| 启明观察篇数 | 6 | ? | | |
| 正文总字数 | 56,000 | ? | | |

## 十、交付前的一句话自检

> 如果把这份底稿直接交给设计师和用户审：
> **有多少处需要人回来问？** 超过 5 处，说明前面的需求对齐没问到位，应该回去补一轮，而不是硬着头皮交付。

- [ ] 成品里**没有** `⟨待确认⟩` / `⟨待补图⟩` 这类标记（三个渲染器都不清理它们，会直接印出来）
- [ ] `progress.md` 已更新到最后阶段（续跑靠它，不靠记忆）
- [ ] 若本期语义层是人工补的（没有 Omni），已在交付说明里挑明

## 十一、交付动作（不是「回一句已生成」）

- [ ] 版面稿 `draft.pdf` 与文字稿 `draft.docx` 已用文件预览**打开给用户看**
- [ ] 交付说明只讲三句：页数与达成率 / 阻塞项条数 / 还需要用户做什么
- [ ] `review.md` 末尾有交付清单（文件名 → 给谁 → 下一步动作）
- [ ] **阻塞项清单要"可一次改完"**：每一条给出 ①`content.json` 的**精确 JSON 路径**
      （如 `pages[16].units[0].body`，不是"业绩快讯那一页"）②现状（沿用第几期 / 草稿 / 空缺）
      ③**已经试过哪些公开渠道、结果如何**（例：官网该项目页只写牵头合伙人、无团队名单；
      `/contact` 页抓取失败）。只写"请业务方核对"会把复核成本推回给用户；
      而写清"已试过 A/B/C 都不行"才能证明这不是偷懒漏查。
- [ ] **既有的草稿别写成"缺失"**：占位项若已有可用草稿（如免责声明），要写明草稿所在路径与原文，
      让业务方"确认或替换"而不是"从零提供"——`fixed-pieces.md` 之类固定件台账里与之矛盾的旧记录要同步订正
- [ ] `progress.md` 标 `done`；`pending.md`（若有）已随交付一并说明
- [ ] **未复现项已逐条列出**：命中 `SKILL.md` §1「能力边界」表的情形（双栏 / 非 A4 开本 /
      高图表页 / 双语 / 汇编表格页）时，`review.md` 里要写明「哪一项没复现、谁来接」，
      且**这一项在 `+learn` 收尾时已经口头告知过用户**（不是交付时才第一次说）
- [ ] **需多角色会签时附签核清单**：按 `journal-types.md` §一 定出会签部门
      （市场 / 法务 / HR / 董秘-IR / PR / 合规），在 `review.md` 里列出
      「谁签 / 签什么 / 当前状态」；文字稿按角色拆节，便于各口分头批注
- [ ] **双语刊**：两份 `content.json` 都已过 `crosscheck.py`，页数差异 >10% 已查是否漏译
