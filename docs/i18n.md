# Bilingual docs (i18n)

**[English](i18n.md) · [中文](i18n.zh-CN.md)**

This repo keeps documentation bilingual, following the convention of
[sensedeal/cue-skills](https://github.com/sensedeal/cue-skills).

## File pairs

| File | Language | Role |
|---|---|---|
| `README.md` | English | canonical |
| `README.zh-CN.md` | Simplified Chinese | full translation |
| `SKILL.md` | see [per-skill policy](#per-skill-policy) | the file the agent loads |
| `SKILL.zh-CN.md` | Simplified Chinese | full translation |

## Rules

1. **Naming** — append `.zh-CN` before the extension. No `_en` / `_zh` suffixes, no `lang/` or `locales/` directories.
2. **Frontmatter is identical in both files** (`name`, `description`, `license`, `metadata.version`). Only the body language differs — the agent must not see two different skill identities.
3. **The translated file opens with a pointer** to the canonical one, e.g. "This is the full Chinese translation of `SKILL.md`; semantics match the English version. Loading follows the English `SKILL.md`."
4. **Language switch line** at the top of every bilingual page: `**[English](X.md) · [中文](X.zh-CN.md)**`.
5. **Edit both in the same commit.** A version bump applies to both files; never let them drift.
6. **Never translate**: code, script paths, CLI flags, JSON keys, file names, hard-rule numbers, or domain terms that have a fixed form.

## Per-skill policy

Each skill declares which language is canonical in its own `README`. Two accepted shapes:

- **English-canonical** (matches cue-skills): `SKILL.md` is English, `SKILL.zh-CN.md` is the Chinese translation.
- **Chinese-canonical**: `SKILL.md` is Chinese, `SKILL.en.md` is the English translation. Use this when the skill is authored for Chinese users and translating the whole file would be high-risk (large files with numbered hard rules).

Pick one per skill and state it in that skill's README. Do not mix shapes inside one skill.
