# 民事二审翻案工程

## 目的

把一份**败诉判决书**加一堆**零散材料**（起诉状、庭审笔录、录音转文本、聊天截图、查询结果），工程化地转化为一套可直接递交的二审作战体系：一份上诉状、一套配套文书、一张事实台账、一份按优先级排序的待办。

本技能不提供法律意见，也不替代律师。它提供的是**结构化工作流与纪律约束**，核心解决三个问题：

1. **定位真正的败诉原因**——多数败诉不是"证据不足"，而是争点被框错、法律路径被漏审、关键事实没进入法官视野。
2. **把论证铺成阶梯而非单点**——避免押注单一请求权基础，一旦不被认可即全线失守。
3. **让每一句话都有出处**——杜绝推断与虚构，杜绝同一份材料前后矛盾。

## 何时使用

出现下列任一情形时启用：

- 一审判决败诉，需要决定是否上诉、如何上诉
- 需要拆解判决书、找出可以攻击的点
- 需要起草或复核上诉状
- 需要准备二审配套文书（继续保全、调取证据、责令提交、到庭接受询问、新证据清单）
- 当事人自行诉讼（不委托律师），需要明确期限、递交渠道、费用
- 需要在上诉期内压缩出一套可执行的作战方案

## 边界与前置声明

**开工前必须向使用人明确：**

1. 本技能产出的是**工作稿与结构**，不是法律意见；关键法条条号、期限、费用标准须由使用人核对。
2. 模型可能记错法条条号。**所有引用条号处必须标注"递交前核对条号"**，不得让使用人直接照抄。
3. 对事实的定性一律以**可核验的来源**为准；网络检索、第三方平台信息须标注为"待以官方来源核对"。
4. 涉及投诉法官、投诉律师、信访、举报的内容**另开文件**，不得混入诉讼文书与论证主线。
5. 交付文件中对身份证号、手机号、住址、银行账号、未成年人信息一律留占位符。

## 八条硬约束（违反即返工）

| # | 约束 | 说明 |
|---|---|---|
| 1 | **判决自认优先** | 论证起点必须是**判决自己已认定的事实**。这类事实最难被驳，也最省力。 |
| 2 | **每个论断带出处与等级** | 三级：**A＝判决已认定**／**B＝在案已提交但未经认定**／**C＝待调取或待核实**。禁止把 C 当 A 用。 |
| 3 | **不预断、不虚构、不推断** | 未核实事项一律标注"待核实"，禁止写入文书。对款项流向、身份归属等易错事实，统一使用**开放式/择一**表述。 |
| 4 | **定性更正必须全库执行** | 一旦某事实的定性被更正（如项目名称、时间、主体归属），必须检索全部既有文件更正，并在更正处留痕说明"前一版结论作废"。 |
| 5 | **钱 > 期限 > 证据** | 财产保全与上诉期限优先于一切取证动作。顺序不可颠倒。 |
| 6 | **情绪线与诉讼主线分离** | 追责、投诉、不满另立文件。 |
| 7 | **输出脱敏** | 见边界第 5 条。 |
| 8 | **不替代程序资格判断** | 是否属于二审新证据、能否在二审增加诉请、当事人能否作证等程序问题，必须显式核查后给出结论，不得想当然。 |

## 工作流

### Phase 0 · 收口（最先做，不超过半天）

1. 确认**判决送达日**，据此计算上诉期（民事判决 15 日，自送达次日起算），得出死线日期。
2. 确认**保全状态**：是否已保全、保全金额、保全届满日、一审驳回后是否面临解冻。**若已保全，把《继续保全申请书》列为最高优先级**——上诉不自动延续保全。
3. 确认**诉讼主体与代理人现状**：是否有代理律师、是否已解除、送达地址是否为本人。**若已解除委托而文书仍列律师，必须删除该行并书面变更送达地址**，否则期限照常计算而当事人收不到通知。
4. 用 `scripts/init_case.py` 初始化案件工作目录，生成四张表与主控骨架。

### Phase 1 · 判决逆向工程

目标不是"找错误"，而是**还原法官的推理链**，判断争点被框定在哪一层。

1. 逐段摘录判决的"本院认定"与"本院认为"，**还原成一条推导链**（如：A → B → C → 驳回）。
2. 找出**框架层错误**：本案的核心问题被表述成了什么？若被表述为"某人是否有代理权／某文件是否有效／某形式是否具备"，则举证责任往往已被转到弱势一方。**判据：若按该框架举证，所需证据是否全部由对方单方控制？若是，框架极可能被框错。**
3. 列出**应适用而未适用的条文**：适用条文清单 vs 本案可能涉及的请求权基础，逐条比对。
4. 填入 `assets/判决书拆解表.md`。

详见 `references/01-judgment-reverse-engineering.md`。

### Phase 2 · 证据逐字比对

1. 把判决书对每一份证据的摘录，与原始材料（录音转文本、聊天记录、书证）**逐句对照**。
2. 重点标记三类：**被截断**（摘录到某句即打省略号）、**被省略**（整段未提）、**被割裂**（同一陈述只采信其中一句）。
3. 对每一处差异，写明：原文是什么、判决写了什么、该差异影响哪个法律要件的认定。
4. 若发现判决疑似只接触到片段（如转文本节选），把"提交完整版 + 申请当庭播放原始载体"列为二审动作。
5. 填入 `assets/证据比对表.md`。

详见 `references/02-evidence-diff-protocol.md`。

### Phase 3 · 法律路径阶梯

1. 识别本案的**责任归属问题**（谁应为该行为或该笔款项负责）。
2. 列出全部可能的请求权基础，按**主攻 → 备位 → 兜底**排序，形成阶梯。
3. 逐层填写：构成要件／本案已有证据（标 A/B/C）／缺什么／怎么补／判决漏了什么。
4. **关键判据：阶梯的前几层应当不依赖任何新证据**，只建立在 A 级与 B 级证据之上；依赖新证据的层级放在后面并注明取证路径。
5. 填入 `assets/法律阶梯表.md`。

详见 `references/03-legal-ladder.md`。

### Phase 4 · 事实台账与纪律

1. 建立事实台账，每条事实标注：内容／来源／等级（A/B/C）／是否已用于文书／纪律备注。
2. 输出**纪律清单**（红线）：哪些表述禁止使用、哪些事实未保全前不得引用、哪些时间只能写区间不能精确到日。
3. 建立**更正留痕机制**：任何定性变更后，检索全库更正。

详见 `references/04-fact-ledger-and-discipline.md`。

### Phase 5 · 文书包产出

产出结构见 `references/06-document-pack.md`。要点：

- **上诉状**：理由之前加一段**总述**（一页内：一个核心争点 + 判决自认的关键事实 + 三项致命错误）。法官时间有限，总述决定他会不会往下读。
- **配套文书**：继续保全、调取证据、责令提交、到庭接受询问、新证据清单——**必须与上诉状同日递交**，否则很可能书面审理、不开庭。
- **同步机制**：上诉状每次修改后，同步更新配套文书包与主控清单中的对应段落，并在版本说明中记录。

### Phase 6 · 待办与递交

1. 按 T+0／T+1~3／T+4~7／死线 重排待办，每项标注"为什么"与"产出"。
2. 核对递交渠道、份数、费用、缴费期限。
3. 输出风险清单与纪律清单。

详见 `references/05-self-represented-filing.md`。

## 交付物约定

每个案件至少产出：

1. **主控清单**（待办 + 案件档案 + 文件索引 + 纪律）
2. **复核报告**（败诉根因 + 扭转路径 + 命门证据 + 待办）
3. **上诉状**（含总述）
4. **配套文书包**（同日递交）
5. **四张表**（拆解／比对／阶梯／台账）

交付前自检：

- 每一处事实论断是否都带 A/B/C 等级？
- 每一处条号是否都标注了"递交前核对"？
- 是否存在把 C 级当 A 级使用的表述？
- 定性更正是否已在全库执行并留痕？
- 敏感信息是否已脱敏？
