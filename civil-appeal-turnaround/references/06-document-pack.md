# 06 · 文书包结构与同步机制

> **门牌锚点**：动词 **搜集**（三份申请）+ **查证**（脱敏与红线落地） · Phase 5 · 落点 `上诉状.md` + `配套文书包.md`
> **读到哪为止**：本节只管成文与同步。理由的骨架来自 `01` §归置（面二、面三），层级来自 `03`，能不能写来自 `04`，递交渠道与期限见 `05`。

## 一、产出结构

```
案件工作目录/
├── 主控清单.md              待办 + 案件档案 + 文件索引 + 纪律   ← 唯一入口
├── 复核报告.md              败诉根因 + 扭转阶梯 + 命门证据 + 待办
├── 上诉状.md                含总述
├── 配套文书包.md            继续保全 / 调证 / 责令提交 / 到庭询问 / 新证据清单
├── 判决书拆解表.md          Phase 1
├── 证据比对表.md            Phase 2
├── 法律阶梯表.md            Phase 3
├── 事实台账.md              Phase 4
└── 归档/                    判决原文、起诉状原文、笔录、转文本、查询结果原始记录
```

**主控清单是唯一入口**：任何一次变更后，必须回头更新主控清单的对应条目与文件索引。否则文件越多越失控。

## 二、上诉状的写法

### 总述（置于上诉理由之首，一页以内）

**法官时间有限，总述决定他会不会往下读。** 结构：

1. **一个核心争点**：本案全部争点可归纳为……
2. **判决自己已认定的关键事实**（表格形式，标注出处页码）——表明上诉不依赖新证据
3. **三项致命错误**：认定基本事实不清／适用法律错误／举证责任分配错误与未尽释明
4. **请求**：撤销原判 → 改判或发回重审；申请开庭审理

### 理由部分的编排

| 顺序 | 内容 |
|---|---|
| 前段 | **程序性硬伤**（缺席后果未适用、对到庭当事人陈述未评价）——最容易判断，先给法官一个"确实有问题"的印象 |
| 中段 | **事实类问题**（逐项指其未认定、选择性采信、割裂采信） |
| 后段 | **法律适用**（未适用的条文、阶梯式路径） |
| 末段 | **程序违法**（举证责任、释明义务、未调取） |

### 每条理由的写法

- **先引判决原文**（带页码），再指出问题，最后给法律后果。
- 使用**加粗**标出判决原文中的关键词。
- 每条理由结尾必须落到法定后果："属于认定基本事实不清，请求二审法院……"。
- 理由编号必须连续，**插入新内容后必须重新编号**（这是最常见的形式硬伤）。

### 常见形式硬伤（递交前必查）

- [ ] 理由编号是否连续、有无重复或跳号（如"第一、第四、第五、第五、第六"）
- [ ] 交叉引用是否仍然成立（"详见理由十二"在编号变动后是否还指同一条）
- [ ] 代理人署名是否与现状一致（已解除委托的须删除）
- [ ] 当事人信息是否完整、是否脱敏
- [ ] 全部条号是否已标注"递交前核对"

## 三、配套文书包

| 文书 | 说明 |
|---|---|
| **继续保全申请书** | **最高优先级**，与上诉状同日递交并另交一审承办法官 |
| **调取证据申请书**（可合并） | 向各被调查人分别写明材料名称、控制情况、不预断内容、穷举检索口径、拒不提交后果 |
| **责令提交证据申请书** | 针对对方当事人控制的材料 |
| **传唤当事人到庭接受询问申请书** | ⚠️ 当事人**不能**写为"证人" |
| **二审新证据清单** | 逐项写明：名称、来源、证明对象、为何一审未提交（逾期理由） |
| **开庭审理申请书**（或在上诉状中载明） | 说明为何书面审理无法查清（需当庭播放原始载体、需当事人到庭） |

## 四、同步机制（核心纪律）

**上诉状的每一次实质修改，必须同步下列位置：**

1. 配套文书包中的对应段落（如调证申请的检索口径、事实表述）
2. 主控清单中的案件档案与文件索引
3. 事实台账中的"已用于哪些文书"列
4. 版本说明（记录本轮改了什么、为什么）

**未同步的后果**：上诉状改了而配套文书没改，两份文书在同一事实上表述冲突，会被对方直接抓住。

### 同步检查清单

- [ ] 案件名称/项目名称的表述是否全文一致？
- [ ] 时间点表述是否全文一致（约数、区间）？
- [ ] 被调取主体的名称是否全文一致？
- [ ] 关键定性（如某事实属于哪一主体）是否全文一致？
- [ ] 被推翻的旧论证是否已在全部文件中删除？

## 五、版本说明规范

在上诉状末尾保留版本说明，逐版记录：

```
> 📌 版本说明（日期 · 第 N 次更新）：
> 本轮新增/修正：①…… ②…… ③……
> 此前各版：……
> 上诉理由现共 N 项。
```

**作用**：回溯修改轨迹、防止回退、便于他人接手。

## 七、Word 递交稿（导出与保真校验）

### 为什么要有第二套产物

| | markdown | Word |
|---|---|---|
| 谁用 | 你与模型：diff、批量检索、再加工 | 法院、对方当事人、打印店、帮你核的律师 |
| 定位 | **唯一事实源** | 递交与打印载体 |
| 能否改 | 直接改 | 直接改（改完要回写 md） |

**markdown 是事实源，Word 由它导出，不是并行维护的第二份稿。** 两边都改就会分叉——而分叉通常在递交前夜才被发现。

Word 版**不承担精确版面**（这条来自 `journal-draft` 的实测教训）：想让 docx 保持 mm 级定位，它会退化成一堆互相打架的文本框，编辑一动就散。本件只求「打印出来是规整的公文」，不求还原任何设计。

### 硬纪律：转换 ≠ 重写

导出**只做格式投影，不改动一个字**：不润色、不精简、不「优化措辞」。上诉状里一个字的改动可能改变意思，而这种改动**不报错**，只会静静变成另一个说法。

### 格式（`--style court`，公文体，默认）

| 项 | 值 |
|---|---|
| 页面 | A4；上 3.7 / 下 3.5 / 左 2.8 / 右 2.6 cm |
| 文种标题 | 黑体二号，居中 |
| 一级标题 | 黑体三号；二级以下楷体小三 |
| 正文 | 仿宋三号（16pt），行距固定 28pt，首行缩进 2 字符 |
| 引用块 | 楷体小四，缩进 |
| 表格 | 宋体小四，Table Grid，表头加粗 |
| 页码 | 页脚居中（PAGE 域） |

`--style brief`（诉状体：宋体小四、1.5 倍行距）给律师核或自己看，页数少一半。

### 保真校验（必做）

```bash
python <skill>/scripts/export_docx.py 上诉状.md -o 递交/上诉状.docx --strip-emoji --check
# 校验通过：281 行源文本全部出现在 Word 中
```

`--check` 逐行比对源 md 与 docx 的文本覆盖，少了哪一行直接报出来。**为什么必须有**：内容丢失不会报错，只会静静少一段——递交法院的文书尤其不能接受。实测六件共 1619 行零丢失。

纪律：`--strip-emoji` 开启时校验会同步对源文本去 emoji。**两个开关必须一致**，否则会把「按要求去掉的符号」误报成「丢失的内容」。

### 已知坑（实测）

| 现象 | 真因 | 处理 |
|---|---|---|
| Word 里中文掉回宋体 | python-docx 的 `font.name` 只写 ascii/hAnsi | 脚本额外写 `w:eastAsia`（与 journal-draft 同一个坑） |
| 递交件里出现反引号残留（如 \`xxx.md\`） | 粗体内部还套着行内代码，整段按粗体原样写入 | 粗体分支递归解析内部 code / link |
| 校验报「缺 N 行」但没真缺 | 导出开了 `--strip-emoji`，校验却拿带 emoji 的源去比 | 校验与导出共用同一开关 |
| 代码块在 Word 里很难看 | 等宽字体 + 缩进已是折中 | 递交件里本就不该有代码块；有就说明那段不是递交内容 |

### 递交前

- **递交件开 `--strip-emoji`**：⚠️ 📌 ★ 这类符号在法院文书里不合适，部分字体还会显示成方框。自用件可保留。
- 打印前翻一遍**页码与签名位**（脚本不替你放签名）。
- **份数**按受理法院要求（通常正本 1 份 + 副本按对方当事人人数）。
