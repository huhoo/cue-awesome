# civil-appeal-turnaround

**一审你委托了律师，还是输了。二审轮到你亲自指挥——本技能不承诺翻案，它把案子从律师的脑子里，交回最懂它的人手上。**

**给一份败诉判决，还一套能直接递交的二审作战体系。**

不是「帮我写份上诉状」——是把判决书**逆向拆成法官的推理链**，定位争点被框错在哪一层，再从原始材料里找出被截断、被省略、被割裂的内容，最后把论证铺成**阶梯**而不是单点押注。所以它交出的东西是一整套互相咬合的文书，而不是一份孤零零的上诉状。

**输入**：一审判决书 + 手上的零散材料（起诉状、庭审笔录、录音转文本、聊天记录、查询结果）
**输出**：`今日三件事.txt` · `主控清单.md` · `复核报告.md` · `上诉状.md` · `配套文书包.md` · 五张表（拆解 / 比对 / 阶梯 / 台账 / 败诉三面）· **Word 递交稿**（`*.docx`，由 markdown 导出，公文体排版 + 页脚页码）
**代价**：Phase 0 半天收口，之后按判决书与卷宗的体量推进；**上诉期 15 日是硬约束**
**线索通道**：路径与先例线索可由 `cue-research` 列候选（法条、司法解释、类案）——**线索不是结论**，裁判结果不作承诺，一律以官方来源核对后才入表。

## 开宗：这门牌只有四个动词

你要做的全部动作，收在四个动词里；每张表都是其中一个动词的落点：

| 动词 | 做什么 | 落点 |
|---|---|---|
| **盘点** | 把判决拆成推理链，再把败诉分成三面：天然不利的、打法失误的、裁判层错误的 | `判决书拆解表.md` + `败诉三面表.md`（模板在 `assets/`） |
| **搜集** | 逐字比对原文与判决摘录；差出来的那口气列成待调取——调取证据、责令提交、二审新证据清单三份申请 | `证据比对表.md` + 待调取三份申请 |
| **查证** | 每条事实挂 A/B/C 等级，每条条号留「递交前核对」那条线 | `事实台账.md` + 红线清单 |
| **todo** | 把前三件排进日历，按 T+0／T+1~3／T+4~7／死线倒推 | `主控清单.md`（前提确认 + 待办） |

Phase 0-6 不是这四个动词之外的第五件事，它们是这四个动词的**细则**（见 §二）。

### 第一天：今天三步

今天只做三步，每步都标了「不做会怎样」：

| 今天 | 怎么做 | 不做会怎样 |
|---|---|---|
| ① 确认送达日、算死线 | 判决上诉期 15 日、自送达次日起算；两个日期一律**以判决书尾部与送达回证为准**，不凭记忆推算 | 上诉期届满不可恢复，一审生效，全盘被动 |
| ② 查保全状态 | 已保全 →《继续保全申请书》最优先（上诉不自动延续保全）；未保全 → 先估对方转移财产的空间 | 保全被解冻或届满释放，即便翻案也拿不到钱 |
| ③ 查委托现状 | 律师已解除 → 上诉状删掉代理人那行，并**书面**变更送达地址 | 文书寄给旧代理人或旧地址，期限在你不知情中被消耗 |

这三步是 Phase 0 的头三项；拆判决与逐字比对排在它们之后，不是之前。

## 一、它跟「写份上诉状」的区别

### ① 先找框架错，不是先找证据

多数败诉不是「证据不足」。判决写「现有证据不能证明……」时，通常是争点被框成了一个需要由弱势方举证的问题，而所需证据全在对方手里、对方还缺席。

判据只有一句：**按判决的框架举证，所需证据是不是全在对方单方控制之下？是，就说明框架被框错了**——在框架内补证据是徒劳的，二审必须重新定义争点。

### ② 逐字比对，不靠印象

判决书对证据的摘录，决定了法官实际「看见」了什么。把每一份证据的原始材料与判决摘录逐句对照，标出三类差异：**截断 / 省略 / 割裂**。

截断的找法很实操：**找到判决摘录里最后一个省略号，回原文读它后面紧跟着的 1–3 句**。判决停在这里，通常意味着后面是它不想处理的内容。

### ③ 论证铺成阶梯，不押单点

单点押注单一请求权基础的失败模式是：二审法院不认可该路径，全线失守、无退路。

```
第一层　主攻：最契合事实，且不需新证据
   ↓「纵使二审法院认为……」
第二层　备位：同样不需新证据，要件不同
   ↓
第三层　需新证据支撑
   ↓
第四层　兜底：需法院释明变更
```

**硬判据：前两层不许依赖任何新证据**，只建立在 A 级（判决已认定）与 B 级（在案已提交未认定）事实之上。

> **先用不需新证据的层级把「撤销原判」拿下，再用需新证据的层级把「查清事实」做实。**

## 二、工作流细则：六个阶段（门牌四动词的展开）

| Phase | 做什么 | 产出 |
|---|---|---|
| **0 · 收口** | 确认送达日与上诉期死线、保全状态、代理人现状 | 前提确认表 |
| **1 · 判决逆向工程** | 还原推导链，找「跳跃最大的一步」，五层根因；同轮填败诉三面表 | `判决书拆解表.md` + `败诉三面表.md` |
| **2 · 证据逐字比对** | 原文 vs 判决摘录，标截断 / 省略 / 割裂 | `证据比对表.md` |
| **3 · 法律路径阶梯** | 主攻 / 备位 / 兜底，逐层列要件与「判决漏了什么」 | `法律阶梯表.md` |
| **4 · 事实台账与纪律** | A/B/C 出处等级、红线清单、定性更正留痕 | `事实台账.md` |
| **5–6 · 文书与递交** | 上诉状（含总述）+ 配套文书，同日递交 | `上诉状.md` / `配套文书包.md` |

### 素材与线索的两条通道（都是可选辅助，且都带上界）

本件的脚本与流程不联网。下面两条是**使用人另装的可选辅助**，只在「素材进不来」与「找候选线索」两处帮忙，用不用由使用人确认；它们的格式清单、大小上限与覆盖域一律以各自文档**现值**为准，本件不复制、也不预告结果。

**素材桥 · `cue-omni-reader`**：证据是扫描件、录音、录像或打包卷宗，若被 agent 自带的上传通道拒（格式或大小不合），可先交它解析成**可定位文本**（含页码/时间锚），再放进案件目录。上界逐条，一条都不省：

- **格式看本地允许清单的现值**：`rar`/`tar`/`tgz`/`gz`/`bz2` 在列，`parquet`/`xmind`/`mmap` 不在列——全表以该件 `references/compatibility.md` 现值为准，本件抄一次就开始腐烂，故不抄。
- **单源 ≤256 MiB**：超限在解析前就被 `constraints.max_bytes` 这道闸挡下（实测值 268435456 字节），不是解析失败。
- **音视频只按本地小段/切片实证**：全长会议解析未臻（实测：两场合共三枚 90 秒切片走通全链、逐字回查 8/8；公开全长 URL 五枪全拒、本地全长受上条闸）。
- **能否解析与是否计费以服务端返回为准**：本件不承诺任何未开放的域、不推算费率。
- **转写文本仍按本件纪律分级**：录音的谐音与误听不自动校正（解析产出照原样留痕），须**回听原始载体**核对后才能升 A/B 级；核对前先按 C 级挂「待核」。

**检索桥 · `cue-research`**：Phase 1 找「应适用而未适用的条文」、Phase 3 铺阶梯各层的构成要件时，可用它检索法律法规、司法解释与类案，产出的是**候选清单**——法条原文与案号一律先记 **C 级（待核）**、标「待以官方来源核对」，递交入卷后方可升 B，与本件既有的出处分级同一套纪律（八条硬约束与六阶段语义一字不改）。上界：该通道只覆盖公开数据源，域表以其文档现值为准（本件不硬编码），**线索不是结论**——不承诺裁判结果，也不承诺「查到即用」。

## 三、八条硬约束（违反即返工）

| # | 约束 |
|---|---|
| 1 | **判决自认优先**——论证起点必须是判决自己已认定的事实 |
| 2 | **每个论断带出处等级**：A＝判决已认定 / B＝在案未认定 / C＝待调取。**禁止把 C 当 A 用** |
| 3 | **不预断、不虚构、不推断**——款项流向、主体归属一律开放式 / 择一表述 |
| 4 | **定性更正必须全库执行并留痕**——写明「前一版结论已作废」，并复查依赖它的推论 |
| 5 | **钱 > 期限 > 证据**——保全与上诉期优先于一切取证动作 |
| 6 | **情绪线与诉讼主线分离**——投诉、追责另立文件 |
| 7 | **输出脱敏**——身份证号、手机号、住址、账号留占位符 |
| 8 | **不替代程序资格判断**——新证据、二审增诉请、当事人能否作证，一律显式核查 |

## 五、边界

- 本技能产出的是**工作稿与结构**，不是法律意见；**所有法条条号须由使用人递交前核对**，技能内一律标注「递交前核对条号」。
- 不替代律师，也不替代法院对程序问题的判断。期限、金额、递交渠道以受理法院的现行规定与通知为准。
- 本件的脚本与流程离线自包含：不联网、不依赖外部仓库、不调用任何 API。§二 末那两条通道是使用人另装的可选辅助，只在素材解析与线索检索两处帮忙；是否开通、能否取到、如何计费以服务端返回为准，本件不承诺任何未开放的域与结果。
- 涉及具体条号与期限的地方，技能刻意使用**描述性表述**而非硬编码条号——模型记错条号的风险由「递交前核对」这道闸门兜住。
- **预期管理**：二审改判、发回重审的比例历来不高，**本件不赌翻案**。它只把可控的部分做完——重新框争点、取回被截断的、看住钱和期限。裁判结果不由本件决定；把四个动词做完，你手里得到的是**一套有出处的表、一份能递交的上诉状、一张倒排到死线的日历**，本件的承诺到此为止。

### 防二次收割：三道警

败诉之后最容易被再收一次钱、再误一次事，三条逐个自查：

1. **解冻与转移的迹象**：一审驳回后，对方可能申请解除保全并转移财产。出现这类迹象，第一反应是《继续保全申请书》与保全届满日，不是先写上诉状——这就是硬约束 5「钱 > 期限 > 证据」的用处。
2. **「包赢」代理与来路不明的模板**：宣称包赢、包翻案的代理，以及不看你卷宗就发来的「二审改判模板」，一律按风险处理。本件要求每个论断带出处与等级（硬约束 2）；一份不基于你的在案材料生成的文书，递上去只会多一处要更正的定性（硬约束 4）。
3. **自媒体的法律答案**：短视频与帖子里的「二审就这么写」，不核对法条原文与现行有效版本就不使用。检索得到的候选一律先挂 C 级、标「待以官方来源核对」，递交入卷后方可升 B（§二 检索桥同一套纪律）。

### 最小外包：单点付费，不是重回全委托

默认**由你指挥**。两种情形值得再掏一次钱：标的金额大；或程序资格存疑——是否算二审新证据、能否增加诉请、当事人能否作证，这类问题硬约束 8 不许本件替你判断。

做法是**一次要点核验**，不是重新委托：带上 `事实台账.md` 与 `复核报告.md` 的『序：一句话结论』『二、扭转路径』两节，把要问的写成三个具体问题，请人只核这三点；核完仍由你更正、由你递交。外部意见同样标注为待核，不直接顶替你的事实等级。

## 六、依赖

- `python3`（`scripts/init_case.py` 用，标准库，无第三方包、无网络请求）
- `python-docx`（**可选**，仅 `scripts/export_docx.py` 导出 Word 递交稿时需要）：`python -m pip install python-docx -i https://pypi.tuna.tsinghua.edu.cn/simple`。不装只是不能出 docx，其余流程不受影响；脚本缺少该依赖时会明确报安装命令，不做静默降级。
- 除上面两条**可选**辅助（`cue-omni-reader` 解析素材、`cue-research` 列法条与类案候选）外无其他依赖：不装不报错，用前先经使用人确认；判决书与材料由使用人提供，素材进不来时见 §二 末「素材与线索的两条通道」。
