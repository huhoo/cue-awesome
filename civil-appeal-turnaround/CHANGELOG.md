# CHANGELOG（civil-appeal-turnaround）

### 0.1.0

首次发布。把一份败诉判决加一堆零散材料，工程化地转成一套可直接递交的二审作战体系。

**六个方法**

- **判决逆向工程**：还原「本院认定 → 本院认为 → 条文适用 → 结论」的推导链，找跳跃最大的一步；框架层判据为「按此框架举证，所需证据是否全在对方单方控制之下」。附 20 项拆解清单。
- **证据逐字比对**：截断 / 省略 / 割裂三类差异的识别与表述模板；截断的实操找法为「回原文读判决最后一个省略号后面紧跟着的 1–3 句」；关键词出现次数法（原告诉称 vs 本院认为）。
- **责任归属阶梯**：主攻 / 备位 / 需新证据 / 兜底四层；硬判据为前两层不依赖任何新证据。附四种案型范式与表见代理三要件写法。
- **事实台账与出处等级**：A（判决已认定）/ B（在案未认定）/ C（待调取），禁止把 C 当 A 用。
- **定性更正机制**：确认 → 全库检索 → 逐处更正 → 留痕「前一版作废」→ 更新红线 → 复查连带论证。
- **自行诉讼操作**：上诉状递**原审法院**而非二审法院；当事人（含第三人）不能作证人，正确路径是「传唤到庭接受询问」；二审增诉请走不通，时机在发回重审后。

**八条硬约束**：判决自认优先 / 出处等级 / 不预断 / 定性更正全库留痕 / 钱 > 期限 > 证据 / 情绪线分离 / 输出脱敏 / 程序资格显式核查。

**交付物**：主控清单、复核报告、上诉状（含总述）、配套文书包、四张表。

**资源**：`references/` 六份方法文档 + 一份脱敏实例；`assets/` 四张表模板；`scripts/init_case.py`（标准库，零网络，不覆盖已存在文件）。

**来源**：提炼自一起真实民事一审败诉案件的完整复盘（已脱敏，见 `references/07-worked-example.md`）。
