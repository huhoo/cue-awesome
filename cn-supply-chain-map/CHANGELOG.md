# 更新日志

### 0.1.0 — 2026-11-09（首版：产业链上下游图谱，六节契约 + 五道机检）

- 本件做什么：把「这条链上有哪些环节、各环节有谁」变成「一张每条都能回到一处带检索日来源的结构图」。上游／中游／下游三层，每行环节行点名一家代表公司并写它在链条里的位置，行末挂 `[S#]`，第六节逐条给 URL 与检索日；没查到的环节逐条写「未取到」，不补常识。
- 与 `sector-overview` 的分界（本件存在的理由）：那一件做**行业景气全景**——一个行业的量价、产能、格局与趋势；本件做**链条结构**——谁在哪个环节、上下游关系是什么。本件不判景气、不判好坏、不选股。头部那行 `链条口径：` 是这条分界的机检入口：写成「景气」由道五点名改走那一件，写个认不出的值由道一发红。
- 环节行形制（本件的要害）：`- 环节：<环节名>｜代表公司：<公司名>（<在链条里的位置>）[S#]`。三字段缺一不可——只列环节不点公司是环节表不是图谱，点了公司不写位置是名单不是图谱。没查到的环节写成 `- 环节：<环节名>｜代表公司：未取到 [S#]`，这一形不要求位置括号（没有公司就没有位置），但必须同时出现在第五节。
- 五道机检（`scripts/check_chain.py`，零网络、纯标准库）：
  - 道一 `E-FORMAT` 形制：六节齐且有序；头部四件自标逐字在位；`链条口径：` 行在场且值为结构口径；链条一句话非空非占位；三层各至少一行环节行；每行环节行三字段齐（缺环节名／缺代表公司／缺位置括号／位置括号为空，四形各发一条）。
  - 道二 `E-ANCHOR` 锚：环节行行末一个 `[S#]`；该编号在第六节有对应行；来源行同时带 URL 与检索日 `YYYY-MM-DD`。
  - 道三 `E-BANWORD` 红线：评级／目标价／建仓清仓／必涨必跌／稳赚无风险／跑赢大盘／严重低估严重高估一类断言零命中；**另加本域推荐词族**——受益标的／受益股／核心标的／弹性标的／首选标的／龙头／潜力股／值得关注／建议关注／重点推荐／推荐关注／布局良机／上车，一律零命中；改数词（约／左右／大概）不得替数字打底。要写只能同行挂 `[待人工]`。
  - 道四 `E-COVERAGE` 未取到两向点名：正文写了未取到而第五节没列发红，第五节列了而正文没有这条表述同样发红；两向都按**名目同指**对（剥括号注与标点后，字面全等／一方完整含另一方且短的一方 ≥4 字／汉字集合重合率 ≥0.6），同一件事换个写法不判红。
  - 道五 `E-SCOPE` 边界：`链条口径：` 写成「景气」时点名改走 `sector-overview`，不是只报形制错。
- 红线里那条收窄（写进件内，防后人放宽）：**裸「受益」不收**——「受益于硅料降价」是因果陈述，不是推荐；只收「受益标的／受益股」这种把公司当推荐对象的形。裸「关注」不收，只收「值得关注／建议关注／推荐关注」。runner 档⑤ 的「事实陈述不误红」与「推荐词必红」成对钉住这个收窄的两个方向。
- 零通道那一头：`scripts/make_outline.py` 把材料清单排成一张待填骨架，三层各留一行「代表公司：未取到」的待填位，第五节逐条点名，链条一句话留占位。**代价同句写清**：缺的正是公告检索与原文解析那一层，所以骨架只会有形状、不会有权衡后的链条结构——骨架过不了机检是设计，不是待补的疏漏。材料清单里非法 JSON 行、缺键行、日期不合形的行一律未采信并逐行点名，不静默跳行；一条可用行都没有时退 1。
- 离线 runner（`scripts/fixtures/run_fixtures.sh`，零网络、零计费、产物只落临时目录跑完即删）五档：① 机检自测（好样 1 枚 + 坏样六道 6/6 + 钉阈三形 + 反证四档 + 本域两形 + 临时根自清）② 好样与六枚坏样逐枚单跑，每枚报它自己的退码与码集，不并成一个总数 ③ 零通道骨架 ④ 骨架过机检须红在链条一句话占位那一行 ⑤ 边界形逐枚单跑（口径写景气→道五点名／口径值认不出→形制红／推荐词必红／事实陈述不误红／改数词必红／「代表公司：未取到」这一形不误红）。末行自报「档数=5｜不合=N｜不可判=N」；退码 0 全合期望、1 有不合、3 取值域故障（脚本或夹具取不到，不读成「零违例」）。
- 工件名：`consumes: industry-material-pack`（在册 canonical，由 `sector-overview` 产出，故本件入度 ≥1）；`inputs: announcement-doc`（在册 inputs 族，写进包面 `inputs:` 键，不参与算边）；`produces: industry-material-pack`（在册 canonical；产方有、消方无，图上留空是诚实的）。未新增任何工件名，未改 `artifact-types.yaml`。
- 通道与降级：主路＝公告与年报的定位（数据腿 `cue-data-mcp`）＋长附件与 PDF 的正文取回（解析腿 `cue-omni-reader`）；降级＝零通道骨架。三层自查照仓内既有面写：**装好 skill ≠ 已配凭据 ≠ 通道已连**。本件不发请求、不代付费，消耗以服务端返回为准。
- 未做（写在这里防后人误读）：不判行业景气与量价格局（走 `sector-overview`）；不判链条上哪一环更赚钱、哪家公司更强；不做估值建模与财务预测；不选股、不给评级与目标价；不持久存用户文件；不发布、不代下结论。
