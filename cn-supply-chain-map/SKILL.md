# 产业链上下游图谱·逐条挂源

**给一个行业或一家公司，产出六节产业链图谱：上游／中游／下游三层，每个环节点名代表公司与其在链条里的位置，每条挂 `[S#]` 与来源；链条上没查到的环节逐条写「未取到」，不补常识。**

要点不稀缺，**稀缺的是「谁在哪个环节」这句话能回到一处带检索日的来源**。差异化不在排版，而在两道硬门禁：没有位置括号的公司进不了环节行，没点名的缺口过不了机检。

**输入**：一个行业或一家公司 ＋ 一批材料（公告／年报／行业材料包／新闻），或一个待查问题
**输出**：六节图谱（链条一句话／上游／中游／下游／未取到与口径／来源）
**代价**：六节契约 + 一道机检；通道腿（公告检索／原文解析）开没开，决定的是「代表公司与其位置」那一层——两条路各自缺什么、走哪条，写在 README §二 与 §四
**机检**：`scripts/check_chain.py` 五道（形制／锚／红线／未取到两向点名／边界），零网络；反证矩阵长在这支脚本里

**它和 `sector-overview` 不是一件事（这一句是本件存在的理由）**：那一件做**行业景气全景**——一个行业的量价、产能、格局与趋势；本件做**链条结构**——谁在哪个环节、上下游关系是什么。本件**不判景气、不判好坏、不选股**。头部那行「链条口径：」就是这条分界的机检入口——写成「景气」会被点名改走那一件。

## 一、六节契约

| 节 | 内容 | 硬要求 |
|---|---|---|
| 一、链条一句话 | 这条链从哪起、经哪几段、到哪终 | 至少一行实句，不留占位 |
| 二、上游 | 原材料／零部件／设备 | 至少一行环节行 |
| 三、中游 | 制造／集成 | 至少一行环节行 |
| 四、下游 | 渠道／终端 | 至少一行环节行 |
| 五、未取到与口径 | 逐条点名没查到的环节与公司；口径差异 | 与正文两向对齐 |
| 六、来源 | 每条来源一行，带 URL 与检索日 | 编号与正文锚一一对应 |

**头部四件自标**（写在第一个 `## ` 之前，逐字在位）：`AI 整理初稿`、`请回原文核对`、`不构成投资建议`、`判断位 [待人工]`。

**头部「链条口径：」行**：以「结构」起头，如 `链条口径：结构（谁在哪个环节、上下游关系；不判景气、不判好坏）`。写成「景气」由道五点名改走 `sector-overview`；写个认不出的值由道一发红。

## 二、环节行的形制（本件的要害）

```
- 环节：<环节名>｜代表公司：<公司名>（<在链条里的位置>）[S#]
```

三字段缺一不可：

- **环节名**：这一环叫什么（`多晶硅料`、`电池片`、`集中式电站`）；
- **代表公司**：这一环上点名的一家公司；
- **位置括号**：它在链条里的位置（`硅料产能位于链首，向下自供硅片`）。

**只列环节不点公司是环节表，不是图谱；点了公司不写位置是名单，不是图谱。** 位置括号是本件与「公司名单」的分界，机检按形制发红。

**没查到的环节**写成这一形：

```
- 环节：<环节名>｜代表公司：未取到 [S#]
```

这一形不要求位置括号（没有公司就没有位置），但它**必须同时出现在第五节**——两向点名照旧。

## 三、五道机检

`python3 -B scripts/check_chain.py <图谱.md>`，零网络、纯标准库。

| 码 | 道 | 判什么 |
|---|---|---|
| `E-FORMAT` | 道一 形制 | 头部四件自标逐字在位；「链条口径：」行在场且值为结构口径；六节齐且按一至六有序；链条一句话非空非占位；三层各至少一行环节行；每行环节行三字段齐（缺环节名／缺代表公司／缺位置括号／位置括号为空，四形各发一条） |
| `E-ANCHOR` | 道二 锚 | 环节行行末带 `[S#]`，且该编号在第六节有对应行；第六节每行必须同时带 URL 与 `YYYY-MM-DD` 检索日 |
| `E-BANWORD` | 道三 红线 | 评级／目标价／买卖与走势类断言零命中；**另加本域推荐词族**——受益标的／受益股／核心标的／弹性标的／首选标的／龙头／潜力股／值得关注／建议关注／重点推荐／推荐关注／布局良机／上车，一律零命中；改数词（约／左右／大概）不得替数字打底。要写只能同行挂 `[待人工]` |
| `E-COVERAGE` | 道四 未取到与计数 | 正文写了「未取到」的，第五节必须逐条点名它；第五节列了而正文没有这条表述的同样发。两向都按**名目同指**对（剥括号注与标点后，字面全等／一方完整含另一方且短的一方 ≥4 字／汉字集合重合率 ≥0.6） |
| `E-SCOPE` | 道五 边界 | 「链条口径：」写成「景气」时点名改走 `sector-overview`，不是只报形制错 |

**红线里那条收窄（写进件内，防后人放宽）**：裸「受益」不收——「受益于硅料降价」是因果陈述，不是推荐；只收「受益标的／受益股」这种把公司当推荐对象的形。裸「关注」不收，只收「值得关注／建议关注／推荐关注」。runner 档⑤ 的「事实陈述不误红」与「推荐词必红」成对钉住这个收窄的两个方向。

## 四、零通道骨架

`python3 -B scripts/make_outline.py --sources 材料.jsonl --out 我的骨架.md` 把材料清单排成一张待填骨架：三层各留一行「代表公司：未取到」的待填位，第五节逐条点名，链条一句话留占位。

**代价同句写清**：缺的正是公告检索与原文解析那一层，所以骨架只会有形状、不会有权衡后的链条结构——骨架过不了机检是设计，不是待补的疏漏。材料清单里非法 JSON 行、缺键行、日期不合形的行一律未采信并逐行点名，不静默跳行；一条可用行都没有时退 1。

## 五、边界与不承诺

- 不判景气、不判好坏、不选股：行业量价与格局走 `sector-overview`；评级、目标价、买卖与时机建议一律 `[待人工]`；
- 未检索到＝照实写「未检索到」，禁以行业惯例补写，也不写「无该项」顶替；
- 单一来源的场景不要用本件——那是一篇转述；多源互校才是它的用途；
- 域与工具名以 live catalog 现值为准，本件不列固定清单、不承诺枚数，也不承诺该域是否开放与文件的实时性。
