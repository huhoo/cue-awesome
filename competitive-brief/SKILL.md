# competitive-brief

> 给一个决策问题和竞品清单，还一份带证据链的对比简报。

## 这是干什么的

你在做一个决策——进不进这个市场、跟不跟这家竞品、定什么价、差异化打哪——需要知道对手在做什么，也需要知道自己凭什么判断。

这个技能把两件事分开：**取证归取证，判断归判断**。取证靠 omni-reader 收来源、cue-research 做交叉验证；判断在交付时逐条标清楚 confidence，不替用户做决策，但让用户能基于证据做决策。

## 怎么用

```
+brief "我们要不要进入北美中小律所的合规工具市场"
  → 先问清楚决策是什么、要看谁、到什么程度
  → 开收素材 + cue 深研
  → 出简报
```

也可以从中间开始：

```
"帮我对标一下这几家的定价"            → 定位 + 定价对比
"补一下竞品A最近的融资和团队变化"       → cue 深研指定维度
"核一遍这些结论，哪条证据不够"          → 校验
```

## 四层结构，不是七个阶段

跟流水线式的阶段不同，这里只有四层。每层可以独立起手，也可以按需跳过：

```
         ┌───────────┐
         │ ①界定问题  │  ← 必须，定锚
         └─────┬─────┘
         ┌─────▼─────┐
         │ ②采集证据  │  ← omni-reader + cue-research
         └─────┬─────┘
         ┌─────▼─────┐
         │ ③判断置信  │  ← 标 confidence，分层
         └─────┬─────┘
         ┌─────▼─────┐
         │ ④交付简报  │  ← 结论 + 追溯
         └───────────┘
```

### ① 界定问题

一次对话定锚。不需要分批次问，就三个问题：

1. **做什么决策？** 不是「了解竞品」，是「判断要不要进入这个市场」/「决定下季度功能优先级」/「评估是否跟进调价」。写不出决策的，不做。
2. **看谁？** 竞品列表 + 排除清单。3 家专注，5 家是上限——超过 5 家说明问题还没收窄。
3. **什么程度？** 全景扫描（2h 出稿） / 标准对比（半天） / 深度（研报级，跨源交叉验证）

这三个问题决定后面的所有取舍。**没定之前不收素材。**

### ② 采集证据

按来源类型走对应的取证通道。不需要统一叫 intake，也不需要定义什么优先级矩阵，就一句话：**按决策问题找能回答的证据。**

| 来源类型 | 怎么取 | 谁 |
|---|---|---|
| 网页（产品页、定价、博客、帮助文档） | omni-reader `parse(url)` | omni |
| 扫描件/文字层 PDF（年报、白皮书、技术规格） | omni-reader `parse(local_path)` | omni |
| 录音/视频（财报电话会、产品演示、播客） | omni-reader `parse(local_path)` 音频/视频通道 | omni |
| 非公开信息（融资估值、团队背景、客户口碑、竞品动态） | cue-research 深研，优先搭子 | cue |
| 需交叉验证的判断（市场份额、法规影响、方案对比） | cue-research 核验搭子 | cue |
| App Store / G2 / SimilarWeb 等结构化数据 | 直接读取 | — |

**关于 omni-reader 和 cue-research 会不会计费**：会，跑之前报预估值，用户确认再跑。不装也能做，但少了扫描件/音视频的取证覆盖和跨源交叉验证。用户不要 → 退回纯网页 + 人工补录，交付时写清楚缺了什么。

**取证不是赛道**——不需要竞品一家一家全跑完再下一个阶段。哪个来源能最快回答决策问题就先取哪个。明显跟决策无关的维度（比如比上市公司的财报电话会议记录，但你的决策只是工具选型），跳过。

### ③ 判断置信

每条进入简报的结论性语句标三个属性：

```
分层：fact / inference / opinion
来源：具体到 URL + 发布日期
可信度：一手 / 二手 / 待验证
```

| 标注 | 含义 | 例子 |
|---|---|---|
| **fact** | 可从原始来源直接证实 | 「定价 $99/月 → 官网 2026-09-01」 |
| **inference** | 从多个 fact 推导的合理结论 | 「高价+企业案例结合暗示目标客群是 enterprise」 |
| **opinion** | 作者判断，无直接引用 | 「这个交互比竞品好」 |

**事实就是事实，推断就是推断。** 把 inference 写成 fact 是最常见的简报问题——凑起来都对，但每一条差一点，整体判断就偏了。

不在最终结论页放没有来源的数字。不是必须每句话都标，但结论性判断必须可追溯。

### ④ 交付简报

不是一个阶段的产物，是整个过程中**随时可出的中间态**。

- **素材阶段就能出**「目前看到的对比」——标清楚哪些维度还没覆盖到
- **判断阶段出**「竞品对比 + 标注 confidence」
- **最终交付**在结论之外另附一页：我们没看什么、什么没验证、什么需要用户自己确认

## tools/ 目录

可选辅助脚本，不绑定执行流：

```
tools/build_brief.py     — 从证据包 → 简报（markdown / html）
tools/crosscheck.py      — 对照 evidence/index.csv 标出无源 claim
tools/export_pdf.py      — HTML → PDF
```

缺了不影响核心价值。核心价值是**界定问题 → 取证 → 标 confidence → 给结论**这个思考流程。

## 几条约束

1. **先定决策再动手。** 用户说不清决策 → 先帮用户理清。理不清的，不做。
2. **claim 可追溯。** 进简报的判断性语句必须能找到来源。找不到的就标 opinion，不藏。
3. **不说自己不知道的。** 竞品私有路线图、成交价、登录后功能——公开拿不到就写「未获取」，不编、不推。
4. **计费先说。** omni-reader 和 cue-research 计费，跑之前报预估，用户确认再执行。
5. **交付附反思。** 最后给一段：这份简报覆盖了什么、没覆盖什么、什么维度用户应该自己去验证（如内部销售数据、客户访谈）。让用户拿着这份简报，知道自己还需要做什么。
