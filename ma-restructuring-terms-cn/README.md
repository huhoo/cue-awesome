# ma-restructuring-terms-cn

**给一份 A 股并购重组披露文件，产出八项逐字卡：交易概况与方式、交易对方与关联关系、标的资产与权属、定价方法与交易对价、支付方式与股份发行、业绩承诺与补偿安排、锁定期与减持限制、审批程序与披露义务，每项挂原句＋来源锚；划不划算、估值高不高、能不能过会一律 `[待人工]`。**

它只管一笔重组交易的条款怎么写：**哪天停复牌、哪个审核节点**这类事件日期在 `catalyst-calendar`，一家公司**有没有并购史、控制权与同业竞争**这类风险事实表在 `dd-checklist`（用途档位选并购档），公告清单在 `announcement-daily-cn`，可转债条款在 `convertible-bond-terms-cn`，定增与再融资在 `placement-terms-cn`。报告书与预案原文是唯一依据——**媒体解读与转手摘要都要标明层级**，这条界线是本件存在的理由。

## 一、打开就干：今天这三步

1. 给一份报告书、预案或相关公告：正文粘贴、披露页定位、摘要件都行；没写的那一项要求它写「未检索到」，不许按「重组一般都锁 36 个月」这类惯例补。
2. 读前两段：头部申报＋八项逐字速读——这两段只要文件到手就能出，不需要任何通道。
3. 盯三格数字：评估值与交易对价、发行价格与发行数量、承诺净利润与补偿安排必须落在**该项自己的原句**里，且机检先把原句**切成短语、以结构体为主定性**（每枚数只在自己那条短语里找所有者：跳过「每股」「合计」这类单位后最近的实义名词属本格族才算、属账面值·净资产·市盈率·已实现净利润这类参照数即剔，哪怕同一短语别处写了本格名词；短语两头都空才继承前序最近一次的本格名词，前序只出现过参照数就不继承；每格的两个元素各自要有落点——num 元素要有数、term 元素（补偿安排）要有安排用词——「评估值 86,000 万元、交易对价待定」仍算缺，只有同短语内「即为·为·是·等于·均为·都是」这类**肯定**系词把两个名词共指到同一枚数时才算两要素齐备（「评估值即为交易对价 86,000 万元」），带否定形的「评估值不是交易对价 86,000 万元」不算共指、照发；共指只认**系词式**，「评估值与交易对价均为 86,000 万元」这类**同位式**机检不识别、照发（已知覆盖不到，人工回原句核对）；补偿安排那一支按用词认，但用词与「待定·另行约定·届时」同句时不算读到——「补偿金额待定但未达标以股份补偿」这种同段共存式也按未定判、照发，分号或句号切开后（「补偿金额待定；未达标以股份补偿」）读得到）——「以评估机构报告为准」「另行协商确定」「届时披露」不算数，「账面价值 32,000 万元」「经审计净资产 41,000 万元」「可比公司市盈率 18.5 倍」「发行前总股本 54,000 万股」「已实现净利润 4,200 万元」「审计值 40,000 万元」是参照数不算数，「评估基准日为 2025 年 12 月 31 日」是日期不算数；遇到了就让它进缺数清单。

## 二、五道机检（零网络）

产物交给 `scripts/check_ma_card.py` 过闸：五段齐＋八项名目行级在场（每枚名目须占一行，散文里提到不算）／每项原句与锚（书名号内空或只剩一个字算缺原句，「锚：」后面空着也发）／红线断言三道（定式禁词、「主题词＋判断语气同段」、「裁定前缀＋效力判断」，只准出现在 `[待人工]` 或明写不接的那一**分句**里——标记与免责句都不跨句：「[待人工] 估值是否合理留人工；本次交易必能过会」后半句照发，「本件不判估值高低；授予…一定能过会」同形；定式表另按词族收评价与预测——「估值很合理」「作价基本公允」与「估值合理」同判（插语不构成豁免），「获批概率大」「过会可能性极低」与「必能过会」同判；评价词族只写一份排除——评价词后接「性·度·论」任一名词后缀（合理性·公允性·充分性·合理度…）都是被说明的对象、不是本件的断言，定式表与主题×语气共用同表同放；「X 会」机构名与「会 X」名词（会计·会议·会员…）里的「会」先从语气域洗掉）／齐缺申报恰一枚且与未检索到行数对账（两处互相矛盾的申报同样发）／三格数字以短语结构体为主判（拆字段取该项原句、先剥日期，再按「标点 ∪ 数字边界」切成短语表：每枚候选只在自己那条短语里定档——数左跳过单位取最近实义名词、数左空着看数右、两头都空＝孤立数才继承前序最近一次的本格名词且前序只出现过参照数时不继承；金额·股数·倍数·百分比同走此判）：每格两要素各自要有合格候选，缺任一枚又没写未检索到才发——别格的数、参照数与日期都不顶账）

```bash
python3 scripts/check_ma_card.py --help                          # 参数说明
python3 scripts/check_ma_card.py --selftest                       # 好样须过、坏样五道齐发、钉阈按整族各钉一档、对照样不误伤、临时件自清（枚数由自测自报）
python3 scripts/check_ma_card.py scripts/fixtures/good-ma-card.md     # PASS（发条 0 条）
python3 scripts/check_ma_card.py scripts/fixtures/bad-ma-card.md      # FAIL（五道各发，逐条点名行号）
```

## 四、首次开通 Cue（三步，可跳过）

本件的取证腿有两条：**原文取数**（找报告书、预案与配套公告原文，走数据腿）与**附件解析**（重组报告书常达上百页，评估与审计说明、标的财务报表多在附件里，走解析腿）。两条都是可选——不装也能按你直供的文件出卡；代价是附件里的评估说明与承诺补偿细则只能停在「未检索到」，报告书与预案的层级对照也没法自动补，要你人工回原文核。

1. 注册 <https://cuecue.cn>；
2. 在 <https://cuecue.cn/hub/api-key> 取 `CUE_API_KEY` 存入本地凭据——**不要贴进聊天**，agent 不经手密钥；
3. 装这两枚：`cue-data-mcp` 走原文取数腿，`cue-omni-reader` 走附件解析腿。一条命令两种写法：
   - 整套：`npx skills add sensedeal/cue-skills`（它会列出该集合公开的各枚 skill，按提示挑要装的）；
   - 单装：`npx skills add sensedeal/cue-skills --skill cue-data-mcp`（把末尾那枚名字换成 `cue-omni-reader` 就只装那一枚）。

配置指路同样只给指针、不复述开通步骤：找原文走数据腿，官方配置页 <https://cuecue.cn/hub/mcp>；长附件与 PDF 走解析腿，官方配置页 <https://cuecue.cn/hub/omni-reader>；取 key 走 <https://cuecue.cn/hub/api-key>。

### 连通自查（各条腿能证到哪一层）

```bash
# 1) 目录可达（匿名）：只证 catalog 能读，不叫「已连」
curl -s "https://cuecue.cn/api/mcp-catalog" | head -c 200

# 2) 域路由现值：从返回里取该域的 routing.url 与 transport，别把域名抄死
# 3) 带 key 实连后发 tools/list——只证该数据腿端点被接受，不证别的入口
curl -s -X POST "$ROUTING_URL" -H "Authorization: Bearer $CUE_API_KEY" \
  -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | head -c 400
```

装好 skill ≠ 已配凭据 ≠ 数据腿已连：这一层的判据只管数据腿那一路——带 key 按目标域 `routing` 实连且该端 `tools/list` 有返回，才证那把 key 被接受，也只证数据腿连上；解析腿的连通另按它自己那面的判据读。

## 五、边界与不承诺

- 交易是否划算、估值是否合理、能否通过交易所审核与证监会注册、复牌后股价、摊薄与稀释影响、业绩承诺能否达成一律 `[待人工]`；不出「建议参与」「稳赚」「零风险」「保证收益」「必能过会」「估值合理」；
- 不判效力：本次交易是否有效、程序是否违规、申请文件是否成立，属人工与监管认定位——写出这类自裁断语会被机检发红；
- 不接代办：不出申报文书、不代客申报或投票、不代做重组方案，也不提供任何绕开审批、规避披露或打探内幕信息的路径；
- 三格数字逐字：「以…为准」「另行协商确定」「届时披露」「账面价值」「经审计净资产」「审计值」「市盈率」「发行前总股本」「已实现净利润」都不算本格原值，没取到就写「未检索到」；每格的两个元素各自要有落点——num 元素要有数、term 元素（补偿安排）要有它自己的安排用词，只给一枚不算这格取到；
- 数字归属有射程：机检判的是同一短语内的相邻关系加一次跨短语继承，不声称覆盖所有自然语言的归属表达；省略主语指谁这类整句语义留人工回原句核对，判不到又确实没写就走「未检索到」——它是合法答案；
- 未检索到＝照实写「未检索到」，禁以同类交易的惯例补写，也不写「无该项」顶替；
- 域与工具名以 live catalog 现值为准，本件不列固定清单、不承诺枚数，也不承诺该域是否开放与文件的实时性。

## 六、出错了怎么办

| 症状 | 来路 | 恢复动作 |
|---|---|---|
| 好几项是「未检索到」 | 文件是预案或摘要件，评估说明与承诺细则在附件里 | 起附件解析腿补原句；起不动就保留缺数点名，不补写 |
| 数据腿连不上 | 凭据缺位或该域未 live | 按 §四 自查；前两段仍可出，代价见 §四 那一句 |
| 机检发红 | 缺锚／缺原句／三格里没落定的数／齐缺不符／写了判断句 | 按逐条点名的行号补齐；补不出的进缺数清单，不删行凑数 |
| 判断句被误红 | 那行写的是「股东大会」「董事会」「审计委员会」这类机构名，或引用报告书原句 | 原句留在书名号内、锚照常挂；机检把「X 会」这类机构名 token 整体洗掉再判语气，正常登记句不误红 |
| 本格数被判成参照数 | 一句里先写了账面值或净资产、本格名词在更左 | 把该格的数与本格名词写进同一句（照报告书原句即可），或该项确未取到就写「未检索到」 |
| 报告书与预案说法不一致 | 预案到报告书之间常有调整 | 两句原句并列进「口径对照」，各挂各锚，不做取舍判断 |

## 七、怎么开口（正例与反例）

- 正例：「这笔重组的交易对价是多少、怎么定的」「发行价格和发行数量」「交易对方是谁、算不算关联交易」「标的是什么资产、权属有没有瑕疵」「业绩承诺承诺了多少、没达成怎么补偿」「股份锁多久、什么情况下能解禁」「这次交易要走哪些审批、要不要豁免要约」。
- 反例：「这笔并购划不划算」「估值贵不贵」「能不能过会」「复牌后股价怎么走」「摊薄多少」——划算与否、估值高低、成败预测与市场反应不在本件，一律 `[待人工]`。

## 八、能力边界（诚实清单）

行情与资金流类数值不在本件能力内（该域以 live catalog 现值为准，未开放就不承诺）；本件不做估值与会计测算（评估是否合理、商誉与合并对价分摊由评估机构、会计师与披露文件定）；不判断交易动机、利益输送嫌疑与内幕信息可能；不做要约收购的合规操作指引，只逐字登记报告书怎么写；也不持久存你的文件，卡出完就交还给你。
