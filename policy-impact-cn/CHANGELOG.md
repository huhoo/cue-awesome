# 更新日志

### 0.1.0 — 2026-11-02（本枚首次建包：政策文件的要点逐字卡与受影响环节候选链，两条取证腿与四道机检随包）
- 选题来路：清单级速览（`announcement-daily-cn`）与单份方案条款拆解（`placement-terms-cn`）之后，剩下那一问是「一份政策文件字面上牵动哪些环节」。仓内相邻三件各管一层、都不重叠：一家公司的处罚与监管措施底稿在 `event-risk-scan`，行业面综述在 `sector-overview`，已披露日期入表在 `catalyst-calendar`；「政策原文逐字＋环节候选链＋每级挂一句原文依据」这一层本仓没有对应件，本枚补这一层，分工四处写在 `SKILL.md` 的定位句、`README.md` 的导语与能力边界那两节、`README.en.md` 同形两处。
- 产出契约（政策卡五段，缺一即退回）：头部申报（文件名与机关／文号／成文·印发·生效三格日期／候选链条数申报／本次是否发起过解析腿）→ 政策要点逐字（形制＝`- 要点：原句逐字 锚：<来源定位>`）→ 受影响环节候选链（形制＝`- 环节链：环节A → 环节B → 环节C 依据：「政策原文一句」 锚：<来源定位>`）→ 时间与窗口表（生效日、过渡期、申报窗各占一行、各挂各锚，没写的格子写「未检索到」）→ 缺数与待人工。原文在 `SKILL.md`「输出契约」那一节；三格日期与三格时间表的名目由随包机检逐判，缺哪一格也要占一行点名，不靠约定。
- 本枚最关键的一条口径：候选链每一级必须落地成政策原文里的一句依据——挂不住依据的那一级不进链，宁可链条剪短。链条末端不接投资结论、不接涨跌、不点名具体主体；解读、受益与受损判断、执行强度与落地节奏一律挂 `[待人工]`。这条既是红线也是机检：机检把书名号内的原文引用从红线断言里剥出来再判，所以「条文原句里有那个词」不会被当成「我们自己下了那个判断」。
- 两条取证腿：文件清单在数据腿上，正文与附件在解析腿上。两条都写成可选并各自带代价——不装也按用户直供的原文出卡，代价是依据句落在附件里时挂不上、链条只能剪短，时间与窗口表那三格也可能停在「未检索到」。指路只给指针、不复述开通步骤：数据腿官方配置页 <https://cuecue.cn/hub/mcp>；解析腿官方配置页 <https://cuecue.cn/hub/omni-reader>；取 key 走 <https://cuecue.cn/hub/api-key>；深研那枚 `cue-research` 是独立入口（自带运行脚本）；它的凭据同那把 key，取 key 走 <https://cuecue.cn/hub/api-key>。域与工具名以 live catalog 现值为准，三面不列固定清单、不承诺枚数与政策文本的实时性。
- 名形制：`displayName` 取「政策影响链」＝意图词落在词首＋名短；目录名与 frontmatter `name` 同值 `policy-impact-cn`，`slug` 为 `cue-policy-impact-cn`，`SKILL.md` 的 H1 随 displayName 走同一短形。
- 随包机检：`scripts/check_chain.py` 四道——五段齐与名目在场、每级依据与锚、红线断言只准出现在 `[待人工]` 行、候选链条数与申报对账；零网络。`--selftest` 直接吃 `scripts/fixtures/` 那两份样例（好样须过、坏样四道齐发并逐条点名行号），另含剥锚、剥依据、把链条数申报改歪三档反证，各判各的道；两份样例里的文件、机关与文号均为虚构示例，不当作任何真实政策文本的引用。临时件建在一次性目录里、退出时自清。
- 首测：本枚建包当拍各闸的读数与出包 digest 以各闸自报行为准，本条不复写。
