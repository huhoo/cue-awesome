### 0.1.1 — 2026-11-09（修一处影响全站的渠道曝光缺陷：envVars 里的 description 撞了顶层 description）
- 缺陷与它的证据：skillhub 的 frontmatter 解析器是逐行 `key: value`（只认行首键名、不认缩进层级）。本包 `metadata.openclaw.envVars[].description`（缩进八格的凭据说明）被当成顶层 `description` 并**后写覆盖先写**，于是平台上本包的 `description_zh` 变成「可选凭据：缺位时本件按面文所述走用户直供与降级路径……」——一句与业务无关的话。搜索相关度正是靠这个字段，实测本包在真实用户会搜的短词上排到 15 位之外（全名可排第 1）。
- 修法：把嵌套那枚键改名 `desc:`（语义不变、仍给人读），**业务描述一个字未动**；同批 43 枚件同形修正。探针加一格判据，按渠道自己的解析器判，不再回退。
- 本版不改任何能力：八项名目、五道机检、两条取证腿、红线与边界全部照 0.1.0。

### 0.1.0 — 2026-11-08（本枚首次建包：A股员工持股计划草案的八项条款逐字卡，两条取证腿、五道机检与中英双技能面随包）
- 选题来路与它的弱处（写在顶条不藏）：套件里没有把**一份员工持股计划草案读成条款卡**的交付形状。撞题核全包现读（逐词命中文件枚数，含 .md∥.py∥.yaml∥.json，**本包自身不计**）：员工持股 3 枚（`cn-earnings-note/references/data-channels.md` 的 `esop` 域一行、`catalyst-calendar/references/event-taxonomy.md` 的「届满/终止」事件行、`scripts/artifact-types.yaml` 的两行登记）、**持有人会议 0 枚、管理委员会 0 枚、受让价格 0 枚**、股票来源 5 枚（全在 `equity-incentive-plan-cn`，是激励计划的股票来源格）、锁定期 11 枚（`ma-restructuring-terms-cn` 6 枚＋`placement-terms-cn` 5 枚，都是别的域的期限格）、资金来源 1 枚（`event-brief-cn` 的样例卡里一行回购资金来源）——**持股语汇那三格（持有人会议·管理委员会·受让价格）全包没人写过**。上下文逐枚读过：`equity-incentive-plan-cn` 读的是激励对象、授予价格、行权与解除限售，规则来源是《上市公司股权激励管理办法》，与持股计划不是一件事；`cn-earnings-note` 的 `esop` 只是数据通道表里的一行域登记，不是交付形状；`catalyst-calendar` 只把「届满/终止」当事件行，不读条款；`ma-restructuring-terms-cn` 只在八项里判「交易对方是否关联方」，无持股条款。**限度照写**：本枚的选题依据是「套件里没有这个交付形状」与「真实公告里八项都能逐字取到」两条，不以任何名次、下载量或转化为承诺；首版能力只到「一份员工持股草案的八项条款读成逐字卡」。
- 切割句（写进 SKILL.md 与 README 的定位段，不只写在这里）：**员工持股计划走《关于上市公司实施员工持股计划试点的指导意见》，股权激励计划走《上市公司股权激励管理办法》，两者不是一件事**——规则来源不同、参加对象与定价口径不同、审议与披露程序不同。一份员工持股草案里不会出现「授予价格」「行权」「解除限售」这套激励语汇，一份激励草案里也不会出现「持有人会议」「管理委员会」「受让价格」这套持股语汇。所以**员工持股的条款在 `equity-incentive-plan-cn` 里读不到，激励计划的条款在本件里也读不到**；两枚包不互相覆盖，也不互为替代。同一家公司同一年既做激励又做持股时，是两份文件、两套规则、两张卡。**这一句是用户能不能分清两枚包的唯一依据，所以它必须在面文里，不能只躺在更新日志里。**
- 与其它几件的分工（切割句写进定位，只写在新增侧）：**哪天过户、哪个解锁窗口开闭**这类事件日期在 `catalyst-calendar`；自选清单里**这项计划推进到哪一步**的日增量在 `watchlist-digest-cn`；公告清单在 `announcement-daily-cn`；定增与再融资方案在 `placement-terms-cn`，可转债条款在 `convertible-bond-terms-cn`，关联交易公告与协议在 `related-party-terms-cn`；本件只管**一份员工持股草案的条款**。
- 产出契约（条款卡五段，缺一即退回）：头部申报（文件名与来路层级／八项齐缺申报／本次是否发起过解析腿）→ 八项逐字速读（形制＝`- 项名：原句逐字 锚：<来源定位>`）→ 口径对照（草案与摘要或实施公告两句并列、各挂各锚）→ 缺数清单 → 待人工。八项名目与每行的原句、锚由随包机检按行判，不靠约定。
- 八项名目（按真实公告的取数面定，不按教科书目录定）：计划名称与期次／参加对象与确定标准／资金来源／股票来源／受让价格与规模／存续期与锁定期／管理模式与持有人会议／变更终止与权益处置。
- **名目按「任一表述命中即算在场」认，不钉死单一措辞**（这一条是真实公告逼出来的，不是设计偏好）：四份语料实测——工业富联那份「受让价格」0 次、「购买价格」2 次；恒铭达那份「参加对象」0 次、「持有人」181 次；股票来源有的公司写「股份来源」。**章节标题的写法同样要认**：晶盛机电与恒铭达写「持有人的确定依据、范围及份额分配情况」，工业富联写「价格和规模」，宁德时代写「存续期、锁定期、考核设置」，四份都写「变更、终止及持有人权益的处置」——写卡人照抄章节标题当项名时，若别名表只收卡面叫法，真实公告会整项判缺。所以机检建 `ITEM_ALIASES` 别名表（含章节标题原样），`canon()` 把不同叫法归一到同一枚 canonical 名，行级在场、齐缺对账、缺项点名都按 canonical 名走。**别名只解决「这一项在不在」，不解决「这一项取没取到」**——取没取到仍按原句与锚判，这一句写进 SKILL.md 取数纪律第 3 条、README 边界段与 references 第一节。
- 本枚独有的一格：**两格数字归属**——资金来源与资金总额、受让价格与标的股票数量这两项，凡不写「未检索到」的，机检先把项行拆成字段、取该项自己的原句作判据域，剥掉日期（草案公布日、过户日、公告日一律剔除），按「标点 ∪ 数字边界」切成短语表，每枚候选只在自己那条短语里定档：本格名词族（受让价格·购买价格·标的股票数量·资金总额…）才算，参照数族（交易均价·收盘价·面值·每股净资产·股本总额·总股本·每份份额·授予价格·行权价格…）更靠数即剔，**哪怕同一短语别处写了本格名词**；**每格两元素各自要有落点**——受让价格要有元/股原值、标的股票数量要有股数原值，一枚合格候选只算它那一个要素到位；资金来源按用词认（自筹·合法薪酬·奖励基金·借款·法律法规允许的其他方式），但与「待定·另行确定·届时·协商确定」同句时只算还没定；比率与期限不参与归属（以 ％·%·倍 收尾的候选不结算任何元素，被比率词紧领的金额同样不结算）。
- **名词族按真实公告的写法收，不按教科书叫法收**（五份语料逐句实测出来的三处真漏，不是设计偏好）：数量那一格原先只收「标的股票数量／标的股份数量／股票数量」，真实公告写的是「标的股票上限」（工业富联）、「标的股票规模」（宁德时代）、「认购的股数上限」（金达威）——收窄了真实原句就整格判缺；价格那一格原先只收「购买股票的价格」，恒铭达写的是「购买股票（含预留部分）的价格」、宁德时代写「受让价格（含预留）」，括注把名词打断了。三处都补进名词族并各钉一枚对照（`对照·真实写法「标的股票上限」按数量格认` 等五枚），面文四处（SKILL 纪律 5、机检节、references 第二节、README 边界段，英文面同形）同步写清。
- **本域不设共指补判**（与姊妹尺 `related-party-terms-cn` 的结构性差异，写进 docstring 与面文）：两格的元素量纲都不同——受让价格是元/股、标的股票数量是股，资金来源是安排用词、资金总额是金额——一枚数在结构上不可能同时满足两个元素，所以姊妹尺里那条「肯定系词共指」的分支在本域没有适用面，不搬过来。**继承规则比姊妹尺更严**：孤立数继承前序最近一次的本格名词，但**前序最近的若是参照数就不继承**——因为真实草案会写「不低于交易均价的 50%，为 16.24 元/股」，盲目继承会把均价当成受让价格。
- 那一格的承诺边界（首版就写死，不等被问）：机检判的是同一短语内的相邻关系，加一次跨短语继承，**不声称覆盖所有自然语言的归属表达**；同位式共指（「受让价格与标的股票数量均为 17.35 元/股」）与「价格待定但数量已定」的同段共存式属**已知覆盖不到**，按严格式发红并明写为已知覆盖不到，请人工回原句核对；省略主语指谁属整句语义，机检不解析。判不到而文件确实没写，`未检索到` 是合法出口——它是答案，不是失败。
- 红线形状：这份方案值不值得参与、受让价格是否公允、考核目标能否达成、解锁能否实现、个人所得税与递延纳税如何处理、对当期业绩与股价的影响一律 `[待人工]`；不判效力（计划是否有效、程序是否违规、决议是否成立属人工与监管认定位）；不判规则适用（该走自行管理还是委托管理、该不该提交股东会，只按原文登记）；不接代办（不出方案文书、不代拟草案、不代算税、不代客投票或申报），不碰内幕信息与规避披露的做法。
- **税务断言是本域独有的第三支词族**：应缴·需缴·须缴·免征·可递延·适用后接个人所得税·个税·纳税，以及税负为·节税·避税·税务筹划·税收筹划·个税测算，一律禁，只准出现在 `[待人工]` 那一分句里。理由：切割句把本件与激励计划分开，税务判断是另一条更硬的边界——草案写「按国家有关规定执行」就逐字登记，写「递延纳税」就登记递延纳税，该缴多少、能不能递延、怎么筹划属税务位与人工。这一支在姊妹尺里没有对应物，是本域加出来的。
- 书名号豁免按**白名单准入**（与姊妹尺同形，四条缺一不给）：①那行有「锚：」；②书名号之外只剩引用标签或干脆是空的；③书名号内以「短标签：」起头时那个标签也得是引用标签；④书名号内不得出现本件自称（本件·本卡·本速读·笔者）。**「本公司」「本计划」「本员工持股计划」不在自称表内**——它们是公告主体与计划自身的自称，原文里真会出现（「本员工持股计划由公司自行管理」），收进来就误伤一片。**自称按前邻词性认、不按子串认**：`样本件`／`基本件`／`成本件`／`副本件` 这类复合词里「本件」只是尾巴，不算自称；前邻在有限虚词表内才算。**该表是有限白名单、不覆盖自然语言全部虚词**——`通过本件判断`／`围绕本件`／`仍本件认为` 这类前邻不在表内的形机检认不出、照绿，属**已知覆盖不到**，请人工回原句核对。
- 两条取证腿：员工持股计划草案、实施公告与持有人会议决议原文在数据腿上；草案全文、法律意见书、独立财务顾问报告与持有人会议决议多在附件里，那一路在解析腿上。两条都写成可选并各自带代价——不装也出卡骨架，代价是附件里的价格与考核细则只能停在「未检索到」，草案与实施公告的层级对照也没法自动补，要人工回原文核。
