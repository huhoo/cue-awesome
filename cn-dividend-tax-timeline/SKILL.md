# 分红到账与扣税时间轴

给一份权益分派实施公告，排出**三个日期节点**（股权登记日 → 除权除息日 → 现金红利发放日），
并按**五类股东**分别列出适用税率、计税基数、扣税后实得，每条挂公告原句与锚。

**切割句**：本件只回答「钱什么时候到、扣多少」；**分红方案本身说了什么归 `cn-shareholder-return`**，
本件不重复登记方案，也不给择时建议、不判税负高低。

## 0. 是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 三日期节点的时间轴，节点有序 | 择时建议（该不该持有到登记日） |
| 五类股东各自的税率·计税基数·扣税后实得 | 用税法默认税率替公告补数 |
| 每条挂公告原句与锚 | 税务筹划或代办申报 |
| 公告没写的类型逐条写「未取到」 | 用「不适用／无需扣税」替公告下结论 |

## 1. 触发场景

- 用户拿到权益分派实施公告，问「我什么时候能拿到钱」。
- 用户问「分红要扣多少税、到手多少」。
- 用户是机构或境外投资者，问「我们这类股东适用什么税率」。
- 用户要把登记日、除权除息日、发放日三个时点排清楚。

## 2. 取数纪律

1. **三节点必排**：股权登记日、除权除息日、现金红利发放日各占一行，且**日期须有序**（登记日 ≤ 除权除息日 ≤ 发放日）。
2. **五类股东必列**：个人股东、证券投资基金、合格境外机构投资者、香港投资者、其他法人股东各占一行。
3. **税率只认公告原句**：某类股东的税率数字必须出现在该行自己的书名号原句里；公告没写就写「未取到」，
   **不许凭常识填 20%／10%**——税率是公告说的，不是税法默认的。
4. **三要素齐**：非「未取到」的股东行要有适用税率（百分比）、计税基数（每股派息类名词）、扣税后实得（税后／实得／净额类名词）。
5. **未取到两向点名**：头部「共五类股东·未取到 N 类」只写一处，N 必须等于分类型税负段里「未取到」的行数；
   多报是虚报，少报是漏报，两个方向都算错。
6. **不写「不适用」**：把「未取到」写成「无此项／不适用／无需扣税」是替公告下结论，不是登记。
7. **判断留人工**：到手金额够不够、该不该持有到登记日、税负高不高，全部进「待人工」。

## 3. 输出契约（时间轴卡五段）

```
## 一、头部申报
- 文件：<公司> <公告名>｜来路：官方原文／用户直供｜附件腿：已发起／未发起
- 共五类股东·未取到 N 类

## 二、时间轴
- 股权登记日：「<原句>」 锚：<出处>
- 除权除息日：「<原句>」 锚：<出处>
- 现金红利发放日：「<原句>」 锚：<出处>

## 三、分类型税负
- 个人股东：「<原句，含税率·计税基数·扣税后实得>」 锚：<出处>
- 证券投资基金：「<原句>」 锚：<出处>
- 合格境外机构投资者：「<原句>」 锚：<出处>
- 香港投资者：「<原句>」 锚：<出处>
- 其他法人股东：未取到（未取到清单已点名）

## 四、未取到清单
- 未取到 N 类：<类型>——<缺什么>，需回<哪份文件>核对。

## 五、待人工
- [待人工] <到手金额／是否持有到登记日／税负高低> 全部留人工；本件不接代办，也不给择时建议。
```

股东类型在真实公告里有别名（自然人股东、公募基金、QFII／RQFII、沪股通／深股通投资者、法人股东等），
卡面写哪个别名都认，机检按 canonical 类归位。

## 4. 数据通道（以 live catalog 现值为准）

真实任务走通道正路：先看目录，再按工具名取原文与附件正文。

```bash
# 1) 看目录，拿端点
curl -s https://cuecue.cn/api/mcp-catalog | head -c 500

# 2) 按 MCP 协议握手，确认三枚工具在场
curl -s -X POST "$MCP_ENDPOINT" -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

拿到端点后确认 `parse` / `get_parse_status` / `read_result` 三枚在场，
再用 `parse` 把公告 URL 或本地路径交给通道，`get_parse_status` 轮询，`read_result` 取正文与表格。

**零 key 降级**：没有 `CUE_API_KEY` 时本件只走用户直供的公告正文与本地文件，代价是取不到渠道侧的披露原文与附件正文解析，锚只能落在用户给的那份上，跨文件核对做不了。

## 5. 合规红线（随套件）

- 不给择时建议（建议持有到登记日、登记日前买入、抢权、填权行情）。
- 不给评级与目标价。
- 不承诺收益（稳赚、零风险、保证收益、必涨、必跌）。
- 不代拟、不代算、不代申报、不代客。
- 不判税负高低（税率划不划算、税负偏高偏低）。
- 不裁断效力（扣税口径是否合规、是否有效）。

## 6. 快速流程（用户视角）

1. 把权益分派实施公告（URL 或本地文件）交给本件。
2. 本件排出三日期节点，按五类股东分列税率、计税基数、扣税后实得。
3. 公告没写的类型进未取到清单，点名要回哪份文件。
4. 判断类问题全部进「待人工」，本件不接。

## 7. 机检

```bash
python3 -B scripts/check_dividend_tax_timeline.py <卡面.md>     # 五道码逐条发红，全过则 PASS
python3 -B scripts/check_dividend_tax_timeline.py --selftest    # 好样须过、坏样五道齐发
bash scripts/fixtures/run_fixtures.sh                           # 离线样例三档（零网络零计费）
```

五道码：`DT-STRUCT` 五段齐·三节点行级在场且有序·五类股东行级在场且三要素齐／
`DT-QUOTE` 原句与锚不得为空／`DT-LINE` 红线三道／
`DT-GAP` 未取到两向点名 + 税率不得套默认／`DT-BOUND` 写成分红方案速读时点名改走 `cn-shareholder-return`。
