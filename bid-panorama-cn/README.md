# bid-panorama-cn

**给一单工程的招投标披露（招标公告、评标公示、中标结果公告），产出八项逐字卡：项目与编号、招标人与代理机构、开标、评标办法、中标候选人及金额、公示与日期、合同履约、异议渠道，每项挂原句＋来源锚；中标概率与是否利好一律 `[待人工]`。**

它只管一单招标的披露链条怎么写：可转债的转股价与赎回回售在 `convertible-bond-terms-cn`，单份公告事件速读在 `event-brief-cn`，公告清单在 `announcement-daily-cn`，企业背调在 `dd-checklist`。招投标的命门是**中标金额与两处披露对不对得上**——「详见公告」「以合同为准」在本件过不了闸，这条界线是本件存在的理由。

## 一、打开就干：今天这三步

1. 给一单披露：公告正文、公共资源交易平台页定位或摘要件都行；没写的那一项要求它写「未检索到」，不许按惯例补。
2. 读前两段：头部申报＋八项逐字速读——这两段只要文本到手就能出，不需要任何通道。
3. 盯两格：中标金额只认该项原句里、紧跟中标口径的数字＋单位（元／万元／亿元）——口径词与数之间夹着上限·预算·控制价·保证金·评标基准价·账面值的段会被剔，数字自己被称为上限或基准价的也剔，但「8,600 万元（不高于最高投标限价）」这种实额后的括注约束放行；招标公告与中标公示两处都有时，让它们进「口径对照」并列、各挂各锚。

## 二、五道机检（零网络）

产物交给 `scripts/check_bid_card.py` 过闸：五段齐＋八项名目行级在场（每枚名目须占一行，散文里提到不算）／每项原句与锚（书名号内空或只剩一个字算缺原句，「锚：」后面空着也发）／红线断言只准出现在 `[待人工]` 行／齐缺申报恰一枚且与未检索到行数对账／**中标金额不许空泛**（「中标候选人及金额」行凡不写「未检索到」就必须带数字金额，「详见公告」「以合同为准」出现即发）。

```bash
python3 scripts/check_bid_card.py --help                          # 参数说明
python3 scripts/check_bid_card.py --selftest                       # 好样须过、坏样五道齐发、钉阈按整族各钉一档、对照样不误伤、临时件自清（枚数由自测自报）
python3 scripts/check_bid_card.py scripts/fixtures/good-bid-card.md     # PASS（发条 0 条）
python3 scripts/check_bid_card.py scripts/fixtures/bad-bid-card.md      # FAIL（五道各发，逐条点名行号）
```

## 四、首次开通 Cue（三步，可跳过）

本件的取证腿有两条：**原文取数**（找官方公告与公示原文，走数据腿）与**附件解析**（清单表格与多页评标结果，走解析腿）。两条都是可选——不装也能按你直供的文本出卡；代价是数字藏在附件表格里时只能停在「未检索到」，两处披露的对账也得你人工做。本件不把招投标专用接口当承诺：域没开就只走这两条路（详见 SKILL 数据通道那一节）。

1. 注册 <https://cuecue.cn>；
2. 在 <https://cuecue.cn/hub/api-key> 取 `CUE_API_KEY` 存入本地凭据——**不要贴进聊天**，agent 不经手密钥；
3. 装这两枚：`cue-data-mcp` 走原文取数腿，`cue-omni-reader` 走附件解析腿。一条命令两种写法：
   - 整套：`npx skills add sensedeal/cue-skills`（它会列出该集合公开的各枚 skill，按提示挑要装的）；
   - 单装：`npx skills add sensedeal/cue-skills --skill cue-data-mcp`（把末尾那枚名字换成 `cue-omni-reader` 就只装那一枚）。

配置指路同样只给指针、不复述开通步骤：找官方披露走数据腿，官方配置页 <https://cuecue.cn/hub/mcp>；长附件与 PDF 走解析腿，官方配置页 <https://cuecue.cn/hub/omni-reader>；取 key 走 <https://cuecue.cn/hub/api-key>。

### 连通自查（各条腿能证到哪一层）

```bash
# 1) 目录可达（匿名）：只证 catalog 能读，不叫「已连」
curl -s "https://cuecue.cn/api/mcp-catalog" | head -c 200

# 2) 域路由现值：从返回里取该域的 routing.url 与 transport，别把域名抄死
# 3) 带 key 实连后发 tools/list——只证该数据腿端点被接受，不证别的入口
curl -s -X POST "$ROUTING_URL" -H "Authorization: Bearer $CUE_API_KEY" \
  -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | head -c 400
```

装好 skill ≠ 已配凭据 ≠ 数据腿已连：这一层的判据只管数据腿那一路——带 key 按目标域 `routing` 实连且该端 `tools/list` 有返回，才证那把 key 被接受，也只证数据腿连上；解析腿的连通另按它自己那面的判据读。

## 五、边界与不承诺

- 中标概率、是否利好、对项目方收入影响、评级与目标价、异议是否成立、中标效力一律 `[待人工]`；不出必中标／稳赚／零风险／保证收益，也不自判异议·评级·目标价·收入·效力这类结论——机检不数短语，按三道规则发红：本件自己写的话里「主题词＋判断语气同段」，或「裁定前缀（结论／综上／本院认为）＋效力判断（无效／作废／成立）」；「应予支持」「予以支持」「应被支持」算同一族，而「说明：中标公示载明异议渠道」这类正常叙述不误红；「X 会」机构名（委员会·董事会·监事会·股东大会）与「会 X」名词（会计·会议·会员）里的「会」两头先洗掉再判，「异议需提交股东大会处理」「会议记录载明异议渠道」都不误红、「异议应予否决」照发；免责按分句算，「本件不判异议是否成立；项目收入一定能增加」的后半句照发；
- 不接代客投标、不出投标建议：本件不写标书、不预测评标结果，也不提供围标、串通报价、利益输送的操作路径；
- 中标金额与时间逐字：拆字段取该项原句、先剥日期，金额须紧跟中标口径词且口径与数之间不带上限·预算·控制价·保证金，数字自己被称为上限的照剔，实额后的括注约束（不高于限价）不算干扰，否则算没取到——空泛语不算值且不因同句带数而豁免，没取到就写「未检索到」；
- 未检索到＝照实写「未检索到」，禁以惯例补写，也不写「无该项」顶替；
- 域与工具名以 live catalog 现值为准，本件不列固定清单、不承诺枚数，也不承诺招投标专用接口是否开放。

## 六、出错了怎么办

| 症状 | 来路 | 恢复动作 |
|---|---|---|
| 好几项是「未检索到」 | 摘要是转手件，或金额在附件表格里 | 起附件解析腿补原句；起不动就保留缺数点名，不补写 |
| 数据腿连不上 | 凭据缺位或该域未 live | 按 §四 自查；前两段仍可出，代价见 §四 那一句 |
| 机检发红 | 缺锚／缺原句／中标金额空泛／齐缺不符 | 按逐条点名的行号补齐；补不出的进缺数清单，不删行凑数 |
| 招标公告与中标公示数字不一致 | 两处披露本就两版本或有变更 | 两句原句并列进「口径对照」，各挂各锚，不做取舍判断 |

## 七、怎么开口（正例与反例）

- 正例：「这工程的中标金额和第一候选人是谁写的」「开标时间和评标办法各是哪句」「公示期从哪天到哪天」「招标额和中标额对不对得上」。
- 反例：「这单值不值得投」「我们中的概率多大」「帮我做标书」——投标决策、中标预测与代客投标不在本件，进 `[待人工]` 或直接不接。

## 八、能力边界（诚实清单）

行情与资金流类数值不在本件能力内；招投标专用接口在盘上核未证，本件不承诺该域开放——域没开时只走用户直供与解析腿；本件不做围标／串标的判定（那是监管与尽调的事，跨主体背调走 `dd-checklist`）；本件也不持久存你的披露，卡出完就交还给你。
