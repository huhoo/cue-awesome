# 商誉减值风险·逐条挂源

把一份年报／半年报或收购公告里的**商誉科目**拆成八节台账：商誉余额、被收购标的、
业绩承诺完成度、减值测试关键假设、本次计提与未计提，每行挂「」原句与锚。

**切割句**：`cn-restructuring-tracker` 记**重组事件与对价**（停牌、预案、过会、实施这条时间轴，
每步对价怎么变）；本件只做**商誉科目这一组**——账面余额、被收购标的、业绩承诺完成度、
减值测试关键假设、本次计提与未计提。`cn-earnings-note` 做**已出财报的点评**（收入、利润、毛利率
怎么变、为什么变）；本件不评业绩，只把商誉科目逐项挂到原句上。**本件不判会不会减值、不判计提是否充分。**

## 0. 是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 一份披露的商誉科目逐项摘成台账 | 一份财报的整体点评 |
| 每行一个金额／比例，都挂「」原句与锚 | 卡面自己拿余额减可收回金额算出减值额 |
| 业绩承诺完成度写成承诺数／实现数／完成率三格 | 只写「完成情况良好」这种结论 |
| 减值测试关键假设逐条登记（折现率、增长率、预测期） | 评价这些假设合不合理 |
| 披露没写的逐条写「未取到」并两向点名 | 用「无减值／不适用」替披露下结论 |

## 1. 触发场景

- 用户拿到一份年报或半年报，问「这家公司商誉有多少、今年计提了多少」。
- 用户问「收购的那个标的业绩承诺完成了没有、完成率多少」。
- 用户问「减值测试用的折现率、增长率是多少」。
- 用户问「商誉余额这两年怎么变的、哪个标的占大头」。

## 2. 取数纪律

1. **只认披露原文**：每个金额、比例、日期都要能回到一份年报／半年报／收购公告的原句与锚。
   研报、新闻、股吧转述、行情软件拆解一律不作来源。
2. **本件最要紧的一格——金额与比例只认原句**：某行的金额（万元／亿元／元）与比例（%）必须
   **逐字出现在该行自己的「」原句里**。披露写「计提商誉减值准备 1,200.00 万元」就写
   `1,200.00 万元`，不许写成 `1,200 万元`、`1200万元`、`0.12 亿元`。
   **不许拿商誉余额减可收回金额自己算减值额，也不许拿减值额除以余额自己算计提比例**——
   分母可能是商誉原值、可能是账面价值、可能是资产组口径，算错一个分母，风险读数就全错。
   披露没写比例就写「未取到」，那是答案，不是失败。
3. **业绩承诺完成度三格齐**：承诺数、实现数、完成率，三格都要有落点；披露只给两格时，
   第三格写「未取到」并进第六节，不许自己拿实现数除承诺数补出完成率。
4. **减值测试关键假设逐条登记**：预测期、折现率、增长率——披露怎么写就怎么登记，
   税前折现率与税后折现率是两回事，别混。
5. **未取到两向点名**：第六节申报的「未取到 M 项」必须等于正文各节里写「未取到」的行数。
   申报多了是虚报，少了是漏报，两个方向都发。

## 3. 八节契约

| 节 | 内容 | 硬要求 |
|---|---|---|
| 一、头部申报 | 文件与来路、`减值口径：` 行、`共 N 项·未取到 M 项` | 三件逐字在位 |
| 二、商誉余额 | 逐标的期末余额、期初余额、口径 | 至少一行；缺该标的就写未取到 |
| 三、业绩承诺完成度 | 逐标的承诺期、承诺数、实现数、完成率、口径 | 至少一行；无承诺安排写「未取到」 |
| 四、减值测试关键假设 | 逐标的预测期、折现率、增长率 | 至少一行；未披露写「未取到」 |
| 五、计提与未计提 | 逐标的本期计提金额、计提比例、累计计提、账面余额 | 至少一行；未计提要在原句里说得出来 |
| 六、未取到清单 | 逐条点名没取到的项 | 与正文两向对齐 |
| 七、来源 | 每条一行，带 URL 与 `YYYY-MM-DD` 检索日 | 编号与正文 `[S#]` 一一对应 |
| 八、待人工 | 判断位留白 | 至少一行 `[待人工]` |

**头部三件**：第一条写文件与来路；第二条是 `减值口径：商誉科目（…；不判会不会减值）`，
**这一行是本件与重组跟踪、财报点评的分界**，机检按它判边界；第三条是 `共 N 项·未取到 M 项`，
**全文只准出现一处**。

## 4. 数据行的形制（四形，缺一即发）

```
- 余额：标的：<被收购主体>｜期末余额：<N>万元｜期初余额：<N>万元｜口径：<合并口径> 「<原句逐字>」 锚：<定位> [S#]
- 承诺：标的：<被收购主体>｜承诺期：<期间>｜承诺数：<N>万元｜实现数：<N>万元｜完成率：<N>%｜口径：<口径> 「<原句逐字>」 锚：<定位> [S#]
- 假设：标的：<被收购主体>｜预测期：<期间>｜折现率：<N>%｜增长率：<N>% 「<原句逐字>」 锚：<定位> [S#]
- 计提：标的：<被收购主体>｜本次计提金额：<N>万元｜计提比例：<N>%｜累计计提：<N>万元｜账面余额：<N>万元 「<原句逐字>」 锚：<定位> [S#]
```

- **行首四字**（`- 余额：`／`- 承诺：`／`- 假设：`／`- 计提：`）是行级在场的判据：
  只在散文里提到「商誉余额 12,500 万元」不算一行；
- **`「」` 里是原句**，从披露里逐字抄；`锚：` 后是定位词（章节、附注号、页码都行），不得为空；
- **`[S#]` 挂到行末**，编号必须在第七节有对应行；
- 取不到整行的，写 `- <行首>：未取到（未取到清单已点名）`——这一形不要求原句与锚，
  但会计入第六节的 M，两向对账。

## 5. 五道机检

`python3 -B scripts/check_goodwill.py <台账.md>`，零网络、纯标准库。

| 码 | 道 | 判什么 |
|---|---|---|
| `GW-STRUCT` | 道一 形制 | 八节齐；头部三件在位；`减值口径：` 以「商誉科目」起头；四类数据行行级在场且各节至少一行；每行要素齐（余额四格／承诺六格／假设四格／计提五格），缺一即发 |
| `GW-QUOTE` | 道二 原句与锚 | 每行 `「」` 内原句非空且不止单字；`锚：` 在场且值非空；行末 `[S#]` 在第七节有对应行；第七节每行带 URL 与 `YYYY-MM-DD` |
| `GW-LINE` | 道三 红线 | 会不会减值／计提是否充分／评级与目标价／股价预测／收益承诺／代办，一律零命中；`[待人工]` 与免责句**只管自己那一分句**（按分号句号逗号切开逐段判），同一行后半写的断言照发 |
| `GW-GAP` | 道四 未取到与不得自算 | ①`共 N 项·未取到 M 项` 恰一处，N＝四节数据行总数、M＝写「未取到」的行数，两向都发；②「无减值／不适用／无需计提」这类替披露下结论的写法一律发；③**每行出现带单位的金额与百分比，必须逐个出现在该行自己的原句里**，不在即为卡面自算 |
| `GW-BOUND` | 道五 边界 | `减值口径：` 写成「重组／对价／交易」时点名改走 `cn-restructuring-tracker`；写成「财报点评／业绩点评」时点名改走 `cn-earnings-note`；出现 `- 交易对价：`／`- 支付方式：`／`- 标的资产作价：` 这类重组项行同样点名；出现 `- 营业收入：`／`- 归母净利润：` 这类财报点评项行同样点名 |

**那道不得自算的口径（写进件内，防后人放宽）**：判的是**逐字在场**，不是数值相等。
`1,200.00 万元` 与 `1200 万元` 数值一样，但后者是卡面加工过的写法；单位换了（万元↔亿元）、
小数位补了、千分位去了，都算不在原句里。理由：本件卖的就是「这枚数字回得到那一句」，
一旦允许换算，「回得到」就成了「算得出」，两件事。同族判据在 `cn-share-pledge-tracker` 的
`SP-GAP`（比例不得自算），本件把它扩到金额与百分比两类。

## 6. 边界与不承诺

- **不判会不会减值**：存在减值迹象／可能减值／将减值／减值压力大／商誉高估，一律 `[待人工]`；
- **不判计提是否充分**：计提充分／计提不足／减值不充分／该计提未计提，一律 `[待人工]`；
- **不给评级与目标价、不预测股价**：买入卖出、目标价、利好利空、拖累股价，一律 `[待人工]`；
- **不接代办**：不代算减值、不代为会计处理、不代拟问询回复、不代客申报；
- 重组事件与对价跟踪走 `cn-restructuring-tracker`；已出财报的整体点评走 `cn-earnings-note`；
  单份重组文件的条款速读走 `ma-restructuring-terms-cn`；
- 未检索到＝照实写「未检索到」，禁以行业惯例补写，也不写「无减值／不适用」顶替；
- 域与工具名以 live catalog 现值为准，本件不列固定清单、不承诺枚数，也不承诺该域是否开放与文件的实时性。

## 7. 通道（数据腿与解析腿）

本件的取证腿是两枚可选辅助：`cue-data-mcp`（年报与收购公告的定位）与 `cue-omni-reader`
（把 PDF／网页转成可摘的文本）。通道侧的实连走这条正路——目录入口只在此处赋一次，
域 id 与 routing url 现取现用，不把域名或路径抄死：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | python3 -c 'import json,sys
rows=json.load(sys.stdin)["data"]["domains"]
[print(r.get("id"), r.get("external_status"), (r.get("routing") or {}).get("url", "-")) for r in rows]'
DOMAIN_ID="<把这里换成上一行列出的那个域 id>"
ROUTING_URL="$(curl -s "$CATALOG" | python3 -c 'import json,sys
rows=json.load(sys.stdin)["data"]["domains"]
hit=[r["routing"]["url"] for r in rows if r.get("id")==sys.argv[1] and r.get("routing")]
print(*hit,sep="\n") if hit else sys.exit("未取到：该 id 不在目录现值里")' "$DOMAIN_ID")"
[ -n "$ROUTING_URL" ] || { echo "取值失败：ROUTING_URL 为空" >&2; exit 1; }
curl -s -X POST "$ROUTING_URL" \
  -H "Authorization: Bearer $CUE_API_KEY" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' \
  -w '\nHTTP %{http_code}\n'
```

三层各自能证到什么，互不等价：**装好 skill ≠ 已配凭据 ≠ 通道已连**。匿名 GET 只证目录可达；
带 key 实连且 `tools/list` 有返回才证那把 key 被接受（通过＝HTTP 200 且 `result.tools` 非空，
只按形状认，不列工具名、不承诺枚数）。解析那一腿走宿主 MCP：连上之后宿主列出的工具里应能看到
`parse`、`get_parse_status`、`read_result` 这些名字——名字在场只证它们被暴露，不证解析跑得通。
目录返回里没有的域本件不装也不承诺；连接报错不等于域无数据，如实报。key 取自本地凭据设施，
不进聊天、不在终端回显。消耗以服务端返回为准，花之前先问。
