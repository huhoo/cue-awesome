# cn-customer-concentration

**给一家公司，产出六节客户集中度台账：分期合计、单客户占比、关联与依赖事实，每行数据同时带期间与口径并挂 `[S#]`；披露没点名的客户，台账不替它点名；缺的逐条写「未取到」。**

要点不稀缺，**稀缺的是「这家公司收入靠几个客户」这句话能回到一处带期间、带口径、带检索日的来源**。差异化不在排版，而在三道硬门禁：占比不带期间进不了数据行，匿名客户被具名即发红，单客户之和大于合计即发红。

**输入**：一家公司（名或代码）＋ 一批披露材料（年报／募集说明书／问询回复／公告），或一个待查问题
**输出**：六节台账（集中度一句话／分期集中度／单客户明细／关联与依赖事实／未取到与口径／来源）
**代价**：六节契约 + 一道机检；通道腿（公告检索／原文解析）开没开，决定的是「单客户占比」那一层——两条路各自缺什么、走哪条，写在 §二 与 §四
**机检**：`scripts/check_concentration.py` 五道（形制／锚／红线／未取到两向点名／边界），零网络；反证矩阵长在这支脚本里

**它和 `prospectus-digest-cn`、`cn-supply-chain-map` 不是一件事（这一句是本件存在的理由）**：`prospectus-digest-cn` 读**一份招股书**、把八项逐字摘成速览卡，客户与供应商集中度只是其中一项；本件做**跨期客户依赖台账**——多期、多份披露、占比怎么变、客户怎么进出前五名。`cn-supply-chain-map` 画**链条结构**（谁在哪个环节、上下游关系）；本件问的是**收入来自哪些客户、占比多少**。本件**不判客户质量、不判风险大小**。头部那行「集中度口径：」就是这条分界的机检入口——写成「招股书」或「产业链」都会被点名改走对应那一件。

## 一、打开就干：今天这三步

| 步 | 动作 | 怎么做 | 不做会怎样 |
|---|---|---|---|
| ① | **先看形状**（30 秒、零网络、零计费） | `bash scripts/fixtures/run_fixtures.sh` —— 五档一次跑完：机检自测、好样坏样逐枚单跑、零通道骨架、骨架该红就红、边界形逐枚单跑。末行自报「档数=5｜不合=0｜不可判=0」 | 没见过形状就上手，容易把「排得整齐」当成「有出处」；这一档 30 秒就能看出两者的差别 |
| ② | **登记来源，逐条挂源** | 每个来源一行写进第六节：`- [S#] 标题（URL ｜检索日 YYYY-MM-DD）`；每条合计行与单客户行行末挂一个 `[S#]`。跨源不一致就两条都留，不合并、不取平均 | 缺检索日的来源行发 `E-ANCHOR`；没有锚的数据行同样发 `E-ANCHOR`——那时你要回来逐条补，比现在一条条挂贵 |
| ③ | **过机检，再交人** | `python3 -B scripts/check_concentration.py <台账.md>`，按详行的 `E-*` 码逐条改；改完仍只是**草稿**：这个集中度意味着什么、客户质量如何，由人定 | 未取到没点名、判断词漏进正文、匿名客户被替它点名，都会跟着台账进到人的判断里；这几类都是机检能拦的形制层，内容层还得回原文 |

判断客户质量与风险大小、评级与目标价、买卖与时机建议**不在这三步里**——本件只对「这家公司的客户依赖被逐条挂实地排成一张跨期台账」负责，且只对形制负责。

## 二、装上机 → 连通道 → 出结果

**装本件自己（主路）**：`npx skills add huhoo/cue-awesome --skill cn-customer-concentration`——这条只装本包；装完在你这一侧重列一次已安装 skill，清单里看得到 `cn-customer-concentration` 这个名字才算文件到位。没有 CLI 环境时的兜底是把本目录整个放进宿主支持的 skills 目录（`~/.workbuddy/skills/`）。

本件的取证腿是两枚可选辅助：`cue-data-mcp`（公告与年报的定位，走数据腿）与 `cue-omni-reader`（把 PDF／网页转成可摘的文本，走解析腿）。通道侧的实连走这条正路：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | python3 -c 'import json,sys
rows=json.load(sys.stdin)["data"]["domains"]
[print(r.get("id"), r.get("external_status"), (r.get("routing") or {}).get("url", "-")) for r in rows]'
DOMAIN_ID="<把这里换成上一行列出的那个域 id>"
ROUTING_URL="$(curl -s "$CATALOG" | python3 -c 'import json,sys
rows=json.load(sys.stdin)["data"]["domains"]
hit=[r["routing"]["url"] for r in rows if r.get("id")==sys.argv[1] and r.get("routing")]
print(*hit,sep="\n") if hit else sys.exit("未取到：该 id 不在目录现值里（或它没有 routing 里的 url 字段）——先跑上面那行列出现场的 id 再填")' "$DOMAIN_ID")"
[ -n "$ROUTING_URL" ] || { echo "取值失败：ROUTING_URL 为空——先跑上面那行列出现场 id，再把 DOMAIN_ID 换成其中之一" >&2; exit 1; }
curl -s -X POST "$ROUTING_URL" \
  -H "Authorization: Bearer $CUE_API_KEY" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' \
  -w '\nHTTP %{http_code}\n'
```

`CATALOG` 是本面唯一一处目录入口字面（赋一次、散文不重抄）；`$ROUTING_URL` 是从该域 `routing` 里的 `url` 字段现取的逐字值，别把域名或路径抄死在这张面上。三层各自能证到什么，互不等价：**装好 skill ≠ 已配凭据 ≠ 通道已连**。匿名 `GET` 只证**目录可达**，本面不把它叫「已连」；带 key 实连且 `tools/list` 有返回才证那把 key 被接受，通过＝HTTP 200 且 `result.tools` 非空（只按形状认，本面不列工具名也不承诺枚数）。解析那一腿走宿主 MCP：**连上之后**宿主列出的工具里应当能看到这些名字——remote-only 那一面是 `parse`、`get_parse_status`、`cancel_parse` 三枚，带 Bridge 的那一面再加 `read_result`、`read_outline`、`discard_result`、`save_result`，共七枚；两路枚数不同，拿一个固定数判两路必错一边。名字在场只证它们被暴露，不证解析跑得通——URL 那一腿要拿一枚真实 URL 跑一次 parse 才证该路，本地文件那一腿要拿一枚真实本地文件跑一次 parse 才证该路（remote-only 不读本地件）；本件不自证也不代跑。目录返回里没有的域本面不装也不承诺；连接报错不等于域无数据，如实报。key 取自本地凭据设施，不进聊天、不在终端回显，本面不新增任何凭据读取动作；解析与检索的消耗以服务端返回为准，本件不代估也不代付，花之前一定先问。配置指路：数据腿官方配置页 <https://cuecue.cn/hub/mcp>、解析腿官方配置页 <https://cuecue.cn/hub/omni-reader>（本件两条腿都可能用上——年报与募集说明书的定位走数据腿，长附件与 PDF 的正文取回走解析腿），取 key 走 <https://cuecue.cn/hub/api-key>。

## 三、离线样例：30 秒看到形状

```bash
cd cn-customer-concentration
bash scripts/fixtures/run_fixtures.sh
# 档① 机检自测：好样须过、七枚坏样须各发它该发的那一道 → selftest: ALL GREEN
# 档② 好样与七枚坏样逐枚单跑：每枚报它自己的退码与码集，不并成一个总数
# 档③ 零通道骨架：scripts/make_outline.py 把 scripts/fixtures/sources.jsonl 排成一张待填骨架
# 档④ 骨架过机检：期望发 E-FORMAT——集中度一句话仍是占位，骨架不该被当成台账交付
# 档⑤ 边界形逐枚单跑：口径写招股书→道五点名／口径写产业链→道五点名／口径值认不出→形制红／
#      判断词必红／事实陈述不误红／改数词必红／匿名客户具名必红／占比大于合计必红
```

自己上手时同样两条命令：

```bash
python3 -B scripts/make_outline.py --sources 你的材料.jsonl --out 我的骨架.md
python3 -B scripts/check_concentration.py 我的骨架.md
```

来源行必需三键：`title`／`url`／`asof`（检索日 `YYYY-MM-DD`），`id` 可省、缺省按行序给 `S1／S2…`。非法 JSON 行、缺键行、日期不是 `YYYY-MM-DD` 的行一律**未采信并逐行点名**，不静默跳行；一条可用行都没有时退 1——空清单不出骨架，那是没有出处，不是待填。

## 四、依赖与两条路的代价

**主路（有通道）**：年报与募集说明书的定位走数据腿，长附件与多页 PDF 的正文取回走解析腿。两条腿都开时，本件能给出「每条占比都回到一处带期间、带口径、带检索日的原文」这一层；缺哪条腿，缺的就是那一层——数据腿缺位时披露件只能靠你直供，解析腿缺位时附件里的原句只能停在「未检索到」。

**降级（零通道）**：`scripts/make_outline.py` 把已有材料清单排成一张待填骨架。**代价同句写清**：缺的正是公告检索与原文解析那一层，所以骨架只会有形状、不会有权衡后的集中度事实——第二节留一行合计待填位、第三节留一行单客户待填位、第四节留一行依赖事实待填位，集中度一句话留占位，机检按设计发 `E-FORMAT`。骨架不是台账，别把它当交付。

## 五、边界与不承诺

- 不判客户质量、不判风险大小：风险可控／严重依赖／优质客户／护城河这类判断一律 `[待人工]`；评级、目标价、买卖与时机建议同样 `[待人工]`；
- **判断词族零命中**：风险可控／风险不大／风险较小／风险极低／风险很高／风险极大／严重依赖／过度依赖／高度依赖／优质客户／标杆客户／大客户背书／客户质量高／深度绑定／绑定龙头／护城河／粘性强／订单饱满／业绩确定性；改数词（约／左右／大概）不得替数字打底；
- **收窄（防后人放宽）**：裸「依赖」不收——「公司对前五大客户存在一定依赖」是年报原文的事实陈述，照常登记；只收「严重依赖／过度依赖／高度依赖」这种加程度的判断。裸「集中」不收，只收「风险可控／风险不大」这种下结论的形；
- 读单份招股书摘八项走 `prospectus-digest-cn`；画产业链上下游结构走 `cn-supply-chain-map`；
- **匿名客户不得具名**：披露写成「客户一」「第 N 名客户」的，括号注只能是「未具名／匿名／未披露／未点名」这一类；括号里出现公司名即发红——披露没点名，台账就不能替它点名；
- 未检索到＝照实写「未检索到」，禁以行业惯例补写，也不写「无该项」顶替；
- 单一来源的场景不要用本件——那是一篇转述；多期多源互校才是它的用途；
- 域与工具名以 live catalog 现值为准，本件不列固定清单、不承诺枚数，也不承诺该域是否开放与文件的实时性。

## 六、出错了怎么办

| 症状 | 来路 | 恢复动作 |
|---|---|---|
| 好几条是「未检索到」 | 材料只有披露标题，正文在附件里 | 起解析腿补原句；起不动就保留缺数点名，不补写 |
| 数据腿连不上 | 凭据缺位或该域未 live | 按 §二 自查；骨架仍可出，代价见 §四 那一句 |
| 机检发红 `E-ANCHOR` | 数据行没挂锚，或锚在第六节没有对应行，或来源行缺 URL／检索日 | 按逐条点名的行号补齐；补不出的进第五节缺数清单，不删行凑数 |
| 机检发红 `E-COVERAGE` | 正文写了未取到而第五节没列，或第五节列了而正文没有这条表述 | 两向都要对得上；同一件事换个写法不判红（按名目同指对），真没点到才红 |
| 机检发红 `E-SCOPE` | 头部「集中度口径：」写成了「招股书」或「产业链」 | 改走对应那一件，或把问题收窄成「这家公司收入靠哪几个客户、占比多少」 |
| 机检发红 `E-BANWORD` | 写了评级／目标价／买卖建议，或用了「风险可控」「优质客户」这类判断词，或用了「约／左右」替数字打底 | 改中性陈述或同行挂 `[待人工]`；数值照来源写，口径不齐落第五节 |
| 机检发红 `E-FORMAT`（形制） | 数据行缺期间或缺口径，或匿名客户的括号里写了公司名，或单客户之和大于同期合计 | 补上期间与口径；匿名客户改回「披露未具名」；占比照来源写，不自造 |
| 判断句被误红 | 那行写的是「存在一定依赖」这类事实陈述 | 机检按词族收（加了「严重／过度／高度」才红），裸「依赖」不红；若仍红，看是不是同句带了别的判断语 |

## 七、怎么开口（正例与反例）

- 正例：「这家公司收入靠哪几个客户、占比多少」「前五大客户合计占比这几年怎么变」「第一大客户是谁、是不是关联方」「2023 年和 2024 年的客户结构有什么变化」。
- 反例：「客户集中度风险大不大」「这家公司值不值得买」「目标价多少」「客户质量好不好」——判断客户质量与风险大小不在本件，一律 `[待人工]`；读单份招股书走 `prospectus-digest-cn`，画产业链走 `cn-supply-chain-map`。

## 八、能力边界（诚实清单）

本件不判客户质量与风险大小（那是判断位，`[待人工]`）；不做估值建模与财务预测；不替匿名客户点名，也不以行业惯例补写缺数；不持久存你的文件，台账出完就交还给你。披露件本身的可得性与实时性以 live catalog 现值为准，未开放就不承诺。
