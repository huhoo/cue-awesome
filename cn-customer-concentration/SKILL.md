# 客户集中度与依赖风险·逐条挂源

**给一家公司，产出六节客户集中度台账：分期合计、单客户占比、关联与依赖事实，每行数据同时带期间与口径并挂 `[S#]`；披露没点名的客户，台账不替它点名；缺的逐条写「未取到」。**

要点不稀缺，**稀缺的是「这家公司收入靠几个客户」这句话能回到一处带期间、带口径、带检索日的来源**。差异化不在排版，而在三道硬门禁：占比不带期间进不了数据行，匿名客户被具名即发红，单客户之和大于合计即发红。

**输入**：一家公司（名或代码）＋ 一批披露材料（年报／募集说明书／问询回复／公告），或一个待查问题
**输出**：六节台账（集中度一句话／分期集中度／单客户明细／关联与依赖事实／未取到与口径／来源）
**代价**：六节契约 + 一道机检；通道腿（公告检索／原文解析）开没开，决定的是「单客户占比」那一层——两条路各自缺什么、走哪条，写在 README §二 与 §四
**机检**：`scripts/check_concentration.py` 五道（形制／锚／红线／未取到两向点名／边界），零网络；反证矩阵长在这支脚本里

**它和 `prospectus-digest-cn`、`cn-supply-chain-map` 不是一件事（这一句是本件存在的理由）**：`prospectus-digest-cn` 读**一份招股书**、把八项逐字摘成速览卡，客户与供应商集中度只是其中一项；本件做**跨期客户依赖台账**——多期、多份披露、占比怎么变、客户怎么进出前五名，不读单份招股书。`cn-supply-chain-map` 画**链条结构**（谁在哪个环节、上下游关系）；本件问的是**收入来自哪些客户、占比多少**，不画链条。头部那行「集中度口径：」就是这条分界的机检入口——写成「招股书」或「产业链」都会被点名改走对应那一件。

---

## 一、六节契约

| 节 | 内容 | 硬要求 |
|---|---|---|
| 一、集中度一句话 | 最新一期前五大客户合计占比、与上期比怎么变、第一大客户占比 | 至少一行实句，不留占位 |
| 二、分期集中度 | 逐期前五大客户合计占比 | 至少一行合计行 |
| 三、单客户明细 | 逐期每个客户的占比 | 至少一行单客户行 |
| 四、关联与依赖事实 | 关联关系、重大合同、客户进出前五名 | 至少一行；一条都没有就写「未取到」并进第五节 |
| 五、未取到与口径 | 逐条点名没查到的项；口径差异 | 与正文两向对齐 |
| 六、来源 | 每条来源一行，带 URL 与检索日 | 编号与正文锚一一对应 |

**头部四件自标**（写在第一个 `## ` 之前，逐字在位）：`AI 整理初稿`、`请回原文核对`、`不构成投资建议`、`判断位 [待人工]`。

**头部「集中度口径：」行**：以「客户依赖」起头，如 `集中度口径：客户依赖（收入来自哪些客户、占比多少、跨期怎么变；不判客户质量、不判风险大小）`。写成「招股书」由道五点名改走 `prospectus-digest-cn`；写成「产业链」由道五点名改走 `cn-supply-chain-map`；写个认不出的值由道一发红。

## 二、数据行的形制（本件的要害）

两形，四字段缺一不可：

```
- 期间：<期间>｜前五大客户合计：<N>%｜口径：<口径> [S#]
- 期间：<期间>｜客户：<客户名>｜占比：<N>%｜口径：<口径> [S#]
```

- **期间**：`2024年度`、`2025年1-6月`——照披露原文写，不换算、不合并；
- **占比**：照来源写，不用「约／左右」打底；
- **口径**：`合并口径，营业收入`、`母公司口径，主营业务收入`——**占比不带期间是孤数，不带口径是不可比数**，两者各发一条。

**匿名客户不得具名**：披露写成「客户一」「客户二」「第 N 名客户」的，括号注只能是「未具名／匿名／未披露／未点名」这一类。括号里出现公司名即发红——**披露没点名，台账就不能替它点名**；要写公司名，得有一处披露原文点了名并挂锚。

**占比自洽**：同一期间的单客户占比之和不得大于该期前五大客户合计（差在四舍五入以内，≤0.5 个百分点，不算）。

## 三、五道机检

`python3 -B scripts/check_concentration.py <台账.md>`，零网络、纯标准库。

| 码 | 道 | 判什么 |
|---|---|---|
| `E-FORMAT` | 道一 形制 | 头部四件自标逐字在位；「集中度口径：」行在场且值为客户依赖口径；六节齐且按一至六有序；集中度一句话非空非占位；第二节至少一行合计行、第三节至少一行单客户行、第四节至少一行；每行数据行四字段齐；匿名客户不得具名；单客户占比之和不得大于同期合计 |
| `E-ANCHOR` | 道二 锚 | 数据行行末带 `[S#]`，且该编号在第六节有对应行；第六节每行必须同时带 URL 与 `YYYY-MM-DD` 检索日 |
| `E-BANWORD` | 道三 红线 | 评级／目标价／买卖与走势类断言零命中；**另加本域判断词族**——风险可控／风险不大／风险较小／风险极低／风险很高／风险极大／严重依赖／过度依赖／高度依赖／优质客户／标杆客户／大客户背书／客户质量高／深度绑定／绑定龙头／护城河／粘性强／订单饱满／业绩确定性，一律零命中；改数词（约／左右／大概）不得替数字打底。要写只能同行挂 `[待人工]` |
| `E-COVERAGE` | 道四 未取到与计数 | 正文写了「未取到」的，第五节必须逐条点名它；第五节列了而正文没有这条表述的同样发。两向都按**名目同指**对（剥括号注与标点后，字面全等／一方完整含另一方且短的一方 ≥4 字／汉字集合重合率 ≥0.6） |
| `E-SCOPE` | 道五 边界 | 「集中度口径：」写成「招股书」时点名改走 `prospectus-digest-cn`；写成「产业链」时点名改走 `cn-supply-chain-map`；不是只报形制错 |

**红线里那条收窄（写进件内，防后人放宽）**：裸「依赖」不收——「公司对前五大客户存在一定依赖」是年报原文的事实陈述，照常登记；只收「严重依赖／过度依赖／高度依赖」这种加程度的判断。裸「集中」不收，只收「风险可控／风险不大」这种下结论的形。runner 档⑤ 的「事实陈述不误红」与「判断词必红」成对钉住这个收窄的两个方向。

## 四、零通道骨架

`python3 -B scripts/make_outline.py --sources 材料.jsonl --out 我的骨架.md` 把材料清单排成一张待填骨架：第二节留一行合计待填位、第三节留一行单客户待填位、第四节留一行依赖事实待填位，第五节逐条点名，集中度一句话留占位。

**代价同句写清**：缺的正是公告检索与原文解析那一层，所以骨架只会有形状、不会有权衡后的集中度事实——骨架过不了机检是设计，不是待补的疏漏。材料清单里非法 JSON 行、缺键行、日期不合形的行一律未采信并逐行点名，不静默跳行；一条可用行都没有时退 1。

## 五、边界与不承诺

- 不判客户质量、不判风险大小：风险可控／严重依赖／优质客户／护城河这类判断一律 `[待人工]`；评级、目标价、买卖与时机建议同样 `[待人工]`；
- 读单份招股书摘八项走 `prospectus-digest-cn`；画产业链上下游结构走 `cn-supply-chain-map`；
- 未检索到＝照实写「未检索到」，禁以行业惯例补写，也不写「无该项」顶替；
- 单一来源的场景不要用本件——那是一篇转述；多期多源互校才是它的用途；
- 域与工具名以 live catalog 现值为准，本件不列固定清单、不承诺枚数，也不承诺该域是否开放与文件的实时性。

## 六、通道（数据腿与解析腿）

本件的取证腿是两枚可选辅助：`cue-data-mcp`（年报与募集说明书的定位）与 `cue-omni-reader`（PDF／网页转成可摘的文本）。通道侧的实连走这条正路——目录入口只在此处赋一次，域 id 与 routing url 现取现用，不把域名或路径抄死：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | python3 -c 'import json,sys
rows=json.load(sys.stdin)["data"]["domains"]
[print(r.get("id"), r.get("external_status"), (r.get("routing") or {}).get("url", "-")) for r in rows]'
DOMAIN_ID="<把这里换成上一行列出的那个域 id>"
ROUTING_URL="$(curl -s "$CATALOG" | python3 -c 'import json,sys
rows=json.load(sys.stdin)["data"]["domains"]
hit=[r["routing"]["url"] for r in rows if r.get("id")==sys.argv[1] and r.get("routing")]
print(*hit,sep="\n") if hit else sys.exit("未取到：该 id 不在目录现值里")' "$DOMAIN_ID")"
[ -n "$ROUTING_URL" ] || { echo "取值失败：ROUTING_URL 为空" >&2; exit 1; }
curl -s -X POST "$ROUTING_URL" \
  -H "Authorization: Bearer $CUE_API_KEY" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' \
  -w '\nHTTP %{http_code}\n'
```

三层各自能证到什么，互不等价：**装好 skill ≠ 已配凭据 ≠ 通道已连**。匿名 GET 只证目录可达；带 key 实连且 `tools/list` 有返回才证那把 key 被接受（通过＝HTTP 200 且 `result.tools` 非空，只按形状认，不列工具名、不承诺枚数）。解析那一腿走宿主 MCP：连上之后宿主列出的工具里应能看到 `parse`、`get_parse_status`、`read_result` 这些名字——名字在场只证它们被暴露，不证解析跑得通。目录返回里没有的域本件不装也不承诺；连接报错不等于域无数据，如实报。key 取自本地凭据设施，不进聊天、不在终端回显。消耗以服务端返回为准，花之前先问。
