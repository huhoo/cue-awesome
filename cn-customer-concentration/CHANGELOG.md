# 更新日志

### 0.1.0 — 2026-11-09（首版：客户集中度与依赖风险台账，六节契约 + 五道机检）

- 本件做什么：把「这家公司收入靠几个客户」变成「一张每条占比都能回到一处带期间、带口径、带检索日来源的跨期台账」。逐期前五大客户合计占比、逐期单客户占比、关联与依赖事实，行末挂 `[S#]`，第六节逐条给 URL 与检索日；没查到的项逐条写「未取到」，不补常识。
- 与 `prospectus-digest-cn`、`cn-supply-chain-map` 的分界（本件存在的理由）：`prospectus-digest-cn` 读**一份招股书**、把八项逐字摘成速览卡，客户与供应商集中度只是其中一项；本件做**跨期客户依赖台账**——多期、多份披露、占比怎么变、客户怎么进出前五名。`cn-supply-chain-map` 画**链条结构**（谁在哪个环节、上下游关系）；本件问的是**收入来自哪些客户、占比多少**。本件不判客户质量、不判风险大小。头部那行 `集中度口径：` 是这条分界的机检入口：写成「招股书」由道五点名改走 `prospectus-digest-cn`，写成「产业链」由道五点名改走 `cn-supply-chain-map`，写个认不出的值由道一发红。
- 数据行形制（本件的要害）：两形，四字段缺一不可——`- 期间：<期间>｜前五大客户合计：<N>%｜口径：<口径> [S#]` 与 `- 期间：<期间>｜客户：<客户名>｜占比：<N>%｜口径：<口径> [S#]`。**占比不带期间是孤数，不带口径是不可比数**，两者各发一条。期间照披露原文写，不换算、不合并。
- 匿名客户不得具名：披露写成「客户一」「客户二」「第 N 名客户」的，括号注只能是「未具名／匿名／未披露／未点名」这一类；括号里出现公司名即发红——披露没点名，台账就不能替它点名。
- 占比自洽：同一期间的单客户占比之和不得大于该期前五大客户合计（差在四舍五入以内，≤0.5 个百分点，不算）。
- 五道机检（`scripts/check_concentration.py`，零网络、纯标准库）：
  - 道一 `E-FORMAT` 形制：头部四件自标逐字在位；`集中度口径：` 行在场且值为客户依赖口径；六节齐且按一至六有序；集中度一句话非空非占位；第二节至少一行合计行、第三节至少一行单客户行、第四节至少一行；每行数据行四字段齐；匿名客户不得具名；单客户占比之和不得大于同期合计。
  - 道二 `E-ANCHOR` 锚：数据行行末一个 `[S#]`；该编号在第六节有对应行；来源行同时带 URL 与检索日 `YYYY-MM-DD`。
  - 道三 `E-BANWORD` 红线：评级／目标价／建仓清仓／必涨必跌／稳赚无风险／跑赢大盘／严重低估严重高估一类断言零命中；**另加本域判断词族**——风险可控／风险不大／风险较小／风险极低／风险很高／风险极大／严重依赖／过度依赖／高度依赖／优质客户／标杆客户／大客户背书／客户质量高／深度绑定／绑定龙头／护城河／粘性强／订单饱满／业绩确定性，一律零命中；改数词（约／左右／大概）不得替数字打底。要写只能同行挂 `[待人工]`。
  - 道四 `E-COVERAGE` 未取到两向点名：正文写了未取到而第五节没列发红，第五节列了而正文没有这条表述同样发红；两向都按**名目同指**对（剥括号注与标点后，字面全等／一方完整含另一方且短的一方 ≥4 字／汉字集合重合率 ≥0.6），同一件事换个写法不判红。
  - 道五 `E-SCOPE` 边界：`集中度口径：` 写成「招股书」时点名改走 `prospectus-digest-cn`，写成「产业链」时点名改走 `cn-supply-chain-map`，不是只报形制错。
- 红线里那条收窄（写进件内，防后人放宽）：**裸「依赖」不收**——「公司对前五大客户存在一定依赖」是年报原文的事实陈述，照常登记；只收「严重依赖／过度依赖／高度依赖」这种加程度的判断。裸「集中」不收，只收「风险可控／风险不大」这种下结论的形。runner 档⑤ 的「事实陈述不误红」与「判断词必红」成对钉住这个收窄的两个方向。
- 改数词判据的位置（首版实现时踩过，写在这里防回退）：HEDGE 检查**必须排在形制匹配之前**，且两个数据行正则要给占比前后的改数词留位（`(?:约|大约|大概)\s*` 与 `(?:左右)?`）。否则「约 27.85」会让 `\d+` 失配、形制分支先命中并 `continue`，改数词那条判据永远够不着，runner 档⑤ 会变成「只报形制、不报改数词」；同时该行会被悄悄排除在合计自洽之外，占比之和少算一行。2026-11-09 首轮探针即此实发。
- 零通道那一头：`scripts/make_outline.py` 把材料清单排成一张待填骨架，第二节留一行合计待填位、第三节留一行单客户待填位、第四节留一行依赖事实待填位，第五节逐条点名，集中度一句话留占位。**代价同句写清**：缺的正是公告检索与原文解析那一层，所以骨架只会有形状、不会有权衡后的集中度事实——骨架过不了机检是设计，不是待补的疏漏。材料清单里非法 JSON 行、缺键行、日期不合形的行一律未采信并逐行点名，不静默跳行；一条可用行都没有时退 1。
- 离线 runner（`scripts/fixtures/run_fixtures.sh`，零网络、零计费、产物只落临时目录跑完即删）五档：① 机检自测（好样 1 枚 + 坏样七道 7/7 + 钉阈三形 + 反证四档 + 本域四形 + 临时根自清）② 好样与七枚坏样逐枚单跑，每枚报它自己的退码与码集，不并成一个总数 ③ 零通道骨架 ④ 骨架过机检须红在集中度一句话占位那一行 ⑤ 边界形逐枚单跑（口径写招股书→道五点名／口径写产业链→道五点名／口径值认不出→形制红／判断词必红／事实陈述不误红／改数词必红／匿名客户具名必红／占比大于合计必红）。末行自报「档数=5｜不合=N｜不可判=N」；退码 0 全合期望、1 有不合、3 取值域故障（脚本或夹具取不到，不读成「零违例」）。
