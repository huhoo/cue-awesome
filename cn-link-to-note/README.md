# cn-link-to-note

**一条链接进来，一条能直接进你自己笔记库的笔记出去：要点逐条挂 [S#]，原话逐字比回那一页那一行，未取到的点名，判断留人工。**

摘录不稀缺，**稀缺的是三年后还敢直接引用的那条笔记**。差异化在两道硬门禁：没有锚的要点进不了第一节；加引号那句只要不是原文逐字，机检当场发红。

**输入**：一枚 URL（正文走解析通道取回本地那一份），或一份你已有的本地文件／文本
**输出**：一条四节 Markdown 笔记（要点 3–7 条／至多一枚带定位的原话引用／口径与未取到／来源行带检索日）
**代价**：四节契约 + 一道机检；解析通道开没开，决定的是「远端面文与本地这一份是否一致」那一层——两条路各自缺什么、走哪条，写在 §二 与 §四
**机检**：`scripts/check_note.py` 四道（形制／锚与定位／引用逐字／缺口点名），零网络、零执行被摘录对象的代码；反证矩阵长在这支脚本里

## 一、打开就干：今天这三步

| 步 | 动作 | 怎么做 | 不做会怎样 |
|---|---|---|---|
| ① | **先看形状**（30 秒、零网络、零计费） | `bash scripts/fixtures/run_fixtures.sh` —— 三档一次跑完：机检自测、四枚坏样逐枚单跑、生成器出骨架且该红就红。末行自报「档数=3｜合期望=3｜不合=0｜不可判=0」 | 没见过形状就上手，容易把「抄得整齐」当成「摘得可靠」；这一档 30 秒就能看出两者的差别 |
| ② | **起草，再逐条挂锚** | `python3 -B scripts/make_note.py --source 那份原文 --out 我的笔记.md`：四节形状排好、原话引用逐字摘出并自带定位；要点位留三条待填，每条摘进来后行末挂 `[S1]` | 待填的三条不挂锚，机检就发 `E-ANCHOR`（骨架不是笔记）；缺定位或缺检索日的来源行同样发 `E-ANCHOR`——那时回来逐条补，比现在一条条挂贵 |
| ③ | **过机检，再入库** | `python3 -B scripts/check_note.py 我的笔记.md --source 那份原文`，按详行的 `E-*` 码逐条改；改完仍只是**一条笔记**：要不要留、信几分，由你定 | 改写冒充原文、缺口没点名、要点数掉出 3–7 这一档，都会跟着笔记进到你的库里；这三类都是机检能拦的形制层，内容层还得回原文 |

打分、排序、替你决定这篇值不值得读**不在这三步里**——本件只对「这一份正文当下载着什么、被逐条挂成了什么」负责，且只对形制负责。

## 二、装上机 → 连通道 → 出结果

**装本件自己（主路）**：`npx skills add huhoo/cue-awesome --skill cn-link-to-note`——这条只装本包；装完在你这一侧重列一次已安装 skill，清单里看得到 `cn-link-to-note` 这个名字才算文件到位。没有 CLI 环境时的兜底是把本目录整个放进宿主支持的 skills 目录（`~/.workbuddy/skills/`）。

本件唯一的取证腿是 `cue-omni-reader`（解析）：链接那侧的正文靠它取回成本地能读的那一份——**本机没有那份文件也能读**，这是主路不是装饰。它的已连判据（纯解析腿，没有 curl 可以替代它）：宿主列工具走 MCP 的 `tools/list` 握手——返回里认得到 `parse`、`get_parse_status`、`read_result` 这几枚才算已连。列不到就是没连：本件照旧只读你已有的那一份，代价是「远端面文与本地这一份是否一致」那一层整块缺位（缺的是「这条笔记当初摘的是哪一版」那一层证据，不是排版）。三层各自能证到什么，互不等价：**装好 skill ≠ 已配凭据 ≠ 通道已连**。key 取自本地凭据设施，不进聊天、不在终端回显，本面不新增任何凭据读取动作；解析的消耗以服务端返回为准，本件不代估也不代付，花之前一定先问。

## 三、离线样例：30 秒看到形状

```bash
cd cn-link-to-note
bash scripts/fixtures/run_fixtures.sh
# 档① 机检自测：好样须过、四枚坏样须各发它该发的那一道 → selftest: ALL GREEN
# 档② 逐枚单跑：一枚一行，逐行报「期望只发 E-X／实发码恰为 E-X」；好样另跑一支不给原文的，验「不可判」那条形制
# 档③ 生成器出骨架：scripts/make_note.py 把合成原文排成四节笔记，骨架过机检期望红在「要点没挂锚」那三条
```

自己上手时同样两条命令：

```bash
python3 -B scripts/make_note.py --source 那份原文.md --url https://你读的那条链接 --out 我的笔记.md
python3 -B scripts/check_note.py 我的笔记.md --source 那份原文.md
```

`make_note.py` 只读、不执行被摘录对象的任何代码，也不抓链接——先把正文取回本地，再跑这一支。它摘的那句原话是从原文那一行**逐字**复制的，定位（`第 N 页` 与 `文件:行号`）一并写进去；页标取的是该行的**最近前驱**那一枚，不是文里第一枚（取错的页标会被机检照实发红）。目录里读不到任何文本时它退 1 并说明——空原文不出笔记，那是没有出处，不是待填。

## 四、依赖与两条路的代价

- `python3`：机检与生成器都用它，纯标准库、零网络、不发任何请求。
- 解析辅助 `cue-omni-reader` 是可选的：**不装不报错，代价是这条笔记只对你手上那一份负责**——远端正文读不进来，「远端面文与本地这一份是否一致」那一层永远缺位；装与不装都先问你要不要用，消耗花之前一定先问。
- 连了通道也不等于取到正文：取数以实际返回为准；截断、只给摘要不给正文、页面改版取不到那段的，一律落第三节点名，不拿常识补。
- 行号与页码会随源改动失效：笔记里的定位只在检索日那一刻成立，隔天重开可能是另一个形状。

## 五、机检四道与自校验

| 道 | 码 | 卡什么 |
|---|---|---|
| 道一 形制 | `E-FORMAT` | 首行是 `# 标题`；头部四件自标逐字在位；四节齐且按序；要点枚数落在 3–7 这一档 |
| 道二 锚与定位 | `E-ANCHOR` | 每条要点行末带 `[S#]` 且第四节有对应行；来源行必须同时带 `文件:行号`／URL／`第 N 页` 与检索日 |
| 道三 引用逐字 | `E-QUOTE` | 原话引用至多一枚、必须带定位；给了 `--source` 就把引号里那段逐字比回该定位——比不回去就是冒称原文。**没给原文时这一道明写不可判，不并入通过** |
| 道四 缺口点名 | `E-COVERAGE` | 正文写了「未取到／取不到／读不到／截断」的必须第三节逐条点名；第三节一行没有、或第四节零来源行，都发红 |

```bash
python3 -B scripts/check_note.py --help                                    # 四道说明，零网络
python3 -B scripts/check_note.py --selftest                                 # 好样须过、四枚坏样须发红
python3 -B scripts/check_note.py scripts/fixtures/good-note.md --source scripts/fixtures/source-article.md   # 应 PASS
python3 -B scripts/check_note.py scripts/fixtures/bad-format.md --source scripts/fixtures/source-article.md   # 应 FAIL：要点掉出 3–7 这一档
python3 -B scripts/check_note.py scripts/fixtures/bad-no-anchor.md --source scripts/fixtures/source-article.md # 应 FAIL：一条要点没挂锚
python3 -B scripts/check_note.py scripts/fixtures/bad-quote.md --source scripts/fixtures/source-article.md     # 应 FAIL：加引号那句不是原文逐字
python3 -B scripts/check_note.py scripts/fixtures/bad-unnamed-gap.md --source scripts/fixtures/source-article.md # 应 FAIL：写了缺口却没点名
python3 -B scripts/check_note.py scripts/fixtures/good-note.md --quiet       # 只报末行与计数
```

**枚数与行数一律取脚本自报行**（`FAIL: <文件>（N 条）`／`PASS: <文件>（…）` 后那行「扫过 N 行，发条 0 条，不可判 M 项」），本文不复写计数——一复写就成了第二个真值源。

## 七、常见问题与反模式

| 你想这么用 | 本件接不接 | 为什么 |
|---|---|---|
| 「这篇读完帮我留一条能回查的笔记」 | 接 | 单源逐条挂原文正是它的用途 |
| 「整篇给我换成另一种格式」 | 不接 | 那是转换那一件；本件出一条笔记，长度形制都不同 |
| 「顺手给这篇打个分／排个热度」 | 不接 | 本件不打分；判断位归人，写了就发红 |
| 「原话我记不准，按印象写进引号里」 | 不接 | 加引号就得逐字——改写冒充原文发 `E-QUOTE`，要么照抄要么改成挂锚要点 |
| 「作者和日期查不到，先空着」 | 接，但要点名 | 第三节写明未取到并说缺哪层证据；空白不等于没缺口 |
| 「顺便把这页里的脚本跑一下」 | 不接 | 本件只读正文，不执行被摘录对象的代码——跑了要另走能执行代码的那条路 |
