# meeting-minutes-cn

**会议录音进，每个字都对得回原话的纪要出：逐字带 [mm:ss] 时间锚，话题归段自标「此归类非原文所有」，决策与待办逐条挂原话锚，说不清的全挂 `[待人工]`。**

不实时、不改写、不补没说的话——也不凭记忆给人起名。素材面只有一条：本地录音文件（闸按**单件字节**准入，上限以通道自报的 max_bytes 为准，不按时长拦）或可解析链接，形制与大小以通道返回为准；实时转写不在本件能力内。

**输入**：录音文件路径（Bridge 授权目录内）或可解析链接——Bridge 是 `cue-omni-reader` 的本地通道件，装法与目录授权以该件自己的面为唯一出处，本件不复述一份；可选议程／白板图（同走解析）
**输出**：`assets/会议纪要卡.md` 填好的一张卡——基本信息、逐字带锚、话题分段、决策与待办、待核清单
**代价**：前两段只依赖通道返回；归段与待办整理按需再做
**机检**：`scripts/check_minutes_card.py` 四道（形制与边界申报／锚／红线／计数与申报），零网络

---

## 一、打开就干：今天这三步

这三步是本件唯一的「现在就要做」。第一句可以照抄：**「整理这段录音，先出逐字和待办。」**

| 步 | 动作 | 怎么做 | 不做会怎样 |
|---|---|---|---|
| ① | **先报素材形制** | 头部填录音来源，并在「单段／切片／整场直投·已停用」里勾一个，再勾时间轴基准（单切片内 mm:ss／多切片拼接·跨片未建立实证） | 超闸的单件直投会撞在字节闸（max_bytes=268435456）上白等一场——闸按时长不拦，字节数在闸内的整场音频有 1 例走完，那只是一例；跨片不声明，锚就会被当成能横着比的证据 |
| ② | **逐字先带锚** | 每段原文配一个 [mm:ss]；谐音、误听**照原样抄**并挂进第五段待核 | 没有锚的纪要就是转述，回查无路；把谐音「洗干净」等于伪造原话 |
| ③ | **决策与待办逐条挂原话锚，再跑机检** | 每条＝结论句＋负责人（录音自报才写）＋ [mm:ss]；然后 `python3 scripts/check_minutes_card.py 我的卡.md` 按 `E-*` 码改 | 「这事谁负责」变成猜测，纪要带着猜测发出去，收的人无从核对 |

话题归段与决策抽取**排在这三步之后**：前者是笔记法，后者要原话撑腰，都快不得。

## 二、五段纪要与四道机检

| 段 | 内容 | 机检卡不卡 |
|---|---|---|
| 一 基本信息 | 会议名／日期／时长／说话人数／材料——日期取自录音内自报或用户给定，无则标「缺」 | 卡：有内容无依据发 `E-ANCHOR` |
| 二 逐字带锚 | 分段原文 + [mm:ss]，不改写不概括 | 卡：无时间锚发 `E-ANCHOR` |
| 三 话题分段 | 每段挂起止双锚，并自标「此归类非原文所有」 | 卡：单点锚、没自标分别发 `E-ANCHOR`／`E-COVERAGE` |
| 四 决策与待办 | 结论句＋负责人＋原话锚；负责人只在录音自报时写，否则「未自报·待核」 | 卡：无原话锚发 `E-ANCHOR`；负责人裸写发 `E-ANCHOR`；「大家都同意」无锚发 `E-BANWORD` |
| 五 待核清单 | 谐音疑点、指代不明、跨片锚，一律 `[待人工]`；每行状态格是**待核／已核 二选一**——同勾两枚发红并点名第几行，两枚都空算尚未复核（放行） | 卡：缺 `[待人工]` 汇总发 `E-COVERAGE` |

头部另有一组硬要求：**「AI 整理纪要」「决策请对回原话确认」两件套**＋录音来源已填＋素材形制三选一已勾＋时间轴基准已勾，缺一即 `E-FORMAT`；勾了「整场直投·已停用」却还有逐字行＝自相矛盾，也发 `E-COVERAGE`。 **同一字段的申报可以写在下一物理行**（行首缩进或全角空格起头即算续写，仍属同一字段）：闸按「这个字段中了几项」判，不按「勾落在第几行」判，所以把第二个勾挪一行不会变成合规，详行会点名勾落在哪几行。

### 首次开通 Cue（三步，可跳过）

本件的取证腿是一条：音频与视频件的解析（omni），本地件按字节准入、上限由闸自报。
**不装不报错**，代价是纪要卡只剩手填那一层——可以照样过机检，但未开通道时没有逐字稿、没有 [mm:ss] 锚与说话人标签，出处也回查不到——那些只来自通道返回，本件不猜形制，也不伪造 ASR 谐音后的「清洗版」。

1. 注册 <https://cuecue.cn>（新账号注册送 500 积分、每日 10 积分，以服务端为准）；
2. 在 <https://cuecue.cn/hub/api-key> 取 `CUE_API_KEY` 存入本地凭据——**不要贴进聊天**，agent 不经手密钥；
3. 安装本件取证用到的一枚 skill：`cue-omni-reader`——纪要卡的逐字、[mm:ss] 锚与说话人标签都来自它的返回。这些都由 Cue 官方技能集合（sensedeal）发布，一条命令两种写法：
   - 整套：`npx skills add sensedeal/cue-skills`（它会列出该集合公开的各枚 skill，按提示挑要装的）；
   - 单装：`npx skills add sensedeal/cue-skills --skill cue-omni-reader`。

   装完把三件事分开自查，它们互不等价：**装好 skill ≠ 已配凭据 ≠ 通道已连**。
   - 装好＝你这一侧重新列一次已安装 skill，清单里能看到上一步那几枚的名字（这只证明文件到位，不证明取到数）；
   - 配好凭据＝第 2 步那把 `CUE_API_KEY` 存在于本地凭据设施即可——不要把它的值贴进聊天，也不要在终端回显；
   - 已连＝带上那把 key 按目标域 `routing` 里的 `url` 实连（`Authorization: Bearer <$CUE_API_KEY>`，并带 `Accept: application/json, text/event-stream`——缺这个头会 406，是协议行为不是鉴权失败；上一格判的是那把 key 在不在本地凭据设施里，**它被不被服务端接受，要到这一格才判得出**），且 `tools/list` 有返回。怎么问：向该域 `routing` 给出的地址发一个 JSON-RPC 的 `tools/list` 请求。算通过的回字：HTTP 200，且返回体里 `result.tools` 非空（逐字形如 `{"result":{"tools":[…]}}`，工具名与入参 schema 就在那一格里）——**工具清单以那份返回现值为准，本件不预先承诺有哪几枚、也不硬编码工具名**。匿名 `GET` 块里那枚 `CATALOG` 拿得到当场返回**只证目录可达**，本件不把它叫「已连」：它给的是各域 `external_status` 与 live 域的 `routing`，返回里没有的域本件不装也不承诺。连接报错≠域无数据，如实报，只重试错误标明可重试的部分。

   ```bash
   CATALOG="https://cuecue.cn/api/mcp-catalog"
   curl -s "$CATALOG" | python3 -c 'import json,sys
   rows=json.load(sys.stdin)["data"]["domains"]
   [print(r.get("id"), r.get("external_status"), (r.get("routing") or {}).get("url", "-")) for r in rows]'
   DOMAIN_ID="<把这里换成上一行列出的那个域 id>"
   ROUTING_URL="$(curl -s "$CATALOG" | python3 -c 'import json,sys
   rows=json.load(sys.stdin)["data"]["domains"]
   hit=[r["routing"]["url"] for r in rows if r.get("id")==sys.argv[1] and r.get("routing")]
   print(*hit,sep="\n") if hit else sys.exit("未取到：该 id 不在目录现值里（或它没有 routing 里的 url 字段）——先跑上面那行列出现场的 id 再填")' "$DOMAIN_ID")"
   [ -n "$ROUTING_URL" ] || { echo "取值失败：ROUTING_URL 为空——先跑上面那行列出现场 id，再把 DOMAIN_ID 换成其中之一" >&2; exit 1; }
   curl -s -X POST "$ROUTING_URL" \
     -H "Authorization: Bearer $CUE_API_KEY" \
     -H "Accept: application/json, text/event-stream" \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' \
     -w '\nHTTP %{http_code}\n'
   ```

   块里 `CATALOG` 是本面唯一一处目录入口字面（赋一次、散文不重抄）；`ROUTING_URL` 由上面那两行现取——取的是该域 `routing` 里的 `url` 字段逐字值，本面不硬编码域名或路径，凭据变量取自上一层那把本地凭据（不进聊天、不在终端回显），本块不新增任何凭据读取动作。通过判据仍以那句为准，本块不另立第二套。
   一句现场精度：这处端点可能以 SSE 形回字（一行 event、紧跟一行 data），要看的 result.tools 就在那条 data 载荷里——判据不变，只是回字在外层多包了一层。
   一条命令形（不必手改块里那一行）：`cd meeting-minutes-cn && python3 -B scripts/cue_connectivity_check.py --domain <你的域 id> --post`。这支随包件缺省一个包都不发——不带 --post 时只把该域 routing 里的 url 取出来给你看；有哪些域 id 可填，先跑同一支脚本的 `--list`（只列在场域与 url，不发 POST）。本件不另立判据：退码 0，退 4＝还没证过连通（带上 --post 再跑一次），退 5＝连上了但现场值没满足它，退 1＝取不到、发不出去、或 HTTP 层报错（含 4xx 与 5xx），退 6＝目的地没过凭据外发两关（本件拒发，一个凭据字节都不附），退 7＝目录入口本身不是 https。按默认目录入口时，本件只验运行端点连通，不向渠道发布、不产生受理。**换源不免检**：无论那个 url 来自缺省目录、--catalog-url 还是 --catalog-file 那份快照，带 key 那一次发出去之前都要过同一道两关——scheme 必须是 https，且 host 命中授权后缀（缺省那一枚由件头那处目录入口现值推出，不是本件另编的一张清单；要显式放行别处请带 --allow-host）；过不了就拒发，并把拒绝原因与那个 host 印在回字里，本件不读 key、也不构造那个请求。代价同句写明：老的「换进去什么就打什么」那一形关掉了，换来的是凭据不会外发到未授权目的地；若你的正当端点恰在授权后缀之外，退 6 是请你用 --allow-host 显式认下它，不是断言那枚端点不该存在。

解析类消耗**花之前一定先问**：发起前报要解析几份、各是什么，等你确认；先报的是耗时量级与这笔消耗是否发生，不是报价格——计费状态以服务端返回为准，本文不给任何价格（机检对价格字面直接发红）。

装本件自己：npx skills add huhoo/cue-awesome --skill meeting-minutes-cn（这条只装本包；装完在你这一侧重列一次已安装 skill，清单里看得到 meeting-minutes-cn 才算文件到位）。手动放置也行：把本目录复制进宿主的 skills 目录（如 ~/.claude/skills/meeting-minutes-cn）。

## 四、边界与不承诺

- **实证边界只有一句话：拦人的是字节数（单件 ≤256 MiB，实测闸值 268,435,456 字节），不是时长。** 这条有 av-backtest 实测账（两场次共三枚 90 秒切片走完解析到导出全链、逐字回查 8/8）；被闸拒的是两形——公开全长视频 URL 路五枪全拒，本地整场件超 `constraints.max_bytes` 即拒（同一场会的整场视频 1,406,940,817 字节那一枚就撞在这里）。与之相对，同一场会的整场**音频**（87 分钟、21,060,472 字节，未超闸）本地直投走完并出了整场五段纪要（详见 §五）。所以被拒的是**超字节与 URL 两形**，不是时长本身；超限就停用并说明理由，不硬试、不假装读到了。
- **整场录音直接投喂＝未臻（上一条那枚整场音频除外）**：系统化长会样本未做，跨素材连续与真实表决分工面也未覆盖，故长会仍建议先切片——这不是「长会可用」的宣称。
- **切片之间不假设连续**：av-backtest 的 limits 明写「per-split stitching／timestamp continuity 未建立」。多切片拼接的卡必须勾「跨片锚一律标待核」——机检认这个声明，也不校验跨片时间轴：未在证的面上不建闸。
- ASR 谐音**原样入纪要并标待核**，本件不冒充清洗过的转写；通道返回什么锚形制（[画面 mm:ss]／[说话人 mm:ss]／（幻灯片标题））以实际为准，本文不锁形制清单。
- **不实时**：实时转写、边录边转不是本件的面。**不改写**：润色、「漂亮版」、美化改写一律不做。
- **人名不凭记忆补**：参会人只在录音自报时引用；说话人标签以通道返回为准，本件不给人起名。
- **计费与可用性以服务端返回为准**，本卡与本文都不写任何价格数字（机检对价格字面直接发 `E-BANWORD`）。
- **分发前一次显式确认**：纪要里的每条决策与待办，发给团队前把「对象＋后果＋时点」复述一遍并取得明确回应；「好的」「嗯」「行」这类单字应答不构成确认。没做成之前，不写「已经帮您发出去了」这类完成时话术。
- 输出头部的两件套不是免责装饰，是第五段存在理由的重述：决策请对回原话确认。

## 五、出错了怎么办（症状 → 原因 → 恢复动作）

**未见于本次返回的一律写「未检索到」**：参数名、字段名、枚举值没有出现在本次工具返回里的，不得凭印象填写；写「未检索到」并记入待核清单或覆盖率账，不得留空顶替。

**Error 级＝blocker**：机检报出的 Error 级条目不得称「无害」「可忽略」「先交出去再说」；修完，或在交付面显式申报，才算出口。

出口形制按 `check_minutes_card.py` **当前出口**现跑取得：失败是一行 `FAIL: <文件>（N 条）`，其下每条详行**先打错误码前缀（四枚 `E-*` 之一）**（如 `[E-FORMAT] [边界申报]`、`[E-ANCHOR] [负责人]`、`[E-BANWORD] [清洗冒充]`），道名后是行号与该道规格；末行 `码表:` 只列本次真正用到的码与含义。全过印 `PASS: <文件>（…）` 并附「扫过 N 行、发条 0 条」两类计数。

本件用**四枚**码，与姊妹件的码表逐字同源（姊妹包不随本发布物交付，比对须回仓内看）；第五枚 `E-LEDGER` 属账本状态机面，本件无账本，故明写不启用（不是漏配）。全集与归类规则以脚本现值为准，任意目录整行粘贴即可定位：

    grep -n "^E_LEGEND" ~/.workbuddy/skills/meeting-minutes-cn/scripts/check_minutes_card.py

| 症状（详行前缀） | 原因 | 恢复动作 |
|---|---|---|
| `[E-FORMAT] [头部] / [来源]` | 两件套缺件，或录音来源仍是占位 | 补齐头部；来源只填授权目录内路径或可解析链接——来源不填，锚无处可回 |
| `[E-FORMAT] [边界申报] / [时间轴] / [五段] / [状态互斥]` | 素材形制或时间轴基准没勾，五段缺序；待核行状态格「待核／已核」同勾 | 三选一并勾选；整场直投就勾「已停用并说明理由」；跨片就勾「跨片锚标待核」；状态格二选一，两枚都空算未复核（不报） |
| `[E-ANCHOR] [基本信息] / [逐字] / [段锚] / [决策锚] / [负责人]` | 有内容没有时间锚；话题段只有单点锚；负责人裸写名字 | 补 [mm:ss]；段锚改起止双锚；负责人写「说话人N 自报 [mm:ss]」或「未自报·待核」——**补不出锚就删该行，不猜** |
| `[E-BANWORD] [越界] / [清洗冒充] / [改写] / [外推] / [价格]` | 写了实时面；声称已清洗校对；做润色；「大家都同意」无原话锚；出现价格数字 | 删实时话术；谐音照原样并挂待核；只忠实原话；补原话锚或删该句；价格一律交给服务端返回 |
| `[E-COVERAGE] [停用矛盾] / [逐字空] / [归段自标] / [申报]` | 勾了停用却有逐字行；没停用却零产出；归段没自标；待核段缺汇总 | 停用与产出二选一；没取到就勾停用并说明；每段勾「此归类非原文所有」；第五段补 `[待人工]` |

## 六、怎么开口（触发示例：三条正例 + 一条反例）

**开口请带上日期，输出标会议日期与录音时点**：请求里说明这场会哪天开的、录音是哪一段；成品首行标注**会议日期与录音时点**，当它与用户所指日期不一致时，正文禁用「今日」「最新」，一律改写为「截至 <日期>」。

| 正例 | 会得到 |
|---|---|
| 「整理这段录音，先出逐字和待办，每句带 mm:ss」 | 第一、二段：带时间锚的逐字＋基本信息；待办随后 |
| 「会上都定了哪些事，谁认领的，只按录音里说过的」 | 决策与待办表，每条挂原话锚；没自报的一律「未自报·待核」 |
| 「这段录音里这个词我听不清，先标出来别改」 | 待核清单挂 `[待人工]`，谐音原样保留 |
| **反例：「帮我把纪要改写得漂亮点，顺便把没说完的补全，再算下这次转写多少钱」** | 本件不做。润色与外推被机检拦下，价格不进任何面；实时面也不是本件能力 |
