# dd-checklist

**[中文](README.md) · [English](README.en.md)**

**公开信息能替你尽到什么程度？** 这份清单的答案是：**能查到的逐条带锚摊开，查不到的逐类写清是「域面没工具」还是「窗口内零条」**。它不给结论——结论位是三行 `[待人工]`。

给「唯一主体 + asof + 回看窗口 + 用途档位」，还你一张固定七列的风险事实表：每条都能回指一条在场披露（公告号 / 函件号 / 裁判文书号 / URL / 研究件 / 法条原文），外加一份九类覆盖率对账表和全链证据快照。
本件最大的敌人不是漏查，而是**编一条看起来像的风险**——所以入类第一闸写死三条：有在场锚、有在场日期且落在窗内、归属可判；任一不满足即不入表，进账。

**输入**：`--subject`（唯一主体）· `--asof` · `--lookback`（如 `36m`，必传）· `--purpose`（investment/credit/mna）· `--sources` · `--evidence`——六参数全必传
**输出**：`dd-<代码>-<asof>/` —— `report.md` · `sources.jsonl` · `evidence/`（含 `LEDGER.sha256`）· `references/coverage-map.md` · `progress.md`
**代价**：五段管线 + 一道八层门禁；深研按缺口发起（发起前报耗时与消耗），计费一律以服务端返回为准

## 一、是什么 / 不是什么

| 你要 | 用什么 |
|---|---|
| 单一主体一段窗口内的公开面风险事项，逐条带锚 | **本 skill** |
| 见客户前多主体速览 | 姊妹件 `tear-sheet` |
| 未来窗口的确定日期 | 姊妹件 `catalyst-calendar` |
| 财报深度点评与兑现度对账 | 姊妹件 `cn-earnings-note` |
| 投资结论、法律定性、宣称「已查全查尽」 | 不做——判断位留白，这三类措辞本身就是机检级禁语 |

## 二、四条为什么钉死

- **锚只认最后一列**：把公告号写进事实列不补位，把金额写成「像事件号」的数字也不算锚。宁可这行空着，不可那行有锚的幻觉。
- **未检到要分三种**：无工具（域面外，需人工/商用库）／零条（查了，窗内没有）／未发起（本次没查）。把第一种写成「该公司无 X」是本件的红线。
- **证据 fail-closed**：`evidence/` 缺失、为空或哈希对不上即不交付，不放行「先交后补」。表内每一行的锚都要能在快照里逐字找到——法定推导行更要找到法条原文。
- **日期算术零自由**：「报告期后 N 日内应披露」这类推导，只有当场取回法条原文（法名+条号+短引三件齐）才落行；`statute` 域不含部门规章与交易所规则，所以这条路径当前**预期零锚**，取不到就拒推并在台账写理由。

## 三、快速开始（三步）

1. **装**：本目录放进 agent 的 skills 目录。
2. **说**：「给我做一份北辰股份近三年的公开信息预尽调清单」——缺窗口或用途档位会被反问，不会替你猜。
3. **收**：五段管线跑完过门禁：

   ```bash
   python3 scripts/check_dd.py report.md \
     --subject '北辰股份有限公司（600001.SH）' --asof 2026-09-21 --lookback 36m --purpose investment \
     --sources sources.jsonl --evidence evidence
   ```

   八层诊断码（`DD-INPUT/DD-TABLE/DD-ROW/DD-REDLINE/DD-COVERAGE/DD-EVIDENCE/DD-STATUTE/DD-OMISSION`），**不过不出**。题库自跑：`bash scripts/fixtures/run_fixtures.sh`。

## 四、首次开通 Cue（三步，可跳过）

注册 <https://cuecue.cn>（新账号注册送 500、每日 10，以服务端为准）→ <https://cuecue.cn/hub/api-key> 取 `CUE_API_KEY` 入本地凭据（**别贴进聊天**）→ 装 `cue-data-mcp`（`cue-omni-reader` 按需）。
不装也能跑：你贴披露原文，agent 组织成表并标「用户直供（L2）」——但覆盖率账会如实写明「本次未经域直查」，这份清单的价值恰好在那张账上。
