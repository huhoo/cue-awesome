# 覆盖率对账表模板（dd-checklist）

**每次运行**把填好的表写到输出目录的 `references/coverage-map.md`（机检 `DD-COVERAGE` 读的就是这个路径）；本文件是模板与规则，不是产物。

对账表回答的问题只有一个：**这次到底查了哪些域、每域拿到几条、哪些域根本没有工具**。它是 README「当前状态」诚实清单的母本——对外能说到的边界，不超过这张表。

---

## 1. 固定表头与取值

| 列 | 取值 |
|---|---|
| 类目 | §3 的九项封闭枚举，逐类一行，一类都不能省 |
| 所需域/工具 | 该类目本次依赖的域名；无工具时写 `—` |
| 本次实际调用 | 实际连上的域名；未发起时写 `—` |
| 结果 | 封闭三值：`检到 N` / `零条` / `无工具` |
| 注记 | 有锚项写锚；`无工具` 必须写「域面外，需人工/商用库」类说明 |

```markdown
| 类目 | 所需域/工具 | 本次实际调用 | 结果 | 注记 |
|---|---|---|---|---|
| 股权与控制权 | entity_data | entity_data | 检到 0 | 无新增带锚事项 |
| 合规与处罚 | regulatory_cn | regulatory_cn | 检到 1 | AN202605100000000001 |
| 诉讼与仲裁 | disclosure_cn | disclosure_cn | 检到 0 | 公开披露检到零条 |
| 财务与披露质量 | fr_fact_index | fr_fact_index | 检到 0 | 公开披露检到零条 |
| 关联交易与资金占用 | disclosure_cn | disclosure_cn | 检到 0 | 公开披露检到零条 |
| 业务资质与许可 | disclosure_cn | disclosure_cn | 检到 0 | 公开披露检到零条 |
| 人力与社保 | — | — | 无工具 | 域面外，需人工/商用库 |
| 上市与在审状态 | ipo | ipo | 检到 0 | 公开披露检到零条 |
| 其他已披露重大事项 | disclosure_cn | disclosure_cn | 检到 0 | 公开披露检到零条 |
```

## 2. 三条「未检到」的区分（不可混写）

| 形 | 含义 | 允许写法 |
|---|---|---|
| **无工具** | 公开域面里没有能答这个问题的工具 | 「域面外，需人工/商用库」；**禁**写「该公司无 X」 |
| **零条** | 域有工具、查了、窗口内检到 0 条在场披露 | 「公开披露检到零条（窗口内）」 |
| **未发起** | 本次没查（省时省耗或依赖缺失） | 「本次未检索，不构成任何结论」——不得进结果列，写进 `progress.md` |

## 3. 机器核什么（与 `check_dd.py` 一一对应，承 §v2-2）

- 九类**逐类有账且唯一**：少一行 → FAIL；同一类目多行 → FAIL（未列类目不等于零条，重复行也不等于两条账）；
- 结果列取值封闭 `检到 N | 零条 | 无工具`：越界写法（`无`、`N/A`、`未见`、**`未发起`**）FAIL——「本次没查」只能写进 `progress.md`，不许填进结果列；
- 标 `无工具` 的行必须注「域面外 / 需人工」；全表至少要有一行域面外明示（本件公开面必有能力边界，写不出边界=没查清）；
- **零条目的三条件（§v2-2，防「未发起」伪装成「查了是零」）**：
  ① 「本次实际调用」非空且取值在本件域枚举内；
  ② evidence 里有该域的原始结果快照，且**件内标出这条账属于哪个类目**（`"category": "<类目>"`；快照与台账 `LEDGER.sha256` 同规则，哈希可核）；
  ③ 正文「本节检索域」行列出的域，必须是本表「本次实际调用」集的子集，且 `N 域` 须等于实列域数；
- 正文每类的行数与本表 `检到 N` 计数互校：本表记 `零条/无工具` 而正文有行 → FAIL；记 `检到 N` 与正文行数不等 → FAIL；
- **反沉默漏报（§v2-10，发码 `DD-OMISSION`；题单 §0.3 明写此码不得折回 `DD-COVERAGE`——本族只管账的形制与账↔正文计数）**：本表每行的 N 不得低于 `evidence/calls.jsonl` 里该类目的原始命中 M；N<M 须在 `progress.md` 逐条写 `降级: <类目> | <锚或查询串> | <窗外/归属不判/非本主体>`；「本次实际调用」是合法域却查无流水行、流水链 `seq`/`prev_sha256` 断裂或被回写、流水指向的快照被删/哈希被改，都是 `DD-OMISSION`——**删证据不等于没查过**；但链只证同一次交付自洽，整链重写须靠服务端回执与人工抽 3 对原文对抗（SKILL §7.8）。
- **零行表是合法交付**（九类账齐 + 每类零结果证据齐 = 诚实的「本次没查到」），但缺①②③任一即按伪装零条 FAIL——机器分开的正是「真查了」与「没发起」。

## 4. 用途档位（`--purpose`）对账加严

三档共用同一九类枚举，只在**取数面**加严，不扩判定权：

- `investment`：默认九类全开；
- `credit`：`关联交易与资金占用` 须额外覆盖担保总额与被担保对象、资金占用与清占（拿不到就记「无工具/零条」，不得沉默）；
- `mna`：`股权与控制权` 须额外覆盖控制权与一致行动、同业竞争、并购史与业绩承诺补偿。
